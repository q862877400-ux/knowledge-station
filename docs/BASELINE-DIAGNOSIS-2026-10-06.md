## 一、跨文档引用：**抽到了，也存下来了，但没有连成边**

### 1.1 事实

| 项 | 数 |
|---|---|
| 正文里提到【其他标准号形态】的条款 | **63,162 条（12.1%）** |
| 分布在 | **6,107 篇**（全库 6,797 篇） |
| `evidence_edge` 总边数 | **13,606** |
| 边类型 | **全部是 `reference_relation`** |
| **同文档边 / 跨文档边** | **13,606 / 0** |
| 有出边的条款占比 | **11,392 / 522,021 = 2.2%** |

**样本（证明跨文档引用真实存在）：**

> 「**2 规范性引用文件** 下列文件中的内容通过文中的规范性引用而构成本文件必不可少的条款… **GB 2894** 安全标志及其使用导则 **GB/T 3608** 高处作业分级…」
> 「4.3 进入作业现场的人员应正确佩戴满足 **GB 39800.1** 要求的个体防护装备。」

### 1.2 机制（代码层，已读原文）

`src/core/ingestion/law_text.py`：

```python
number_to_id: dict[str, str] = {}          # L163：建的是【本文档】的「条款号 → 条款 ID」表
for no, body in articles:
    number_to_id[no] = cid                 # L169

for m in models:                           # L184
    for ref in m.cross_refs:
        raw_edges.append(("reference_relation", m.clause_number, ref))   # L186

edges = [(t, number_to_id[m.clause_number], number_to_id[ref])           # L187
         for t, src, ref in raw_edges
         if src in number_to_id and ref in number_to_id]                 # L189 ← 🔴 就是这一行
```

**⇒ L189 的 `ref in number_to_id`：只有"引用的目标也在【本文件】的条款号表里"才保留。**
**⇒ 引用别的国标时 `ref` 不在本文档表里 ⇒ 被这一行丢掉。**

**⚠ 但引用【已经被抽出来并存下来了】**——L179：

```python
legal_refs=tc.external_refs,      # 外部引用（别的国标/法规）
cross_refs=tc.cross_refs,         # 交叉引用
```

**⇒ 所以链条断在最后一环：抽到了 → 存进条款字段了 → 没连成 `evidence_edge` 的边。**

### 1.3 成因（业主亲述）

**⇒ 也就是说：L189 那个过滤不是"写错了"，是当时【根本没把跨文档关系当成需求】。**

## 二、🔴 切分质量是真问题（业主确认：**没解决**）

### 2.1 实测

| 项 | 数 |
|---|---|
| 条款数 / 文档数 | 522,021 / 6,797 |
| **平均** | **76.8 条/篇** |
| 条款正文长度 | 中位 **55 字** / 均值 **98 字** / P90 **202 字** / 最大 4,001 字 |
| **长度 < 40 字的条款** | **192,205 条 = 36.8%** |
| 全库条款正文合计 | **51.0 M 字** |

### 2.2 成因（业主亲述）

> 「**有些 chunk 会把单独一行的标题切成单独一块，所以现在有的东西的质量其实很差，怎么切我其实没解决。**」

**⇒ 那 36.8% 的短条款，主体就是【被单独切出来的标题行】。**

**⇒ 后果**：**索引里混着大量"只有标题、没有内容"的块**。
用户搜一个概念时，**这些空壳块会和真正有内容的条款在同一个索引里竞争** —— 挤掉正确的那些。

**⚠ 我没有实测过"它们到底挤掉了多少"**（这是我打算抽样看但没做完的事）。
**⇒ 这一条目前是【业主确认的成因 + 我的推断后果】，不是实测结论。**

### 2.3 现状定性

**"怎么切"这件事目前【没有方案】。** 业主原话：「怎么切我其实没解决」。

## 五、多跳的"乘法"（我的说法与其边界）

**意思**：假设答案要走两步——先找到 A，再从 A 走到 B。
**第一跳只有 41.6% 能找着 ⇒ 100 个问题里 58.4 个在第一步就断了，根本没机会走第二步。**

**⇒ 所以多跳不是在 41.6 上加东西，是在【已经漏了一半多】的基础上再叠一层。**

**⚠ 边界（必须一起读）**：
- 我此前写过「跳两次 ≈ 41.6² ≈ 17.3%」。**那个算法假设"两跳互相独立、且成功率相同"——这个假设我没有验证过。**
- **能站住的只有这一句**：**多跳会把第一跳的漏继承下去，最终成功率不可能高于第一跳。**
