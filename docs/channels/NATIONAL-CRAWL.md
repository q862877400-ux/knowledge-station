## 三、方法：发现 → 验证 → 抓取 → 下载

### 阶段 1：栏目发现（`scripts/national-crawl-discover.py`）

1. 抓门户首页（每站 1 次，同主机串行）。
2. 抽全部 `<a>`，按**关键词**打候选分：
   - 强命中：`公告`、`公示`、`通知公告`、`政策文件`、`政策法规`、`法规规章`、`政府文件`、`规范性文件`、`标准`、`地方标准`
   - 弱命中：`信息公开`、`政务公开`、`通知`、`文件`
3. 每个候选取**最强的 3 条**，逐条抓一次，用「像不像文章列表」判据打分：
   - 页面里 `<a>` 数量 ≥ 8
   - 链接文本里**含日期**（`2026-09-01` / `2026年9月1日`）的比例 ≥ 20%
   - 文本长度中位数 ≥ 8 字（滤掉导航）
4. 得分最高且**通过判据**的那条 = 该站的公告栏目；都不过就记 `no_board_found`。

### 阶段 2：列表抓取

- 复用 `announce.parse_list_page` 的正则思路，但要更宽（政府站 CMS 五花八门）。
- 分页：优先 `?page=N` / `index_N.html` 两种；追到「连续 3 页没有新条目」就停（同 `announce` 的 `STOP_AFTER_BARREN_PAGES`）。
- 每站上限：**20 页 / 1000 条**（防某站无限翻）。

### 阶段 3：附件下载

- 条目详情页或列表页里的 `href` 以 `.pdf .doc .docx .xls .xlsx .zip .rar` 结尾 → 下载。
- 上限：单文件 **30 MB**、单站 **500 个文件 / 2 GB**。
- 落盘：`var/data/national/<省份>/<站点>/<sha256前16>_<原名>`，同时记 `url / 字节 / sha256 / 来源条目`。
- **不下载**：`.exe .msi .apk` 等可执行、以及任何需要登录/cookie 的。

### 阶段 4：入库与状态

每站一条记录（新表 `national_board`，或复用 `update_channel` 加列）：

| 字段 | 说明 |
|---|---|
| `site_id` | 用域名 |
| `province` / `city` / `level` | 省/市、地级/省级/中央 |
| `home` | 门户 URL |
| `board_url` | 发现到的公告栏目 |
| `discover_score` | 判据得分与命中关键词 |
| `status` | `ok` / `no_board_found` / `blocked` / `unreachable` / `parse_empty` |
| `items_total` / `attachments_total` | 实测条数 |
| `last_run_at` / `last_error` | 诚实记账 |

## 四、硬约束（不许破）

1. **只抓公开页面**；遇到验证码/WAF/需登录 → 记 `blocked` 并停，**不绕**。
2. **同主机串行 + 1 秒间隔**（复用 announce 的 per-host 锁思路）。
3. **不并行轰同一站**；不同站可以并行（已验证：110 源 6.8 分钟 → 55 秒）。
4. **不覆盖已有数据**：新表/新目录，不往 `announcement_observed` 里混。
5. **失败如实记**：`blocked` / `unreachable` / `parse_empty` 各是各的，不许合并成"0 条"。
6. **附件不下载可执行文件**；单文件超 30 MB 跳过并记 `too_large`。

## 七、R1 实测记录（2026-11-02）：判据改了三版

### 版本 1：按「链接文本里带日期」判 → 0/6（错）

三亚 `simple_list.shtml` 32 条链接，`date_ratio` 只有 **0.031**。
原因：政府站典型写法是 `<li><a>标题</a><span>2026-09-01</span></li>`，
**日期在链接外面**。⇒ 真列表页被判成「不像列表」。

### 版本 2：关键词含「通知公告/公告/公示」→ 挑到了**新闻/事务类**

业主明确：**「新闻公告我不要」**，要的是规范性文件（法规、条例、办法、规章、标准）。
实测很多市首页只有「通知公告」入口（巡视公告、干部任免、招标采购都混在里面）。

### 版本 3（当前）：关键词只认规范性文件 + 判据两条都要

- 强命中改为：`政策法规` / `法规规章` / `地方性法规` / `政府规章` / `规范性文件` /
  `政策文件` / `政府文件` / `文件库` / `地方标准` / `标准公告` …
- 排除表：`新闻` / `要闻` / `动态` / `巡视` / `干部` / `任免` / `招标` / `采购` /
  `会议` / `活动` / `通知公告` / `公示公告` / `公共资源交易` …
- 列表判据：`links≥8` **且** `详情链接占比≥0.25` **且** `整页日期≥3`（三条都要）

**实测 8 站：1/8 通过**（三亚挑对了 `政策文件`）。原因已定位：**很多市的政策文件

### R3（2026-11-02）：抓列表（已跑 10 站），发现两个新事实

**做了什么**：写 `scripts/national-crawl-fetch.py` —— 列表分页 → 抽条目 → 详情 → 附件。

**10 站实测**：6 站 `ok`（共 81 条**带日期**的条目）/ 4 站 `js_unparsable`；附件 **0 个**。

**两个新事实（都会影响后续排期）**：

1. **条目必须带日期，否则全是导航**
   第一版只按标题长度判，结果 30 条"条目"里混进「山西省人民政府网」「办公室文件」
   这类导航链接，附件自然 0。改判据后（无日期一律不做条目）才有真条目。
   临汾等 4 站抽不到带日期条目 ⇒ 栏目是 **JS 渲染**，如实标 `js_unparsable`。

2. **规范性文件的正文直接就是网页，多数没有附件**
   抽查详情页：`.pdf` / `.doc` / `附件` / `download` 各出现 **0 次** —— 文件正文在
   HTML 里，没有另挂原件。⇒ **「下附件」不是这类栏目的主要形态**，
   需要：(a) 抓正文 HTML 存为文本；(b) 只对确有附件的文件下载附件
   （常见形态：`/module/download/downfile.jsp?filename=…`、`/attach/0/xxx.pdf`）。

**下一步（R4）**：
- 条目做**规范性文件过滤**（保留 条例/办法/规定/规范/标准/细则/规则/制度/决定；排除 任免/招聘/表彰/会议/培训/预算/决算/招标）
- 正文抓取（HTML → 文本，落盘）
- 附件再扩几种常见形态；`js_unparsable` 的站改用浏览器渲染或列人工清单
- 从 10 站扩到 129 站


### R4（2026-11-02）：按业主要求改口径 —— 两个产出、存量优先

业主明确产出（这条改了目标）：

> ① 能接入这些网站、抓最新公告；**上次抓取状态 vs 这次**对比就有增量 —— **接入能力要能复用**；
> ② 把历史所有规范性文件发布的公告**全部把存量先抓下来**，以后监测增量。

⇒ 目标已改写。本轮做了三件事：

1. **累积存库**：`items.jsonl` 按 URL 去重合并「上次 + 本次」，新条目记 `first_seen`。
2. **每站快照 `site-state.json`**：`items_total / items_new_this_run / newest_date /
   oldest_date / pagination / run_at`。**下次一跑与它对比即得增量** —— 这就是产出 1 的骨架。
3. **翻页规则标定** `calibrate_pagination()`：逐个候选规则（`?page= / ?p= / ?pn= /
   ?currentPage= / ?pageIndex= / ?pageNo= / index_N.shtml / x_2.shtml / x-2.shtml / /2.html`）
   抓第 2 页，**要求第 2 页出现第 1 页没有的 URL** 才算命中。

**实测（5 站）**：`pages=1`，`pagination.rule=None` —— 上述 10 种规则**一种都没命中**。
三亚 `?page=2` 与第 1 页 **30/30 重合**（服务端忽略该参数）。

⇒ **这批 CMS 的翻页不是静态链接**（多半是 POST 接口或 JS 渲染），
所以「存量翻到底」还差一块：**逐站找出它自己的翻页机制**（读页面里的分页 JS / 试 POST /
或改用浏览器渲染）。下一轮 R5 专做这一块。

**当前能力边界（如实）**：接入 + 单页抓取 + 累积 + 快照 + 增量判定骨架 **已可用**；
「翻到最后一页」**尚未打通**，所以存量还不完整。


### R5（2026-11-02）：翻页真相 —— 分页是 **JS 生成**，静态抓不到

试了两条路都失败，但把原因钉住了：

1. **猜参数 10 种**（`?page= / ?p= / ?pn= / ?currentPage= / ?pageIndex= / ?pageNo= /
   index_N.shtml / x_2.shtml / x-2.shtml / /2.html`）→ **0 命中**；
   三亚 `?page=2` 与第 1 页 **30/30 完全重合**（服务端忽略参数）。
2. **跟页面自己的「下一页」链接**（`find_next()`）→ 3 站全部返回 `None`。

**实测证据（页面里的分页痕迹）**：

| 站 | totalPage | pageCount | pageNum | createPageHTML | 「下一页」字样 |
|---|---:|---:|---:|---:|---:|
| 三亚 | 0 | 0 | 0 | 0 | 0 |
| 三门峡 | 0 | **4** | **13** | **3** | 2 |
| 临汾 | 0 | 0 | 0 | 0 | 1 |

⇒ 三门峡用的是经典 `createPageHTML(pageCount, pageNum, …)` **JS 分页函数**；
「下一页」存在于 JS 字符串里，不是 `<a href>`。三亚则连分页痕迹都没有（可能是
"加载更多"接口）。

**结论**：存量「翻到底」**必须用浏览器渲染**（点击下一页后读 DOM），
或逆向出每站的 POST/JSON 接口。静态 HTTP 抓不到 JS 生成的分页。

**下一步（R6）**：用 `chrome-devtools` 渲染栏目页 → 点「下一页」→ 读条目 →
翻到没有下一页为止；把每站实际翻了多少页记进 `site-state.pagination`。


### R6（2026-11-02）：翻页机制打通了一半 —— 找到 `pageNum` 与「从 JS 提取模板」

**关键发现**：三门峡的翻页不是 `<a href>`，而是页面 JS 里的一句

```js
location.href = '/pageView/zcwjList.html?pageNum=' + n
```

而我前一轮试的 10 种参数里**没有 `pageNum`** —— 所以全落空。

**本轮做了两件**：

1. `PAGE_RULES` 补上 `pageNum` / `curPage` 等真正常见的写法；
2. 新增 `js_page_template()`：从页面 JS 里**自动捞出翻页模板**
   （形如 `location.href='…pageNum=' + n`），优先用它翻页 —— 这是站点自己的写法，
   比猜参数可靠。

**实测（6 站）**：`丹东市` 成功翻到 **3 页**（`rule=query`）；
`三亚/临沧/三门峡` 仍 `rule=None`（三门峡的模板缺 `lmid/searchType` 上下文，
需要把原参数拼回模板里 —— 已知怎么修，见下）。

**修法（下轮 R7）**：提取到模板后，把**原栏目 URL 的查询参数**合并进模板再试，
例如模板 `…?pageNum=%d` + 原参数 `lmid=8200&searchType=1`
⇒ `…?pageNum=%d&lmid=8200&searchType=1`。


### R7（2026-11-02）：模板并入原参数，20 站实测 **6/15 能翻多页**

改动：`js_page_template()` 抓到的模板（如 `…?pageNum=%d`）与**原栏目 URL 的查询参数**
合并后再试（三门峡需要 `lmid=8200&searchType=1`），并保留「跟下一页链接」作兜底。

**20 站实测**（能解析的 15 站）：

另 5 站 `js_unparsable`（列表本身渲染不出来，跟翻页无关）。
