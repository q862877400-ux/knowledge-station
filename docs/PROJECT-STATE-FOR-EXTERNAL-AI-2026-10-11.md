## 1. 一句话：这是什么

**让不懂行的人用大白话，对自己机器上的任意资料提问，直接定位到那段可点开的原文。**

- 用户问："动火作业怎么分级"（用的是自己的说法，不是法条里的词）
- 系统在**本地知识库**里找出最相关的那几段原文，标出出处（哪一篇、哪一条、哪一版）
- 点一下引用 → 跳到那份文件的**那一页**，红色箭头标出原文位置
- 答案分三段（**依据 / 推导 / 结论**），且过**机器可判定的核验**（数字、模态词、法理三层）
  —— 核验不过，不许复制

**关键定位**：产品主体**不是"法规问答"**，是**"任何资料的定位与取证"**。
法规/国标只是数据源之一（虽然目前是最大的那类）。
用户自己的资料（PDF/DOCX/TXT/MD）也是一等公民 —— 但**只有用户本人能批准它进结论**。

**三条"别人没有"的（2026-09-25 复核过）**：

1. 引用精确到**条款**（同类产品最多到"文档/片段"）
2. **机器可判定**的核验（不是靠模型自说自话）
3. 用户自己的资料也能当依据，**但批准权只在用户手上**

## 2. 形态与技术栈

**形态 = 两个进程一起交付，没有独立 EXE。**

| 进程 | 是什么 | 谁拉起 |
|---|---|---|
| DSH 宿主 | 跑插件、给界面（侧栏 React） | 用户（`dsh web`） |
| **Python 引擎** | 跑检索/入库/核验，对外是本地 HTTP `/api/v1/...` | **插件按需懒拉**（随机端口 + 一次性 token） |

| 层 | 技术 | 规模（实测） |
|---|---|---|
| 引擎 | Python 3 + FastAPI + SQLite | `src/core/` **154 文件 / 38,982 行** |
| 测试 | pytest | `tests/` **173 文件 / 36,348 行** |
| 插件 | Node + TypeScript + React（DSH 插件） | `plugin/` **114 文件 / 96,572 行** |
| 存储 | SQLite + FTS5 + **sqlite-vec（vec0）** | **62 张表**，生产库 **2.88 GB** |
| 检索 | 六通道混合 + RRF 融合 | 见 §3 |
| 向量模型 | `bge-small-zh-v1.5`（512 维，**CPU/ONNX**） | 现役生产 |
| 文档解析 | PyMuPDF + MinerU + OCR | 入库链 |
| 门禁 | PowerShell 一条命令 | **12 步** |

**API 端点：176 个**（`src/core/api/` 9 个路由文件 + `server.py`）。

## 3. 已经实现了什么（按能力列，全部已交付）

### 3.1 检索：六通道混合 + RRF

代码真源 `src/core/domain/models.py` 的 `SEARCH_CHANNELS`：

| 通道 | 是什么 | 生产是否恒开 |
|---|---|---|
| A `exact` | 条款号精确（权重 2.0） | 只在提问含条款号时 |
| B `fts` | 全文 FTS5（jieba 分词） | **恒开** |
| C `vec` | 向量（vec0 暴力精确扫描，**无近似索引**） | **恒开** |
| D `modality` | 模态词（"必须/应当/不得"） | 只在提问含模态词时 |
| E `legal_element` | 法理要素 | **恒关**（全库仅 2,171/663,634 条有该字段） |
| F `behavior_scope` | 行为客体 | **恒关**（该字段全库 0 行非空） |

**实测一条真检索**（`perform_hybrid_search("动火作业怎么分级", top_k=5)`，2026-10-11 本机跑通）：
返回 `GB 30871-2014` 第 `5.1.1` 条 —— "固定动火区外的动火作业一般分为二级动火、一级动火、特殊动火三个级别…"

### 3.2 取证问答（`ks_answer`）

三段式（依据/推导/结论）+ 效力徽章 + 置信度 + 三层核验（数值/模态/法理）。
**LLM 只收到"问题 + 本地检索出的证据片段"** —— 没有机会凭记忆编造。
引用不可支撑时（`verification.unsupported_context`）**必须披露**，不许当成依据用。

### 3.3 材料平面（用户自己的资料）

- 项目 + 参考资料文件夹 → 扫描收件（PDF/DOCX/TXT/MD 解析成切片，**引用可点回原文位置**）
- **评审是硬门**：`review_status != 'approved'` 的材料**不进检索、不进结论、不出现在产出物引用里**；
  批准/拒绝**只能由用户**做（没有"全部通过"按钮）
- **两个轴分开**：轴 A 来源可信度 `T0~T4`（原件/官方/权威转载/仅线索/不可用）
  × 轴 B 任务内效力（本任务准则 / 仅作参考）
- 实测规模：**3 个项目 / 81 份材料 / 7,872 个切片**

### 3.4 效力核验与更新

- **效力报告**（五色统计：在用已废止 / 即将实施 / 现行有效 / 状态未知 / 参考资料）+ 标准树/法规树分计
- **查号巡检**：逐个标准号走渠道降级链 probe"这个号还有效吗" → `update_change_event`
  （实测 **6,471 条**变更事件 / 39 个批次）
- **公告发现**：盯部委"公告栏/通知公告"列表页，逐页翻 → 零 LLM 启发式解析 → URL 去重落库 →
  抓正文入库 → 提取"发布/修订/废止/征求意见"四类信号
  （实测 `announcement_observed` **1,326 条**）
- **渠道台账**：**286 个渠道**（引擎侧 `update_channel` 表），含链接/有效性/上次成功查询三列，
  可人工增删复核（写操作留痕）
  ⚠ **别和 gov-qa 的 353 个渠道混淆** —— 那是**另一条线**的台账（`tools/gov-qa/SITE-REGISTRY.md`）

## 5. 现在卡在哪：检索质量（**这是核心问题**）

### 5.1 一句话结论

**术语式提问已经很好用（92.8%），大白话提问只有 20%。**

### 5.2 实测数字（用 500 个跨领域术语 × 1,832 条外行说法实测）

| 结论 | 数字 |
|---|---|
| **大白话与原文一个字都对不上** | **53.0%**（971/1,832）⇒ 按字找**原理上无解** |
| 有重合、但排不进前五 | 47.0% 里只有 **4.4%** 进前五 ⇒ **排序是独立问题** |
| 按字找 / 按意思找 | 6.8% / 5.8%（前五）⇒ **无差别** |
| 两条路合起来 | **11.8%**（前五）、24.5%（前二十）⇒ 比最强单条多 59% |
| **上限**（直接用术语问） | **68.8% / 87.0%** |
| 材料平面：术语式 vs 大白话 | **92.8% → 20.0%**（前五）；前 1 直接 **0** |

### 5.5 ⚠ 一条"已经静默坏掉"的能力（**外部 AI 应该知道**）

**合规哨兵**（`src/core/llm/jev_guard.py`）的设计是：Jev 不可用 ⇒ 返回 `None` ⇒ 退回词表。

而 **Jev 在本机被地域封锁（HTTP 451）** ⇒ 这一层**已经静默退化为纯词表**，
且**界面上看不出来**（降级只写一条 `logger.info`）。

实测差距：识别"隐性合规"（一句话里没有任何法规词，但内容要受规管 —— 如"让程序自动点已阅读并同意"
"工伤私了""身份证号发公开站"）—— **词表 1/8，Jev 8/8**。

⇒ **本机这一层能力等于没有**。修它要么**花钱/换网络出口**，要么**换产品承诺**，属业主级决定。

## 8. 我自己的错（留痕，供外部 AI 判断可信度）

按本项目纪律，写错的**保留原文 + 就地更正**。挑三条对判断有影响的：

1. **`rerank()` 的缺陷**：我起初按 OpenAPI 的**字段描述**推断根因，被独立复核推翻 ——
   **字段描述 ≠ 运行时语义**。实测发现生产里 `rerank` **恒不生效**且分数贴错条款。
2. **别名抽取**：原判是"没跑过抽取"，实际查出来是**抽取器本身有两个真缺陷**
   （术语段边界没限定、回退走滑窗）—— 修掉后退役 **27 条假别名**。

## 10. 我建议外部 AI 重点回答的问题

### 10.1 核心矛盾：**"换模型"这个杠杆要不要现在就用掉？**

**事实**：E4 实测"换成 `Qwen3-Embedding-0.6B`"能让 `Vector@1000` **+32.50pt**（0.3583 → 0.6833），
"查询指令前缀"再 **+15.84pt**。**方案与可续跑重建脚本都已写好（`exp-17`），但没接生产。**

**要权衡的**：

- 收益是**检索侧**的（`Vector@1000`），**用户看到的是 `fused@20`** —— 本目录已**三次**量到两者转换率极低
  ⇒ **"`Vector@1000` 的 +48.34pt 很可能大幅缩水"**，**拿到 `fused@20` 之前"该不该切"没有依据**
- 代价：现役模型是 **CPU/ONNX**，换成 0.6B 要 GPU（冷启动 5.1 s、显存峰值待量）；重建全库 663,634 条向量
- **本地已缓存该模型**（不用下载），**显卡可用**

**⇒ 建议先补的那一格**：把 E4 量的终点从 `Vector@1000` 接到 **`fused@20`**（用户真实看到的那一格）。
这是**成本可控、结论决定性**的一步。

### 10.2 排序问题（P0.4b + P2）：为什么"有重合却排不进前五"

**事实**：47% 的说法与原文有重合，**只有 4.4% 进前五**。
且**通道 A/D/E 现在的排序等于"灌库序"，与相关性无关** —— 不修它，"取前几名"都是任意的。

**⇒ 问题**：在**不引入新语料**的前提下，修排序键的**正确顺序**是什么？
（注意：那两个排序键承载"未核验不得承重"的**语义**，改它可能更像**产品决策**。）

### 10.3 翻译层（P1）：53% 零重合，路怎么走

**事实**：53% 的大白话与原文**一个字都对不上** ⇒ 按字找**原理上无解**。

**现在的方向**：用**库里自己的术语表**做有界选择。

**⇒ 问题**：这个方向的天花板在哪？剩余 20% 该由什么补？

### 10.4 P4 被地域封锁挡住：有没有替代方案

**事实**：P4（检索分类闸）要用 **Jev** 做有界判断，而 `api.typesafe.ai` **对本机返回 HTTP 451**。
