### verifier-B 补的两条很有价值

**(a) `xfail` 假红的第二种形态**（我原来只写了第一种）：
一条真 skip 都没有、只有 xfail 时，汇总行根本不出现 `skipped`
⇒ `$pytestSkipped` 是 `$null`、`[int]$null` = 0，而 `$skipNodeIds.Count` = N ≠ 0
⇒ **照样判红**。

**(b) 我只有诊断没有处方** —— 它指出 `run-gates.ps1:398-400` 收 skipNodeIds 时
不区分 `type`，而 pytest 写 junit 时会区分 `pytest.skip` / `pytest.xfail`。
⇒ 加一个类型过滤即可。**处方已补进 §4.5，但明确标注「未实跑验证」。**

### verifier-B 发现的、文档完全没写的一件事

`plugin/src/chatmode.js::chatModeFilePath()` 的兜底是
`join(dirname(sessionFilePath()), 'ks-chatmode.json')` ——
如果 `KS_DATA_DIR` 与 `KS_CHATMODE_DIR` 同时缺席，chatmode 状态文件的默认落点是
**仓内 `var/data/`**。`smoke-chatmode.mjs` 恰好只拼路径不写盘，所以没出事。

⇒ **这是一条靠实现细节侥幸成立的安全边界，不是靠设计。**
一旦有人把 `chatModeFilePath()` 改成顺手 `mkdir`，那套冒烟就会往仓里写文件。
**已登记，未修**（属于「冒烟是否可能污染生产库」这一类，见 README §6.5）。
