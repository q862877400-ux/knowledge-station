# 开源吞并收益决策报告（四队收益分析合成）

> 2026-08-25 四队并行收益研究合成。前序调研见 docs/OPEN_SOURCE_FUSION_SURVEY.md（项目清单）。
> 本报告回答一个问题：**吞进来，用户到底得到什么**（全部量化、吞前 vs 吞后）。

## 一、四波收益全景

### P0 语料吞并（lawtext + LawRefBook + just-laws）——「让产品变大」
| 指标 | 吞前 | 吞后 |
|---|---|---|
| 法规部数 | 7 部手选 | **~2,500±300 部**自动入库 |
| 条文级单元 | ~1,700 条 | **15–20 万条（≈100×）** |
| 可答法域 | ~5 个（安全+民事通则） | **15+**（劳动/婚姻/借贷/税务/网安/刑事/行政…） |
| 问答完整可引率 | **<20%** | **≥80%**（100 问自测集推算） |
| 成本 | — | 数小时机器时 + 1–3 GB（docx/md 直读无 OCR） |

场景跃迁：《劳动合同法》39 条（裸答可能过时→秒答带引用+现行标记）、省属地方法规（空白→直接命中）、司法解释颗粒度（借贷利率上限→解释第 N 条）、版本轴（旧事故按哪版安法）、跨法域法条链。
**核心风险**：三源同名多版本 → 「法名+机关+效力版本」幂等键去重，flk 效力状态为权威。

### P1 权威性升级（cn-law-hub + OpenSTD_Spider + cnccs/ICS）——「让产品值得托付」
一条完整「法定效力核验链」：元数据（Spider）× 十源效力状态（law-hub）× 分类底表（cnccs/ICS）。
| 指标 | 吞前 | 吞后 |
|---|---|---|
| 🔴 高危误报（废标当现行） | 零防护 | **↓80–90%**，red_precision 具备 ≥95% 验收条件 |
| 🟡 伪更新（改版噪声） | 改版即伪黄灯 | **约降一半**（仅替代关系+实施日期触发） |
| ⚪ 灰名单可解释性 | 0% | **60–80%**（编号变体对齐/指路正确库/明示不确定） |
| 元数据覆盖 | CCS 推断/归口缺/英文名缺 | **≈100%** |

用户从「知道网页变了」→「**确定该标准/法规现在还能不能用**」，判定挂官方证据链接可自证。
**风险**：cn-law-hub 非开源（只借 10 源清单自研适配）+ openstd 反爬波动（已有 curl_cffi 经验）。

### P2 评测与审查（LawBench + DISC-LawLLM + contract-review-pro + compliance-checker-algo）——「让产品离不开」
| 指标 | 吞前 | 吞后 |
|---|---|---|
| 准确性可度量 | 无基线（引用错法条概率未知） | **回归门禁**：每次改动出硬数字（n=500 可分辨 ±3%） |
| 审查点覆盖 | ~5 个（人工经验） | **21 个（×4.2）**：16 门禁+15 风险标签+义务四问 |
| 幻觉率 | 单引擎自证无从察觉 | **预期降幅 ≥50%**（双引擎分歧检测+弃权率正向激励，机制推算） |
| 模型升级风险 | 不敢动/赌运气 | 升级前存基线、升级后跑同套评测，门禁不过不发布 |

场景：隐藏对赌/反稀释条款（吞前想不到→吞后必经之门）、「AI 说合规」实际漏条款（双引擎分歧→显式警报）、两次审查结论不一（16 门禁固定语义→可复现可比对）。
**风险**：LawBench 通用法域与站内国标有域差需抽样校准；16 门禁未经本域校准的误报会反噬信任。

## 二、战略合成（组合路线队）

**三级火箭**：P0 让产品**变大**（规模），P1 让产品**值得托付**（信任），P2 让产品**离不开**（智能）——三者是因果链而非平行特性。

**定位跃迁**：安全生产垂直工具 → 全领域法规知识库（P0）→ 可信法规核验工作站（P1）→ **装在自己电脑上的可信合规法务台**（P2 终态）。

## 三、投入产出排序（若只能做一波 → 先做 P0）

| 波 | 工程量 | ROI | 理由 |
|---|---|---|---|
| **P0** | 25–40 人日 | ★★★★★ | 地基性（P1 核验对象、P2 评测题库的共同前提）；单位成本收益最高；纯本地无外部风险 |
| P1 | 30–50 人日 | ★★★★ | 护城河（本地私有+可验证权威=云端产品给不了的）；外部源存活率方差最大 |
| P2 | 35–60 人日 | ★★★☆ | 乘数后置；LawBench 高分≠业务正确需本域校准 |

**战术修正（重要）**：P2 的**评测管线骨架（+5 人日）应提前至 P0 期并行预埋**——度量越晚建，语料污染导致的退化越晚被发现；契合项目宪法「准确性最高优先」。

**每波阿喀琉斯之踵**：P0 怕消化不良（垃圾进垃圾出）、P1 怕外部源静默失效（核验通道自身沦为不可信源）、P2 怕评测分虚假安全感。

## 四、行动建议

1. **立即启动 P0**（语料吞并）：lawtext docx → MinerU 批量入库 + LawRefBook 解析器 + just-laws 基线对账；**同步预埋评测骨架**（+5 人日）。
2. P0 验收：入库部数/去重率/与 flk 抽样对账一致 + 评测基线数字落盘 eval/。
3. P1/P2 依次跟进；每波验收口径见 docs/OPEN_SOURCE_FUSION_SURVEY.md §五。
