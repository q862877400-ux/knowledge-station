## 3. ★ P1：我自己发现并更正的**数据错误**（最重要的一条）

**我原来写**：「阈值依据：全库 20 万 span ⇒ **误伤率 0.02%**」。**这是错的**，两个错叠在一起：

### 错一：抽样偏差（数值偏低 **686 倍**）

我用了 `SELECT bbox_json FROM source_span WHERE … LIMIT 200000` ——
SQLite 按**行序**返回，前 20 万行**集中在少数正常文档** ⇒ 只数到 40 条退化框（0.02%）。
改 `ORDER BY RANDOM()` 后：**27283 / 200000 = 13.64%**。

⇒ 同一张表、同一个阈值，**换个取法差 686 倍**。

### 错二：把两个不同的数**混为一谈**

- **退化率** = 有多少 span 是碎片（**13.6%**）；
- **误伤率** = 有多少**本该能画箭头的正常行**被阈值拒掉（**≈ 0**）。

我拿"退化率"的量去说"误伤率"的事，还说成 0.02%。

### 更正后的事实（随机抽样 20 万；全库 184 万 span）

尺寸分布**双峰**：

| 宽度区间 | 占比 |
|---|---|
| 0–0.5pt | 7.76% |
| 0.5–1pt | 5.88% |
| **1–3pt** | **0.00%（0 条）** |
| **3–5pt** | **0.00%（7 条）** |
| 5–10pt | 0.01% |
| 10–20pt | 0.83% |
| 20–50pt | 4.98% |
| 50–100pt | 16.15% |
| ≥100pt | 64.39% |

- 阈值**下方**（宽<5pt）27282 条：**最大 4.66pt、中位 0.41pt** —— 全是碎片；
- 阈值**上方**（宽 5–20pt）1684 条：**最小 6pt** —— 是短条款号等正常内容。

⇒ **`1–5pt` 区间几乎是空的** ⇒ 阈值 5pt 落在**两个峰之间的空隙**里 ⇒ **误伤率 ≈ 0**。

### 结论怎么变

| 项 | 原（错） | 更正后 |
|---|---|---|
| 阈值是否合理 | "误伤率 0.02% ⇒ 合理" | **仍然合理**（双峰空隙，误伤≈0）—— **结论没变，依据换了** |
| 退化框规模 | "0.02%" | **13.6%**（全库 span）｜**13.8%**（首个 span） |
| 多少条款箭头画不出来 | 没说 | **≈13.8%** —— 但它们**本来也画不出来**（坐标就是碎片） |

⚠ **本批的行为一个字节都没改**（阈值仍是 5/3、过滤逻辑不变）—— 改的只是**我说的数字与理由**。
