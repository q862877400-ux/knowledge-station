# 检查计划：怎么把整个项目「检一遍」并保证没有漏

> **这份文件的用途**：说明这次检查**检查什么、怎么检查、怎么证明没有漏**。
>
> ## 我的角色边界（业主 2026-10-24 明确）
>
> **只做检查与记录。不做判断。不治病。**
>
> | 做 | 不做 |
> |---|---|
> | 枚举、统计、交叉引用、复述原文 | 不说「这是 bug」「这该修」「这不好」 |
> | 记下「观察到什么 + 怎么复核」 | 不改代码、不动数据 |
> | 记下「同一件事有两份实现」这个**事实** | 不说「应该合并」 |
> | 记下「0 个调用方」这个**事实** | 不说「这是死代码该删」 |
>
> **对下一棒 Agent 的承诺**：你不需要从零读这个项目。这份地图告诉你
> **东西在哪、长什么样、谁引用谁、验过没有** —— 该不该改、怎么改，是你的判断。

## 一、「所有内容」到底指什么（九个面，逐面机械枚举）

含糊的「全面了解」不可验证。这里把「所有内容」拆成**九个可枚举的面**，
每一面都有**确定的枚举命令**和**可核对的计数**。

| 面 | 枚举对象 | 怎么枚举（机械） | 覆盖证明 |
|---|---|---|---|
| **A 文件面** | 仓里每一个受控文件 + 每个未跟踪文件 | `git ls-files` + `git status --porcelain` | 清单条数 == 两份来源之和；**每个文件恰好出现一次** |
| **B 符号面** | 每个 `.py` 的模块/类/函数（含签名、行范围、docstring 有无） | `ast.parse` 逐文件 | 解析成功数 + 解析失败数 == 发现的 `.py` 总数 |
| **B' 符号面（前端）** | 每个 `.ts/.tsx/.js/.mjs` 的导出与声明 | `tsc` 可用则用，否则正则 + **明确标注「近似，非 AST」** | 同上 |
| **C 引用面** | 谁 import 谁（模块图）、谁调用谁（近似调用图）、零引用符号、循环依赖 | `ast` 扫 Import/Call + 模块名匹配 | 每个符号都有「被引用次数」字段（0 也要有） |
| **D 数据面** | 表 / 列 / 索引 / 触发器 / FTS / config 键 / 环境变量 | 用**随仓的种子库**反射 schema（`PRAGMA`）；config 键与环境变量靠 `grep` | 表数与 `sqlite_master` 一致；每个表列出全部列 |
| **E 接口面** | 后端每条路由（方法 + 路径 + 处理函数 + 文件:行）+ 前端每条路由注册 | 装饰器扫描 + `ctx.webServer.register` 扫描 | 路由数 == 扫描命中数；**逐条列出，不抽样** |
| **F 测试面** | 每条测试节点；每个源码模块被多少测试文件引用 | `pytest --collect-only -q` + 测试文件 import 扫描 | 节点数 == pytest 报的总数 |
| **G 文档面** | 每份 `.md` 的标题、首段、出链、入链、是否孤儿 | `grep` 链接 + 反向索引 | 文档数 == `git ls-files '*.md'` |
| **H 门禁面** | 门禁每一步跑什么、预算多少；冒烟每一套验什么 | 解析 `run-gates.ps1` + `smoke-all.mjs` | 步数 == 解析结果 |
| **I 运行时面** | 引擎怎么起停、端口/令牌/会话在哪、健康检查验什么 | 读代码 + 只读探活 | 每个结论附可搜索文字 |

**九面之外的东西明确不检**（写下来，免得下一棒以为漏了）：
浏览器里的像素效果、真机安装包、`tools/gov-qa` 那 948 MB 的**内容细节**
（只检结构与归属，抽样看隐私，已写明是抽样）。

## 二、怎么保证「没有漏」——三条硬机制

这一节是整份计划的核心。**「我读了很多」不是覆盖证明。**

### 机制 1：三重账本对账（文件面）

```
账本甲 = git ls-files | wc -l                      （受控文件）
账本乙 = git status --porcelain 里 ?? 的条数        （未跟踪文件）
账本丙 = 我们清单里的条目数                          （--check 会核）
判据：甲 + 乙 == 丙，且清单里没有重复路径
```

`scripts/survey/00-inventory.py --check` 会自动核这个账，不平就 exit 1。

### 机制 2：解析成功率必须 100%，失败要具名（符号面）

```
判据：解析成功的 .py 数 + 解析失败的 .py 数 == 找到的 .py 总数
     失败清单必须逐文件列出（不许静默跳过）
```

**失败也是记录**：解析不了的（比如语法用了新版特性）照样进清单，标 `parse_error`。

### 机制 3：每条记录都带「复核命令」

这是给下一棒的：**任何一条记录都必须能被别人重新算出来**。
所以 `data/*.json` 里每一条都带来源（文件 + 可搜索文字），
每份 `.md` 的每节都写清用了什么命令。

> ⇒ **不许出现「据说」「应该是」「大概」**。算不出来的就写「未验证」。

## 三、产出物：机器可读 + 人可读，两份都要

### 机器可读（给 Agent 用，读 JSON 不读散文）

```
docs/survey/data/
  inventory.json     每个文件一条：路径、字节、行数、sha256、语言、分类
  symbols_py.json    每个 Python 符号一条：模块、名字、kind、起止行、参数、有无 docstring
  symbols_web.json   每个前端声明一条（近似，标注）
  references.json    每个符号被引用几次；每个模块被谁 import
  schema.json        每张表：列、类型、约束、索引、触发器
  endpoints.json     每条路由：方法、路径、处理函数、文件、行号
  tests.json         每个测试节点：文件、名字、覆盖的源码模块
  docs.json          每份文档：标题、字节、出链、入链、有无入链（孤儿）
  gates.json         门禁每一步：名字、跑什么、预算
  corpus.json        种子库每张表的行数
```

### 人可读（给下一棒 Agent 当上下文用）

```
docs/survey/
  README.md          ← **唯一入口**：先读这个，再按需翻下面
  00-method.md       ← 本文件（检查方法与覆盖证明）
  01-inventory.md    全仓有什么、哪些是产物、哪些不能删
  02-code-map.md     代码按子系统分块：每块干什么、入口在哪、谁依赖谁
  03-cross-ref.md    引用关系、零引用、循环
  04-data-shape.md   表/列/index/config 键/环境变量
  05-api-surface.md  全部接口（后端 + 前端路由）
  06-test-surface.md 测试覆盖到什么、哪些模块零覆盖
  07-doc-surface.md  每份文档说什么、哪些是孤儿
  08-gate-surface.md 门禁每一步验什么
  09-runtime.md      起停、端口、令牌、会话、健康检查
  10-observed.md     **中性观察记录**（不下结论、不分级、不排优先级）
```

## 四、执行顺序（每步都能独立跑完、独立验证）

| 步 | 做什么 | 产出 | 验收判据 |
|---|---|---|---|
| **1** | 写生成器：文件清单 | `inventory.json` | 三重账本平 |
| **2** | 写生成器：Python 符号 + 引用 | `symbols_py.json` `references.json` | 解析率 100% 或失败具名 |
| **3** | 写生成器：schema（反射种子库）/ config / 环境变量 | `schema.json` | 表数 == sqlite_master |
| **4** | 写生成器：接口（后端 + 前端路由） | `endpoints.json` | 逐条列出 |
| **5** | 写生成器：测试节点 + 源码模块覆盖映射 | `tests.json` | 节点数 == pytest 总数 |
| **6** | 写生成器：文档图（出链/入链/孤儿） | `docs.json` | 文档数 == `git ls-files '*.md'` |
| **7** | 解析门禁与冒烟清单 | `gates.json` | 步数 == 解析结果 |
| **8** | 反射种子库行数 + 生产库统计 | `corpus.json` | 表数与 schema 一致 |
| **9** | 由 JSON **生成**人可读的 11 份 md（不手抄） | `docs/survey/*.md` | 数字与 JSON 逐项一致 |
| **10** | 总对账 | `docs/survey/COVERAGE.md` | 九个面各自「已枚举 / 未枚举」+ 计数 |

**第 9 步刻意不手写**：手抄数字必然漂移（本仓已实测 2.6% 失真）。
人可读文档**由 JSON 生成**，所以两边永远一致。

## 五、旧文档怎么处置（业主已授权随意改删融合）

**现状**：`docs/` 223 份，其中 9 组数字互相矛盾；`docs/uniformity/` 14 份是我前几轮边摸边写的。

**处置原则**：
1. `docs/survey/` 成为**唯一的「项目现状」入口**；
2. `docs/uniformity/` 里的**事实**（调查结果）并入 `docs/survey/`，**判据与裁决**留在原处不动
   （那属于"统一化"这条线，不属于"检查"这条线）；
3. 与新地图**冲突的旧数字**：以新地图为准，旧处就地标注「已被 `docs/survey/` 取代」并保留原文；
4. **孤儿文档**（没有任何入链）：在 `07-doc-surface.md` 里列出来，**不擅自删**——删是判断，我只记录。

## 六、这份计划自身的边界（明确不承诺什么）

| 不承诺 | 为什么 |
|---|---|
| 不说「某个东西是对是错」 | 业主明确：我只检查不判断 |
| 不保证「运行时行为都验过」 | 静态检查能枚举**代码写了什么**，验不了**跑起来会怎样**。运行时的部分只做只读探活，并标明 |
| 不保证 `tools/gov-qa` 那 948 MB 的内容都读过 | 只检结构与归属 + 抽样看隐私（**写明是抽样**） |
| 不保证前端符号清单是 AST 级 | 没有现成的 TS AST 工具链，用正则，**明确标注「近似」** |
| 不修任何东西 | 业主明确：我只检查 |

## 七、为什么这样能帮到下一棒

下一棒 Agent 拿到这份地图后，**不需要**：

- ❌ 从零 `grep` 找某个功能在哪 → 查 `02-code-map.md`
- ❌ 猜某个函数有没有人调用 → 查 `references.json`
- ❌ 猜某张表有哪些列 → 查 `schema.json`
- ❌ 猜某条接口在哪实现 → 查 `endpoints.json`
- ❌ 猜某块有没有测试 → 查 `06-test-surface.md`
- ❌ 猜某个数字对不对 → 所有数字都标了口径与复核命令
- ❌ 重复我已经查过的事实 → 但**必须重核**引用来的结论（本仓实测过一次：二手结论错了 2.6%）

**一句话**：我把「读一遍项目」这件事**做一次、存下来**，
让后面每个 Agent 不用再花那 20 分钟。
