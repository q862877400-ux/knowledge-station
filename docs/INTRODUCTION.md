# KnowledgeStation 产品介绍 —— 让每一句合规结论，都有法可依

> 本文是产品的**详细介绍**：它是什么、解决什么问题、怎么做到可信、用起来什么样。
> 技术细节见 `ENCYCLOPEDIA.md`；需求源头见 `REQUIREMENTS-v4.3.md`；开发历程见 `DEVELOPMENT-HISTORY.md`。

## 一、我们解决的问题

安全生产、职业健康、环保、消防、电力、化工……这些行业的日常工作被国标（GB/GB/T）与法律法规层层约束。
工程师的真实处境是：

- **查得慢**：一份 GB 30871 就 40 多页，找"动火作业怎么分级"要翻半天；标准还会被新版替代，你手上的可能是旧版。
- **不敢信 AI**：通用大模型答合规题会编造条款号、混淆版本、张冠李戴——恰恰在最不能出错的领域最不可信。
- **证据难落地**：就算 AI 答对了，你怎么向检查组证明？口说无凭，必须能翻到 PDF 原文的对应位置。

**KnowledgeStation 的答案：把国标/法规 PDF 变成本地知识库，让 AI 的每句话都带可点击的证据链。**

## 二、产品形态（2026-09 定稿）

**引擎 + DSH 插件一体**：不再单独打包 EXE。Python 引擎作为本地服务按需拉起；所有交互界面（问答、证据查看、入库、设置）都在 DSH Web 宿主的侧边栏里。

```
你在 DSH 会话里提问 ──→ 引擎检索本地知识库 ──→ 只依据证据作答 ──→ 三段式取证答案
   │                                                      │
   │                                                      ▼
   └── 点击答案里的引用蓝链 ────→ 侧栏 PDF 证据 tab 跳页 + 红色定位箭头高亮原文
```

一句话：**问题进，带依据的结论出，点依据见原文**。

## 三、核心能力（全部已交付，非规划）

### 1. 可信问答（取证模式）

输入 `/forensic 动火作业怎么分级`，得到三段式结构：

- **依据区**：每条证据带标准号、条款号、版本年份、效力徽章，全部是可点击蓝链；
- **推导区**：正文以 [1][2] 引用依据，推理过程可复核；
- **结论区**：最终答案。

LLM **只接收问题 + 本地检索出的证据片段**——它没有机会凭记忆编造。答案再经数值/模态/法理三层核验，附置信度徽章。

### 2. 溯源核对（点击即达原文）

每条引用点击后，侧栏 PDF 查看器自动跳到对应页，**红色定位箭头**精确指向条款位置（bbox 底部原点坐标契约）。证据卡片可收藏、可批注，批注会参与后续推理并注明"含您的批注"。

### 3. 只引现行版

引用规则收紧到红线级别：**只允许引用现行有效版本**；废止/被替代版本一律不作为依据（用户点名问旧版时说明其状态与差异）；即将生效的新版会单独提示施行时间。

### 4. 六通道混合检索

精确条款号 / 全文(jieba) / 向量语义 / 模态（数值/表格/流程图）/ 法要素 / 行为域——六通道 RRF 融合 + rerank 精排。Golden Set 基线门禁（96 问答对冻结快照）保证检索质量只涨不跌：exact_hit@1 = 88.9%，recall@5 = 97.8%。

### 5. 纠错闭环

发现识别错误？**快速修改**（补丁文字/表格）或**完整编辑**（Word/WPS 往返）双轨。补丁落库不可变快照，修订记录可撤销，跨版本平移不丢。

### 6. 合规落地四件套

- **义务清单**：从法规标准抽取"应当/必须/禁止"义务条目生成检查表；
- **合同审查**：上传合同，逐条比对法规要求，三色点卡（合规/风险/缺失）；
- **制度差距分析**：公司制度 vs 法规国标，输出差距清单；
- **条款释义 + 批量问答**：单条深挖或整批扫描。

### 7. 入库便利

PDF（识别版/扫描版自动分流）、Word(docx 官方公文)、监听目录、自动标签、**Dry-Run 预览**（先看解析质量再落库）、万级批量导入（分桶验收：✅ 直接可用 / ⚠️ 需复核 / ❌ 隔离）、入库坐标体检（异常当日告警）。

### 8. 自动更新与时效巡检

每日自动扫 8+ 官方渠道公告（cssn/openstd/标准公告网/部委官网/flk/gov.cn…）：发现新版/废止 → 静默下载新版 → 切换默认引用 → 旧版备份 → 轻通知 + 影响清单（波及哪些旧引用/义务清单）。会话里 `/效力报告` 随时查看全库现行状态（四色分组 + 时间窗 + 导出）。

### 9. 数据可信

快照不可变 + 补丁平移 + SHA-256 校验 + 滚动备份（VACUUM INTO 快照，7 份滚动，可指向独立物理盘 KS_BACKUP_DIR）+ 版本链跨版本对照。

### 10. 外发全程可审计（红线 D2）

每次云调用（LLM/OCR）的完整 payload 落库，UI 可查可导出。Prompt 只含问题与最小必要证据片段。引擎绑定 127.0.0.1 随机端口 + 一次性 token，不暴露网络面。

## 四、关键设计决策（可信度从哪来）

| 决策 | 内容 | 为什么 |
|---|---|---|
| D1→D2 | "零外发"改为"外发可审计" | 完全离线做不了取证级问答；改为全量留痕、用户可查可导出 |
| 只引现行版 | 废止版不作依据 | 合规场景引用过期标准 = 出事故 |
| OCR 文本永不展示 | 展示面只有原 PDF 或官方 docx 文本 | 机器层文本不可信，不进人眼 |
| 答案排序红线 | 现行性 > 效力层级 > 内容匹配度 | 收藏/偏好权重不得越过前三条 |
| 规范题禁止凭记忆 | 静默检索后再答 | 幻觉压制的制度级保障 |
| 冲突不黑箱 | 跨源冲突全量列出 + 判断逻辑 + 用户选口径 | 法规 vs 国标冲突时让用户拍板并存画像 |

## 五、安全约束

- API Key 只存引擎加密存储 `<data_dir>/secrets.json`（Windows DPAPI）；环境变量/注册表仅只读覆盖，引擎绝不写注册表。
- 凭据变量名命名空间化（`KS_LLM_API_KEY` 等），不占用裸全局名——不遮蔽宿主（DSH）的凭据层。
- 外发 Prompt 仅含问题 + 最小必要证据；完整 payload 落库追责。

## 六、技术底座（一段话）

Python FastAPI 引擎（sqlite + sqlite-vec 向量 + fastembed + jieba + PyMuPDF + MinerU 解析）+ Node DSH 插件（宿主桥 + 侧栏 React tab）+ Golden Set 检索质量门禁 + 828 项测试基线只涨不跌。数据与代码彻底分离：运行产物全在 `%APPDATA%\KnowledgeStation\`。

## 七、差异化

- vs 通用大模型：**证据链可核验**，条款号不编造，版本不混淆；
- vs RAG 演示项目：**面向取证**——三段式、效力徽章、PDF 跳页高亮、数值核验、版本时效、外发审计，全链路；
- vs 文档管理系统：**会答题**——六通道检索 + 合规引擎，不只是存文件。

## 八、现状与规模

- 引擎 16 个子系统模块，`schema.sql` 冻结 34 张表对象（32 实体 + 2 虚拟表；另有 1 张 `law_catalog` 由法规源模块懒建）；
- 知识库：法规官方源 + 国标语料，支持 3.5 万级标准目录接入；
- 测试基线 **1214 passed + 3 skipped + 1 xfailed**（pytest）+ 插件 smoke 11 段 + verify:commands 15 项 + tsc / mypy 类型门禁 0 错误；
- git 仓库 71 commits，全程可溯。
