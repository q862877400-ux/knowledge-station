## 零、结论先行

**他做的是一件真活，而且规模很大**：4 天 297 个提交，把全国 345 个政务问答来源的采集通道打通，落了 **39.5 万条**数据。技术上有几处是扎实的（`poll.py` 的增量轮询、`coverage.py` 的覆盖口径修正）。

**但按我们自己的规范，有四处是硬的、必须处置的**：

1. **它完全在门禁之外。** 本仓门禁（`scripts/run-gates.ps1`）**一步都不跑它**；根 pytest 的 `testpaths=["tests"]` 也不收它。它自己那 4 项"闸门"在一个**不在版本控制里**的脚本（`D:/AI/output/check.sh`）里。
2. **它没有经过一次独立复核。** 297 个提交、仓里 14 份 VERIFY-REPORT，**全部明令"不碰 tools/gov-qa"**。按我们的必验五种，它命中至少 4 种。
3. **"质量全绿"是四道判据都绕开了真问题的绿。** 实测：8,462 条内容重复、1,030 条答复全空、7,807 条时间倒置 —— 闸门全看不见，且我在实验里证明了它能**假绿**。
4. **它采的东西 98% 不是用户现在要的。** 用户已把口径收窄到"法规/国标/办法/条例的发布·更新·废止公告"，现有语料命中 **1.95%**；而这个"离靶"事实**只写在 GOAL.md 的散文里，没有进任何以退出码说话的判据**。

## 三、诊断：按我们的规范逐条

### 3.1 门禁覆盖 —— 完全在门外 ❌ 高

| 事实 | 证据 |
|---|---|
| 本仓门禁不跑它 | `Select-String scripts/run-gates.ps1 -Pattern 'gov-qa'` → **0 命中**（12 个 Add-Step 无一步涉及） |
| 根 pytest 不收它 | `pyproject.toml` → `testpaths = ["tests"]`；`pytest --collect-only` 中 gov-qa **0 条** |
| 它自己的闸门不在版本控制里 | `D:/AI/output/` **不是 git 仓库**；`git ls-files` 里没有 `check.sh` / `GOAL.md` |
| 地板文件没人自动写 | 全仓 grep `round-floor` 只有 `health.py` 读它、测试造它，**没有任何写入者** —— 靠人手写 |

**后果**：本仓"一条命令、以退出码为准"的纪律对它不成立。它那 58 个测试和 4 项判据**全靠人记得跑**。

### 3.2 独立复核 —— 零次 ❌ 高

- gov-qa 相关提交 **297 个**；命中"必验五种"至少 4 种（新增判据/门禁、触碰真数据、结论由作者自检得出、面向上线的契约）。
- 仓里 **14 份 `docs/verify-briefs/VERIFY-REPORT-*.md`**。逐份 grep `gov-qa`：**5 份明写"不碰 `tools/gov-qa/**`"**（`e4b-round2` / `exp13-query-rewrite` / `exp15-pool-depth-fusion` / `p010-long-tail` / `t016-t017-p1fix`，其中 `p010-long-tail` 写得最直白："任务明令**不碰**（别的自动化在写）→ 未验（按要求）"）；其余 9 份里 6 份**只字未提** gov-qa，另 3 份提到它只是把它的提交当作"冻结窗口里的无关夹带"排除掉。
  ⇒ **14 份报告里，没有任何一份把 `tools/gov-qa` 当作被验对象。**
- 297 个提交里带"复核"字样的只有 2 个，且都是**作者自己**做的数据完整性检查，不是独立复核。

⇒ **这个模块从未被第二个人验过。** 这是它所有质量问题的总根因。

### 3.3 "质量全绿"是四道判据绕开了真问题的绿 ❌ 高

闸门实测（`check.sh` 4 项）**确实全绿**：

```
TOTAL=394944   EMPTY=0   DUPS=0   COVERAGE=100.0
```

但我在它**判绿的同一份数据**上独立复现出：

| 缺陷 | 实测 | 闸门为何看不见 |
|---|---|---|
| **内容重复 8,462 条**（5,642 组，id 各不相同） | 我独立算：`content-dup groups: 5642 / extra records: 8462` | 判据③只比 `id`，不比内容 |
| **`xz-lasa` 全源答复为空** | `xz-lasa records: 1030 empty answers: 1030`（100%） | 判据只看条数，条数正常 |
| **`ln-8890` 时间全倒置** | `both=7807 inverted=7807`（100%，答复早于提问） | 无任何字段语义判据 |
| **答复截断 3,445 条** | 模块自带 `--answers` 判据得 13 源 / 3,167 条，独立复现一致 | 不在 4 项判据内 |
| **问题为空 153 条 / 近空 6,722 条** | 我独立算：153（`shannan-igi-*` 为主）、6,722（`hb-wuhan-10` 3,153 为首） | 不在 4 项判据内 |

**更硬的一条：我证明了这道闸门能"假绿"。**

我把 `adapters/__init__.py` 注入一个 `ImportError`，再跑它唯一的指标源：

```
ADAPTERS_ERR=ImportError
TOTAL=394944
ADAPTERS=0        ← 注册表整个读不到
EMPTY=0           ← 判据②读到的仍是 0
DUPS=0
```

`check.sh` 只 `grep '^EMPTY='`，读到 `0` ⇒ **判据②报绿**。也就是说：**适配器注册表整体失效时，闸门照样全绿。**
（实验后已 `git checkout` 还原，`git status` 干净，58 测试仍全过。）

### 3.4 两个工具对同一指标给出不同数字 ❌ 中

| 工具 | 标签覆盖率 | 口径 |
|---|---|---|
| `recon/label-coverage.py --quiet`（**闸门判据④用它**） | **100.0** | 优先 `msg_type_norm`，**回落到原始脏 `msg_type`** |

⇒ **同一指标两个出处**（违反"单一出处"）；闸门用的是**宽**的那个。

### 3.6 采的东西 98% 不是用户现在要的 ❌ 高

用户在 2026-10-10 明确收窄口径：**只保留"法律法规/国家标准/办法/条例"的发布·更新·废止公告**。

- 交接文档给的路径 `standards-audit/govstd/lawstd_filter.py` **在本机不存在**；实体在 **`D:\AI\std-law-watch\govstd\`**（**不是 git 仓库、不在 zcode 内**）。
- 索引 `lawstd_scope.jsonl` **7,879 行**确实存在，分类与 GOAL.md 逐项一致。
- **但索引与语料接不上**：索引的 `source` 是文件名主干（`ah-kb-安徽省直部门·共享问答知识库`），语料的是适配器 key（`ah-kb`）⇒ 精确 `(source,id)` 命中 **0/7,879**。
- **在今天的 394,944 条上重跑该过滤器 = 7,689 条 = 1.9469%**（GOAL.md 写的 2.20% 用的是旧分母 357,823）。**离靶 98.05%。**
- **zcode 内 import 该过滤器的次数 = 0**；`check.sh` 里 `lawstd|govstd|公告` 命中 **0**。
- zcode 自己的 `_scope_filter` 按 `extra.scope_tag` 过滤，而全库 `scope_tag` **0 条** —— 是个恒空壳。

⇒ **闸门在"98% 不符合用户当前口径"的语料上报"质量全绿"。** 这条事实只活在 GOAL.md 的散文里。
