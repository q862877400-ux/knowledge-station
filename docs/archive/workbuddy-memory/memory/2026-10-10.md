## 02:0x 修掉冒烟 flake（`e55f118`）+ 红项换人

**★ 一次「单次读数骗了我」的更正**：`smoke-materials-rows.mjs` 的「① 两行真渲染 … **行 0**」，
我先前**四次单跑都过**就下了"单跑必过、链里挂"的结论 —— **错了**。

**取率（同一份代码，各 10 次）**：

| 启动方式 | 修前 | 修后 |
|---|---|---|
| node 父进程 spawn（`inherit`） | **5/10** | **10/10** |
| node 父进程 spawn（`pipe`） | **7/10** | **10/10** |
| 直接跑 | **8/10** | **20/20** |

⇒ **20–50% 失败率的真 flake**（`0.8^4 ≈ 41%`，所以"4 次都过"完全不稀奇）。
**根因** = 脚本里 3 处**定死的** `setTimeout(30)/(30)/(20)`：面板还没渲染出行就往下读了。
**修法** = 改成**等条件**（`waitFor(条件, 上限 5s)` + `settle()`），**断言一个字没动**。
⚠ **连带作废**：我上一轮试 `stdio` 各档得出的"A/B 是 `['ignore','inherit','inherit']` 能过" —— **那次 PASS 是噪声**
（随后同一档连跑 3/3 全挂）。

**效果**：冒烟链**从第 27 套推进到第 37 套**（`materials-rows` 已过）。

**红项换人**：现在挂在 `smoke-kb-pad-pixels.mjs` 的场景 `kb|nav-channels@1300` ——
`ui-render-shot` 子进程 **exit=1 且没吐 JSON**（`SyntaxError: Unexpected end of JSON input`）。
**单跑 3/3 全过** ⇒ 又是"只在链里挂"。调用方只留了 **3 行 stderr**（只剩一个截断的栈）⇒ 看不出崩在哪。
**已先做"让它可诊断"**：改成打印**全量 stderr** + `signal` / `stdout` 长度 / `error`（超时被杀时
`status=null` 而 `signal` 有值 —— 这是关键区分）。**正在跑整条链抓诊断**。
