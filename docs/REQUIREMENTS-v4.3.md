## 第一部分：执行摘要、软件定位、双栏交互与技术选型基线

### 0. 执行摘要

本项目构建一款**运行在 Windows 11 操作系统上的本地优先、深度证据驱动、防幻觉的通用国标与法律法规 AI 知识工作站**。

与 v4.2 的关键差异：v4.2 的世界观是单一的"带数字的工程规范条款查询"，本 v4.3 升级为**三型知识统一建模**：

| 知识类型 | 典型内容 | 核验对象 | 核验手段 |
| :--- | :--- | :--- | :--- |
| **数据型** | "防火间距不应小于 13m" | 数值是否被篡改 | 数值闭包 + 单位校验 |
| **规则型** | "楼梯间**应**设置乙级防火门""**严禁**采用可燃材料" | 义务模态是否被篡改（应→宜、严禁→不应） | 模态词字典 + 强度比较 |
| **法理型** | "除法律另有规定外，经营者不得……""依照本法第 X 条追究责任" | 法理结构是否被歪曲（例外丢失、主体错位、引用断裂） | 法理要素完整性 + 引用链一致性 |

软件通过免费开源的视觉多模态大模型 **MinerU (magic-pdf `>=0.10.0`)** 对国标、行业规范、法律法规 PDF 进行本地版面分析与结构化入库，完整提取多栏正文、复杂跨页表格（转 Markdown）、公式（转 LaTeX）、★强制性条文标记及页面几何元数据（含 Rotation / CropBox / MediaBox）；数据全部持久化在本地单文件 **SQLite 数据库**（启用 WAL + 单写者队列）中；检索阶段采用**六通道并行召回 + RRF 融合**（精确号 / FTS5 / 向量 / 模态 / 法理要素 / 行为客体），并基于 **sqlite-vec** 虚拟表实现亚线性的向量检索，杜绝全库 NumPy 扫描；生成阶段通过用户自配的 **DeepSeek 官方 API Key**（或直连本地离线 LM Studio）执行受控流式推理，**流式阶段带"核验中"水印且禁用复制**，核验通过后方可复制；前端基于 **Electron + React + pdfjs-dist**，采用 **PDF.js `viewport.convertToViewportRectangle()`** 变换实现**毫秒级穿透核验**，正确处理旋转页与 CropBox 偏移。

#### 0.1 六条系统核心红线 (MUST NOT)

1. **[MUST NOT] 无 Evidence 不出结论 (Zero Hallucination)**：大模型生成的每一条结论，必须严格绑定本地数据库返回的不可变条款快照；禁止在无依据情况下强行作答。
2. **[MUST NOT] 无留痕外发 (No Unaudited Egress)**：任何云端调用（LLM / rerank / 云解析）都**禁止不留痕**——每次调用的完整 payload 必须落库，用户可在 UI 查看并导出（= `ENCYCLOPEDIA.md` §1.5 红线 4「外发可审计」/ §16.2 决策 D2）。
   > **2026-09-17 业主撤销原「原始文档零外发 (Data Egress Zero-Trust)」禁令**（见 `ENCYCLOPEDIA.md` §16.2 新增 **D5**）。原表述为"用户导入的任何 PDF、合同、图纸及生成的本地数据库**绝对禁止**上传至任何云端服务器"——它与同仓库既有的 **D1**（2026-08-23 已删除"零外发"验收红线）**自相矛盾**，且代码按它**结构性地锁着**深度解析通道（`dry_run.py` / `preview_jobs.py` / `routes_ingest_preview.py`）。撤销后：**是否把原始文档送往云端由用户自行决定，系统不再代为禁止，但必须留痕。**
   > 发往 DeepSeek 官方 API 的 Prompt 仍按"当前问题 + 检索出的最小必要文本片段"组织——但这是**成本与准确性**的工程口径（送全库既贵又稀释相关性），**不再是外发禁令**。
3. **[MUST NOT] 分型核验门禁 (Typed Verification Gate)**：大模型输出必须经过**分型核验器**校验——数据型核数值、规则型核模态、法理型核要素完整性；**Prompt 约束不是唯一的安全层**。
4. **[MUST NOT] 核验前禁可复制 (No Copy Before Verification)**：SSE 流式输出阶段，前端必须显示"核验中"水印并禁用复制按钮；核验事件 (`verification`) 通过后，方解锁复制与导出。杜绝用户复制尚未核验的错误答案。
5. **[MUST NOT] 零外部环境依赖 (Zero External Setup)**：最终交付必须为 Windows 11 单一可执行安装包（Setup.exe），内置嵌入式 Python 运行时；模型权重采用"基础包 + 模型管理器按需下载"策略，严禁安装包内置全部模型导致体积爆炸。
6. **[MUST NOT] 本机端口零信任 (Local Port Zero-Trust)**：后台 Python 引擎**不得**固定绑定 `127.0.0.1:28108`；启动时随机分配空闲端口并生成一次性 token，所有 IPC 请求必须携带 token，防止本机其他用户态进程越权调用。

#### 1.1 核心交互行为规范

* **引用标签（Badge）**：AI 回答中的引用标识统一渲染为带有链接样式的徽标（如 `[引用:GB50016-6.4.2]` 或 `[引用:民法典-496]`），内部绑定不可变 `clause_revision_id`、物理页码及 BBox 坐标。
* **原页穿透高亮机制（v4.3 重写坐标变换）**：用户点击引用 Badge 时，右侧 PDF 阅读器必须在 **200ms** 内响应。**v4.2 的 `bbox × scale` 公式在遇到旋转页、CropBox 偏移时必然错位，v4.3 强制改用 PDF.js 官方 `viewport` 变换**：

  ```typescript
  // src/renderer/pdf/PdfHighlighter.ts (v4.3 标准实现)
  // 后端返回的 bbox 为 PDF 坐标系下的 [x1, y1, x2, y2]（左下原点，Point 单位）
  // 必须使用 pdfjs-dist 的 viewport 转换，自动处理 rotation / CropBox / MediaBox
  
  import type { PDFPageProxy, PageViewport } from 'pdfjs-dist';
  
  function renderHighlight(
    page: PDFPageProxy,
    viewport: PageViewport,
    bbox: [number, number, number, number]   // [x1, y1, x2, y2] PDF 坐标
  ): HTMLDivElement {
    // 关键：使用 viewport.convertToViewportRectangle，自动处理旋转与 CropBox
    const [left, top, width, height] = viewport.convertToViewportRectangle(bbox);
    
    const div = document.createElement('div');
    div.style.position = 'absolute';
    div.style.left = `${Math.min(left, left + width)}px`;   // 处理 width 可能为负（旋转 90/270）
    div.style.top = `${Math.min(top, top + height)}px`;
    div.style.width = `${Math.abs(width)}px`;
    div.style.height = `${Math.abs(height)}px`;
    div.style.backgroundColor = 'rgba(255, 235, 59, 0.45)';
    div.style.border = '1.5px solid #FBC02D';
    div.style.pointerEvents = 'none';
    div.style.animation = 'highlight-pulse 0.3s ease-out';
    return div;
  }
  ```

  * **禁止**自行实现 `xmin × scale` 等公式；
  * 后端 `source_span.bbox_json` 必须同时存储原始 Point 坐标与页面 `rotation`，前端实时读取 `page.rotate` 并交由 viewport 处理；
  * 高亮样式：背景色 `rgba(255, 235, 59, 0.45)`，边框 `1.5px solid #FBC02D`，0.3s 呼吸渐隐动画。

* **核验中水印与复制锁（v4.3 新增，修 SSE 竞态）**：SSE 流式阶段，左栏回答顶部必须显示醒目的 `⏳ 核验中...` 水印，**复制按钮置灰禁用**；接收到 `verification` 事件且 `is_valid === true` 后，水印消失、复制按钮解锁；若 `is_valid === false`，水印变为 `⚠️ 核验未通过（详见报告）`，复制按钮保持禁用，并展开核验失败详情。

### R4a 模态强度核验（v4.3 新增，规则型知识核心防线）

> **背景**：v4.2 的核验器只做条款号闭包 + 数值核验，无法发现 LLM 将"**应**设置乙级防火门"篡改为"**宜**设置乙级防火门"、将"**严禁**采用可燃材料"篡改为"**不应**采用可燃材料"等**义务模态减弱**的严重错误。工程人员按"宜"执行和按"应"执行的法律后果天差地别。

* **功能**：
  1. **知识单元分型**：入库时由 LLM 半自动为每条 `clause_revision` 标注 `knowledge_type`（`data` / `rule` / `legal`）；对 `rule` 型与 `legal` 型条款，强制抽取 `modality` 字段；
  2. **模态词字典（强制规范）**：

     | 强度等级 | 模态词（规范/法规通用） | 法律后果 |
     | :---: | :--- | :--- |
     | 5（最强禁止） | 严禁、禁止 | 行为无效，可能违法 |
     | 4（强禁止） | 不得、不应、不能 | 行为无效 |
     | 3（强义务） | 应当、应、必须 | 不履行=违法 |
     | 2（弱义务） | 宜、一般应、原则上 | 引导性，不履行需说明理由 |
     | 1（许可） | 可以、有权、可 | 赋权性，可放弃 |
     | 0（鼓励） | 鼓励、提倡、支持 | 引导性，无强制力 |

  3. **核验规则**：LLM 输出中引用某条款时，抽取其表述该条款义务的模态词 `output_modality`，与原条款 `clause_revision.modality`（`source_modality`）比对：
     * 若 `strength(output_modality) < strength(source_modality)` → **拦截**，标记 `modality_weakened: true`；
     * 若 `strength(output_modality) > strength(source_modality)` → **警告**（LLM 擅自加强义务），标记 `modality_strengthened: true`；
     * 若 `strength(output_modality) == strength(source_modality)` → 通过；
     * 若 LLM 输出未包含任何模态词但原条款有模态 → **警告**（模态丢失）。
  4. **核验结果呈现**：拦截时在 `verification` 事件返回 `modality_violations` 数组，每项含 `{clause_revision_id, source_modality, output_modality, source_strength, output_strength, violation_type}`；前端以红色高亮标注被篡改的模态词。
* **用法**：
  * **原条款**："封闭楼梯间**应**设置乙级防火门"（`modality=应`, `strength=3`）
  * **LLM 输出**："封闭楼梯间**宜**设置乙级防火门"（`output_modality=宜`, `strength=2`）
  * **核验结果**：`is_valid=false`，`violation_type=modality_weakened`，拦截并提示"⚠️ 检测到义务模态被减弱：原条款为「应」，输出为「宜」"。
* **验收**：
  1. 模态词字典覆盖规范与法规高频模态词，抽检 200 条 `rule` 型条款，`modality` 抽取准确率 $\ge 92\%$；
  2. 对抗性测试：LLM 故意将"应"改为"宜"、"严禁"改为"不应"，拦截率 100%；
  3. 误报率：LLM 正确复述模态时，误拦截率 $\le 2\%$。
* **字段**：`clause_revision`（`knowledge_type`, `modality`, `modality_strength`），运行时核验响应结构体。

### R5 混合检索
* **功能**：
  1. **六路并行召回（v4.3 从三路扩展为六路）**：
     * **通道 A**：条款号/法条号正则精准匹配（如命中 `6.4.2` 或"第四百九十六条"赋予最高优先级）；
     * **通道 B**：本地关键词检索（SQLite FTS5 + 纯 Python Jieba 行业专有分词词典）；
     * **通道 C**：本地 Dense 向量语义检索（通过 `fastembed` 运行 `bge-small-zh-v1.5`，**v4.3 改用 sqlite-vec 虚拟表，禁止全库 NumPy 扫描**）；
     * **通道 D（v4.3 新增）**：模态召回——按 `modality` 字段过滤，如用户问"哪些情况**严禁**使用 X" → 召回所有 `modality=严禁` 且 `action` 命中的条款；
     * **通道 E（v4.3 新增）**：法理要素召回——按 `subject`（义务主体）与 `object`（权利客体）召回，如用户问"经营者的**义务**有哪些" → 召回所有 `subject=经营者` 且 `behavior=义务` 的条款；
     * **通道 F（v4.3 新增）**：行为客体召回（合规审查专用）——按 `behavior_scope` 匹配，如审查"人脸数据收集" → 召回所有 `behavior_scope` 含"生物识别信息/敏感个人信息/人脸"的条款。
  2. **RRF 融合排序**：六路召回结果经互惠排序融合算法（RRF，衰减常数 $k=60$）合并打分：
     $$\text{RRF\_Score} = \sum \frac{w_i}{60 + \text{rank}_i}$$
  3. **跨文档同名条款召回**：若用户直接查询条款号但未指定标准名称（如仅输入"查 5.2.3"），系统必须跨全库返回各本标准/法规的同名候选条款供用户选择。
* **用法**：前端在用户提问时自动触发本地后台 `perform_hybrid_search(query, search_config)` 接口；`search_config` 可指定启用哪些通道（默认全开，合规审查场景强制启用 D/E/F）。
* **验收**：
  1. 条款号直查在已有库中的首位命中率（Hit@1）$\ge 99\%$；
  2. Golden Set 测试集上综合语义召回率 Recall@5 $\ge 85\%$，Recall@10 $\ge 92\%$；
  3. **（v4.3）向量检索 p95 延迟 $\le 20\text{ms}$（1 万条条款规模，sqlite-vec）**，杜绝 v4.2 全库扫描的性能坍塌；
  4. **（v4.3）模态召回：查询"严禁使用可燃材料"时，`modality=严禁` 的相关条款 Top-5 命中率 $\ge 90\%$**。
* **字段**：`clause_revision`, `clause_fts`, `clause_vec`（sqlite-vec 虚拟表）全部检索相关字段。

### R5a 证据链扩展检索（v4.3 新增，防例外/但书/引用遗漏）

> **背景**：v4.2 的 Top-K RAG 容易漏掉"但""除外""另有规定"等例外条件、修正系数、以及被引用的关联条款。一个完整的工程或法律结论必须基于证据链，而非单个召回片段。

* **功能**：
  1. **证据依赖图（Evidence Graph）**：入库时半自动抽取条款间的五类关系，存入 `evidence_edge` 表：
     * `clause_relation`：母条款 ↔ 子条款（如"第 5.2.3 条" ↔ "表 5.2.3"）
     * `exception_relation`：主条款 ↔ 例外条款（如"但书""除……外""另有规定"）
     * `definition_relation`：术语定义 ↔ 使用该术语的条款
     * `reference_relation`：条款 ↔ 被引用的内部/外部条款（如"应符合本规范第 5.2.1 条""依照本法第 X 条"）
     * `correction_relation`：主条款 ↔ 修正系数/折减条款
  2. **证据链扩展算法**：首轮 RRF 召回 Top-K 后，沿 `evidence_edge` 图扩展 1~2 跳，将关联的例外、定义、引用条款纳入证据集，标记 `expanded_from` 溯源；
  3. **半自动抽取 + 人工确认**：自动抽取置信度 $\ge 0.85$ 的边直接入库；置信度 $0.6 \sim 0.85$ 的边进入"待确认队列"，由管理员在 UI 上审核；$< 0.6$ 的边丢弃。**承认全自动抽取是研究级难题，v4.3 不追求全自动**；
  4. **答案生成必须基于证据链**：LLM Prompt 中明确要求"若证据集含例外条款，必须回答例外情形；若含引用条款，必须说明引用关系"。
* **用法**：
  * **用户**："封闭楼梯间防火门要求"
  * **首轮召回**：GB50016-6.4.2（封闭楼梯间应设乙级防火门）
  * **证据链扩展**：发现 `exception_relation` → 6.4.2 注（"但多层建筑……除外"）、`reference_relation` → 6.4.3（楼梯间门要求）
  * **回答**："根据 GB 50016-2022 第 6.4.2 条，封闭楼梯间应设乙级防火门并向疏散方向开启；**但**多层建筑另有规定（见 6.4.2 注）；关联条款 6.4.3 对门的具体要求……"
* **验收**：
  1. 抽取的 `evidence_edge` 中，自动入库（置信度 $\ge 0.85$）的准确率 $\ge 90\%$；
  2. 对抗性测试：含"但书/除外"的条款，证据链扩展后例外条款被纳入证据集的比例 $\ge 85\%$；
  3. 答案覆盖例外条件的比例较 v4.2 提升 $\ge 40\%$。
* **字段**：`evidence_edge`（`edge_type`, `source_clause_id`, `target_clause_id`, `confidence`, `status`），运行时证据集结构体。

> **v4.3 升级说明**：v4.2 的 R9 仅针对工程参数追问，v4.3 将其升级为 **Query Understanding Layer** 的组成部分，同时覆盖工程参数与法律要素的追问。Query Understanding Layer 流程：用户问题 → 问题分类（数据查询/规则查询/合规审查/释义）→ 参数/要素槽位识别 → 缺失参数判断 → 追问策略 → 知识检索 → 回答。

* **功能**：
  1. **意图澄清与问题分类**：用户提问后，系统先判定问题类型（数据型查询 / 规则型查询 / 合规审查 / 条款释义），据此选择检索通道组合与核验策略；
  2. **参数/要素槽位识别**：
     * 工程场景：建筑类别、耐火等级、建筑高度、火灾危险性类别等；
     * 法律场景：行为主体（企业/个人/经营者）、行为客体（合同/数据/劳动）、行为类型（收集/使用/传输/删除）、行业领域等；
  3. **四档追问策略**：
     * **打破沙锅档**：最多 5 轮，每轮最多 3 问，力求穷尽所有参数/要素；
     * **正本清源档（默认推荐）**：最多 2 轮，每轮最多 3 问，仅追问最核心的定性参数/要素；
     * **差不多就行档**：最多 1 轮，仅问 1~2 个最关键参数/要素；
     * **纯靠猜档**：0 轮追问，直接按通用默认场景作答并列出前提假设。
  4. **免追问前置声明语法**：若用户提问时已主动输入结构化参数（如 `[丙类厂房/高层/耐火二级] 疏散宽度` 或 `[企业/收集/人脸信息] 是否合法`）或自然语言已包含完整参数，系统判定"槽位已满"，**直接跳过任何档位的追问直出答案**，并在答案末尾标注"已识别参数/要素：……"；
  5. 追问必须严格基于工程参数 Schema 或法律要素 Schema，严禁编造参数；用户回复"跳过/不知道"时立即按默认常见场景兜底作答。
* **用法**：
  * **用户**："两栋楼防火间距多远合规？"
  * **系统（正本清源档）**："请问现场情况是：1. 建筑火灾危险性类别（甲/乙/丙/丁/戊类）？2. 是否属于高层建筑？3. 耐火等级分别是几级？（若不确定可直接回复'按常见多层民用回答'）"。
  * **用户**："我们公司想在 App 里收集用户人脸做考勤，合规吗？"
  * **系统（正本清源档）**："请补充：1. 收集对象是员工还是外部用户？2. 是否已取得个人信息主体的单独同意？3. 是否已完成个人信息保护影响评估？（若不确定可回复'按一般企业场景回答'）"。
* **验收**：模糊提问下正本清源档追问合理性 100%；带前置参数提问时 100% 免追问直出答案。
* **字段**：`user_profile`（`query_mode`），`scene_param_schema`，`legal_element_schema`（v4.3 新增）。

### R41 工程参数反查适用条款（v4.3 升级为条件推理检索）

> **v4.3 升级说明**：v4.2 的 R41 仅是"工程参数 → 条款"的关键词反查，v4.3 升级为**条件推理检索**，引入 Clause Applicability Model。

* **功能**：用户给出工程参数或法律场景参数（如"丙类厂房、耐火二级、建筑高度 24m"或"中小企业、收集员工生物识别信息、用于考勤"），系统根据条款的适用条件（`applicability_condition`）、限制条件（`restriction`）、例外条件（`exception`）反向筛选适用的条款清单，分组呈现，注明"仅供参考，适用性需人工复核"。
* **Clause Applicability Model**：
  ```
  条款
   ├─ 适用条件 (applicability_condition): 该条款适用的场景描述
   ├─ 限制条件 (restriction): 该条款不适用的场景描述
   └─ 例外条件 (exception): "除……外"的例外情形
  判断结果: 用户参数 → 命中适用条件且不命中限制/例外 → 适用
  ```
* **用法**：方案设计自检或合规预判时输入参数反查适用条款/法规。
* **验收**：反查用例列出的条款均包含对应适用条件，无明显不相干条款混入；条件推理的适用性判定准确率 $\ge 90\%$。
* **字段**：`clause_revision`（`applicability_condition`, `restriction`, `exception`）。

### R-L6 逐点合规判定

### 5. SQLite 权威物理表结构设计 (DDL，v4.3 扩展)

全系统数据使用单一 SQLite 文件存储：`%APPDATA%/KnowledgeStation/database/knowledge.db`。数据库初始化时必须执行：

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;
PRAGMA busy_timeout=5000;  -- v4.3 新增：写冲突时等待 5 秒而非立即失败
```

#### 5.1 核心数据表

```sql
-- 1. 文档元数据表 (v4.3 扩展 legal_hierarchy 与 doc_type)
CREATE TABLE IF NOT EXISTS doc_meta (
    doc_id TEXT PRIMARY KEY,                  -- 稳定文档ID (ULID)
```

```python
from pathlib import Path
from typing import Dict, Any
import fitz  # PyMuPDF
from magic_pdf.data.data_reader_writer import FileBasedDataWriter
from magic_pdf.data.dataset import PymuDocDataset        # v4.3: 0.10+ API
from magic_pdf.model.doc_analyze_by_custom_model import doc_analyze
from magic_pdf.config.enums import SupportedPdfParseMethod

def extract_page_geometries(pdf_path: Path) -> Dict[int, Dict[str, Any]]:
    """v4.3: 提取每页 PDF 的 Point 宽高、旋转角、CropBox、MediaBox"""
    doc = fitz.open(pdf_path)
    geometries = {}
    for page_idx in range(len(doc)):
        page = doc[page_idx]
        rect = page.rect
        # v4.3: 同时提取 CropBox 与 MediaBox, 前端 viewport 变换需要
        cropbox = page.cropbox
        mediabox = page.mediabox
        geometries[page_idx + 1] = {
            "width": float(rect.width),
            "height": float(rect.height),
            "rotation": int(page.rotation),
            "crop_box": [float(cropbox.x0), float(cropbox.y0), float(cropbox.x1), float(cropbox.y1)],
            "media_box": [float(mediabox.x0), float(mediabox.y0), float(mediabox.x1), float(mediabox.y1)],
        }
    doc.close()
    return geometries

def parse_pdf_with_mineru(pdf_path: Path, output_dir: Path) -> Dict[str, Any]:
    """v4.3: 调用 MinerU 0.10+ API, 在独立 Worker 子进程中执行"""
    pdf_bytes = pdf_path.read_bytes()
    writer = FileBasedDataWriter(str(output_dir))
    ds = PymuDocDataset(pdf_bytes)
    
    is_ocr = ds.classify() == SupportedPdfParseMethod.OCR
    infer_result = ds.apply(doc_analyze, ocr=is_ocr)
    pipe_result = infer_result.pipe_ocr_mode(writer) if is_ocr else infer_result.pipe_txt_mode(writer)
    
    model_output = pipe_result.get_model_output()
    geometries = extract_page_geometries(pdf_path)
    
    return {
        "blocks": model_output,
        "geometries": geometries
    }
```

```python
def perform_hybrid_search(

    channels: Optional[List[str]] = None,
    modality_filter: Optional[str] = None,

    behavior_scope_filter: Optional[str] = None,
) -> List[ClauseRevisionModel]:

    channels: 启用的通道, 默认全开 ['exact','fts','vec','modality','legal_element','behavior_scope']
    """
    conn = get_db_connection()
    k = 60  # RRF 衰减系数
    scores: Dict[str, float] = {}
    if channels is None:
        channels = ['exact', 'fts', 'vec', 'modality', 'legal_element', 'behavior_scope']
    
    # 通道 A: 条款号/法条号精确匹配
    if 'exact' in channels:
        clause_match = re.search(r'(\d+\.[\d\.]+|第[一二三四五六七八九十百千]+条)', query)
        if clause_match:
            exact_no = clause_match.group(1)
            cur = conn.execute(
                "SELECT clause_revision_id FROM clause_revision WHERE clause_number = ?", (exact_no,)
            )
            for rank, row in enumerate(cur.fetchall()):
                scores[row[0]] = scores.get(row[0], 0.0) + (1.0 / (k + rank + 1)) * 2.0
    
    # 通道 B: SQLite FTS5 全文检索
    if 'fts' in channels:
        words = [w for w in jieba.cut_for_search(query) if len(w.strip()) > 1]
        if words:
            fts_query = " OR ".join(words)
            cur = conn.execute(
                "SELECT clause_revision_id, rank FROM clause_fts WHERE clause_fts MATCH ? ORDER BY rank LIMIT 20",
                (fts_query,)
            )
            for rank, row in enumerate(cur.fetchall()):
                scores[row[0]] = scores.get(row[0], 0.0) + (1.0 / (k + rank + 1))
    
    # 通道 C: sqlite-vec 向量检索 (v4.3 替换全库 NumPy 扫描)
    if 'vec' in channels:
        query_emb = list(_dense_model.embed([query]))[0]
        # v4.3: 使用 sqlite-vec 虚拟表, 亚线性复杂度
        cur = conn.execute(
            "SELECT clause_revision_id, distance FROM clause_vec WHERE embedding MATCH ? ORDER BY distance LIMIT 20",
            (query_emb.tolist(),)
        )
        for rank, row in enumerate(cur.fetchall()):
            scores[row[0]] = scores.get(row[0], 0.0) + (1.0 / (k + rank + 1))
    
    # 通道 D: 模态召回 (v4.3 新增)
    if 'modality' in channels and modality_filter:
        cur = conn.execute(
            "SELECT clause_revision_id FROM clause_revision WHERE modality = ? AND legal_status = 'effective'",
            (modality_filter,)
        )
        for rank, row in enumerate(cur.fetchall()):
            scores[row[0]] = scores.get(row[0], 0.0) + (1.0 / (k + rank + 1)) * 0.8
    
    # 通道 E: 法理要素召回 (v4.3 新增)
    if 'legal_element' in channels and subject_filter:
        cur = conn.execute(
            "SELECT clause_revision_id FROM clause_revision WHERE subject = ? AND knowledge_type = 'legal'",
            (subject_filter,)
        )
        for rank, row in enumerate(cur.fetchall()):
            scores[row[0]] = scores.get(row[0], 0.0) + (1.0 / (k + rank + 1)) * 0.8
    
    # 通道 F: 行为客体召回 (v4.3 新增, 合规审查专用)
    if 'behavior_scope' in channels and behavior_scope_filter:
        words = [w for w in jieba.cut_for_search(behavior_scope_filter) if len(w.strip()) > 1]
        if words:
            fts_query = " OR ".join(words)
            cur = conn.execute(
                "SELECT clause_revision_id, rank FROM clause_fts WHERE behavior_scope_segmented MATCH ? ORDER BY rank LIMIT 20",
                (fts_query,)
            )
            for rank, row in enumerate(cur.fetchall()):
                scores[row[0]] = scores.get(row[0], 0.0) + (1.0 / (k + rank + 1)) * 1.2  # 合规审查场景加权
```

```python
import re
from typing import List
from src.core.domain.models import VerificationResult, ModalityViolation
from src.core.retrieval.hybrid_engine import MODALITY_STRENGTH

def verify_llm_output(
    llm_output: str,
    evidence_clauses: List[dict],  # 检索返回的证据集 (含 knowledge_type, modality 等)
) -> VerificationResult:
    """v4.3 分型核验器: 数据型核数值, 规则型核模态, 法理型核要素"""
    
    unsupported_clauses = []
    unverified_numbers = []
    modality_violations = []
    legal_element_violations = []
    
    # 1. 条款号闭包校验 (所有类型通用)
    cited_numbers = set(re.findall(r'(?:GB[\s\d\-]+|民法典|个保法|数安法)?\s*(?:第?[一二三四五六七八九十百千\d]+条|\d+\.[\d\.]+)', llm_output))
    evidence_numbers = {c['clause_number'] for c in evidence_clauses}
    for num in cited_numbers:
        if num and num not in evidence_numbers:
            unsupported_clauses.append(num)
    
    # 2. 分型核验
    for clause in evidence_clauses:
        ktype = clause.get('knowledge_type', 'rule')
        
        if ktype == 'data':
            # 数据型: 数值闭包核验 (复用 v4.2 逻辑)
            numbers_in_evidence = re.findall(r'(\d+(?:\.\d+)?)\s*(m|米|MPa|kPa|%|°C|h|分钟)', clause['content_text'])
            for val, unit in numbers_in_evidence:
                pattern = rf'{re.escape(val)}\s*{re.escape(unit)}'
                if not re.search(pattern, llm_output):
                    # 检查是否被篡改为其他数值
                    tampered = re.search(rf'(\d+(?:\.\d+)?)\s*{re.escape(unit)}', llm_output)
                    if tampered and tampered.group(1) != val:
                        unverified_numbers.append({
                            'clause_id': clause['clause_revision_id'],
                            'original': f'{val}{unit}',
                            'output': tampered.group(0),
                            'violation': 'number_tampered'
                        })
        
        elif ktype == 'rule':
            # 规则型: 模态强度核验 (R4a)
            source_modality = clause.get('modality')
            source_strength = MODALITY_STRENGTH.get(source_modality, -1)
            if source_modality and source_strength >= 0:
                # 在 LLM 输出中查找描述该条款的模态词
                output_modality = _extract_modality_from_output(llm_output, clause['clause_number'])
                if output_modality:
                    output_strength = MODALITY_STRENGTH.get(output_modality, -1)
                    if output_strength < source_strength:
                        modality_violations.append(ModalityViolation(
                            clause_revision_id=clause['clause_revision_id'],
                            source_modality=source_modality,
                            output_modality=output_modality,
                            source_strength=source_strength,
                            output_strength=output_strength,
                            violation_type='modality_weakened'
                        ))
                    elif output_strength > source_strength:
                        modality_violations.append(ModalityViolation(
                            clause_revision_id=clause['clause_revision_id'],
                            source_modality=source_modality,
                            output_modality=output_modality,
                            source_strength=source_strength,
                            output_strength=output_strength,
                            violation_type='modality_strengthened'
                        ))
                else:
                    modality_violations.append(ModalityViolation(
                        clause_revision_id=clause['clause_revision_id'],
                        source_modality=source_modality,
                        output_modality='',
                        source_strength=source_strength,
                        output_strength=-1,
                        violation_type='modality_missing'
                    ))
        
        elif ktype == 'legal':
            # 法理型: 法理要素完整性核验
            # 检查例外条件是否被保留
            exception = clause.get('exception')
            if exception:
                if not re.search(r'除.{0,50}外|另有规定|但', llm_output):
                    legal_element_violations.append({
                        'clause_id': clause['clause_revision_id'],
                        'violation': 'exception_missing',
                        'original_exception': exception
                    })
            # 检查主体是否被错位
            subject = clause.get('subject')
            if subject and subject not in llm_output:
                legal_element_violations.append({
                    'clause_id': clause['clause_revision_id'],
                    'violation': 'subject_missing',
                    'original_subject': subject
                })
    
    is_valid = (not unsupported_clauses and not unverified_numbers 
                and not modality_violations and not legal_element_violations)
    
    return VerificationResult(
        is_valid=is_valid,
        unsupported_clauses=unsupported_clauses,
        unverified_numbers=unverified_numbers,
        modality_violations=modality_violations,
        legal_element_violations=legal_element_violations
    )

def _extract_modality_from_output(text: str, clause_number: str) -> str:
    """从 LLM 输出中提取描述指定条款的模态词"""

    match = re.search(pattern, text)
    return match.group(1) if match else ''
```

#### 8.6 PDF.js 坐标变换前端实现（v4.3 强制规范）

```typescript
// src/renderer/pdf/PdfHighlighter.ts
// v4.3 强制: 使用 viewport.convertToViewportRectangle, 禁止 bbox × scale
import type { PDFPageProxy, PageViewport } from 'pdfjs-dist';

export function renderHighlight(
  page: PDFPageProxy,
  viewport: PageViewport,
  bbox: [number, number, number, number]  // [x1, y1, x2, y2] PDF 坐标系
): HTMLDivElement {
  // 关键: viewport 自动处理 rotation / CropBox / MediaBox
  const [vx1, vy1, vx2, vy2] = viewport.convertToViewportRectangle(bbox);
  
  const left = Math.min(vx1, vx2);
  const top = Math.min(vy1, vy2);
  const width = Math.abs(vx2 - vx1);
  const height = Math.abs(vy2 - vy1);
  
  const div = document.createElement('div');
  div.className = 'pdf-highlight';
  div.style.cssText = `
    position: absolute;
    left: ${left}px;
    top: ${top}px;
    width: ${width}px;
    height: ${height}px;
    background-color: rgba(255, 235, 59, 0.45);
    border: 1.5px solid #FBC02D;
    pointer-events: none;
    animation: highlight-pulse 0.3s ease-out;
  `;
  return div;
}
```

### 10. 质量验收门禁 (Definition of Done - DoD，v4.3 升级)

任何任务必须满足以下 8 条硬性指标，方可标记为 `Accepted`：

1. **契约一致性**：所有 Agent 必须通过 T00 架构契约测试，禁止私自修改数据模型或 API schema；
2. **类型检查与 Lint 零警告**：Python 端 `mypy` 零报错（✅ 2026-09-13 已建立：`npm run typecheck:py` = `.venv\Scripts\python -m mypy` → 120 文件 0 错误。原愿景 `--strict` 经实测审计降级为**非 strict 保守口径**——`[tool.mypy]` 开 `check_untyped_defs`/`no_implicit_optional`/`warn_redundant_casts`，第三方无 stub（fitz/jieba/mineru 系/curl_cffi/openai SDK）`ignore_missing_imports`，现存 `# type: ignore[code]` 均带行内中文理由注释（环境/SDK 类型限制，运行时有守卫）。strict 里程碑待 ~612 处注解补齐后另立）；前端 `tsc --noEmit` 零报错；
3. **测试覆盖率底线**：核心模块（`ingestion`, `retrieval`, `verification`, `compliance`）单元测试行覆盖率 $\ge 85\%$；
4. **分型核验率**：
   * 数据型：伪引用与数值篡改拦截率 100%；
   * 规则型：模态减弱（应→宜、严禁→不应）拦截率 100%；
   * 法理型：例外条件丢失拦截率 $\ge 90\%$；
5. **性能基准指标**：
   * 六路混合检索 p95 延迟 $\le 50\text{ms}$（含 sqlite-vec 向量）；
   * sqlite-vec 向量检索 p95 延迟 $\le 20\text{ms}$（1 万条规模）；
   * PDF 原页跳转与黄框渲染 p95 延迟 $\le 200\text{ms}$（含旋转页/CropBox）；
   * 软件空闲时内存占用 $\le 200\text{MB}$；
6. **合规审查准确率**：Golden Set 上三色判定准确率 $\ge 88\%$，违法判定（🔴）精确率 $\ge 95\%$；
7. **异常与降级覆盖**：网络中断、DeepSeek API 欠费（402）、PDF 损坏、SQLite 锁死、Parser Worker 崩溃、向量引擎离线等边界用例的处理；
8. **无硬编码机密**：代码库内严禁包含任何 `sk-xxxx` API Key 或本机绝对路径；敏感配置必须 DPAPI 加密。
