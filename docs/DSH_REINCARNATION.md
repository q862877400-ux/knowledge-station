# KS×DSH 转生产品规格（Reincarnation Spec）

> **文档定位**：KnowledgeStation 秽土转生为「DeepSeek Harness（dsh）法规国标强关联 RAG 插件」的**决策记录文件（单一账本）**——把逐项打磨确认过的每一条产品/架构决策固定下来，施工照此执行；改哪条就改本条。
> **版本**：v0.1（2026-09-05，经 23+ 轮逐项问答打磨确认）
> **状态**：方案定稿待评审 → 评审通过后进入施工（先桥后功能）
> **关联**：主计划 `1-v4.3 (1).md`（需求源头 SSOT）｜`docs/ENCYCLOPEDIA.md`（老系统百科全书）｜本文档（转生账本）
> **范围**：只定义"转生成什么样 + 怎么做"；不重复老系统已冻结的引擎细节（查 ENCYCLOPEDIA）。

---

## 0. 一句话定位

在 DeepSeek Harness 里做一款**法规国标强关联 RAG 插件**：合规问题强制走"官方发现 + 本地原件核验"链路；答案**只引现行版**、依据全部带链、点链即到原 PDF；日常轻（不打扰聊天）、取证重（一键三段式）；把幻觉从体验层面压到最低。老 KnowledgeStation **引擎与数据全部保留**，双栏 SPA / Electron 壳退役。

## 1. 转生总则（铁律）

1. **引擎代码与数据原样保留**：`src/core/` 全模块、数据区（`%APPDATA%\KnowledgeStation\`，`KS_DATA_DIR` 可重定向）、存量标准目录（`D:\AI\work space\标准\`）、schema.sql 冻结、513 测试、Golden Set 门禁——全部为转生后引擎本体，不动。
2. **数据/代码分离**（用户级工程原则）：运行产物写数据区、脚本参数化、GBK CSV 给 Excel、代码树零运行产物——转生后依然成立。
3. **只换"壳"与"交互通道"**：DSH 会话 = 左栏；better-sidebar = 右栏工作台；被砍的是重复造的轮子（Electron / 双栏 SPA / SSE 前端消费 / dev_launcher / supervisor 进程看门狗——职责移交插件 host）。
4. **契约红线继承**：SSE 顺序、bbox 底部原点、单写者队列、egress 审计、密钥零明文——老红线在引擎侧全部继续生效。
5. **信任语义**：OCR/机器层文本永不进展示面（纯后台推理）；展示 = 原件。

## 2. 总体架构

```
DSH Web
├─ 会话（左）          ← 问答/审查/确认/修订，agent 编排
│   输入框内斜杠命令：/forensic（查法规模式）· /bookmarks（仅收藏，依附前者）
├─ better-sidebar（右）← 常驻工作台 tabs：
│   ├─ 📖 PDF 证据    （原 PDF + bbox 高亮跳转 + 目录树/缩放/打开外部）
│   ├─ 📘 法规目录    （flk 29,764 条目：分类/搜索/效力徽章/下载入库）
│   ├─ 🔍 数据体检    （问题条款清单 + 纠错工作台 + Word/WPS 往返）
│   └─ 📊 合规审查    （三色点卡/义务清单/检查表/差距分析/释义）
└─ 引擎（Python sidecar，随机端口 + 一次性 token，engine.session.json）
     = 老 src/core 全量保留 + 新增薄层（answer 链 / task_schema / 工具路由）
插件 host（Node）: 懒拉起引擎/单实例锁/空闲自动关停/每日巡检定时器/HTTP 直调
```

- **接入方式**：插件 host 半边直接 HTTP 调引擎（沿用随机端口 + token 发现机制），不走 MCP 壳——少一层、少故障点。
- **生命周期**：首调 `ks_*` 工具时 spawn 引擎；30 分钟空闲优雅关停（2026-09-12 批3：15→30 + 查法规模式 keepalive + 并发 ensureLive 合并；`idleTimeoutMs` 可配）；同数据目录单实例锁（第二个调用复用）。
- **凭据读取链（2026-09-12 批2+批4 定稿）**：权威存储 = `<data_dir>/secrets.json`（DPAPI 加密，引擎与脚本同链）；注册表/环境变量只作**显式覆盖**（CI/脚本/临时调试），引擎与脚本**绝不写**注册表。HKCU\Environment 本项目三键已全部迁移删除（DEEPSEEK_API_KEY / KS_MINERU_CLOUD_API_KEY / SCNET_OCR_API_KEY——后者以 `KS_SCNET_OCR_API_KEY` 名入加密存储）。
- **每日巡检**：DSH 插件内置定时器（dsh 开着即可，无需活跃会话）→ 每日固定时刻 spawn 引擎 headless 巡检（扫官网公告→更新后台→写效力报告→退出，零常驻）；当天 dsh 没开则错过顺延、下次启动补跑。不注册 Windows 计划任务、不做引擎常驻。
- **LLM 双层**：agent 编排/追问走 DSH 模型（session-telemetry）；`ks_answer` 等引擎答案走引擎自己的 LLM 凭据 + 引擎 egress 审计。凭据变量名 `KS_LLM_API_KEY` / `KS_LLM_BASE_URL`（**2026-09-11 命名空间化**；旧名 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` 仅作只读回退——写裸全局名会遮蔽 DSH 凭据层，事故与根因见 §事故档案）。skill 写明成本纪律：能 `ks_retrieve` 快查的不调 `ks_answer`。
- **配置页**（Harness 设置内插件专属分区）：引擎 LLM（DeepSeek Key + 模型名，或本地 LM Studio 端点/模型）、OCR 双通道（**已配置官方云 Key → 云优先、本地兜底；未配置 → 纯本地**）、巡检节奏（默认每日，可改）、数据/下载目录、默认口径画像、效力报告入口。密钥引擎侧 DPAPI 加密存储，明文不进 settings.yaml，配置在页面填、不走聊天框。

## 3. 展示与信任（产品决策 P1 组）

1. **展示分层**：国标 = 只显示原 PDF（OCR/机器文本永不展示）；官方 docx 来源的法规 = 公文排版文本视图（官方结构化文本，非 OCR，可选中复制）+ 原 PDF 并存。来源决定展示方式，不搞一刀切。
2. **引用规则（收紧）**：
   - 只允许引用**现行版**；过期（废止/被替代）版本一律**不作为引用依据**——用户点名问旧版时说明其已过期 + 与现行差异，不当作依据引用。
   - 涉及**即将生效**的新版：主答按现行口径，**单独加一句**（何时施行、届时将如何改变要求）。
   - 引用 = 蓝色下划线链；**悬停无任何动作**；点击 → 右栏原 PDF 跳到对应条款黄框高亮。
3. **答案骨架（三段式，取证模式专属）**：① 依据区（每条：标准号/条款号/版本年份/效力层级徽章，蓝链）→ ② 推导区（正文以 [1][2] 引用依据）→ ③ 结论区。直接条款答案（1 档）推导极简（"由依据①直接得出"），不注水。
4. **答案排序红线**：现行性 → 效力层级（上位法 > 下位法、强制 > 推荐）→ 内容匹配度。任何收藏/偏好权重不得越过这三条。

## 4. 触发与问答模式（产品决策 P2 组）

1. **双层模式**：
   - **轻模式（默认）**：模型自动识别合规类主题（具体标准号/数值限值/分级/义务表述/合规判断/新旧版废止等）→ **静默检索** → 流水正文 + 内联蓝链。skill 规则 1：规范题**禁止凭记忆作答**（可补充常识并标注）。闲聊不触发。
   - **取证模式**：强提示词（"查法规/查国标/依据是什么"等）或输入框下 **「📜 查法规模式」按钮**（会话级开关）→ 每问强制权威链路 + 三段式。
2. **按钮层级（渐进展开）**：输入框下控件区默认无按钮；点「📜 查法规模式」后才出现第二个开关 **「🔖 仅收藏」**——打开后检索只从收藏集查（取证模式内生效）。
3. **追问策略**：问齐才答；参数模型驱动（按影响度排序、按 key 去重防循环）；缺参数绝不拒答 → **分情况作答**（分支各自带结论 + 链）。追问呈现 = 文本 + 常用选项引导（v1 不做点选控件）。
4. **冲突处理**：检测到跨源冲突（法规 vs 国标/新旧版/强制 vs 推荐/地方更严口径）→ 答案尾部 **⚠️ 冲突块**：按效力**全量列出**冲突条款（蓝链 + 效力层级 + 版本日期）+ **讲清判断逻辑**（上位法优于下位法、新法优于旧法、强制优于推荐、地标不得低于国标，执行常取更严口径）→ **让用户选口径**，不做黑箱定论；**选择存入画像**，之后同类问题默认沿用并显式标注（"按你上次选择的口径：…"），随时可改。
5. **效力报告**：会话调取 `/效力报告` → 法规国标**混排**统一卡，按状态分组（✅ 新施行生效 / 🔴 已废止 / ⏳ 即将施行 / 🟡 已更新新版），每行：名称/标准号 + 状态 + 日期 + 来源（官方核验链接，库内可蓝链跳原文）；时间窗筛选（近 7/30 天/全部）+ 导出 Word/CSV。数据源 = 每日官网公告巡检 + 手动上传件补核结果。
6. **回答引用与批注联动**：引用某条款时，引擎把该条款上的**用户批注一并作为上下文参与推理**；答案在涉及处注明"含您的批注"。批注绑 clause_key，跨版本平移不丢。

## 5. 检索、收藏与库外扩展（产品决策 P3 组）

1. **收藏语义（最简版）**：收藏只有两件事——① 收藏法规/国标；② 取证模式下用「🔖 仅收藏」按钮把检索圈进收藏集。**不做"同分优先权重"**（普通检索里收藏不自动靠前；若将来需要，一行配置加回）。
2. **库内查无 → 外扩流程**：自动搜关键词（官方渠道为主，全网可做线索确认"标准号+年份+状态"）→ 候选清单给你选 → 确认后**官方渠道下载**（cssn/openstd/std.samr/flk/ndls/gov.cn + 部委官网），文件命名 **"标准号+年份"** → 入库后再答；官方无公开全文（如采标）→ 明示 + 引导手动上传。**非官方站永远只给线索链接，不给下载**。
3. **私有文档隔离**：上传的公司制度/个人文稿/项目资料进**独立目录**（可按你建子目录）；默认不参与权威检索；你明确指定（"在我们 XX 制度里查"）才被检索，引用时永远标注"内部文件"，与法规引用区分。分类由引擎自动判定（法规国标 → 主库 / 其余 → 私有），低置信进 ⚠️ 桶待确认。

## 6. 入库与内容运营（产品决策 P4 组）

1. **单本入库**：永远先 **Dry-Run 预览**（识别标准号/条款数/三型分布/表格附录/可疑数/质量分级，秒级不落库）→ 你确认 → 落库 → 质量报告。
2. **批量入库**（几十本~几万本）：跑完出**批量质量总账**分三桶——✅ 直接可用 / ⚠️ 需复核（可疑条款多、附录缺失、表格异常、自动标签置信度 <0.8、元数据待补填）/ ❌ 失败隔离（quarantine）。你审总账 + ⚠️ 桶（进「数据体检」集中处理）。**新语料源首次批量先抽样 3~5 本人工看质量**再全跑；熟悉老源直接全跑。
3. **自动分类入库**：上传内容自动分类（见 P3-3）；自动标签置信度 <0.8 不静默写死，进待确认。
4. **生效校验（新增内容必做）**：
   - 官方源下载 → 自带状态（flk sxx / openstd 状态等）。
   - 手动上传 → 按识别"标准号+年份"自动查官方渠道；**查不到不阻塞入库**，弹**可选填写框**（预填已识别的标准号/名称/年份/状态/生效日期，可改可跳过）；跳过 = 灰标"未核验" + 进巡检队列自动补核（核到默默更正 + 按 P4-5 通知）。批量场景填写框收敛到 ⚠️ 桶集中补填。
   - 状态纪律：查不到就标"未核验"，**绝不假装"现行"**。
5. **自动更新（每日，无人值守）**：每日扫官网公告（8+ 渠道 + flk/gov.cn 新发布监测，守官方限速礼仪；存量 3 万标准号深度滚动体检按日预算顺延或手动触发）。发现新版/废止 → **默默执行**：自动下载新版 → 切换默认引用到现行版 → **旧版自动备份留存** → 完成后**轻通知 + 影响清单**（波及的旧引用/义务清单/检查表/收藏问答），不逐条确认。影响面 = 复用 R49 impact + backlinks。
6. **对接来源范围**：只对接**官网公告源**（含部委官网 + flk/gov.cn）；**不接公众号**（无公开 API、账号风险大、内容与官网同源，边际收益低）。
7. **首次初始化引导**：首会话引导卡——检测存量标准目录 + 法规目录接入状态，四选一（或组合）：① 全量批量导入存量（3.5 万，后台，按总账分桶验收）② 先导高频常用（马上能用）③ 只接法规目录（官方源按需下载）④ 先手动传几本试试。导入期间库标"建设中"，问答不阻塞（查不到走 P3-2 外扩）。

## 7. 修订助手（产品决策 P5 组）

1. **场景**：上传公司制度/个人文稿 → 基于法规国标做**带溯源标记的修订/起草**；原文件自动备份。
2. **流程（两段式，网络发现优先）**：
   - ① 理解你的原文 → **网络检索**相关法规标准候选清单（比本地库全，能发现新版/新规；渠道规则见 P3-2）；
   - ② 候选清单给你**挑选/勾选**（效力层级排序、含条款摘要、可点开原文）；
   - ③ 本地库已有的 → **直接引用本地条款**（可核验）；本地没有的 → **自动切下载流程**（官方下载入库后再引用；官方无公开 → 引导手动上传）；
   - ④ 生成修订稿 docx：改动**加色/加下划线**标注 + **句尾上标引用**（`[GB 30871-2022 §6.1.2]`）+ **文末「依据清单」**一节；产物落私有目录，原稿自动备份；
   - ⑤ 同时附**改动对照清单**（原句 → 新句 → 依据蓝链），你逐条 采纳/回退/改表述——先成稿、清单式事后审计。
3. **与其他能力分工**：深知公文写作 = 文风/格式/红头/范文（在线）；本修订助手 = **本地库条款溯源引擎**（依据可核验到原件）。两者可共存，不抢。

## 8. 老项目转生边界

### 保留（引擎本体，不动）
入库管线（MinerU 2.x/降级/docx/law_source/排版还原/插图）、六通道检索 + RRF + rerank + Golden Set 门禁、typed_verifier、SYSTEM_PROMPT 1~9 与追问/理解层（转生后其"答案生成 + 核验"职责收进 `ks_answer`）、合规引擎/义务清单/差距分析/释义/批量问答、补丁机制与跨版本平移、快照备份/校验、官方源与 8+ 更新渠道、数据包导出导入、外发审计、全套 513 测试。

### 退役（被 DSH 生态替代）
Electron 壳、双栏 React SPA（App.tsx/证据卡/TipTap 阅读面/PdfViewer 面板代码等渲染面）、SSE 前端消费、dev_launcher/restart_dev、supervisor 进程看门狗（职责移交插件 host）、TipTap 原位纠错界面（纠错收敛到「数据体检」tab + Office 往返工具流）。

### 明确不做（v1 起即不做）
公众号抓取、PDF 页级自由批注（条款级批注即可，页级需 schema 契约变更，后置）、引用悬停卡片、非官方渠道下载、多用户/权限（Non-goal）、自建使用统计看板（用 dsh 生态 usage 插件）、引擎模型微调。

### 展示承载（better-sidebar 扩展点）
`registerTab`：PDF 证据 / 法规目录 / 数据体检 / 合规审查；`registerFileViewer`（docx/PDF 官方文件查看可选）。答案内蓝链由极轻客户端插件渲染（带 docId/page/bbox/clause_revision_id 数据 href，点击发事件 → 证据 tab 跳转高亮）。
