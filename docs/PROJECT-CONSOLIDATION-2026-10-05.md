## 一、结论先行

**问题不是"文档太多"，是"文档没有层级"。**

113 份文档、5.3 MB，其中 **37 份只被引用过 1 次**，**13 份零引用**，
而**全仓在两个月亮之前都没有一份总索引**（`docs/INDEX.md` 是本文这一轮才建的）。
⇒ 没有层级 ⇒ 每份文档都得自己写一遍背景 ⇒ **同一件事在 N 份文档里重复** ⇒ 这就是"找不到 + 又臭又长"的机制。

**⇒ 所以清理的重点是"收口 + 建索引"，删只是其中一小步。**

---

## 二、第一性原理：什么文档值得存在

一份文档只有**三种正当身份**：

| 身份 | 内容 | 长度要求 |
|---|---|---|
| **当前真源** | 现在是什么、该怎么做 | 唯一、必须准、**短** |
| **决策理由** | 为什么这么定 | **短** |
| **历史留痕** | 曾如此、何时作废 | **一句话** |

**四种该处理的**：

| 该处理 | 判据 |
|---|---|
| **归档** | 逐轮的完整过程 —— **它本来就在 `git log` 里** |
| **合并** | 同一主题散在多份 |
| **删除** | 已被取代、且无人引用、且不是任何话题的归属层 |
| **保留** | 真源 / 台账 / 决策理由 / 留痕 |

⚠ **两条本仓的硬约束不许破**：
1. 「打回的说法必须**就地更正并留痕**（含我自己写错的）」——**"错话+更正"不许悄悄删**；
2. 「作废的旧计划**直接删掉**，只在**开发史**里留一句」——**删的是旧计划全文，不是留痕**。

## 五、三个真问题

### 🔴 问题 1：开发史是"逐轮全文日志"，与 `git log` 重复

`docs/DEVELOPMENT-HISTORY.md`：**11,888 行 / 1,053 KB / 146 个 `##` / 459 个 `###`**。
看标题就知道形状——`§10.71` 到 `§10.80` **每一节是一轮工作**（"复核 b12 的 MEDIUM-2"、"25 条端点改 def"…）。

**⇒ 它的正文本质是 `git commit message` 全文的副本。**
**⇒ 而它占了根文档体积的 61%。**

⚠ **但不能全删**：规则要求开发史保留"曾如此、何时作废"的留痕与"错话+更正"。
⇒ **该做的是分层，不是删除**（见 §六 提案二）。

### 🔴 问题 2：没有层级 ⇒ 同一件事在 N 份里重复

- **全仓无总索引**（本文这轮才建 `docs/INDEX.md`）
- **37 份只被引用 1 次** —— 这些是"一件事一份文档"的产物，彼此不连
- 后果：新来的会话（或我自己）**不知道哪份是活的**，只能重读

### 关于"删"的一条边界（必须先说）

**删除在 git 里是**可恢复**的**（内容留在历史里），所以它**不是不可逆**。
**但"哪份死"是判断，不是机械事实** —— 所以我不打算一次性批量删，而是**逐个定性 + 你确认**。

**⇒ 我建议的执行顺序：先索引（已做）→ 再归档开发史 → 最后清孤儿。**
