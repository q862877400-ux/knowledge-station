**这一页给接手的人**：读完能说出这个项目要做什么、现在做到哪、主要部件各干什么。
**要找文件在哪**，看 [../README.md](../README.md)（文件地图）。

## 一、目标

**让不专业的人用大白话提问，对任意资料类型，都能定位到可点开的那一段原文。**

三条总判据（取自项目施工总纲 `docs/RETRIEVAL-LONG-RANGE-PLAN.md`）：

| 判据 | 含义 |
|---|---|
| **换词可对** | 同一件事用不同说法问，都能找到同一处原文 |
| **排得上去** | 正确的原文片段要出现在结果前列，不能只"在库里" |
| **换资料类型不塌** | 从法规换到技术文档、从国标换到公司制度，机制不推倒重来 |

**产品定位**：**任何本地资料的检索与取证工具**。

**"任何"是字面意思**——产品要覆盖的资料类型**不限于法规标准**：

| 类型 | 例子 |
|---|---|
| 法规 / 国标 / 行标 / 团标 | GB、GB/T、应急部令…… |
| **文献与论文** | 学术论文、研究报告、技术白皮书 |
| **开源项目文档与源码** | 项目 README、设计文档、代码注释、issue 摘录 |
| 公司制度与内部文档 | 制度、流程、规范、自创规则 |
| 技术手册与合同 | 设备手册、施工方案、合同条款 |
| 个人工作生活资料 | 笔记、教程、收藏的文章 |

**法规问答只是其中一条数据源，不是产品主体。**
（`/forensic` 命令名、侧栏旧名「法规标准知识库」是历史遗留——它们指向的是"取证问答"这条链路，
**对任何资料类型都适用**。）

### 3.2 插件（`plugin/`，Node）

挂在 DSH 宿主上：宿主桥（`plugin/src/` 19 个 js / **9,974 行**）+ 侧栏 React 界面（`plugin/client/` 31 个 tsx/ts / 1,167 KB）。
宿主侧还注册了 **49 条 `/ks/*` HTTP 路由**（与引擎的 `/api/v1/*` 是两套）。

**对 agent 暴露的工具 —— 实际 6 个**（旧文只写了 5 个，缺 `ks_collect`，且把 `ks_effect_report` 说成"效果上报"，那是错的）：

| 工具 | 用途 | 注册处 |
|---|---|---|
| `ks_ping` | 探活：引擎在不在、模型加载没加载 | `index.js` |
| `ks_resolve_clause` | **条款定位** —— 按「标准号 + 条款号」取原文（引用兜底用） | `index.js` |
| `ks_answer` | **取证问答** —— 返回三段式 `依据→推导→结论` + 效力 + 核验结果。自己推理 ⇒ 几十秒，超时给 ≥120s | `index.js` |
| `ks_effect_report` | **效力总览** —— 库内标准/法规的五色统计（已废止 / 即将实施 / 现行有效 / 状态未知 / 仅参考）+ 红黄清单。**不是"效果上报"** | `index.js` |
| `ks_materials` | 材料平面只读（列项目 / 列材料 / 列未登记文件）。**不能批准**——评审是用户的判断 | `materials.js` |
| `ks_collect` | 抓一个网页正文，登记为待评审材料（一次一条；不能自己批准） | `collect.js` |

说明书真源：[`../tool-catalog.md`](../tool-catalog.md)（**生成物，手改必红**）。
