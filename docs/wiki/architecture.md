# KnowledgeStation：项目目标与现状

**这一页给接手的人**：读完能说出这个项目要做什么、现在做到哪、主要部件各干什么。
**要找文件在哪**，看 [../README.md](../README.md)（文件地图）。
**要改某个功能**，看 [components/](components/)。

## 一、目标

**让不专业的人用大白话提问，对任意资料类型，都能定位到可点开的那一段原文。**

三条总判据（取自项目施工总纲 `docs/RETRIEVAL-LONG-RANGE-PLAN.md`）：

| 判据 | 含义 |
|---|---|
| **换词可对** | 同一件事用不同说法问，都能找到同一处原文 |
| **排得上去** | 正确的原文片段要出现在结果前列，不能只"在库里" |
| **换资料类型不塌** | 从法规换到技术文档、从国标换到公司制度，机制不推倒重来 |

**产品定位**：**任何本地资料的检索与取证工具**。

**"任何"是字面意思**——产品要覆盖的资料类型**不限于法规标准**：

| 类型 | 例子 |
|---|---|
| 法规 / 国标 / 行标 / 团标 | GB、GB/T、应急部令…… |
| **文献与论文** | 学术论文、研究报告、技术白皮书 |
| **开源项目文档与源码** | 项目 README、设计文档、代码注释、issue 摘录 |
| 公司制度与内部文档 | 制度、流程、规范、自创规则 |
| 技术手册与合同 | 设备手册、施工方案、合同条款 |
| 个人工作生活资料 | 笔记、教程、收藏的文章 |

**法规问答只是其中一条数据源，不是产品主体。**
（`/forensic` 命令名、侧栏旧名「法规标准知识库」是历史遗留——它们指向的是"取证问答"这条链路，
**对任何资料类型都适用**。）

## 二、当前规模（实测，非宣称）

| 项 | 数字 |
|---|---|
| 法规/国标语料 | **6,797 篇 / 522,021 条条款** |
| 渠道台账 | **131 条**（其中含 github 字样 19 条） |
| 材料平面 | **81 份**材料 / 3 个项目 / 7,872 切片 |
| 引擎源码 | `src/` **152 个 py / 2,244 KB** |
| 插件源码 | `plugin/src/` **19 个 js / 456 KB** |
| 测试 | `tests/` 约 **163 个文件** |

⚠ **以上是某一时点的快照。** 要引用请以最新门禁跑出来的数字为准。

**⚠ 两处数字看起来对不上，是口径不同，不是矛盾**（这一点必须先说清，否则读者会以为哪份写错了）：

| 数字 | 口径 | 来源 |
|---|---|---|
| `src/` **152 个 py** | **文件系统里有多少个 `.py`**（含 `__init__.py`、脚本性模块） | 本节，实测 `Get-ChildItem` |
| mypy **134 个文件** | **门禁实际类型检查了多少个**（有排除规则） | 根 `README.md` 的「五道门禁」基线 |

**⇒ 一个是"有多少文件"，一个是"查了多少文件"，本来就不该相等。**
同理 `tests/` 的「约 163 个文件」与 pytest 的「1708 passed」也是两个口径——**后者是用例数，不是文件数**。

## 三、主要部件

> 每个部件的**职责 / 接口 / 依赖 / 明确不做什么**在 [components/](components/) 里各一篇。
> 这里只给一览，**不重复**那些内容。

### 3.1 引擎（`src/core/`，Python）

| 子系统 | 一句话 |
|---|---|
| `api` | 对外的 HTTP 端点（几十个），插件与外部都调它 |
| `ingestion` | 把 PDF/Office/网页解析成条款并入库 |
| `knowledge` + `law_source` | 法规知识本体 + 官方来源抓取 |
| `retrieval` | 检索（多路召回） |
| `storage` | sqlite 存取、schema、向量索引 |
| `update` + `update/channels` | 渠道巡检与台账 |
| `materials` | 材料平面（用户上传与自采资料） |
| `llm` | 模型调用与作答 |
| `exports` | 交付物导出 |
| `quality` / `verification` | 质检与分型核验 |
| `compliance` | 合规门与差距分析 |
| `query` | 查询理解（检索前把问句读懂） |
| `settings` / `vision` / `domain` | 配置与凭据 / 图像 / 域模型契约 |

> **「改 `retrieval` 具体要动哪个文件、哪个函数」** —— 本页只到**子系统**这一层。
> **要文件级的下手点，看 [`components/retrieval.md`](components/retrieval.md)**：
> 那里逐个列了 `hybrid_engine.py`（六路 + RRF）/ `term_bridge.py`（术语桥）/ `embedder.py` / `reranker.py`
> 各自负责什么、以及谁调它们。**本页不重复那些内容**（一个事实一个归属层）。

### 3.2 插件（`plugin/`，Node）

挂在 DSH 宿主上：宿主桥 + 侧栏 React 界面。
**对 agent 暴露的工具**（这是本产品对外的"手"）：

| 工具 | 用途 |
|---|---|
| `ks_ping` | 探活 |
| `ks_resolve_clause` | **条款定位**——按标准号/条款号取原文 |
| `ks_answer` | 问答（带检索结果） |
| `ks_materials` | 材料平面只读 |
| `ks_effect_report` | 效果上报 |

### 3.3 数据

sqlite（`schema.sql` 冻结 38 张表对象）。运行产物全在 `%APPDATA%\KnowledgeStation\`，
**数据与代码彻底分离**。

### 3.4 独立工具与数据集（`tools/`）

**这不是引擎的一部分**（不改 `src/`、不参与主检索），但**在同一个仓里、共用同一批政府站点**。

| 子目录 | 是什么 | 规模 | 入口 |
|---|---|---|---|
| `tools/gov-qa/` | **政务问答采集**：把部委/省市官网的「公众问答 / 留言答复」扒下来，切成两类资产 —— ① 点名依据**在库里**的 ⇒ **可当考卷**；② **不在库里**的 ⇒ **补料清单** | **924 MB / 3,448 文件**；347 通道 / 40,943 条 / 覆盖 **31 个省级行政区** | [`README.md`](../../tools/gov-qa/README.md) |

**⚠ 两条必须知道的**：

1. **它已进本仓唯一门禁** —— `run-gates.ps1` 的 12 步里有 **3 步**是它的
   （`gov-qa 质量闸门` / `gov-qa 幂等验证` / `gov-qa 通道台账最新`）。
   ⇒ **它红了就是全仓红**，不能当"别人的事"忽略。
2. **那个目录由另一条自动化线高频写入**（实测 2026-10-10 全天持续提交）
   ⇒ **要拿它的东西之前先读** [`REUSE-FOR-ANNOUNCEMENTS.md`](../../tools/gov-qa/REUSE-FOR-ANNOUNCEMENTS.md)
   的「写入边界」节。

**可复用的资产（给主项目用，清单见上述那份文档）**：
中间件指纹（IGI / jact / jpaas / hdjlpt 等）· 全国可达性矩阵 · 水位三型设计（`state.py`）·
纯 ASCII 机器接口（`common.py::ascii_kv`，被 4 层 bug 打出来的教训）· 地级市→省精确映射（`regions.py`）。

## 四、现在做到哪了

**已交付（不是规划）**：可信问答三段式（依据区 / 推导区 / 结论区）、点引用跳原文并高亮、
效力徽章、数值与模态核验、外发审计、材料平面、渠道台账。

**在建**：**检索与通用化长周期计划**（`docs/RETRIEVAL-LONG-RANGE-PLAN.md`，P0–P5）。
当前痛点是**排得上去**——实测：命中集合 41.6%（召回天花板）→ 前二十 24.5% → 前五 11.8%。

**已知缺陷（登记在案，未修）**：

| 缺陷 | 状态 |
|---|---|
| `plugin/client/` 三个页面的图标导出名与 DSH 当前版本不匹配（`tsc` 红） | 见 `specs/001-project-consolidation/baseline.md` |
| `smoke-kb-pad-pixels` 两个菜单场景 `ui-render-shot exit=null` | 原因未确定，登记收口前必办重跑 |

## 五、绝对不做（红线）

取自 `docs/NOT-DOING.md`（**提案前 MUST 先逐条对一遍**）：

- **不许悄悄删**——错话+更正就地留痕；作废的旧计划删全文、开发史留一句
