# KnowledgeStation 功能愿景（客户视角版）

> **为什么重写**：上一版是内部编号 + 缩写（"纠错闭环：快速补丁 / Word-WPS 往返"），客户看不懂，
> 而且**把双栏 SPA 时代的界面当成了今天的能力**。这一版只回答三个问题：
> **客户想干什么 → 今天点得到吗 → 有没有人做得比我们好。**
>
> **状态图例**
> 🟢 今天就能用（有界面或斜杠命令入口）
> 🟡 引擎里有、**界面没接**（老版本界面在 2026-09-05 DSH 转生时没搬过来）⇒ 客户今天够不到
> ⚪ 还没有
> 🔒 查到**无人做等价物**（详见 `docs/research/plan-vs-reality.md`）

---

## 1. 「这条规定到底怎么要求的？」—— 查得到，而且能自己核对

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 直接问一句，拿到答案 | 🟢 | 在 DSH 会话里输入问题。轻模式下系统自动判断这是规范问题，会**先静默检索再回答**，不会凭记忆编 |
| 答案能看出哪句是依据 | 🟢 | `/forensic` 开启"取证模式"后，答案固定三段：**依据区**（每条带标准号 + 条款号 + 版本年份 + 效力徽章，蓝色可点）→ **推导区**（正文用 [1][2] 标出引用）→ **结论区** |
| 点一下就能看到原文那句话 | 🟢 | 点引用，右侧 PDF 自动翻到对应页，并用**红色定位箭头**指向条款位置（坐标契约：bbox 底部原点） |
| 不许引已经作废的标准 | 🟢 | 只允许引用现行有效版本；废止/被替代的版本**不能当依据**；你点名问旧版时，它会说明该版本已废止、被谁替代；即将生效的新版会单独提示施行日期 |
| 法规和国标打架时怎么办 | 🟢 | 冲突（法规 vs 国标 / 新旧版 / 强标 vs 推标 / 地方更严）在答案尾部**全量列出** + 给出判断逻辑，**由你选口径**，选择记入你的画像 |
| 只在某一批资料里找 | 🟢 | `/bookmarks` 只在收藏集内检索；也可绑定"收藏夹"或"参考资料项目"把这次提问限定在范围内 |

## 2. 「这个结论我敢拿去交差吗？」—— 敢，因为有人替你把关

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 没依据就不许给结论 | 🟢 | 模型只收到"你的问题 + 库内检索出的证据片段"，**没有机会凭记忆作答**；规范题禁止凭记忆是写进规则的 |
| 答案有没有"说走样"要能发现 | 🟢 | 系统会**拿答案回原文对一遍**四件事：① 引用的条款号**在不在**检索出的证据里；② 数字和单位有没有被改（证据写 2.00h、答案写成 1.00h 就拦下，且**不放宽容差**）；③ 原文的"应"（强制）有没有被说成"宜"（推荐）——这是最危险的走样；④ 原文的**例外/但书**有没有被吞掉 |
| 云端调用要留痕 | 🟢 | 每次调用云端模型/OCR 的**完整请求内容落库**，你可以在界面查看并导出；不只是"发出去就算了" |
| 排序不许被偏好带偏 | 🟢 | 排序红线：**现行性 > 效力层级 > 内容匹配度**，收藏/偏好权重不得越过前三条 |

## 3. 「我自己的资料能不能一起当依据？」—— 能，但必须过评审门 🔒

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 把公司自己的材料用起来 | 🟡 | 建"项目 → 参考资料文件夹"，把检测报告/内部制度/图纸说明放进去，扫描后切成**带页码和字符区间**的片段 ⇒ 引用仍然能点回原文位置 |
| 未批准的绝不许影响结论 | 🟡 | **评审是硬门**：只有**你本人**能批准或拒绝（界面上没有"全部通过"按钮）；未批准的材料**不会**出现在任何结论里 |
| 分清"来源多可信"和"这次能不能当依据" | 🟡 | 两条轴分开：**来源可信度**（T0 原件 / T1 官方 / T2 权威转载 / T3 仅线索 / T4 不可用）× **本任务效力**（当准则 / 仅供参考）。"未核验不得承重"与法条侧同一条纪律 |
| 从网上现抓一篇正文 | 🟡 | 按网址抓正文，默认判为"仅线索"且**永远待评审** |
| 要交的东西 | 🟡 | **研究报告（Markdown）**："依据"一节按**承重能力分组**，引用行带 ⚠ 标记。**不做 PPT** |
| ⚠ 诚实边界 | | **这套在真机上还没跑过一次**：当前活着的两个进程启动时间都早于这套平面，生产库里还没有对应的表 |

## 4. 「从结论到能落地的动作」—— 引擎齐了，界面没接 🟡

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 把"应当/必须/禁止"抽成清单 | 🟡 | **义务清单**：从库里召回义务条款生成清单，可一键转**检查表**（`compliance/obligation.py`） |
| 上传合同逐条比对法规 | 🟡 | **合同审查**：抽取合同要点 → 对回法规要求 → 出**三色结论**（合规/风险/缺失）（`compliance/engine.py`） |
| 公司制度 vs 法规差在哪 | 🟡 | **差距分析**：导入内部制度 → 构建法定义务清单 → 逐条判定 → 出差距报告（`compliance/gap_analysis.py`） |
| 单条深挖 / 整批扫描 | 🟡 | **条款释义 + 批量问答** |
| 清单导成 Word | 🟡 | 义务清单导出 `.docx`（`api/server.py` 里有落盘实现） |
| ⚠ 共同状态 | | **以上五项引擎里都有，但 DSH 插件里没有面板、也没有斜杠命令** —— 它们是双栏 SPA 时代做的界面，2026-09-05 转生时没搬过来。**客户今天够不到**（只能直接打 API）。这是上一版愿景树最大的失真处 |

## 5. 「我的库是不是最新的？」—— 自动盯着，而且告诉你影响了什么

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 标准更新了要自动发现 | 🟢 | 每日自动扫官方渠道公告：发现新版/废止 → **静默下载新版 → 切换默认引用 → 旧版备份** → 轻通知 + **影响清单**（波及哪些旧引用、哪些义务清单） |
| 随时看全库现状 | 🟢 | `/效力报告`：四色视图（🔴在用已废止 / 🟡即将实施 / 🟢现行有效 / ⚪状态未知）+ 分类清单 + Excel 导出 |
| 每条数据来源可查、可维护 | 🟡 | **渠道台账**：每条来源的链接、是否有效、上次成功时间、失败原因，支持人工增删复核 |
| ⚠ 当前缺陷 | | 已验证：人工增删的接口（`PATCH/DELETE /ks/channels/{id}`、`POST …/{id}/enabled`）在**真派发器下返回 404**（前缀多了一个尾斜杠）⇒ **"人工维护"这条路现在是死的**，修复待做 |

## 6. 「装起来麻烦吗？」—— 这是我们相对同类产品的硬优势 🟢

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 不要让我配一堆中间件 | 🟢 | 界面就在 DSH 侧栏里，引擎按需拉起；**你不需要装数据库、队列、向量库**。（对比：同类开源方案要 Postgres + Redis + 解析服务 + 模型槽位，配置过程本身就劝退） |
| 数据在本地、不外流 | 🟢 | 引擎只绑**本机随机端口 + 一次性 token**，不暴露网络面；数据全在 `%APPDATA%\KnowledgeStation`，与代码彻底分离 |
| 断网也能用 | 🟢 | 无网络时检索/核验/高亮照常，云模型不可用时自动降级为占位 |

## 7. 「知识库怎么喂进去、数据会不会坏？」—— 能纠错、能回退、能验证 🟢

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 各种文件都能进 | 🟢 | PDF（文字版/扫描版自动分流）、Word 官方公文；支持监听目录自动收 |
| 入错之前先让我看一眼 | 🟢 | 单本入库先出**预览报告**再确认落库；批量入库出**分桶总账**：✅直接可用 / ⚠需复核 / ❌隔离 |
| 解析出问题要能发现 | 🟢 | 入库后有**坐标体检**，异常当天告警 |
| 识别错了要能改（且改不坏历史） | 🟢 | 发现识别错误可修改；修改以**不可撤销的修订记录**落库、可回退，旧引用不会错乱、跨版本平移不丢内容 |
| 数据要能证明没被动过 | 🟢 | 快照**不可变** + SHA-256 可校验 + 滚动备份（7 份，可指向独立物理盘）+ 版本链跨版本对照 |

## 8. 「检索质量凭什么不退化？」—— 我们把指标写进了 CI 🟢

| 客户要的 | 今天 | 说明 |
|---|---|---|
| 质量不能悄悄下降 | 🟢 | **96 条冻结问答对**作基准，指标写进 pytest：任何指标回退超过 2 个百分点，**测试直接失败**（这是工程红线，不是产品里的一个评测页面） |
| 到底哪条检索通道有用 | 🟢 已实测 | 消融结论（2026-08-23）：**精确条款号召回是绝对主力——关掉它指标掉 38 个百分点**；全文检索只值 1.1 个百分点；向量/模态/法理要素/行为客体四路在**问答场景贡献接近 0**（保留是为审查场景和将来） |
| ⚠ 需要改的口径 | | 对外不应再说"六路召回"。正确说法：**精确条款号为主 + 全文为辅；另 4 路为审查场景与未来预留，问答场景实测贡献≈0** |

## 附：这份愿景真正的"根"只有三条

其余全部可以被现成开源件替代（解析、通用问答、报告导出、笔记、离线、备份）。
**只有下面三条，我查遍同类项目（含 WeKnora / RAGFlow / LIMS / 工标库 / 北大法宝 / 赛为 / UpCodes）都没找到等价物：**

1. **条款级证据链**（别人最多到"文档/分块 + 来源摘要"——用户在 WeKnora 里实测确认过）
2. **机器可判定的核验闸门**（数值 / 模态 / 法理三层 + 核验前禁复制）
3. **自有材料的评审硬门 + 权威两轴**（别人只服务"他们的权威库"）

## 附：与两个参照物的一句话分界

| | 引用粒度 | 现行性 | 数值核对 | 部署 |
|---|---|---|---|---|
| **我们** | **条款级** | ✅ 只引现行版 | ✅ 分型核验 | **零中间件**（DSH 侧栏） |
| WeKnora | 分块 + **来源摘要**（用户实测） | ❌ 检索接口无过滤 | ❌ | 需 Postgres/Redis/模型槽位（用户实测"很麻烦"） |
| RAGFlow | 分块 bbox + 裁图快照 | ❌ | ❌ | 更重（自带 MySQL + ES + Redis + MinIO） |
