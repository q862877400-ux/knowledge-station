> 归属层：**本文件是这件事的唯一方案真源**。做了什么、复核结论 → [开发史](DEVELOPMENT-HISTORY.md)；

## 一、定案（业主原话要点）

- 知识库管理页改成**真目录**：左边一列目录，点一级进去看里面；一个目录里**既有下级目录也有文件**，
  **先列下级目录、再列文件**；顶上有一行**返回上一级**；原来的**大卡片去掉**。
- 目录能力：**新建（无限层级）· 改名 · 挪动 · 复制**；文件也能挪、能复制。
- **一个文件可以同时放在多个目录里**（业主选"复制=多一处位置"，不是"多一份新文件"）；
  删除=**从这一处拿掉**，只有从所有目录都拿掉才真删。
- **上传**：每一级都能直接上传；**在哪一级上传就落在哪一级**；这种情况**不再自动识别**（用户已指定位置）。
- **「待分类」专区**：库里没有分类的文件 + 用户随手丢进来的文件先落这里；后台**自动识别它该归到哪个现有目录**；
  **只匹配现有目录，绝不自行新建**；识别结果**先让用户确认再放走**，确认时可提示
  「将在 XXX 目录下新建 XXX 文件夹存放此文件」，用户**可以选不新建**、改为放进现有目录；
  **认好放走的文件不在「待分类」展示**。
- **文件状态**：**所有文件**（不只待分类）都要显示处理状态 —— 排队中 / 识别中 / 识别失败 / 识别率 /
  表格识别失败 等，便于一眼看出"哪个文件的识别结果需要人工维护"。点开「待分类」能看到每个文件的状态，
  并能**逐个手动处理**（指定去向、重来一次、删除）。
- **原独立的导入页面取消**，其功能并入**「待分类」点开后的界面**。
- **范围提问**：**每一级目录都能"在此范围内提问"**，范围**包含它下面所有层级**；也支持**多选若干目录取并集**。
  **不单独做"保存的集合"** —— 靠"新建文件夹 + 把选中的挪/复制过去"，以及"多选后集体加标签"来满足。
- **现有数据**：6417 篇按**当前显示的分类**一次性归位；其中**380 篇无分类**的进「待分类」。

## 二、我自定的三条（业主未反对即生效）

1. **改名只改库里的名字**，绝不动磁盘上的原文件（业主原话：「看数据库层面哪种操作不容易出问题就选哪种」）。
2. **删除目录**（业主 2026-09-21 选定"先问一句"这一版）：空目录**直接删**；非空目录**先问一句**，两个选择 ——
   ① **「只删这个目录，里面的东西移到上一层」**：把它的**直接成员**挪到上一层（子目录改挂到上一层；
      文件在这一层的归属换成上一层的归属；本来就已经在上一层里的，只去掉这一层的归属）；
   ② **「连里面的文件一起删」**：删掉这个目录以及它下面所有目录；**只有"在别处也不出现了"的文件才真的删掉**，
      还挂在别的目录里的文件只是**从被删的这些目录里拿掉** —— 与"删除=从这一处拿掉、从所有地方都拿掉才真删"一致。
   ⚠ **一级目录没有"上一层"** ⇒ 对它**只提供 ② 和"取消"**，不提供 ①（不许静默做错事，要给人话报错）。
3. 同一类里（都是目录 / 都是文件）**按名字排**。

## 三、数据形状（决定一切，先定死）

| 存什么 | 形状 | 理由 |
|---|---|---|
| **目录** | `folder(folder_id PK, parent_id NULL, name, sort, created_at)`；`parent_id IS NULL` = 一级目录 | 无限层级；空目录能存在；改名/挪动是**改一行** |
| **归属** | `folder_member(folder_id, item_kind ∈ {folder,file}, item_id, added_at)`，**多对多**，主键 `(folder_id,item_kind,item_id)` | 一个文件可同时出现在多处；复制=加一行，剪切=换一行，删除=删一行 |
| **处理状态** | 文件上的状态：`stage`(排队/识别中/待确认/已归位/识别失败)、`confidence`(识别率)、`failure_kind`(整体/表格/…)、`suggested_folder_id`、`suggest_new_path` | 「待分类」列表 + **所有文件**的状态展示都读它 |
| **归位记录** | 同一张状态里记"谁在什么时候把这个文件放进了哪个目录" | 「待分类」确认环节要能回看 |

**复制目录的语义（我定）**：复制一个目录 = **新建一个目录**，让它**装着和原来一样的东西**（同一个文件、
同一个下级目录的**同一份**，不是各拷一份）。原目录后来加了东西，**复制出来的那份不会跟着变**。

## 四、要做的能力（逐项，界面与接口一一对应）

1. 列出**某一级**的内容：下级目录（含各自有多少文件，含更深层）+ 这一级直接放的文件（分页）。
2. 建目录（在指定目录下）、改目录名、挪目录、复制目录、**删目录（空目录直接删；非空目录按 §二第 2 条的两种模式之一）**。
3. 文件：加进目录（上传/挪入）、从目录拿掉、复制到另一个目录、挪到另一个目录；**批量**做。
4. 「待分类」：列出、看状态、逐个手动处理（指定去向 / 重来 / 删除）、**批量确认归位**
   （含"接受新建目录建议"与"改为放进现有目录"两条路）。
5. 范围提问：把"某一级及其以下"或"多选若干目录的并集"作为提问范围传给引擎。
6. 每级上传：文件直接落进当前这一级，**不进入自动识别**；但仍要显示处理状态。

### 已知、待第 2 步修的一处语义（登记，别当没看见）

> ✅ **第 2 步已修准**（2026-09-21，提交 `603b333`）：见 §十二第 1 条。下面保留原始登记。

`folder.parent_id`（主位置）与 `folder_member(item_kind='folder')`（全部父子边）是**两份表达**，
靠 `folder_store` 维护不变式。它自报的后果：**挪一个同时挂在两处的目录时，那条"另一处"的边也会被一起改掉**
（两种边同表、分不出来路）。⇒ 第 2 步要改成按**"从哪一处、"挪到"哪一处"**来操作（只动这一次出现的那条边；
只有当动的正是"主位置"时才更新 `parent_id`）。**在改准之前，界面上不许暴露"挪目录"**。
另一处取舍：目录排序按 Unicode 码位，**不是拼音**（顶层多为 `A 综合`/`B 农业林业` 这类字母开头，暂够用）。
⚠ **业主 2026-09-21 已定**：排序改成**按拼音**；顶层**预建三个空目录**「标准 / 法律法规 / 公司制度」
（真数据只会自动建出 1 个顶层，见上）。

## 十、第 1 步顺带发现的缺陷（登记，待修，不在本步修）

**「正文条款为零」的文件被踢出目录后，没有任何路径把它放回来。**
- 规则本身没问题：`pipeline.py` 在 `n_normal == 0`（**正文条款**为零）时把 `catalog_hidden` 置 1，
  动机是"正文被乱码吞没的标准不进目录"（2026-08-28 口径）。实测全库只有 2 篇命中，且都是**真国标**：
  `GB/T 12668.8-2017`（唯一正文是 `学兔兔 www.bzf xw.com` 这种**盗版水印**垃圾）、
  `GB 9706.222-2022`（只出到 `前置1` + 三个 `附录`，正文一条没有）。**两篇都不是测试文件。**
- 缺陷在**回来的路**：全仓 grep `catalog_hidden` 的写操作，**只有置 1、没有置 0**。
  代码注释说"修复重导入产生真实条款 ⇒ 新行 DEFAULT 0 自动回归目录"—— 那只在**新生成一行**时成立；
  同一篇重新导入（同一个 `doc_id` 改的是同一行）即使这次解析出了真条款，也**没有任何地方把它放回目录**。
- 后果：这两篇哪天解析问题修好、重新导入成功了，**它们仍然是隐藏的，而且没有人会知道**。
- 归属：与第 4 步「待分类 + 每个文件的状态」是同一件事 —— **解析失败的应当出现在待分类里并标成失败**，
  而不是静默消失；回来那条路要跟状态一起修（并配用例）。

## 十二、第 2 步实测结果（2026-09-21，提交 `603b333` / `ecbb09f` / `d61a9be`）

**四处修准（§九那处语义 + §十一那条"没有牙的保护" + 业主追加的拼音排序 + 环检测）**：

0. **schema 对账**（`scripts/apply-folder-filing.py` 新增 `schema_drift()`）：拿 `schema.sql`
