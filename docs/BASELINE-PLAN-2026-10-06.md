> **性质**：决定与实验路线。**"查到了什么"在 [`BASELINE-DIAGNOSIS-2026-10-06.md`](BASELINE-DIAGNOSIS-2026-10-06.md)，本文是"决定做什么"。**

> **本文可以推翻，但要留下推翻的理由。**

---

## 〇、一句话

**不重写切分器；不训练模型；冻结一次当前基准；然后只做"检索表示重构"。**

**三个实验互相独立，能分别算出各贡献多少。**
**最危险的是同时改「切分 + embedding + 查询改写 + 引用图」——那样即使从 41.6% 涨到 60%，也不知道为什么。**

---

## 一、四条已定的决定

### 决定 1：**原文对象 ≠ 检索表示**（数据模型原则）

**原文必须忠实保存，检索用的文本可以重构。这两个不必是同一个字段。**

```
clause_id       = clx_xxx
source_text     = "6.2.4 产品应保存于清洁、干燥的环境中。"     ← 不改
page / bbox     = 17 / [...]                                    ← 不改
retrieval_text  = 【GB xxxx】/【第6章 试验方法】/【6.2】/【6.2.4 产品储存】
                  + 原文                                        ← 新增
```

**用户点击仍走 `clause_id → 原 PDF 第 17 页 → 原坐标`，完全不受影响。**

**⇒ 业主此前的判断（"只合并检索文本，存储和展示仍按原文"）成立，并被提升为数据模型原则。**

**⇒ 由此推出一条：**
**"标题该在哪里结束"这件事【暂时不用解决】**——要的不是"标题物理拼进下一条"，
而是"**标题成为后代条文的上下文**"。这两个问题不同，后者便宜得多。

### 决定 2：**先测基准再改；旧指标先不进决策**

- **先留一次当前基准**，不是两难，是"**先拍一张照片**"——之后任何改动都有 Before/After 可比
- **旧指标（53% / 6.8% / 5.8% / 41.6% / 24.5% / 11.8%）在口径核清前【不作为决策依据】**
  - 理由：它们的定义（Recall@K？提问命中比例？）**本仓尚未确认**
  - 否则会出现"旧指标 41.6% vs 新指标 58%"，而两者根本不是一回事
- **新实验统一用 `Recall@20 / @100 / @500`**（后续再加 `Evidence Recall`）

### 决定 3：**暂不重写切分器；不删短标题**

- 那 192,205 条短条款（36.8%）**先不物理合并**——抽样证明**约四成是完整的短条款，合并会毁掉**
- **标题节点保留**，改成**结构上下文**而不是普通答案块
- **不追求长度均匀**（平均 98 字本身不是问题），**追求语义原子性**
  —— "无。" "不得……。" "应符合……。" 这些**就是合法的原子知识单元**
- **切分器重构降级为"后续解析质量工程"**：等基准告诉我们"确实因标题与子条文分离造成大量 recall loss"，再回头研究标题边界。**那时手里有具体失败样本，而不是对着 19 万条短文本猜规则。**

### 决定 4：**跨文件引用——建反向索引，做"条件触发的并行召回通道"**

- **能帮第一跳，但条件严格**：**Query 必须能形成"引用锚点"**（出现标准号 / 标准号变体 / 术语能映射到明确标准）
- ✅ 正确用法：问「QB/T 4488 对电子管风琴有什么要求」⇒ 语义路 + **引用路**（所有引用 QB/T 4488 的条文）⇒ 并集 ⇒ 重排
- 🔴 **错误用法**（会召回大量噪声）："问一个概念，就找所有引用这个概念的条文"
- **本质是反向倒排索引，不需要知识图谱**：
  ```
  referenced_standard_no → inverted index → source_clause_ids
  ```
- **原料已有**：63,162 条条文明确提到别的标准号（诊断文档 §一），**丢的只是关联**
- ⚠ **实现前置**（诊断文档 §1.4）：放宽过滤会产生"目标不在库里"的悬空引用，**怎么表示要先定**

## 二、实验路线（四步，按顺序）

### 第 1 步：冻结基准

```
从 1832 条"外行说法"里人工确认 100~200 条 Gold
  每条至少记：query / gold_clause_id / gold_document_id
当前系统【原样】跑：Recall@20 / @100 / @500
同时保存每个 query 的前 100 个结果
```
**产物只有一个：`baseline.jsonl`。**
**⇒ 现有那 96 条防退步金标【保持原用途】，不拿来冒充难度 Benchmark。**

### 第 2 步：Retrieval Text V1（**只改这一个字段**）

```
retrieval_text_v1 = 标准名 + 祖先标题 + 条款号 + 原文
```
- **先只带"祖先标题"**，不要带兄弟/前后条（避免把相邻规则污染进去）
- **不动 source_text / 不动展示 / 不动 PDF 定位**
- 重新算 dense embedding —— **成本可控，因为库里现在只有 522,021 条，不是千万级**
- 同一批 Query 重跑。**明显提高就继续；没有就撤销。**

### 第 3 步：Query 词汇桥

```
原 Query + 术语桥接后的正式术语 → 分别检索 → 融合
例：「消防通道」→ 消防通道 / 疏散走道 / 安全疏散 / 疏散通道
```
- **用已有的 500 术语 / 1832 条外行说法**
- **不训练**
- **这一步才是真正冲"53% 一个字都对不上"的**

### 第 4 步：Cross-file Citation Channel

```
referenced_standard_no → 反向索引 → source_clause_ids
只在 Query Router 判定存在引用锚点时触发
```

**⇒ 四个实验【互相独立】，所以能分别算出：结构上下文贡献多少 / 词汇桥贡献多少 / 引用通道贡献多少。**

## 三、止损线（预先定好，事后不许改）

| 绝对提升 | 处置 |
|---|---|
| **< 3 个百分点** | 不值得单独维护 |
| **3~5 个百分点** | 可作辅助特征 |
| **> 5 个百分点** | 值得推广到全库 |

**标准：在相同 Gold Query、相同语料、相同检索配置下，`Recall@100` 没达到这条线 ⇒ 撤销。**

### 🔴 但这条线和样本量不匹配——**必须一并执行**

```
p ≈ 0.6、n = 150  ⇒  单个方案标准误 ≈ √(0.6×0.4/150) ≈ 4.0 个百分点
                 ⇒  95% 置信区间约 ±7.8 个百分点
```

**⇒ 如果两个方案只差 3 个百分点，150 条查询【测不出来】——差异会被噪声淹没。**
**⇒ 也就是说"< 3% 不值得维护"这条线，在 150 条上执行不了。**

**⚠ 公正地说**：同一批 query 跑两个方案（**配对设计**）比独立样本好得多——难的问题在两个方案里是同一批，方差会抵消一部分。

**⇒ 因此 MUST 额外做两件事之一：**
1. **报告配对差异**：同一批 query 上，**有多少条从"找不到"变成"找到了"**（这个条数比百分比更直观、更抗噪）
2. **或把线提到"明显大于噪声"**（约 ≥8~10 个百分点才算数）

**⇒ 只比两个百分比就下结论，是错的。**

## 四、明确不做（防止被带偏）

| 不做 | 理由 |
|---|---|
| ❌ 重写切分器 | 降级为后续工程；现在做会**同时改两个变量** |
| ❌ 训练 embedding / retriever | 三个便宜实验没跑完之前不谈 |
| ❌ 加第二、第三个索引 | 外部方案前两版列了"六个索引"，**那不是瓶颈** |
| ❌ 做知识图谱 | 跨文件引用**本质是反向倒排索引**，不需要图数据库 |
| ❌ 追求"每条 200~500 字" | **要语义原子性，不要长度均匀性** |

## 六、下一步的唯一动作

> **不修切分器。先从 1832 条外行说法里人工确认 100~200 个 Gold 条文，
> 冻结当前系统跑一遍 `Recall@20/@100/@500`；
> 然后只改 `retrieval_text = 标准名 + 祖先标题 + 条款号 + 原文`，用同一批 Query 重跑。**

**这一个实验同时回答三件事：**
1. 当前所谓"第一跳差"**到底有没有可靠的测量基线**
2. 发现的"标题/短条混杂"**是不是实际的召回损失来源**
3. **不训练模型、只改知识对象的语义表示，能不能把第一跳明显抬起来**
