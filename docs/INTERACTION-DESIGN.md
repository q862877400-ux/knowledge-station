# 交互设计：向 WeKnora 学什么、我们怎么重做

> 来源：WeKnora 站点 `02-architecture`…`06-development` 全 58 篇 + `frontend/` 真源码结构（本地 `D:\AI\WeKnora`）。
> 我们自己的现状取自 `plugin/client/` 代码（文件名+行数），不凭印象。
> ⚠ 边界：**DSH 的对话区是宿主的，我们改不了**——所以重设计只能落在"宿主给我们的座位"上（右侧栏 tab、设置区、斜杠命令、工具）。凡涉及改宿主对话流的地方，本文只写"应向宿主提议"，不当作自己能做的。

## 二、我们现在的交互是什么（一手，来自代码）

```
DSH 会话里提问
├─ 输入框上方：KsScopeChip（显示当前口径/范围）
├─ 斜杠命令：/forensic · /bookmarks · /materials
└─ 右侧栏【只有一个 tab：证据】
     └─ KsEvidenceTab（128.9 KB / 1600+ 行）内部三模式：
          ├─ 文件目录（KsFilesView）
          ├─ 收藏（KsBookmarksView）
          └─ 正文（KsDocTextView）+ PDF 查看器 + 底部工具条

设置区（settings.section）里 4 个折叠类目：
   ├─ 效力报告（KsReportPanel）
   ├─ 参考资料/材料平面（KsMaterialsPanel）
   ├─ 渠道台账（KsChannelsPanel）
   └─ 入库（KsIngestPanel）
```

**结构性问题（这就是要重做的原因）**

1. **没有"本轮"这一层**：WeKnora 的来源/产物/追问都挂在**这一轮回答**上；我们的证据 tab 是**全局浏览器**，看完答案想知道"这轮用了哪几条"，没有对应面板。
2. **日常能力被埋进设置**：效力报告、参考资料、入库都在 `settings.section` 里 —— 它们是每天要用的，不是设置项。（WeKnora 把知识库/Agent 做成独立页面 + 对话内可达。）
3. **一个巨型 tab 承担三种模式**：128.9 KB 的单文件，认知负担重，且与"当前这轮对话"脱节。
4. **没有阶段进度**：我们明明有别人没有的**分型核验**这一段，却没在界面上显式呈现。
5. **没有追问建议**。
6. **没有"即问"通道**：想快速问一份文件必须先**入库**（进入向量索引）——这是个真实的体验断点。WeKnora 的临时附件把"即问"和"入库"明确分开。
7. **对话不可交付**：没有一键导出（我们有"研究报告 Markdown"的能力，却没接到对话上）。

## 三、重设计：一问一屏（Per-turn Workspace）

### 5 条原则

1. **右栏服务"这一轮"，而不是当"全库浏览器"**。回答出现时右栏默认切到「本轮」：这几条证据、命中原因、效力徽章、核验结论、追问建议。全库浏览降为二级。
2. **把埋进设置的日常能力搬出来**，按"使用频率"分家（见下表）。
3. **把我们的独有环节做成视觉主角**：每条证据盖**效力徽章**（现行/即将实施/已废止）+ **承重能力**（法条/本任务准则/仅参考），核验结果做成徽章行而不是日志。
4. **补三个原语**：阶段进度（含"核验中"这一段）、追问建议、**临时附件即问**（明确标注"仅本轮，不入库"）。
5. **对话可交付**：一键导出 Markdown（问题 → 三段式答案 → 引用：标准号-条款号+页码 → 核验结论）。

### 右栏一级 tab 从 1 个变 4 个（语义清晰，不再是巨型文件）

```
┌ 右栏 ───────────────────────────────────────────┐
│ [本轮]  [全库]  [效力]  [材料]                    │
├─────────────────────────────────────────────────┤
│ 本轮（默认，跟着当前回答走）                       │
│   ● 这一轮用了 3 条证据                           │
│     1. GB 51283-2020 第4.2.9条   exact ⭐ 现行有效 │
│        [点开原文] ← 跳 PDF 对应页 + 红箭头高亮      │
│     2. GB 50016-2014 第…          fts              │
│   ● 核验：数值 ✅ 模态 ✅ 例外 ✅（分型核验结果）    │
│   ● 追问：… ／ … ／ …                              │
│   ● 本轮产物：研究报告.md                          │
├─────────────────────────────────────────────────┤
│ 全库：文件目录 ⇄ 收藏 ⇄ 正文（原三模式，降为二级）   │
│ 效力：四色视图 + 时间窗 + 导出（从设置搬出）         │
│ 材料：项目 + 评审硬门（从设置搬出）                  │
└─────────────────────────────────────────────────┘
设置区只留：渠道台账（运维性质，低频）· 凭据 · 入库偏好
```

### 现有面板的映射（谁搬去哪、谁合并、谁保留）

| 现有 | 新位置 | 理由 |
|---|---|---|
| `KsEvidenceTab` 的三模式 | 合并为「全库」一个 tab（内部仍三模式） | 它们是"浏览"语义，不该占主位 |
| `KsReportPanel`（效力报告） | **定义成可按地址打开的 tab 类型**：从回答（出现"该标准已废止"时）、工具回执、斜杠命令一步可达，可停靠 | 它是数据视图不是设置；但够不上"每天看"（属巡检后的周期动作），**常驻一级 tab 会挤掉别的 tab** |
| `KsMaterialsPanel`（参考资料） | **暂不升**；先让"待评审 N 条"可见（待办角标） | 材料只有 `approved` 才进结论——**埋在设置里 = 没人回来点批准 = 材料永远不参与结论**（可预见的误解源）。但它**还没在真机跑过一次**（生产库无 `material*` 表），先给可见性、后给座位 |
| `KsIngestPanel`（入库） | **降为动作**：斜杠命令 + 拖拽入口 + 设置里的偏好 | 入库是"做一件事"，不是"看一个面板" |
| `KsChannelsPanel`（渠道台账） | 留在设置 | 运维性质、低频，符合"设置"语义 |
| 新增「本轮」 | 右栏默认 tab | 补上缺失的那一层（本轮证据/核验/追问/产物） |
| `KsScopeChip`（范围芯片） | 保留并强化：**每个回答上盖"这一轮的口径"章** | 防止用户忘了自己开着 forensic/材料绑定 |
| PDF 查看器 + 红箭头高亮 | **保留，不动** | 这是我们比 WeKnora 更强的地方（条款级 vs 分块摘要） |

### 宿主 tab 模型的约束（决定方案形态，2026-09-19 查证）

`@deepseek-ai/dsh-client-ui-sidebar-right` 的契约（`src/client/contract/slots.ts`）里：

- `'sidebar.right.pane.tab'` 是 **`kind: 'keyed'`**，按 **tab 类型定义的 `id`** 分发；原文注释：
  「A tab type registers here under its definition's `id` … **adding a type is a registration, never an edit here**」（第 44-55 行）；
- tab 是**按地址打开的记录**（`openResource(address)` / `openTab(kind, params)`），支持多 pane / 浮动 /
  `revealIfOpened` / `replaceTab`，每个 tab 还有 `title` 槽位与 `tab.menu.item` 动作菜单，
  另有可被替换的 guide tab。

⇒ **"把一个面板升为一级 tab"在宿主模型里说不通**：正确形态是「**定义成可按地址打开的 tab 类型**」，
并从回答、工具回执、斜杠命令处**一步直达**。**"从会话里点到"比"常驻一个 tab"更贴合宿主设计，也更省侧栏空间。**

### 三条"向宿主提议"的（我们改不了对话区）

- 阶段进度条与长等待提示（宿主对话流的进度语义）；
- 回答下方"本轮产物/追问建议"的挂载点；
- 对话导出 Markdown 的入口位置。

## 四、落地顺序（按"性价比"排，不按"看起来完整"排）

| 序 | 做什么 | 代价 | 收益 |
|---|---|---|---|
| 1 | **右栏加「本轮」tab**：本轮证据集 + 核验徽章 + 点开原文 | 纯前端（数据引擎已有：`latest_info`/证据集/核验结果） | 直接补上最大的结构性缺口，且强化我们最强的那一点 |
| 2 | **效力报告改为"按地址可直达"**：从回答/工具回执/命令一步打开并可停靠（`ctx.sidebarRight.openResource`，能力已在用）；材料先只加"待评审"可见性 | 前端为主（组件已存在，改挂载与入口） | 把周期要用的东西从设置里救出来，且不占常驻 tab 位 |
| 3 | **对话导出 Markdown**（问题→三段式→引用→核验） | 前端 + 复用已有报告渲染 | 让结论能交出去 |
| 4 | **追问建议** | 前端 + 一次额外 LLM 调用（要注意成本，可开关） | 体验提升明显 |
| 5 | **临时附件即问**（仅本轮、不入库） | 要引擎配合（现成链路只支持已入库文档） | 补上体验断点，但要动引擎，排后面 |
| 6 | 阶段进度 / 长等待提示 | 属宿主对话流，需提议 | 依赖宿主 |

## 五、知识库入口与「知识库管理」二级页（业主 2026-09-19 指定）

> 业主原话：把右侧栏那三个按钮里的「PDF 查看器」改成「**知识库**」；像「新建终端」那样旁边有个**下拉菜单**；
> 下拉里放**效力报告、文件导入**等作为二级目录；其中「**知识库管理**」这一页照 WeKnora 的
> `http://localhost/platform/knowledge-bases` 抄，默认两个自带文件夹（**法律法规**、**标准**），用户可自建（如**公司制度**）。

### 6.1 入口层：tab 标题 + 下拉

| 事 | 怎么做 | 依据 |
|---|---|---|
| 把「PDF 查看器」改名「知识库」 | 改 tab 定义的 `title` / `definition.title`（现在标题来自 `evidenceTabTitle()`，见 `plugin/client/ksSidebar.ts:180`、`entry.ts:118`） | 标题属我们自己的 tab 定义，**不涉及宿主** |
| 旁边加下拉 | **两种落点，形状不同**：① 宿主官方座位 `sidebar.right.tab.menu.item`（挂在 tab 的「…」上，是宿主自己的菜单）；② **我们自己 tab 顶栏里的「▾」按钮**（完全在我们控制内，能做成和「新建终端」一样的形状） | ①见 `contract/slots.ts:90-94`；②我们 tab body 自带顶栏（`KsEvidenceTab` 已有顶栏） |
| 建议 | **用 ②**：用户要的是"标签旁边一个 ▾"，而①的触发点是「…」，形状对不上 | — |
| ⚠ 待核对 | 「新建终端」那个下拉的具体实现我没读完（递归扫描超时）；**落地前读一行源码确认它是宿主 strip 里的还是终端 pane 内的**——若在 pane 内，②就是同构做法 | 未验证，已标注 |

**下拉条目（二级目录）**：

```
知识库  ▾
 ├ 知识库管理        ← 二级页（见 6.2）
 ├ 文件导入          ← 把文件导进"当前打开的文件夹"（接既有入库流程）
 ├ 效力报告          ← 现埋在设置区（KsReportPanel），按地址直达
 ├ 每日巡检          ← 现状/上次结果（现在也在设置区）
 ├ ──────────
 └ 渠道台账          ← 运维性质，留在设置；此处只给入口
```

### 6.2 「知识库管理」二级页：照 WeKnora `KnowledgeBaseList` 抄什么

**抄（附出处，均为 `frontend/src/views/knowledge/KnowledgeBaseList.vue` 一手）**

| # | WeKnora 的做法 | 我们照抄成 |
|---|---|---|
| 1 | 顶部**新建按钮**（带 tooltip；受 `contributor` 角色门控） | 顶部「+ 新建文件夹」+ 搜索框 |
| 2 | **可折叠分组 + 计数**：置顶 / 我的 / 他人 / 共享可编辑 / 共享只读 | **置顶 / 自带（法律法规·标准）/ 我建的 / 导入来源**（无共享，故去掉两类） |
| 3 | **卡片网格**，每卡：右上角浮动**星标**、标题、**「…」弹出菜单**（置顶/复制/设置/删除）、描述（无则"暂无描述"）、底部**徽标行** | 同样式：星标、标题、`…` 菜单（置顶/重命名/删除）、描述、底部徽标 = **文档数 · 最近更新 · 类型** |
| 4 | 加载时 **6 张骨架卡** | 同 |
| 5 | 空状态引导新建 | 同 + 引导「文件导入」 |
| 6 | 新建对话框：名称 + 描述（其余是向量库/多模态/ASR/分块） | **只要名称 + 描述**（其余我们没有或已在设置里） |

**不抄（并写清理由）**：向量库绑定、多模态 VLM、ASR、分块调试、Wiki 内容指令（我们没有这些概念）；
组织/共享/只读权限（我们没有多租户）。

### 6.3 数据模型：这是本设计最容易做错的地方

我们**已经有两个"集合"概念**（收藏夹 `bmf_…`、材料项目 `prj_…`）。再加"知识库文件夹"如果不划清边界，就会出现**第四个重叠容器**。

| 概念 | 基数 | 语义 | 谁创建 |
|---|---|---|---|
| **知识库文件夹**（新） | 一个文档**只属于一个** | **归属**：这是哪一类资料 | 两个自带 + 用户自建 |
| 收藏夹（已有） | 多对多，可跨文件夹 | **策展**：我挑出来要常看的 | 用户 |
| 材料项目（已有） | 独立平面 | **自有资料 + 评审硬门**：没过批准不得承重 | 用户 |

**两个自带文件夹必须是"视图"，不是"空目录"**：
库里本来就有法律法规与标准两类（`doc_meta` 可区分）。若把它们做成空文件夹，会出现
**"我库里有 6417 条标准，可『标准』文件夹是空的"**这种荒谬。所以：

- **自带两个 = 按现有类型自动归类的动态视图**（不可删、不可改名）；
- **用户自建 = 真容器**（如「公司制度」），文件经「文件导入」进来并落进它。

### 6.4 落地顺序（等设计确认后再动）

1. tab 改名「知识库」（改 `title` 一处，最低风险）；
2. tab 顶栏加「▾」下拉，先只放**知识库管理 / 文件导入 / 效力报告**三条；
3. 「知识库管理」页**第一版只读**：按自带/自建分组列出文件夹 + 文档数 + 最近更新；
4. 再加新建/重命名/删除文件夹（**自带两个禁改禁删**）；
5. 最后把「文件导入」与文件夹打通（导入时选定归属）。

⚠ 每一步都要单独过门禁：`plugin` smoke + `verify:commands` + `tsc`。**本页只做设计，未动代码。**

## 六、边界与不做的事

- **不照抄 WeKnora 的形态**：它是"知识库管理平台"，入口是知识库列表；我们是"取证工作台"，入口是问题。抄它的页面结构会丢掉我们的中心。
- **不引入它的技术栈**（Vue/TDesign/Pinia…）：我们寄生在 DSH 的 React 侧栏契约里（`KsEvidenceHost` 就是官方座位的适配层），换栈等于重写且失去宿主集成。
- **不做 PPT/多形态分发**（业主已明确：产出物只要 Markdown）。
- 本文是**设计**，不含实现；每条落地都要单独过门禁（`plugin` smoke + `verify:commands` + `tsc`）。
