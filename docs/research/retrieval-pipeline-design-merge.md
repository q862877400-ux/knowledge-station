## 零、一句话结论

**8 份在"骨架"上高度一致，分歧只在"哪条通道当主干"。**
合并后的骨架是：**判据先行 → 标识符精确通道（唯一硬门）→ 多字段词法主干 → 语义只作候选重排 → 名次融合 → 定位锚 → 拒答门**，
而**跨文档跳**用确定性链接（可 replay、可审计），**不用模型抽的图**。

## 二、8 份的真分歧（各自承认对方强项）

### 2.1 主干之争：词法 vs 语义 vs 学习型稀疏

| 流派 | 主张 | 它**自己承认**的死穴 |
|---|---|---|
| #1 词法优先 | 通用/多域/无标注下倒排最稳；词表是人肉硬编码，倒排是语料自动统计 | **词汇不匹配是结构性死穴**：PRF 在命中为 0 时扩不出任何东西 |
| #2 语义优先 | 通用性来自语义（"特殊作业"↔"高风险操作"） | **专名一字不差必错**（GB 30871 vs GB 30872 余弦 >0.99）；**漏检不可枚举 ⇒ 无标注时原则上无法自证召回** |
| #3 学习型稀疏 | 折中：保留"词"的精确，又跟上同义改写 | **无标注学不出权重**；估计 80% 收益会被 identifier 精确通道拿走，自身增量可能只有 1–3 个点 |

**⇒ 合并结论：不是三选一，是分工。**
- **主干 = #1 的词法**（理由：它自己那条死穴由 #3/#5 的标识符通道补；而 #2 的死穴无法补）；
- **语义 = 只对候选重排**，**不当召回通道**（#1、#3、#6 **独立**给了同一改法：#2 自己的算术也支持——570 ms → 对 2,000 候选 ≈2.2 ms）；
- **学习型稀疏 = 后置可选**，且必须先有标注（#3 自认）。

### 2.2 结构/层级：#4 的基石**被实测推翻**

#4 把两条前提称为"**全案基石，未验证**"。我查了（探针 `probe-structure-base2.py`）：

| 它的前提 | 实测 | 判定 |
|---|---|---|
| passage **按文档序单调写入**（区间寻址 `p_lo..p_hi` 依赖它） | 抽查 40 篇，**完全单调 0 篇 / 有逆序 40 篇**（最多 8 处逆序） | ❌ **假** |
| `hierarchy_path` 保留**兄弟序 `ord`** | 表里**没有** `ord/seq/sort` 任何一列 | ❌ **不存在** |
| `hierarchy_path` 是标题路径 | ✅ 是**祖先号路径**（条款 `5.2` → `"5"`；条款 `5.2.3` → `"5 > 5.2"`）；非空 458,579（87.8%），其中多级 63.2% | ✅ 但**不含序号、不含标签** |

⇒ **#4 的 L2（区间寻址 + 分支定界）在没有迁移之前做不了。**
**但它的两条洞见保留**：① **结构信号只许上浮、不许删除**（它自己写死 `gate ×1.15`）；② **"没有页号就如实说没有"**（现状 DOCX 谎称第 1 页）。
**它的 `ord` 概念要吸收**——因为业主要"精确到条款号"，就需要一个**稳定身份**，但那个身份不能拿 `rowid` 冒充。

### 2.3 跨文档跳：#5 独有，且是本轮最可落地的一块

- **机制性根因（它指出、我核过）**：`evidence_edge` 的**两个外键都 `REFERENCES clause_revision`**（[schema.sql:137-147](../../src/core/storage/schema.sql#L137-L147)）
  ⇒ **结构上不可能有跨平面边**。这就是"13,606 条边跨文档 0 条"的机制性原因，不是抽取没做。
- **白送的边表**：标准正文第 2 章「规范性引用文件」= **5,400 篇（79.4%）、47,745 条提及**，是原文自带的跨文档边表，**今天一条没落**。
- **它的独有设计**：**stub node**（库外目标也要建节点，否则把天花板人为压到 1.7%）、**反向边**（"谁引用了我"，合规场景更常用）、
  **replay 门禁**（从 span 重跑同一文法必须复现同一 target）、**四道确定性断言**（replay / 互证 / 时间不可能 / 题名冲突）。
- **它诚实报告了一个真缺陷**：用 `ks_resolve_clause` 核 GB/T 1.1-2020 的「第2章」→ **404**，
  而查 `2` 命中的是**另一部标准**（GB/T 38496-2020，且 `is_suspicious=true`）⇒ 它**拒绝据此下结论**。
  **这正是"跳到隔壁那条"在现网上的活样本。**

## 三、合并后的目标链路 v1

```
[0] 判据先行（离线）        三元匹配金标 + 构造性金标 + 负例集 + 抽样审计        ← #7 骨架 + #1/#2/#6 补充
[1] 锚定与平面切分（离线）  结构感知切块 + 精确 locator + 页眉/清单平面隔离     ← #5 L0/L1 + #4 的“如实说没有页”
[2] 标识符精确通道         形状文法（唯一一份字典）                    ← #1 §B + #5 §B  （唯一硬门）
        ↓ 唯一允许“硬过滤”的层（符号匹配蕴含保真）
[3] 多字段词法主干          BM25F：title_path / body / bigram / ident / num     ← #1 L2 + #4 的结构加权
        ↓ 每字段 N_max 封顶；WAND/BMW 保“与全扫等价”
[4] 语义 = 候选重排          向量只对 [3] 的 top-K 算，不再全扫               ← #1/#3/#6 独立同结论
[5] 名次融合 + 去冗余        RRF(k=60) + per-doc 配额 + section 聚合            ← #1 L6 + #4/#6
[6] 精确重排（预算内）       本地 cross-encoder，仅 top-20~50；可关            ← #6 L5 + #3
[7] 定位锚 + 拒答门          W3C selector 栈（抄 hypothesis/client, BSD-2）；     ← 仓内既有裁定 + #7 L5
                             锚不可解析者不进结论；低分不答而不是猜
[8] 跨文档跳（确定性链接）    node/mention/edge 三表；边可 replay；双向；stub     ← #5 全案
        ↓ 跳数 ≤3、分支 ≤8、全局预算、环路按 node_id、conf×0.7^(d-1)
[9] 答案组织                 三段式（现状已是唯一形态）+ 每条锚回原文 + 显示“跳的理由” ← 现有 + #5
```

**贯穿纪律（合并 #6 与 #7）**：
- **只有"可证明不丢"的层允许删除结果，其余层只许改序**；
- **召回是硬门（只涨不跌的棘轮），延迟是软目标**；
- **每层必须可单独冻结、单独评测、可降级**，且降级必须在答案里显性标注。

## 六、合并后的"不要做"（8 份去重，共 10 条）

1. ❌ **不要保留任何无上限召回通道**（`应` 一次 27% 的库）。
2. ❌ **不要暴力全扫向量**；也**不要只信 ANN**——要用暴力在分层抽样上做 ANN recall 基准（≥0.99 才准上）。
3. ❌ **不要逐块过模型**（摘要/抽实体/生成上下文/LLM 建图）：不只是钱，**它把库变成不可重算的派生物**，换模型即作废。
4. ❌ **不要把 Jev/LLM 放进剪枝或检索路径**（0.5 s/次、按次计费、输出不可作结论依据）。
5. ❌ **不要用领域词表做硬门或硬加权**（混合语料上双向失效）。
6. ❌ **不要把语义相似度写进"引用图"**——相似度归召回通道，引用归确定性边，**两表必须分离**。
7. ❌ **不要静默 pin 到"最新版"**，也不要静默丢弃解析不了的提及（实测 39 组多版本、**78 篇旧版仍标现行**）。
8. ❌ **不要用只比条款号的指标证明质量**（80% 的题判错也发现不了）。
9. ❌ **不要在无标注时调参或上学习型排序**（n=20 时方差淹没效应）。
10. ❌ **不要为代码/JSON 写专门解析器**（NOT-DOING #19）、**不要为 PPT 投入**（#18）。

## 八、最后两份收尾设计补进来的（值得单列）

### 8.1 确定性链接派（#5）补的硬货

- **边类型必须分开**（不能只有一个"引用"）：`CITES_NORMATIVE / CITES_INFORMATIVE / INCORPORATES_CLAUSE / SUPERSEDES / AMENDS / IDT_MOD_NEQ / CONTAINS / INTRA_REF`；配一张 `edge_quarantine`（失败边进隔离区，**不丢弃**）。
- **它自己指出的致命盲区**：**replay 只证"抽取可复现"，不证"语义对"**——把"代替 GB/T 50001-2001"读成"引用"，图的语义就反了，而 replay 照样 100% 通过。
  ⇒ 因此**每种关系文法要单独定向抽样 + 加方向断言**（例：新标准的发布年必须晚于被代替标准）。
- **上多跳之前必须先量"边/节点比"**：现状 **13,606 / 522,021 = 0.026 边/passage**；**目标 ≥0.5/passage，不达标不要上多跳**（否则 3 跳可达集极小、收益≈0）。
- **无标注时估绝对漏检量**：两个**独立**抽取器做 capture–recapture，`N̂ = n1·n2/m2`（⚠"两器错误不相关"未验证）。
- **零成本结构性门禁（可挂棘轮）**：① `normative_refs` 平面里清单在、却抽不到 ≥1 条 mention ⇒ 报错；② `replayable=true` 必须 **100%**；③ `TEMPORAL_IMPOSSIBLE` 占比 >5% ⇒ 文法回归。
- **规模上限的退路**：边到 10⁷ 量级换 **Kùzu**（MIT，嵌入式 Cypher），**不上 Neo4j/JVM**。
- **它承认的最大未知**：**通用域的锚点分布完全未知**——历史文献可能**没有任何可校验标识符** ⇒ 那一块的确定性链接召回**可能接近 0**，只能承认做不到、交回召回通道。

### 8.2 语义优先派（#2）补的硬货（尽管它的主干主张没被采纳）

- **`FTS5 tokenize="trigram"`**（SQLite ≥3.34）：一个**零成本**就能补上 CJK 无词典兜底的手段——我们现在只有 jieba 单字段。
- **嵌入输入带上结构**：`hierarchy_path + "\n" + passage`（零模型成本，覆盖 87.8%）。
- **三级粒度 passage / 节 / doc，父级 = 子级向量均值**（**不重跑模型**）——解决"答案横跨三段"的粒度错配。
- **答案的机器校验（必须做）**：生成后逐句校验——引用片段必须是原文子串（归一化后 `contains`），**标识符必须在被引 span 内逐字命中**，否则**拒答或降级为纯原文摘录**。
- **oracle 上界诊断**（少见的诊断法）：`oracle@1000`（各通道 top-1000 并集里有没有金标）vs `fused@200`——
  前者高后者低 ⇒ 瓶颈在**融合/重排**；两者都低 ⇒ 瓶颈在**召回通道**。
- **它自己给出的退场条件**（很诚实）：若"语义改写型查询"上 dense-only 的 Recall 优势 **<5%**，应立即缩减语义投入。
- **它自己承认的结构性软肋**（这是"语义不当主干"的最硬理由）：
  **BM25 的漏检可枚举（查不到的字符串可以穷举），稠密的漏检不可枚举 ⇒ 无标注时稠密的真实召回原则上无法自证。**

## 九、待业主拍板

1. **是否接受"形状文法"作为领域词表的替代**（这决定"通用化"这条路怎么走）。
2. **评测的人力投入**：常规轮 n=400（上界 0.75%）／发版轮 n≈3,000（上界 0.1%，约 100 人时）。
3. **是否先做只读原型**（#5 的第 1 件，当天出数、零写入、零模型钱，用现成的真实文档与它自带的第 2 章当答案卡）。
4. **`node/mention/edge` 三表迁移是否批准**（需给 `evidence_edge` 换外键；这是"跨文档跳"能不能成立的结构前提）。
