**金标门禁公布的两个数字（`exact_hit@1 = 88.9%` / `recall@5 = 97.8%`）曾被一个缺陷抬高**——
命中判据**只比条款号**（不比是哪本标准的条款号）。**该缺陷已于同日修复**（见 §九）。

> **⚠ 更正（2026-09-24，同一天，我自己写错的）**：本审计初稿把"评测语料库 ≠ 生产语料库"
> 也写成了**缺陷 B**。**那个框架是错的。**
> `eval/golden/knowledge-snapshot.db` 是**有意冻结的评测语料**——金标建在它上面、门禁也跑它，
> 目的就是让 CI 每次结果一致。**把金标拿去对今天的生产库跑，是我测错了对象**，
> 不是"产品少了东西"。业主同日指示"那两份标准的事情忽略掉"，与这个更正一致。
> ⇒ **真正确立并已修的只有缺陷 A（判据）**；下面 §三 保留原文以示留痕。


## 二、缺陷 A：判据只比条款号

`eval/run_benchmark.py:33-34、67-73`：

```python
def _hit(ids: list, answers: list) -> bool:
    return bool(answers and any(a in ids for a in answers))
...
ids = [r.clause_number for r in res]      # ← 只取条款号
```

**`standard_no` 从头到尾没参与比较。** 而同一个条款号在库里有多少条？实测
`clause_number='5.2'` 有 **4,910 条**，其中只有 1 条属于 GB 30871-2022。
⇒ **搜回另一本标准里的同名条款也算命中。**

## 四、~~两个缺陷叠加出的真数字~~（**对真库跑金标的结果，只作参照**）

> **⚠ 更正**：本节标题原写"两个缺陷叠加"，**框架错了**（见 §一）。
> 本节数字是**把金标拿到真库上跑**得到的——**金标不是为真库建的**，
> 所以 22.2% 只说明"金标与真库不同源"，**不能读成产品效果**。
> **唯一仍然成立、且重要的一行是"47 个假命中"**：它在**快照库（正确语料）上同样复现**（见 §九）。


同一批金标、同一套检索、**真库**：

| 指标 | 现状判据（只比条款号） | 诚实判据（标准号 + 条款号） |
|---|---|---|
| 前 1 名命中 | 67/90 = **74.4%** | 20/90 = **22.2%** |
| 前 5 名命中 | 67/90 = **74.4%** | 20/90 = **22.2%** |
| 前 10 名命中 | 67/90 = **74.4%** | 20/90 = **22.2%** |

⚠ 三档**完全相同**不是笔误：精确条款号通道会把**全库所有同名条款**都返回
（见 §六），所以"期望的那条在不在前 k"由**同一条 SQL 的任意次序**决定，与 k 无关。

**把金标期望逐条摊开看（`golden-expect-audit.py`，真库）**：

| 期望条款的状况 | 条数 |
|---|---|
| **库里没有这条** | **70**（AQ 3028-2008 缺 64 + GB 18218-2018 缺 6） |
| 有，且现行 | **20** |
| 有，但已废止/已替代 | 0 |

⇒ **现状判据那 67 个"命中"里，有 47 个是假的**（靠匹配**别的标准**的同名条款拿到）。

**并且可以严格推出**：诚实判据下"命中"必然意味着那个 (标准号, 条款号) 在库里存在
（命中就是搜回了这一对）⇒ **命中集 ⊆ 存在集**。两者都是 20 ⇒ **两集相等**。
⇒ **在"库里真的有答案"的那 20 条上，检索命中率是 20/20 = 100%（前 1 名）。**

**所以真实情况是两句话，而不是一句：**
1. **能答的题，答得对**（20/20，前 1 名）；
2. **但金标里 78%（70/90）的题，对着今天的库根本无从答起**——而现状判据把它们
   **伪装成了命中**，于是公布出 88.9% / 97.8% 这种数字。

## 六、顺带定位到一个生产缺陷（精确通道不按标准号限定）

`src/core/retrieval/hybrid_engine.py:130-158`，通道 A（权重 **2.0，全通道最高**）：

```sql
SELECT cr.clause_revision_id FROM clause_revision cr
JOIN doc_meta dm ON dm.doc_id = cr.doc_id
WHERE cr.clause_number = ?        -- ← 用户问句里明明写着"AQ 3028-2008"，这里不按它筛
  AND (dm.legal_status IS NULL OR dm.legal_status NOT IN ('withdrawn','superseded'))
ORDER BY (dm.legal_status IS NULL), dm.legal_status
```

⇒ 对"查 AQ 3028-2008 第 3.1 条"这类提问，它把**全库所有叫 3.1 的条款**拉出来，
按效力状态排一排，谁在前谁拿最高权重。**正确的 AQ 3028 条款因此被别的标准的 3.1 挤掉**——
§四 里那 47 个假命中就是这么来的。

**修法方向（未实施）**：提问里能认出标准号时，给该通道加 `dm.standard_no` 限定。
需要新写"从提问里认标准号"的逻辑（仓里**没有**现成函数；`canon_standard_no` / `standard_no_key`
只做归一化，不做抽取）。
⚠ 这会改动**排序**并推动**门禁指标** ⇒ 属 AGENTS.md 的**必验类别**，故**本审计一行代码未改**。

## 九、已实施的两处修复（2026-09-24，同日）

### 修复 1（根因）：精确条款号通道在提问认得出标准号时，限定到那本标准

`src/core/retrieval/hybrid_engine.py`：

* 新增 `_STD_IN_QUERY_RE` —— 一条**不列前缀族**的形态正则（`字母 + 号 + 连字符 + 年`）。
  刻意不列前缀，是为了**不与仓里已有的两份前缀表**
  （`text_utils._WM_STD_CORE` 与 `doc_catalog._STD_NO_PREFIX`）形成第三份。
* 通道 A 的 SQL 多取一列 `dm.standard_no`；**提问里认得出标准号时**按
  `standard_key` 过滤，**认不出时行为一字不改**。

**效果（同一批金标、同一快照库）**：

| 指标 | 修前·只比条款号 | 修前·标准号+条款号 | **修后·标准号+条款号** |
|---|---|---|---|
| 前 1 名 | 94.4% | 78.9% | **94.4%** |
| 前 5 名 | 97.8% | 93.3% | **97.8%** |
| 前 10 名 | 98.9% | 98.9% | **98.9%** |
| 「多算」条数 | — | **47** | **0** |

**"多算"归零、旧判据数字一点没动** ⇒ 这是**纯改进**，不推动棘轮。
直接旁证：`查 AQ 3028-2008 第3.1条` 修前第一条返回 `GB 55037-2022`，修后返回 `AQ 3028-2008`。

### 修复 2（关门）：评测器的命中判据改成比 (标准号, 条款号)

`eval/run_benchmark.py` 的 `_hit` 从"只比条款号"改为比 `(standard_key(standard_no), clause_number)` 对。
**因为修复 1 之后两种判据逐条一致**，本改动**不改变任何指标值**，只把口子关上
（今后若有人把标准号从检索里弄丢，门禁当场会红，而不是被假命中掩盖）。

**官方评测器实测（快照库，新判据）**：
`exact_hit@1 = 0.9444` / `recall@5 = 0.9778` / `recall@10 = 0.9889` / `modality_intercept_rate = 1.0`。
对比 `eval/baseline.json`（0.8889 / 0.9778 / 0.9889 / 1）⇒ **只有 `exact_hit@1` 是涨的**，
其余三项一字不差 ⇒ **门禁通过，且未触发任何回退**。
`tests/test_golden_gate.py + test_golden_set.py`：**4 passed / 1 skipped**。

> ⚠ **基线未改**：本次**没有**动 `eval/baseline.json`。理由：它是棘轮，只拦回退；
> 当前值 ≥ 基线即合规，**追涨不是必须的**（追涨反而会让"有人偷偷调低"看不出来）。
> 另注：`exact_hit@1` 基线写 0.8889 而当前 0.9444 —— 那是**基线落后于早先的改进**
> （棘轮只拦回退的固有性质），**不是本次改动造成的**（修前实测同样是 94.4%）。

⚠ **按仓规，本批属"必验"类别**（改了判据/门禁 + 改了检索排序）⇒ **需要独立复核**，
作者不自证。本页只记"做了什么、量到什么"。
