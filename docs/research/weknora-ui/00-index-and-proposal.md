# WeKnora 界面「抄 / 改着抄 / 不抄」清单（草稿 —— 等业主确认）

**这份文件干什么**：把 WeKnora（Tencent，MIT，本地 checkout `D:\AI\WeKnora`）的整套界面读明白，
逐块给出**抄 / 改着抄 / 不抄**的建议 + 理由 + 代价，交给业主点头。
**它不是设计稿**：确认之后才动 UI；动的时候按[交互设计](../INTERACTION-DESIGN.md)的形态落地
（我们寄生在 DSH 侧栏里，React + 宿主原生组件；它是 Vue + TDesign ⇒ 抄结构与视觉，不逐行抄代码）。

**判断依据（三条，两条是既有决策）**：
1. 业主 2026-09-19 裁定：**通用层「纯借鉴」，不造轮子** —— 有现成的就抄；只能自己设计并长期维护的不做
   （[WeKnora 影响评估 §五第 0 条](../weknora-assessment.md)）。
2. 三块护城河不抄、也不让：**时效/效力数据平面**、**取证坐标链**、**合规落地件**（同上 §五）。
3. 形态约束：寄生 DSH 侧栏、不自建账号与多租户、**产出物只出 Markdown**（交互设计 §九）。

**许可证**：WeKnora `LICENSE` = MIT（Copyright (C) 2025 Tencent），抄其自有代码/样式需**随附版权与
许可声明**；第三方组件另有条款 ⇒ 抄进我们 React 侧栏必然是**照结构重写**，并逐处记出处。

**证据文件**（子代理读源码写的，全部带 `文件:行`）：

## B. 知识库管理的组件与视觉语言（第二份读完）

**一句话布局**：列表页 = 可拖拽侧栏(56/208px) + 主区（h2 24px → 可滚动区里 **CSS Grid 卡片网格**，
5 档断点 2/3/4/5/6 列）；详情页 = 面包屑 → 目录树(268px) + 内容区（筛选条 Grid → 唯一滚动区 →
卡片/列表双视图 → **绝对定位悬浮批量条**）。⚠ **全块不用 TDesign 的 `t-row/t-col/t-table`**，
分栏全是手写 CSS Grid —— 说明"抄它"抄的是**结构与尺度**，不是组件库用法。

| 块 | 他们怎么做 | 建议 | 理由 / 代价 |
|---|---|---|---|
| **尺度系统（最重要的一条）** | 自定义 token（非 `--td-*`）：圆角 `4/6/8/10/12/999`、字号 `10/11/12/13/14/15/16/18/20/24`、间距 **4px 网格 4~40**、动效 `120/150/200/300ms`、z-index 阶梯 `10/1000/1100/2500/3000/5000` | **抄（这是治"难看"的根）** | 我这边界面难看的**真正原因**是没有尺度：间距、字号、圆角都是现场拍数字。抄它的**尺度表**（值不必逐个相同，但要有**一套**），比抄任何一个组件都值 |
| **明暗两套** | `document.documentElement.setAttribute('theme-mode', …)` + 属性选择器，三态 light/dark/system；主色 `#07c05f`（深色用 `-6`） | **改着抄** | 抄**机制**（我们已按 DSH 的 token 体系做明暗，机制等价）；**不抄它的品牌绿** —— 我们寄生在 DSH 外壳里，品牌色应随宿主，否则一眼看去像两个产品拼起来 |
| **卡片** | 136px 高、圆角 8、内边距 12/14、网格 gap **12px**、静置阴影 `0 1px 3px rgba(0,0,0,.04)`、hover `0 4px 12px color-mix(brand 12%)` | **抄** | 具体的"卡片高度 + 12px gap + 极轻阴影 + hover 才抬起"是一套成熟手感；我们现在卡片信息密度与间距都不稳定 |
| **列表行** | 行 min-height **60px**、表头 **40px**、左右 padding **16px**、容器圆角 9 | **抄** | 这是行高与呼吸感的基准，和我们的表格现状（挤）比是明显改进 |
| **分隔线与描边** | `--td-component-stroke`（浅 #e7e7e7 / 深 #383838）；**卡片底部分隔 0.5px**、悬浮面板描边也 0.5px | **抄** | 0.5px 细线是"精致"的一大来源（我们上一轮刚在 DSH 侧改用 `.5px`，方向一致） |
| **抽屉内的分段标题** | section 标题前一条 **3×14px 品牌色圆角 2px** 的竖条 | **抄** | 便宜、立刻让"一坨文字"变成"有层级的分段" |
| **空态** | 统一 `EmptyState.vue`；空库用 **162×162 SVG 插图** + 文案「知识为空，拖放上传」 | **改着抄** | 抄"**空态 = 插图 + 一句可执行的话 + CTA**"的形态；插图我们自己画一张（不搬它的 SVG，避免不必要的资源搬运） |
| **加载态** | 骨架屏：列表页 6 张、详情页 8 张（TDesign skeleton 渐变） | **抄** | 比转圈更像"内容马上到"，且实现便宜 |
| **批量条** | `max-width 920px`、`bottom: 12px`、**绝对定位、不跟随滚动** | **改着抄** | 位置与宽度值得抄；但"不跟随滚动"在长列表里会飘出视野 —— 我们列表更长，建议 sticky 固定在底部 |
| **上传进度浮层** | 右下角 `380px`、分段条 + **SVG 环形进度**（`ProgressRing`），"正在上传 N/M"→"正在解析…"→"全部完成" | **抄** | 与 A 段同一结论：这是最该抄的一块 |
| **视图切换/滚动** | 卡片视图 + 列表视图双形态；**知识库与文档列表都不用虚拟滚动**（只 WikiBrowser 用），靠无限滚动 pageSize≈35 | **改着抄** | 抄**双视图**；**不抄**无限滚动+35 条一页：我们库 6000+ 行、要能"定位到某一行"，分页 + 虚拟滚动更合适 |
| **它的**两个坑（别一起抄） | 子代理 grep 出：`DocumentCardView` 的 `.knowledge-card.is-selected` 与 `.batch-mode` **在样式里没有对应规则**；`DocumentListView` 的 `.selected` 只用于 `:not()` 与 `.row-more-btn{opacity:1}` ⇒ **"已选中"几乎没有视觉**，只靠勾选框 | **不抄** | 选了 20 条却看不出哪些被选，是**可用性缺陷**；我们要给选中行**明确底色**（这属于"抄思路不抄 bug"） |

## C. 问答 / 引用 / 预览 / 产物（第三份读完）—— **含一条改变结论的硬事实**

> **⚠ 硬事实：他们的引用不能跳原文页。** 引用的数据里**没有页码、没有相似度分数**；
> 预览组件 `document-preview.vue` 里 **PDF 只是一个 `<iframe>`** —— **无页码跳转、无缩放、
> 无页内查找、无命中定位**（唯一的 focus 逻辑是键盘可达性）。点击行内引用角标只是
> **打开右侧来源抽屉并高亮那张卡**，"查看文档详情"只跳到知识库详情页，**两套系统不联动**。
> ⇒ 这正好答掉了[评估文档 §六](../weknora-assessment.md)那条悬案
> （"它的 UI 能不能点引用跳 PDF 页并高亮那一行"）——**答案是不能**。

| 块 | 他们怎么做 | 建议 | 理由 / 代价 |
|---|---|---|---|
| **行内引用角标** | 模型输出 `<kb doc chunk_id>` → 行内 pill，显示**截断 13 字符的文档名**；hover 80ms 出浮层（按需 `GET /chunks/by-id/{id}` + 进程内缓存）；**点击 = 开右侧来源抽屉并高亮该卡**（不开预览） | **抄** | 这是"证据链看起来专业"的关键交互：**角标 → 浮层（懒加载）→ 右侧来源面板并高亮对应卡**。我们已有"可点开 PDF"的更强能力，缺的是这套**壳** |
| **序号 → 真实 id 的解析层** | 模型写的序号要回退解析成真实 `chunk_id`（`citationMarkdown.ts:84-143`，多级回退） | **抄** | 我们同样有"模型给的引用 ↔ 真实条款/bbox"的映射问题；他们踩过的多级回退值得对着写 |
| **流式渲染的稳定性** | SSE + 打字机（`minCps 72 / drain .42s / maxCps 240`，`reduced-motion` 直出）；**工具栏等打字机追平才出现**；**半截标签/角标/表格的稳定化处理**；等待行两级计时（250ms / 60s） | **抄** | 这些是"流式回答看起来不抽搐"的细节，纯经验值；`prefers-reduced-motion` 也要跟 |
| **右侧来源面板的尺寸** | 固定 `min(420px, 100vw)`，**960px 断点写死** ⇒ **在 IDE 窄栏里会直接退化成遮罩层** | **不抄（必须重做）** | 我们的宿主就是窄侧栏 ⇒ 面板宽度要按容器算，不能写死断点。这是"抄形态、改实现"的典型 |
| **PDF 预览与定位** | `<iframe>` 直嵌，**无跳页/缩放/页内查找/命中高亮** | **不抄（我们自建，且这是护城河）** | 我们已有的"点依据 → 引擎鉴权 PDF → **跳页 + 红色定位箭头**"**他们做不到**（数据里就没有页码）；这条要写进对比材料。改造他们的预览组件不值得（要换成 pdf.js = 重写，收益为零） |
| **会话与知识库的关系** | **会话不绑定知识库**（源码注释「Session 不再和知识库绑定」），限定范围靠**请求体** `knowledge_base_ids`；旧会话靠 `last_request_state` 恢复当时的 agent/模型/知识库/联网 | **改着抄** | 抄"**范围是每次提问的参数、历史会话可复现当时的范围**"这个模型；但我们的产品语义是"查法规"，范围概念要落在**库/合集**上并显示出来（用户要能一眼看到"这次问的是哪批资料"） |

## D. 他们自带的 DSH 插件（第五份读完）—— **同宿主的现成写法，直接对着我们的插件待办**

`D:\AI\WeKnora\packages\dsh-weknora`（MIT，npm 已发布）。**形态结论：没有界面**，纯宿主侧插件
（`package.json` 的 `dsh` 字段只有 `bundle.patch`，全包 0 个 tsx / 无 `dsh.client`）——
所以我们客户端那半边**没有可抄的对应物**，客户端只能抄它的 Vue 前端（A/B/C 三份）。

**两条它「不如我们」的事实（先摆出来，免得抄错方向）**：

1. **它也不拒未知配置键**（实测：把 `config.ts` 复制到 `%TEMP%` 用
   `node --experimental-strip-types` 跑探针，`baseURL` 拼错**静默回落默认值**、`tools.serach` **静默忽略**）
   ⇒ 我们 `plugin/src/index.js` 那道"未知键当场报错"**比它强**，**不许退回**。
2. **它也没用官方 `defineTool`**（全包 0 命中），而是自己声明一份结构类型（`dw/src/harness.ts:1-10`），
   理由是"要发布 npm、不想有运行时依赖、不想锁 harness 版本"。
   ⇒ 我们是**本地 bundle 插件、不发布**，**不该继承它这个取舍**：用官方 `defineTool` 还能拿回
   `presentCall`/`presentResult`/`finalizeContent`（**工具结果做界面呈现的口子**）。

**可直接抄（6 条，按性价比排序）**：

| # | 抄什么 | 抄到哪 | 省掉什么 |
|---|---|---|---|
| 1 | **json-schema 三件套**（`assertSupportedSchema` 含"required 必须在 properties 里"、`validate`、`assertLosslessJson` 拒 `undefined/NaN/循环`），接成门禁：**工具返回值必须满足自己声明的 schema** | 新建 `plugin/scripts/lib/json-schema.mjs` + 进冒烟链 | 我们 30+ 套冒烟全在测行为，**没有一条测"返回值 ↔ 自己声明的 schema"** |
| 2 | **每个工具声明 `output.schema` + `render` 配对**（`render` 只做投影；他们那 25 行三个纯函数 `clip`/`formatScore`/`describeScope`） | `plugin/src/index.js`（`ks_ping` 现在 `additionalProperties:true`）、`materials.js`、`collect.js` | 模型看到的工具结构明确，界面也有稳定呈现口子 |
| 3 | **`isConcurrencySafe`**：只读工具写 `()=>true`，有副作用的（采集/评审写口）**不写** | 工具注册处 | 宿主能安全并发调度只读工具，写口不被误并发 |
| 4 | **`AbortSignal.any([signal, AbortSignal.timeout(ms)])`** + **取消/超时分开给文案** | `plugin/src/engine.js`（现在手搓 `setTimeout`+`clearTimeout`） | 语义统一、少一处手写计时器（我们刚因手写计时器出过泄漏） |
| 5 | **线调用 fixture + 回放比对**（"恰好只发这些调用"的断言；两端夹逼同一份 fixture） | 与现有 `verify:commands`/fixtures 同处 | **我们已因 fixture 不生效踩过一次**（`smoke-lifecycle.mjs` 注释里记着） |
| 6 | **e2e 三段式**：`--dump-config` 断言插件真挂上 + 断言模型被 offer 到的工具名 + 断言工具返回的原文进了模型上下文（配确定性假模型） | 新建 `plugin/scripts/e2e-in-dsh.mjs` | 我们只有"渲染级/路由级"证据，**没有"在真宿主里挂上并进模型上下文"的证据** |

**不该抄（3 条）**：① 手写校验**替代**严格键检查（退回它就丢掉我们唯一的防线）；
② 再复刻一份 harness 结构类型（那是"发布给陌生人"的取舍，我们用官方类型）；
③ `weknora_ask` 的**产品取向**（委派服务端另一个模型、自陈"返回结论而非证据"）——
我们的差异化在**证据链**与**客户端**，不在"再包一层问答"。
