# 红箭头为什么"还是没生效"—— 旧代码与现状的对照核查（2026-10-12）

业主令：「你先阅读那个最开始的代码，因为这个功能你刚开始是有的，最原始的设计，
这个本轮这个环节它是显示在聊天输出的那个地方的，然后一点跳转过去都是实现了的，
都是好好的。你翻一下那些旧代码，现在它把这个证据超链接放到侧边栏以后就不行了，
我觉得可能是跟老代码之间有什么冲突，或者是在衔接哪里出bug了，你先查。」

## 结论（先说）

**业主的判断是对的：确实有两套东西在打架。** 但不是"冲突导致坏了"，而是：

**老代码那条路（聊天输出里的链接）从一开始就没编 `bbox`，而新代码那条路（侧边栏）
后来补上了 —— 可它补的地方不对，被老代码的第二个函数覆盖回去了。**

**外加一个更根本的问题**：`GB 17681-2024` 这份文档的**坐标数据本身是坏的**，
所以就算链路全通，它也画不出来。

---

## 一、老代码是什么样（聊天输出里那条路）

**老设计**（`plugin/src/index.js` L149-166 `evidenceAnchor`）：

```js
export const KS_EVIDENCE_PATH = '/__ks_evidence__'
export const KS_EVIDENCE_ORIGIN = 'http://127.0.0.1:1'

export function evidenceAnchor(ev) {
  const qs = new URLSearchParams()
  qs.set('doc', doc)                    // 必填
  if (page !== null) qs.set('page', ...)  // 可选
  if (rev !== null) qs.set('rev', ...)    // 可选
  return `${KS_EVIDENCE_ORIGIN}${KS_EVIDENCE_PATH}?${qs.toString()}`
}
```

**它的注释自己写着**（L145）：

> `bbox` 参数暂不拼（决策：bbox 黄框推迟到收藏跳转一起做）

⇒ **老路从来就只编 `doc` / `page` / `rev`，没有 `bbox`。**

**这条路的用法**：把 `evidence_url` 交给**模型**（L286-288）：

> P1c 增强①：可直接粘成 Markdown 链接的证据锚点（doc+page+rev，**无 bbox**）
> 模型把答案里对该证据的引用写成 `[依据](evidence_url)` 即得可点 PDF 跳转

⇒ **所以业主记忆里的"在聊天输出里、一点就跳、好好的"—— 那个"好好的"是
"跳页好好的"，本来就没有箭头。** 箭头是后来才要求的。

## 二、新代码是什么样（侧边栏那条路）

`plugin/client/ksEvidence.ts` 的 `evidenceUrlOf` —— **它才是带 bbox 的那个**：

```js
export function evidenceUrlOf(ev) {
  params.set('doc', doc)
  if (page !== null) params.set('page', ...)
  if (rev !== null) params.set('rev', ...)
  if (isBbox(ev.bbox)) {                    // ← 这一段是 2026-10-10 补的
    params.set('bbox', ev.bbox.join(','))
    if (bboxPage) params.set('bboxPage', ...)
  }
  return `${EVIDENCE_ORIGIN}${EVIDENCE_PATH}?${params}`
}
```

**它自己的注释写着**（L148-154，spec 009 那次补的）：

> ⚠⚠（spec 009，**红箭头不出现的决定性一环**）：
> 本函数**原来只编 `doc` / `page` / `rev`，从不编 `bbox`** ——
> 而 `parseEvidence` 早就实现了 `parseBbox`（能**解析** bbox）⇒ 结果是
> **bbox 只进不出** ⇒ 证据 tab 里 `evidence.current?.bbox` 永远 undefined
> ⇒ **箭头永远不画**。

⇒ **所以 10-10 那次已经找到了同一个问题，并在 client 侧补上了。**

## 三、★ 那为什么"还是没生效"？三个独立原因，任何一个都足以让它不画

### 原因 A（真冲突）：**两个 URL 构造者，一个编 bbox、一个不编**

| 构造者 | 在哪 | 编 bbox？ | 谁在用 |
|---|---|---|---|
| `evidenceAnchor` | `plugin/src/index.js` L153 | **❌ 不编**（注释写明"暂不拼"） | 模型拿到的 `evidence_url` |
| `evidenceUrlOf` | `plugin/client/ksEvidence.ts` L135 | **✅ 编**（10-10 补的） | 侧边栏「本轮」的「看原文」 |

**两条路各有一个 URL 构造者 —— 这正是"一个事实两个家"的典型症状。**
`KsTurnTab.tsx` 的注释自己说「`evidenceUrlOf` 是唯一 URL 构造者」（L11），
**但宿主侧的 `evidenceAnchor` 还在，而且还在给模型用。**

⇒ **模型在聊天里写的那个链接，永远不带 bbox** ——
点它跳页正常，但**没有箭头**。

### 原因 B（真数据问题）：`GB 17681-2024` 的坐标是坏的

实测（生产库只读）：

| 标准号 | span 数 | 平均宽 | y 分布 |
|---|---|---|---|
| **GB 17681-2024**（业主截图那份） | 370 | **0.52pt** | **783.9 ~ 784.7**（全挤在页顶 0.8pt 内） |
| GB 30871-2022（正常的） | 379 | **317.77pt** | 56.4 ~ 740.4（正常铺开） |

**370 条条款的 y 全在 0.8pt 高度内** —— A4 页高 841.9pt，这在物理上不可能。
⇒ **不是"框太小"，是这份 PDF 的坐标根本没抽对。**

**影响面**（全库）：**756 篇文档 / 253,222 条条款（13.7%）**坐标是坏的，全是标准。

### 原因 C：两级都主动过滤退化框（这是对的，但掩盖了 B）

- 引擎侧 `attach_bboxes`：宽<5pt 或 高<3pt ⇒ **不写进证据**
- 宿主侧 `/ks/bbox` 路由：同样口径 ⇒ **过滤掉**
- 前端拿到空数组 ⇒ 走"取不到坐标"提示

⇒ **这三层都是"如实降级"，不是 bug。** 但结果是：**坏数据的文档永远画不出箭头**，
而用户只看到一句"取不到坐标"，不知道是数据坏了。

## 四、所以业主说的"跟老代码有冲突"—— 具体是这个

**不是"老代码把新代码弄坏了"，而是：**

1. **老代码那条路（`evidenceAnchor`）没跟着升级** —— 10-10 只在 client 侧补了 bbox，
   **宿主侧那个同功能的函数没改** ⇒ 模型拿到的链接仍然不带 bbox。
2. **两个同功能函数并存** ⇒ 修一个不修另一个，症状就是"改了但没生效"。

**这正好解释了业主的观察**：「放到侧边栏以后就不行了」——
侧边栏那条路（`evidenceUrlOf`）**是修过的**，
而聊天输出那条路（`evidenceAnchor`）**没修** ⇒ 看起来像"换了地方就坏了"。

## 五、要修的话（三条，按该做的顺序）

| # | 修什么 | 为什么 |
|---|---|---|
| **1** | **统一 URL 构造者**：让 `evidenceAnchor` 也编 bbox（或让它调 client 那份口径） | 消掉"两个家"，模型在聊天里的链接也能带箭头 |
| **2** | **查 756 篇坐标为什么坏**（只查不改） | 13.7% 的条款永远画不出箭头，这是数据层问题 |
| **3** | 多条依据的箭头区分（红/半透明红） | 业主 2026-10-12 的新要求 |

⚠ **第 2 条我要先查清根因再动手** —— 它可能不只是"箭头画不出"，
而是入库时那条解析路径有系统性问题（同一份 PDF 的正文可能也受影响）。
