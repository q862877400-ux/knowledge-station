## 二、**最丑的 5 处**（按"业主一眼看到就皱眉"排序）

### #1 三页最抢眼的都是那条**橙色横幅**
- **现象**：`rowh-520.png` / `rowh-1300.png` / `5c-capabilities-900-after.png` 三页首位都是同一块橙底长句。量值：`.ks-kb-banner` **520 下 92px 高（496×92）**、**1300 下 56px 高**、**900 下 54px**；而 `.ks-page-title` 只有 **26px** —— **警告块是标题的 2.2–3.5 倍高**，也是全页**唯一的大色块**。
- **根因**：① 取色用了 `state-warn-tertiary` 整块铺底 + `state-warn-label` 文字（`ksGuideStyles.ts:87-89`），语义是"警告"而不是"临时告知"；② 位置在 `ks-page-rule` 之后、所有内容之前（`KsKnowledgePage.tsx:363`）；③ 内容是 4 行 12px 解释性长句（"……你可以直接点着体验。层级名取自 doc_catalog 的权威 CCS 表；将来这页接 GET /api/v1/documents/categories 即可，不必重画分类法。"）—— 把"实现细节"当成首屏正文。
- **改法**：`plugin/client/ksGuideStyles.ts:87-89` 把 `.ks-kb-banner` 降级为**一行灰字**：去掉 `background` 与 `border`、`padding: 0`、`color: var(--dsw-alias-label-tertiary)`；`KsKnowledgePage.tsx:363` 那段的文案缩到 ≤20 字（结论），细则挪进 `title=` 或帮助浮层。参照的等价物是 `config.png` 里那条**单行**带图标的黄条 —— 我们是它的 4 倍高。

### #2 字号层级被碾平：**卡标题 == 正文 == 13px**，描述与计数**同为 12px 同色**
- **现象（像素事实）**：`rowh-520.json` 量到全页只有三档字号 —— `.ks-page-title` **20px**、`#ks-shell`/`.ks-item`/`.ks-item-tags`/`.ks-kb-tn` 全 **13px**、`.ks-kb-banner`/`.ks-item-add` **12px**。代码里卡标题写死在 13px：`KsKnowledgePage.tsx:473`（`style={{fontSize:13}}`）、`:574`（同）、`KsCapabilityPage.tsx:253`（`var(--ks-fs-base)`=13px）。描述与"3 篇"**用的是同一个类**（`:474`/`:475` 都是 `.ks-kb-hint` = 12px tertiary）。⇒ **卡标题与正文差 0px，描述与计数差 0px**。
- **根因**：缺"卡标题"这一档 —— 受限字号表里有 `--ks-fs-md:14px` 和 `--ks-fs-lg:16px`（`ksGuideStyles.ts:49-50`），但列表卡一处都没用；同时 `--ks-card-h:136px`（`:64`）**定义了却从未被消费**（全仓唯一出现处就是定义本身）⇒ 卡片既没有高度约束、也没有标题档，于是"内容多高就多高、字一样大"。
- **改法**：① 新增 `.ks-kb-ct{font-size:var(--ks-fs-md);font-weight:600;letter-spacing:.01em}`（对照他们 15px/22px w600，`resource-card.less:87-101`），把 `KsKnowledgePage.tsx:473`/`:574`/`KsCapabilityPage.tsx:253` 三处的 13px 换掉；② `.ks-kb-hint` 加 2 行截断并改 `--dsw-alias-label-secondary`（`ksGuideStyles.ts:99`）；③ "N 篇 / N 个旋钮"改用已有的 `.ks-kb-badge`（11px、`:121`），并放进 `.ks-kb-foot`（0.5px 上分隔线）；④ **删掉死 token `--ks-card-h`**（`ksGuideStyles.ts:64`）或真的用上它 —— 不要留着"文档说 136、实际 85/115/212"的暗账。

### #3 窄宽下**左轨吃掉 42% 宽度，文件名被截断**

### #4 卡片是"**描边幽灵**"，同列里三档高度

## 六、施工回填（2026-09-20 第一批 P0 **改完之后**的更正；原话保留，不悄悄改）

这一节是**对上面结论的实测更正**，别把上面的旧说法当事实用（详细记录在 [UI-BASELINE 第六节 5e](../UI-BASELINE.md)）：

1. **§一 B / §二 #3 的"窄宽下左轨吃掉 42% 宽度、文件名被挤"不成立**。实测（`--width 520`）：
   `.ks-rail` = 12/**155**/208、`.ks-main` = 12/**1054**/496 ⇒ `.ks-split` 的 `flex-wrap` 把 main
   **换到了下一行并吃满整行 496**，文件名与左轨宽度**无关**。真正卡住它的是 `.ks-check` 的
   `max-width:40%`（× `.ks-item` 内容盒 480 = 192，与量到的 `nameW=192` 吻合）。

   按本文建议的 `clamp(140px,34%,208px)` 算下来 168.6+8+320 仍 > 496（还是换行），main 依旧是 496，
   文件名不受益，rail 里的树名（本就只有 152px）反被多截一档 —— **净亏**。
2. **§一 B 的"量值自相矛盾"是误读，工具没错**：`#rows[].tagsLeft` 是**相对行左缘**的偏移，
   `.ks-item-tags.x` 是**页面绝对坐标**；520 下 208+12=220 ✓、1300 下 234+228=462 ✓ **完全自洽**。
   ⇒ "先重新量再动列结构"这条纪律保留，但**不要再**把它当"工具不可信"的证据。
3. **§二 #1/#2/#4、§二 #5 已施工**（横幅降级/卡标题档/卡片 elevation/空态/补位卡/批量条危险色），

### 7.4 两种节奏 ⇒ 我们的目标密度值

### 8.3 **IA 决定（2026-09-20 5h）：业主选 B —— 不分页式浏览，改"卡片带 + 目录下钻"**

**这一条不是我们抄来的，是业主当天亲口定的形态**，登记在这里是因为它**同时是一条"我们与他们不同"的
分界线**（清单的方法论要求：抄之前先说清"哪一部分是我们自己的决定"）。

业主原话（**验收标准**）：

> 「搜索框：保留。**B 不分页**（知识库卡片尺寸统一不要展示目录树，我建的（真文件夹；与上面两棵平级）
> 这种乱七八糟东西删了，然后**所有卡片横在顶端**，**一个小框下面自带一个左右翻页滑动条**，
> **下面是文件目录**，**点一个卡片就出来知识库内容**，比如点法律法规，就按目录展示，
> **先占上一级目录文件夹，然后点开是二级目录，进入二级目录就自动出现返回上一级的按钮**）」

| 项 | WeKnora（真机参照） | 我们（业主 2026-09-20 定） | 关系 |
|---|---|---|---|
| 知识库列表的组织 | **分页**（列表页 + 翻页控件） | **B：不分页** —— 顶部**一条卡片带**（一屏 3 张、左右箭头平移、到头/到尾箭头置灰），下面直接是**该库的目录** | **我们与他们不同**：**他们分页，业主明确不分页** |
| 左轨目录树 | 有（左轨树 + 右列表） | **删掉**（业主"不要展示目录树"）⇒ 目录改成卡片带下面的**目录层**，逐级下钻 + 「返回上一级」 | 我们不抄这一块：业主点名否决 |
| 卡片尺寸 | knowledgebases 那张是 grid 卡 | **统一尺寸**（`.ks-kbband .ks-kb-cards` = `repeat(3,minmax(0,1fr))` + `min-height:136`）⇒ 同屏等宽等高 | 抄的是"卡在顶部"，**分组标签不抄**（"我建的（真文件夹…）"已删） |
| 文件表格 | 6 列真表格（`23-kb-detail-list-1440.png`） | 同一张真表格（P2 头条那套，列/图标/chip/搜索都保留）—— 只是现在**只在"最末一级"出现** | 这一块是**照抄结构**（见 §8.2），5h 没动它 |
| 搜索框 | 列表上方"搜索文档名称…" | **保留**（业主 2026-09-20 明确），位置仍在文件表格上方 | 一致 |

**我们与他们不同的三处（写清，别以后拿参照当依据反推）**：
1. **不分页**：他们的知识库列表是分页列表；我们是**一条可翻页的卡片带 + 目录下钻**（业主选的 B）。
2. **没有左侧目录树**：他们在左轨放树；我们**删了树**，目录进主区（逐级 + 返回上一级）。
3. **卡片带窗口是"状态式"**：`BAND_WINDOW=3` 常量 + 窗口下标（为了在任何环境里状态确定），
   **不是**量容器宽度的原生横向滚动 —— 代价写在 [UI-BASELINE 5h](../UI-BASELINE.md) 的"没做/做不到"。
