业主令：「你先把所有根因都查清楚，然后一次性修复，设置好目标自动进行」

## R1 单位错（**根因**，影响 756 篇 / 253,222 条条款 = 13.7%）

### 现象

生产库里 `source_span.bbox_json` 长这样（`GB 1094.1-2013` 第 1 页）：

```
[0.116, 3455.82, 0.937, 3455.86]
  ↑x 是 0~1            ↑y 是 3455（页高 3456）
```

**同一行里 x 是"比例"、y 是"页高减比例"。**

### 根因

`middle_schema._convert_40_to_34` 处理 MinerU **4.0** 产物时：

1. **原始 bbox 是归一化比例**（实测原始文件）：
   ```
   doc_title  bbox=[0.116, 0.138, 0.937, 0.176]
   text       bbox=[0.725, 0.206, 0.912, 0.222]
   ```
   **x 和 y 都是 0~1。**

2. **页尺寸另有其处**（同文件的 `extensions.docvortex_layout.pages`）：
   ```
   {"page_idx": 0, "width_pt": 2456.0, "height_pt": 3456.0}
   ```
   转换器**读了它**（存进 `page_size`），但**没拿它去缩放 bbox**。

3. **下游按"点"消费**（`pipeline` 的坐标契约 = PDF 底部原点，单位点），
   并做 `y' = H − y` 翻转。

### 实测证明（判据 7/7 命中）

对 `GB 1094.1-2013` 第 1 页：

| 判据 | 结果 |
|---|---|
| 库里的 x 值命中原始 x 集合（**x 未被缩放**） | **7/7** |
| 库里的 y 值命中 `{H − 原始y}`（**y 只做了翻转，没乘页高**） | **7/7** |

逐条对照：

```
实测 x=0.116,0.937  y=3455.82,3455.86
原始 x=0.116,0.937  y=0.138,0.176
预测 x=0.116,0.937  y=3455.86,3455.82   ← [x0, H−y0, x1, H−y1]
```

⇒ **库里的值 = `[x0, H − y0, x1, H − y1]`**，其中 `x0/y0` 是**归一化比例**。

### 影响面

- 全库 **756 篇文档 / 253,222 条条款（13.7%）**
- **全部是 `standard`**（没有法规）
- **全部是 `2026-10-07` 同一天入库**（MinerU 4.0 升级那批）

### 为什么以前没暴露

`middle_schema.py` 的模块头注写着：MinerU 4.0 换了顶层结构，
**3.4 是 `pdf_info`、4.0 是 `pages`**，且 4.0 的 `bbox` **改成归一化**——
但转换器只做了**结构映射**（`pages`→`pdf_info`、`blocks`→`para_blocks`），
**没做单位换算**。而 3.4 的 bbox 是绝对点 ⇒ 转换器把两种单位当成同一种。

## R3 两个 URL 构造者（**"改了但没生效"的直接原因**）

| 构造者 | 在哪 | 编 bbox？ | 谁在用 |
|---|---|---|---|
| `evidenceAnchor` | `plugin/src/index.js` | **❌ 不编**（注释：「bbox 参数暂不拼」） | **模型**（聊天里的链接） |
| `evidenceUrlOf` | `plugin/client/ksEvidence.ts` | ✅ 编（2026-10-10 补的） | 侧边栏「看原文」 |

**2026-10-10 只在客户端补了，宿主侧那个没改。**
而 `KsTurnTab.tsx` 的注释写着「`evidenceUrlOf` 是**唯一** URL 构造者」—— **这句话是错的**。

⇒ 这解释业主的观察「放到侧边栏以后就不行了」：
**侧边栏那条路修过，聊天输出那条路没修。**
