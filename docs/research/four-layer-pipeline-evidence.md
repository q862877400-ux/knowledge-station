# 四层检索链路：别人怎么做 / 我们缺什么（对账单）

> **性质**：调研产物（一手来源，逐条给 URL 与日期）。**未改任何产品代码、未写库**（真库全程只读）。
> **用途**：业主问「大项目这几层是怎么弄的」。本文把四层逐层对齐，并标出我们每一层的现状。
> **一句话总览**：①②③ 层别人都有成熟做法、可以抄；**④ 层（答案 + 引用）全世界都没做好**——公开实测最好也只有 **40.8% 完全支持**。

---

## 层的划分（**本节是唯一口径；以前文档里的叫法一律按 §附 的对照表折算**）

**先说一个已经发生的错误**：2026-09-24/25 这段调研里，我用"层"指过**四件不同的事**
（最早的三层粗分、八份设计各自的 L0–L8、本文的四步、以及第 3 步内部的"第一层"），
业主当场指出「你这个一会儿第几层，说法很奇怪」。**故在此把编号钉死。**

```
第 1 步  看懂        判断"这句话是不是个合规问题"（含用户自己没意识到的隐性风险）
第 2 步  翻译        把用户的大白话翻成库里的说法
第 3 步  找          内部再分四个小步：
            3.1 捞候选    用几条不同的路子，同时从全库各捞一把
            3.2 合并      几路捞来的按名次合起来、去重
            3.3 再挑一遍   在剩下一两百条里精挑（最贵，所以只在小范围做）
            3.4 定稿      最后留几条
第 4 步  答+引用      组织答案，并把每一句锚回原文的精确位置
```

**用词纪律**：
- **"步"= 上面这 4 步**（含 3.1–3.4 叫"小步"）；
- **"路"= 只在 3.1 里**——即现在的 6 条找法（按字 / 按意思 / 按条款号 / 按语气词 / 按义务主体 / 按行为客体），
  **实际只跑 4 条**（后两条在生产里从不被调用）。**"路"不是层。**
- **不要再单独说"第一层"**；要说"3.1"或"第 1 步"，避免歧义。

### 附：旧说法 → 新编号 对照（避免旧消息读不通）

| 旧说法 | 实际指 | 处置 |

| 「五件套」 | 已删除的五个产品功能（NOT-DOING #16） | **与检索链路无关** |

## ① 看懂层

| 别人怎么做 | 证据 |
|---|---|
| 输入侧判定是**标准做法** | 微软输入防护官方文档原话："**在内容生成之前**分析用户输入"；误报可从"拦"降级成"**只标注**" |
| 这类小模型**可以不花钱** | OpenAI 审核接口官方写明**免费** |
| 但公开上限很低，只能当"提示器" | ProactiveBench（ICLR 2025）最强模型主动提示 **F1 66.47%**（约 1/3 判错）；医疗症状自查：诊断对第一位 **34%**、分诊建议对 **58%** |
| 合规/EHS 商业产品**没人做这件事** | Benchmark Gensuite / VelocityEHS / 赛为安全：**没有一家做"从口语主动识别受规管事项"**，也**没有一家公布误报率或召回率** |
| 必须给"这次不用看"的出口 | GitHub 密钥拦截永远配一个"我知道，仍要继续"；2023 年必应因拒答太多被骂，ChatGPT 因从不拒答被骂 |

**我们的现状**：**有**。词表 + 外部判断服务（实测你自己的例子：**词表 1/8、判断服务 8/8**）。

## ② 翻译层（把大白话翻成库里的说法）

| 谁 | 怎么做 | 数字 |
|---|---|---|
| **必应** | 改写后的查询是接口**一等字段**，官方原话"**用它替代用户原来的查询**" | — |
| **京东** | **2020 年夏起生产上线、服务数亿用户**；用点击日志训练；2023-12 上大模型改写版 | 只有"显著提升"，无绝对值 |
| **亚马逊** | 专门训练改写器 | 商品覆盖 **+28.6%**（离线） |
| **谷歌** | 拼写纠正 + **同义词系统** | 改善"**超过 30% 的搜索**" |
| **Elasticsearch** | 同义词/行话做成**产品功能**，检索时生效（改词表不用重建索引） | — |
| 学界 query2doc | 先生成一段"可能的答案"再搜 | 字面检索 **+3%~15%** |

**这层为什么必须做（硬数据）**：**同一段金标原文，只把措辞换成大白话，字面检索前 5 名命中率 100% → 44%**；加一层"大白话↔行话"**对照表**后 **44% → 80%**（**还剩 20% 接不住**）。

**三条纪律（有实测支撑）**：
1. **只在真对不上时才改**——无条件改写让 **25.6%** 的查询变差（只有 20.9% 受益）；
2. **不许把已匹配上的专业词换掉**——纯大模型改写某数据集 **−9%**，因为 **95% 的改写只是换词**；
3. **必须能一键关掉**——"选择性改写"实测**打不过"从不改写"**，所以它是增益项不是主路。

**我们的现状**：**完全没有**。[understanding.py](../../src/core/query/understanding.py) 一共 11 个函数，
**全是写死的规则，没有一处调用模型**——即"把大白话翻成库里说法"这件事**今天没有任何代码在做**。

**我在本库上的实测**（业主的例子「自动点击同意用户协议」）：

| 查法 | 结果 |
|---|---|
| 原话字面查 | '自动' 6,522 条、'同意' 705、'点击' 65、'用户 协议' 39 —— **没有任何一条同时含其中两个词** |
| 换成库里说法「个人信息+同意+自愿」 | **1 条** |
| 「个人信息+同意+明确」 | **13 条**（含 GB/T 25069-2022 的「明示同意/默许同意/授权同意」术语条目） |
| 「个人信息+同意+知情」 | 2 条 |

⇒ **差的就是这一层词**。（探针 `var/tmp/probe-user-example.py`）

## ③ 找层：大项目的每层配额

| 系统 | 第一层用什么 | **逐层留多少条** |
|---|---|---|
| **Vespa** [官方](https://learn.vespa.ai/reranking-ltr/multiphase-ranking/) | BM25 | 预砍 **10000** → 每节点保留 **10000** → 二阶段重排 **100** → 全局 **100**（跨编码器示例 **25**） |
| **Elasticsearch** [官方](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion) | BM25 + 向量并行 | 两路**各 50** → 合并 → **出 10** |
| **Azure AI Search** [官方](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview) | 全文 + 向量并行 | 两路**各 50** → 合并 → 可选重排 → **出 10** |
| **淘宝** [KDD 2021](https://ar5iv.labs.arxiv.org/html/2106.09297) | 字表 | **十亿** → 几千 → 粗排 → 精排 → 重排 → **几十** |
| **Facebook** [KDD 2020](https://ar5iv.labs.arxiv.org/html/2006.11632) | 字表 + 向量 | 检索层对**数十亿~数万亿**；**排序层每次只碰几百** |
| **谷歌** [Wide&Deep](https://ar5iv.labs.arxiv.org/html/1606.07792) | 检索 → 排序 | 排序预算 **10 毫秒量级** |

**三条规律**：
1. **第一层永远最便宜**——Vespa 官方明文"**这里不能放神经网络模型**"、"**让文本搜索在第一层挑大梁**"；
2. **缩量比例百万分之一**（十亿 → 几千 → 几十）；
3. **每层都有明确上限**，甚至写成官方默认值。

**我们的现状**：**缺这一条**。实测：**有两条路不设上限**——一句带"应"的话会把**全库 27%（140,555 条）**一次拉进内存；
按条款号 `1` 能拉 **6,379 条**。

**另一处缺口（2026-09-24 实测，跨语种）**：3.1 的"按字找"这一路在**非中文资料**上，
同一个词的另一种写法 **100% 匹配不上**（英文开发文档语料实测 **0 / 291**）——
根因是检索表的分词器不做词形还原，而中文没有词形变化，所以这个洞在中文库上**永远不会自己暴露**。
三种改法的对照数字与取舍见 [非中文资料上的检索口径证据](cross-language-retrieval-evidence.md)。

## ④ 答 + 引用层（**全世界都没做好**）

### 三种做法

| 做法 | 实测 |
|---|---|
| 先生成、再挂引用 | **最差**：引用召回只有"生成时给原文"的 **1/3**（ASQA 26.7 vs 73.6） |
| **生成时给原文、要求逐句标**（主流） | 好得多，但**数据集一换掉一半**（ASQA 73.6 → QAMPARI 20.5）；Anthropic 把它做成 API，返回字符/页/块三种定位，官方说"**保证指针有效**"——⚠ **只保证位置有效，不保证这句话真被那段支持** |
| **生成后逐句校验** | TREC 2024 规模化实测见下——**而且"校验"这一步本身不靠谱** |

### 公开实测的引用质量

| 来源 | 数字 |
|---|---|
| **ALCE** 摘要原话 | **"即使最好的模型，也有 50% 的时候引用支持不完整"** |
| **TREC 2024 人工判 6,742 条**（句子↔引用段） | **完全支持 40.8% / 部分 24.5% / 不支持 34.7%** |
| 人工判官 vs GPT-4o 一致率 | **只有 56%** |
| TREC 各系统加权精度 | 最好 **0.868**、最差 **0.157**（中位约 0.63） |
| **Tow Center：8 个生成式搜索工具、1600 次查询** | 集体 **>60% 答错**；Perplexity 错 37%、Grok 3 错 94%；**ChatGPT 从不拒答** |

### 产品落到哪一级

Perplexity / 必应 / 谷歌 grounding = **只到页**（谷歌给的偏移还是"答案文本里"的，不是原文里的）；
**Glean 是唯一写清楚的**：跳到"**确切段落**"、显示页码、可跳某页幻灯片。

**中国法律产品的天花板（一手核到，2026-09-25）**：

| 产品 | 溯源粒度 | 校验声明 | 公开准确率 |
|---|---|---|---|
| **威科先行（小威 AI+）** | **法规名 + 修正年份 + 条号 + 逐条效力标签**（例："参见：《劳动合同法（2012修正）》第二十三条 `现行有效`"）。**没有款级、没有页码** | 无 | 无 |
| **北大法宝** | 效力状态是**法规级，不是条级**；条级锚点形式 `#tiao_N`、款级 `#tiao_1077_kuan_1`；⚠ **`#tiao_1077.0` 这种带 `.0` 的是坏的**（点开只停在页首） | 无 | 无 |
| **Westlaw Deep Research** | 引用→**链接到全文 + 摘要 + snippet**，另有 Sources 页 | **官方帮助一句都没说"每处引用都校验"** | 无 |
| **CoCounsel 2.0** | 行内超链接引用 + 编号 | **答案尾部强制免责**："结果未使用 Thomson Reuters 的资源，**请始终自行核对引用**" | 无 |
| **Lexis+（Protégé）** | 行内链接 + Shepard's 旗标 | 官方原话划界：**"我们的承诺不是完美，而是所有结果都带法律引用链接"**；并给出反向信号——**"出现没有链接的引用，就说明我们无法校验它"** | 无 |

### 公开实测（**全部是学术机构做的，没有一个是厂商自测**）

| 来源 | 数字 |
|---|---|
| **Stanford HALT**（arXiv:2405.20362；期刊版 22 J. Empirical Legal Stud. 216, 2025-06） | LexisNexis 与 Thomson Reuters 的 AI 研究工具**各自幻觉率 >17%**；厂商"无幻觉/避免幻觉"的宣称被判为 **overstated** |
| **CS&Law '26 Benchmarking Legal RAG**（arXiv:2603.03300，1,647 题） | **Westlaw AI 准确率 58%、Lexis+ AI 64%（召回仅 0.29）**——**均差于标准 RAG 基线**；并记录 Westlaw AI 有 **300 字符输入上限**、Lexis+ AI 为 5,000 字符 |
| **CLaw**（EMNLP 2025 Findings，款级 64,849 条 + 历史修订时点） | "**多数当代 LLM 显著难以忠实复现法条原文**" |
| **LegalCiteTrust**（arXiv:2607.20872，2026-07-23，专测中文长文法律报告） | 把条级引用拆成 **存在性 / 保真度 / 适用性** 三个维度；结论："检索工具能提升证据支撑，却**不能可靠提升 Trust 分**" |

**条号迁移是高频错源（有实例）**：某现行有效的司法解释第 536 条，其转述的上位法条号因民诉法 2023 年修正已从**第 276 条变成第 286 条**。

### 答不出来怎么办

- GPT-4o 在 SimpleQA 上：答对 38.2%、答错 **60.8%**、**明说不知道只有 1.0%**；
- AbstentionBench（NeurIPS 2025）：**推理微调让"弃权"能力平均下降 24%**；
- **"多少拒答率可接受"全世界没有阈值**；两头都有人挨骂（必应拒答太多 / ChatGPT 从不拒答）。

### 成本

- "生成 4 遍挑最好" = **生成成本 ×4**，换来 ASQA 73.6→84.8、ELI5 51.1→69.3，**QAMPARI 几乎零收益**；
- **逐句校验的成本与延迟：没有任何一手数字**（TREC 论文只说"预算内穷举不可行，所以只判每句第一个引用段"）。

### 精确位置

- **标准早在 2017 年就有**：W3C Web Annotation 三种文本定位器（原话+前后文 / 字符偏移 / 范围）——就是为"原文会变"设计的；
- 真做到的：**Anthropic**（字符+页+块）、**Glean**（确切段落）；
- **唯一的公开失败率**：Hypothes.is 两万多条网页高亮，**22% 挂不回原网页**，其中 **88% 彻底成孤儿**；仍挂着的 **53% 处于"一改就掉"风险**（⚠ 网页、2015 年数据，不能直接外推到 PDF）。

**我们的现状**：

| 项 | 我们 | 大项目 |
|---|---|---|
| 依据能点开 | ❌ **实测：`evidence_url` 端口是 1，点不开** | Glean 能到确切段落 |
| 核验不过怎么办 | ❌ **仍给结论**（只标低置信） | 也没有一家做逐句校验 |
| 引用准确率 | ❌ 没有量过（判据只比条款号，**90 条里 72 条判错了也发现不了**） | ❌ 也没有一家公布 |

## 汇总：四层 × 别人做法 × 我们现状

| 层 | 别人做法（可抄） | 我们 | 结论 |
|---|---|---|---|
| ① 看懂 | 输入侧轻量分类器，**只提示不拦截**，这类小模型免费 | **有**（词表 + 外部判断） | 保持；把"只提示"写死 |
| ② 翻译 | 学习式改写 + **词表约束** + 只在必要时触发 + 可回退 | **完全没有** | **必须自建**（最实用的是一个可审计的词表对照） |
| ③ 找 | 第一层最便宜；**每层都有明确上限**；贵模型只跑最后几十条 | 缺上限（两条路能拉走全库 27%） | **改配置 + 换索引**，不是重构 |
| ④ 答+引用 | 生成时约束（主流）+ 逐句校验（**但校验本身不可靠**） | 链接点不开、核验不过仍给结论、引用质量没量过 | **全世界都没做好** → 这里有真差异化的机会，**但必须先量** |

## 战略含义（这一条最要紧）

**①②③ 层我们只是"落后"，抄就是了；④ 层是"没人做到"**——公开最高只有 **40.8% 完全支持**，
而且**校验这一步本身只有 56% 的一致性**。

⇒ 业主那条"**每条结论必须点回原文**"的红线，**在行业里没有可对标物**：
- **它可能是真正的差异化**（别人做不到）；
- **但它也可能是空话**——因为我们今天既点不开链接，也没量过引用质量。

**要让它成立，只有一条路：把它量出来**（三元匹配判据 + 未判定比例 + 负例集 + 抽样审计）。
这不花模型钱，而且做完之后，"我们比大项目好"这句话**才有数字支撑**。

### 第 ④ 层要做的三件最基本的事（按可抄的对象排）

1. **依据链接真的能点开**——⚠ **Lexis 把承诺划在"每条引用都有链接"**（官方原话："我们的承诺不是完美，而是所有结果都带法律引用链接"），
   **而我们连这一条都没做到**（实测 `evidence_url` 端口是 1）。抄它那条反向信号：**"没有链接 = 我们校验不了"，要明说**。
2. **核验不过就别给结论**（现在是给了再标低置信）。
3. **把引用质量量出来**——判据抄 **LegalCiteTrust 的三维度**：**存在性 / 保真度 / 适用性**，
   而不是现在这个"只比条款号"（90 条里 72 条判错了也发现不了）。

### 三个可抄的现成件（第 ④ 层/法规侧）

| 件 | 许可 | 抄什么 |
|---|---|---|
| `chinese-law-corpus` | **CC0** | 412 部法律逐条 JSON，**有"条级稳定 ID"**（如 `civil-code-0577` = 民法典第 577 条）。⚠ **没有条级可引用 URL** ⇒ "可点链接"那层仍要自己做 |
| `chinese-law-mcp` | **Apache-2.0** | 8 个工具里有两个正对我们缺的：**`validate_citation`（零幻觉核对）**、**`check_currency`（是否仍有效/已修改/已废止）** |

### 行业的一个硬事实（对我们有利也有压力）

**中国法律产品溯源的天花板 = 法规名 + 修正年份 + 条号 + 逐条效力标签，没有款级、没有页码。**
而我们要的是"**跳到那一页 + 红色定位箭头指到那一行**"——**这在行业里比最强的那家还细**。
压力在于：**行业最强的两家（Lexis/Westlaw）在公开实测里准确率只有 58%–64%，且都差于标准 RAG 基线**，
所以"接一个大厂产品进来"并不会自动更好。
