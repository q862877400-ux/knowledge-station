# WeKnora（腾讯开源知识库）对我们的影响评估

## 一、它是什么（一手事实，逐条摘自官方文档）

- 腾讯开源的**知识库问答系统**：Go 后端（Gin）+ Vue 3 前端 + Python 解析服务 `docreader`（gRPC）；
  Postgres(ParadeDB)/Redis，可选 qdrant / milvus / weaviate / doris / neo4j / minio / searxng。
- **解析**：PDF 版式分析、扫描件 OCR、Office 转换、网页抓取、图片 VLM 描述、音频 ASR，
  可选接 MinerU / OpenDataLoader / Docling。
- **检索**：向量 + BM25 混合 → RRF 融合 → Rerank；可选知识图谱（GraphRAG）、Wiki 导航、
  query 改写、意图识别。
- **问答/Agent**：SSE 流式、多轮上下文压缩、**引用溯源（点引用看原文）**、ReAct Agent、
  MCP 工具、Skills 沙箱（Docker/Cube/E2B）、Web 搜索。
- **平台面**：多租户 + RBAC（Owner/Admin/Contributor/Viewer）、OIDC、API Key（能力细分
  `retrieve`/`chat`/`ingest`/`manage_kbs`）、**审计日志（默认 90 天）**、Langfuse 全链路追踪。
- **交付形态**：Docker Compose / Helm / Lite 单二进制 / 桌面应用；CLI、Go SDK、
  微信小程序、Chrome 插件、**独立 MCP Server**、网页嵌入、IM 集成。
- ⚠ **它已经有 DSH 插件**（`packages/dsh-weknora`，`dsh plugin --profile web add @wxg-prc-cpg/dsh-weknora`），
  四个工具：`weknora_list_knowledge_bases` / `weknora_search` / `weknora_read_document` / `weknora_ask`；
  配置写在 `$DSH_HOME/profiles/<name>/cordis.patch.yml`。已验证组合：dsh 0.1.0-rc.8 / WeKnora 0.8.0。

## 二、它**确实替代**了我们什么（必须承认的部分）

**"把文档变成一个带引用的可问答知识库"这件事，已经商品化了。**

- 通用解析广度（版式/OCR/VLM/ASR/表格）：比我们宽；
- ~~通用检索（混合 + RRF + rerank + GraphRAG）：与我们同级甚至更全~~ ⇒ **说轻了**：见「更正 3」，
  它的检索/入库工程**明显比我们深**（不是"同级"）；
- 工程成熟度：异步任务、多租户、RBAC、OIDC、可观测性、多部署形态、多客户端、生态——
  **这一面我们不可能追上**，也不该追；
- 免费 + MIT + 腾讯背书：在"功能清单对比"里我们必输。

**结论**：如果产品的卖点是"一个更好的知识库"，那我们已经被替代；
继续往通用 RAG 层投入是**往商品化的方向投入**。

## 二·补（读完架构页之后的更正块）

**更正 1（初版说错，对我们不利）：它的引用**不是**只有"知识 ID + 分块序号"。**
入库文档明写：文本块携带 `StartAt/EndAt`（**原文 rune 偏移，可用于还原/高亮**）；
RAG 文档明写"**源坐标只保留给引用定位使用**"。所以**源坐标是为引用定位保留的**——
我初版那句"没看到页码/坐标/条款级定位"是**错的**（它保留了坐标）。
仍未验证：UI 是否做到"点引用 → 跳 PDF 页 + 高亮到那一行"（我们的具体体验），以及**条款语义**（它不是按条款切的）。

**更正 2（初版说错，对我们不利）：单机/离线不是我们的不对称优势。**
它有 **Lite 模式**：`DB_DRIVER=sqlite`（内置 sqlite-vec）+ 不配 `REDIS_ADDR`（Asynq 退化为
进程内 `SyncTaskExecutor`）+ 前端静态资源内嵌 ⇒ **单二进制**；另有 **Wails v2 桌面版**、
Helm、裸机 systemd、Homebrew。**离线单机它也有**，而且比我们多三种交付形态。

**更正 3（初版说轻了，对我们不利）：通用检索不是"同级"，是它明显更深。**
它的 RAG 是一条**事件驱动插件管线**（`Plugin` 接口 + 责任链 + 按请求动态组装 EventType），
本次读到的工程细节包括（都不是"我也能做"，而是"他们已经在生产里跑"）：
加权 RRF、复合打分（0.6 模型分 + 0.3 检索基础分 + 0.1 来源权重）、阈值降级重试、
**MMR 多样性选择**、父子块解析、短上下文邻居扩展、FAQ 迭代检索 + **负例问题过滤**、
无 LLM 的查询扩展（jieba 分词）、**引用别名注册表**（把内部 ID 换成 `cN/wN` 别名，
让模型吐出的 `ref` 可安全展开、未知别名 fail-closed —— 这是**防模型篡改 ID** 的设计）、
资源句柄别名（`res://`）、断线续传的 StreamManager + 独立 stop watcher、Langfuse 逐 span 追踪。
**入库侧**同样：Asynq 五队列 + 每 attempt 的 span 进度树、**5 分钟一轮的 housekeeping 自愈**
（心跳 + 队列检查判卡死）、原子子任务计数 + 短缺协调 + `context.WithoutCancel` 兜底、
摘要刷新的快照复核（防旧摘要覆盖新摘要）、删除链路的顺序设计、SSRF 三重防线、
解析引擎注册表（MinerU / PaddleOCR-VL / anydoc(Rust, cgo) / MarkItDown / OpenDataLoader）、
图片多模态**每图一个任务**并生成 image_caption/image_ocr 子块。
⇒ **这部分我们不可能追上，而且它正是"看起来简单、做起来是无底洞"的那一层。**

**同时更正一条对"站在它上面"有利的事实**：它的**可复用性是被设计出来的**——
`RetrieveEngine` 注册表（10 种实现，**含 sqlite**）、`EngineFactory` 从 `vector_stores` 表
运行时装配引擎、解析引擎注册表带可用性探针、REST API + 独立 MCP Server + 扩展点指南。
它的 Lite 模式用的就是 **sqlite + sqlite-vec**（和我们同一套栈）⇒
"用它的解析/检索 + 保留我们的领域层"在工程上比我初版估计的更可行。

## 三、它**没有覆盖**我们什么（它的文档里不存在这些概念）

逐项在它的"功能清单 / 核心概念 / API 参考"里找过，**没有**找到任何对应物：

| 我们的东西 | WeKnora 文档里的对应物 |
|---|---|
| **标准/法规现行性、废止、被替代、施行日期** | **无**（它的概念里没有"版本效力"这一维） |
| **每日巡检官方渠道 + 渠道台账（131 条：链接/有效性/上次成功/失败原因）** | **无**；它的数据源是上传/飞书/Notion/语雀/RSS——**不接**"标准号→状态"的权威查询 |
| **五类（发布/修订/废止/现行性/编号核验）** | **无** |
| **条款级坐标引用**（标准号-条款号 → 侧栏 PDF 跳页 + 红色箭头指向原文 bbox） | **部分被覆盖**：文本块带 `StartAt/EndAt`（原文 rune 偏移，明写"可用于还原/高亮"），且"源坐标只保留给引用定位使用" ⇒ **它有坐标**；但**没有条款语义**（不是按 GB 的 5.2.3 切块），也没有"引到 PDF 页 + 箭头"的体验证据（见更正 1） |
| **只引现行版 / 答案排序红线（现行性>效力层级>匹配度）** | 无（这是领域规则，不是 RAG 能力） |
| **外发 payload 逐次留痕可导出**（合规语义的"外发可审计"） | 有**操作审计日志（90 天）**与 Langfuse 追踪——语义不同：那是"谁做了什么"，不是"发给模型的原文片段是什么" |
| **材料评审硬门 + 权威两轴（T0–T4 × 任务内效力）**"未核验不得承重" | 无（它有 RBAC——那是"谁能看"，不是"能不能当依据"） |
| **合规落地件**：义务清单/检查表/合同审查/制度差距分析 | 无 |
| **标准主数据**（6417 个号 + 效力/代替链/废止日期） | 无（它不持有标准主数据） |

**最重要的一条**：我们当前长周期目标（**渠道覆盖 + 渠道台账 + 五类监控 + 现行版正确性**）
**恰好落在它完全不碰的那一格**。它的到来，反过来验证了这个方向是对的。

## 四、风险（不粉饰）

1. **生态位重叠**：它有官方 DSH 插件，和我们抢同一个宿主位置。用户完全可以"装它 + 再用我们的侧栏"。
   ⇒ 我们的插件不能再靠"我也是个知识库"取胜，只能靠**它没有的领域工具**（时效/效力/取证）。
2. **对比清单劣势**：任何按"功能多少/免费/背书"打分的评估，我们输。
3. **"够用"风险**：如果业主要解决的其实是"把一堆资料变可问答"，WeKnora 已经够用，
   我们的额外投入就是**为不需要的能力付费**。

## 五、建议（按优先级）

0. **业主裁定（2026-09-19）：通用层「纯借鉴」，不造轮子。** 原话要点：
   「通用层不要再投，**如果说的是造轮子那我赞成**；但**如果有现成项目和思路、抄一下就能实现很好的效果，
   那我觉得还是可以投**；如果是纯自己研发自己手搓那就算了。**通用层现在要纯借鉴**。」
   ⇒ 判据从"做不做通用层"改成**"是不是在造轮子"**：
   - **有现成实现/现成思路 ⇒ 读它、抄它**（布局/交互/数据结构/算法思路皆可），这是**鼓励**的投入；
   - **没有现成可抄、只能自己从零设计并长期维护 ⇒ 不做**（够用即止），把钱与时间留给三个护城河；
   - **本项目内已有自研的通用件**：不再扩写，能换成现成实现时优先换。
   ⚠ **许可证义务（已核）**：WeKnora 是 **MIT**（`LICENSE`：Copyright (C) 2025 Tencent，
   "Permission is hereby granted … to use, copy, modify, merge, publish, distribute, sublicense,
   and/or sell"），条件是**随附版权与许可声明**；其**第三方组件**另有条款
   （`THIRD_PARTY_NOTICES.md` + `licenses/`）⇒ 抄它的**自有代码/样式**时：① 在我们仓库留一份出处与
   许可说明；② 不整段搬运第三方组件；③ 抄进我们的 React 侧栏必然是**照结构/视觉重写**
   （它是 Vue + TDesign），重写不改变"要署名"这件事，文档里逐处记出处。
1. **停止投资通用层**：解析、向量检索、多模态、Agent/MCP、多租户、Wiki、GraphRAG ——
   要么不碰，要么"够用即止"。近几轮已经在往这个方向走（R6c 五类、渠道台账、废止日期准确性），继续保持。
   （⚠ 与第 0 条合读：这里的"停止投资"= **不再自己设计**，不等于"不能用别人的"。）
2. **把火力压到三个"别处买不到"**：
   (a) **标准/法规时效与效力数据平面**（巡检 + 渠道台账 + 五类 + 现行版正确性）；
   (b) **取证坐标链**（条款级 + 跳 PDF 对应页 + **红色定位箭头**指向原文 + 三段式 + 数值/模态/法理核验）；⚠ 呈现是**箭头**，`bbox` 只是定位坐标 —— 曾误称"bbox 高亮"，业主早已否决高亮框（见 [已否决台账](NOT-DOING.md) 第 2 条）
   (c) **合规落地件**（义务清单/检查表/合同审查/差距分析 + 材料评审硬门 + 权威两轴）。
3. **认真评估"站在 WeKnora 上"**：它 MIT、有 REST API、有 MCP Server、有 DSH 插件，
   而且**可复用性是设计出来的**（`RetrieveEngine` 注册表含 sqlite、`EngineFactory` 运行时装引擎、
   解析引擎注册表、扩展点指南），Lite 模式用的就是 **sqlite + sqlite-vec**（与我们同一套栈）。
   可选路线：用它做通用解析/检索/部署/多租户，我们只保留**标准主数据 + 巡检渠道体系 +
   引用坐标契约 + 合规规则**，把"我们的引擎"缩小成"领域层 + 适配器"。
   —— 代价是承认通用层自研的沉没成本；收益不只是省维护面：**读完架构页能看到那一层的真实成本**
   （housekeeping 自愈、span 进度树、断线续传、死信队列、摘要快照复核、SSRF 三重防线…），
   这些"生产脚手架"我们要自己维护**一辈子**，而它们跟合规专业度**毫无关系**。
   ⚠ 一个必须动手验证的点：**两条定位坐标系不同**——它的 chunk 是 rune 偏移，
   我们是 `clause_revision_id` + PDF bbox。要"用它的检索 + 保我们的举证"，必须先把这两者映射起来。
4. **把优势量化成可验证指标**（功能列表讲不出差异，指标可以）：
   引用准确率（条款号对不对）、**版本正确率**（有没有引用已废止版）、
   **巡检覆盖与发现时延**（标准废止后多少天内被告知）、**举证成功率**（结论能否一键定位到原文）。
   这四个指标 WeKnora 一个都不提供 —— 这才是"没有被替代"的可证明形式。
