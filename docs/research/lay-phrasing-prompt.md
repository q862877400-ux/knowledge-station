# 「大白话 ↔ 行话」生成提示词（A 组：给术语写外行说法）

> **性质**：工作用提示词，版本化留存。配合 [pick-domain-terms.py](../../scripts/pick-domain-terms.py) 出的术语清单使用。
> 本轮结果见 [lay-phrasing-retrieval-test.md](lay-phrasing-retrieval-test.md)（50 术语 × 100 条）。
> **v2 的每一条改动都有实测理由**，不是审美。

## 一、v1 实测暴露的三个毛病（v2 就是为修它们）

| # | 毛病 | 证据 |
|---|---|---|
| 1 | **有几条变成了"给概念下定义"，不是"用户会问的话"** | `光伏发电单元` → "由十几块晒阳板和一个箱式变压装置拼成的一个独立供电小方阵"；`地名专名` → "路牌上扣掉省、市、路这些大尾巴，前面独有的那个称呼"。这类句子**天然与原文共享词汇** ⇒ 测"词汇差距"时会**假好**。根因是我 v1 的规矩 2（要"从现象描述"）与规矩 6（"不要解释术语"）**互相打架**。 |
| 2 | **"写不出来就少写"被理解成"总是给 2 条"** | 50 个术语**全部**给了 2 条，一条空都没有。于是"哪些术语根本没有外行入口"这个信息**拿不到**，只能事后猜。 |
| 3 | 没法按人群切片 | v1 只说"覆盖不同人群"，但**没有字段记录是哪类人**，事后无法分析"哪类人的说法离原文最远"。 |

## 二、v2 的改动与理由

| 改动 | 理由 |
|---|---|
| 2 条 → **4 条** | 每个术语只 2 条时，"这个术语有没有外行入口"的判断噪声太大；4 条才能看出稳定与否 |
| **必须是第一人称问句**（`…吗` / `…多少` / `…怎么办` / `…合不合规`） | 修毛病 1：问句形状天然排除"下定义" |
| **明确禁止下定义**（不许写"这是……" / "指……" / "用来……的东西"） | 同上 |
| 新增 `register` 字段（消费者 / 一线工人 / 小老板 / 家长 / 新人） | 修毛病 3 |
| 新增 `"lay":[]` + `why_empty` | 修毛病 2：把"确实没有外行入口"变成一个**可统计的输出**，而不是让我事后猜 |
| 每条 **≤30 字** | 防长定义句 |
| 不许出现**英文** | 库里的术语条目是**中英双语**的（「粗氩塔 crude argon column」）⇒ 英文名一旦出现等于抄原文。上一轮没发生，但要把口子堵上 |
| 不许出现术语的**简称/缩写** | 同上，简称也是原文里的词 |

## 三、v2 全文（整段复制，末尾接术语清单）

```
你是产品调研员。下面是一批专业术语（每行一个）。请针对每一个术语，写出"完全不懂这个领域的外行会怎么表达同一件事"。

【最重要的一条】写出来必须是**第一人称的问句**——就像一个人真的张嘴在问。
不许下定义、不许写"这是……""指……""用来……的东西"。判断标准：把这句话拿去问一个陌生路人，他听得懂、并且知道你在问什么。

硬规矩（违反就作废）：
1. 不许出现该术语本身；不许出现它连续两个及以上的字；不许出现它的简称或缩写；不许出现英文。
2. 每条不超过 30 个字。
3. 必须从**目的、场景或现象**出发。例：
   术语「动火作业」→ 可以写「在厂里焊东西要先办什么手续吗」
   不可以写「动火作业需要审批吗」（用了原词）
   不可以写「指在禁火区内可能产生火焰的非常规作业」（这是在解释术语）
4. 每个术语写 4 条，并标出说这话的人是谁（consumer / worker / owner / parent / newcomer 五选一）：
   - 至少 1 条**只描述一个具体场景**，不提任何专业词；
   - 至少 1 条带**具体数字或具体物件**（几度电、几厘米、哪个零件）；
   - 至少 1 条问**要不要办手续 / 合不合规 / 会不会被罚**。
5. **如果确实想不出任何外行会这么问的说法**（外行一辈子不会问这件事），
   就把 lay 写成空数组 []，并在 why_empty 里用一句话说明为什么。
   **这不算失败，是有用的信息**；但**不许用它偷懒**——只有真的想不出才留空。
6. 不要解释术语是什么意思，不要给答案。

输出格式：每行一个 JSON 对象，不要任何别的文字，不要 Markdown 代码块标记：
{"term":"<原术语>","lay":[{"text":"说法","register":"consumer"},...],"why_empty":"（只有 lay 为空时才有）"}

输入术语：
```

## 四、配套的批量规模（业主 2026-09-24："测试用例可以再多一点"）

* **术语 300 个**（`terms-300.txt`，由 `pick-domain-terms.py 300` 出，覆盖 17 个 CCS 大类）；
* **每个 4 条** ⇒ 约 **1,200 条**说法。

**为什么是 300 / 4 —— 以及一个必须说清的限制：**

* 上一轮的关键比例是「**大白话与原文一个 2 字重合都没有的术语占多少**」（50 条时是 29/50 = 58%）。
  这个比例在 n=50 时的误差约 **±14 个百分点**，太粗；**n=300 时约 ±6 个百分点**，可用了。
* ⚠ **但路线之间的差别（上一轮"按字找 2% vs 向量 4%"）靠加用例解决不了**：
  那只有 1 条与 2 条命中，要分开这种量级需要**几千条**。所以这一轮的目标**不是**把 2% 和 4% 分开，
  而是 ① 把"没有外行入口的术语占多少"测准；② 从 1,200 条里**找出成类的规律**
  （哪一类说法能搜到、哪一类一定搜不到）——这是数量能买到的、也是我们真正需要的东西。

## 五、已知边界（别把生成结果当真人分布）

* 这是**会答题的模型想象不懂的人怎么问**，通常比真人问得更完整、更有针对性
  ⇒ 它**能**回答"我们漏了哪些说法"（覆盖度），**不能**用来宣布"准确率是 X%"。
* 生成完我仍会做一遍**机械过滤**（算每条说法与原文的字面重合，超阈值的丢掉），
  防止模型偷抄原文的词把效果撑高。
