## 一、结论（三句话）

1. **计划里 P3.2 的那两个判据，只有后半截能定案。**「中文单字占比」是**机制代理量**：
   字级口径把它推到 **81.3%**（最高）却拿了第二好的命中率，领域词典把它降到 **20.1%**（最低）
   拿了最好的 —— 单看占比会得出**相反的结论**。
2. **三条换法在这份语料上都比现状好，但幅度不足以支撑一次索引口径变更**：
   recall@5 现状 **30.8%** → 不动索引的 A+ **34.3%** / 字级 B **40.2%** / 领域词典 C **42.3%**。
   ⇒ **本轮拍板：生产口径一个字不改**（见 §四）。
3. **★ 古籍这条路的主因不是切分，是繁简。** 繁體原文 + 简体提问 = 逐字不同 =
   **0 命中**（实测 A/B/C 三种口径**全 0**，见 §三·⑤）。
   ⇒ 先投切分是**顺序错了**；繁简归一才是前置，而它需要业主定（要加依赖或加转换表）。

## 二、怎么量出来的

* **语料**：`var/fixtures/general-corpus/sanguo.txt`（三國志演義，Project Gutenberg #23950，
  1.86 MB / **641,312 字符 → 712 段**）。与 [cross-language 尺子](cross-language-retrieval-evidence.md)
  的 D 行**同一份文件**，数字可对。出处与许可同那篇 §二。
  ⚠ 这份语料是**繁體**（Gutenberg 的电子版）—— 这决定了 §三·⑤ 那一节。
* **三张内存 FTS5 表**，DDL 与生产 `clause_fts` 逐字一致（`tokenize='ascii'`），
  入库分别用三种切分：

  | 口径 | 索引怎么切 | 查询怎么表达 |
  |---|---|---|
  | **A 现状** | `segment_for_fts`（jieba `cut_for_search`，词典是现代汉语） | `fts_match_expr`（**丢弃单字符词**） |
  | **A+** | **同 A，一个字不动** | 关掉「丢弃单字符词」那条规则 |
  | **B 字级** | 每个汉字一个 token | 每个字一个词、**全部字都要出现**（FTS5 隐式 AND） |
  | **B' 字级（对照）** | 同 B | 每个字一个词、`OR`（更松，**不采纳**，只为说明收益不是来自"变松"） |
  | **C 领域词典** | jieba + `load_userdict`（词典**自挖**，见下） | 同 A |

* **考卷自动生成，且词典来源与考卷来源段级不相交（留出法）**：n=2/3/4 的汉字 n-gram，出现 ≥3 **段**才算候选；
  **词典只从语料前半段（356 段）挖，查询词只从后半段（356 段）挖** ⇒ C 的收益
  构造上不可能来自"把答案塞进词典"（同 E3b 的留一法思路）。
  每个查询词的目标 = 含该词的段落集合；量 recall@5 / recall@20 / MRR。
  ⚠ 说"**来源**不相交"不等于"**词表**零交集"：实测 `dict_terms(5000) ∩ queries(1200) = 269` 条
  （同一串词在前半段进词典、又在后半段进考卷）—— 但**考卷的答案从未注入词典**，泄漏仍不可能
  （这一处措辞由本批独立复核抓出，见 §十·3）。
* **可复跑**：连跑两次，**剔除建表耗时行（`建表 X.Xs`）后逐字节相同** ——
  口径：**只取 stdout**、`sed -E 's/建表 [0-9.]+s/建表 Xs/g'`，md5 = `c527a555…`。
  ⚠ 必须**只取 stdout**：jieba 初始化会往 **stderr** 打一行 `Loading model cost X.XXX seconds.`，
  把 stderr 并进来（`2>&1`）会让哈希**每次不同**（这是本批独立复核抓出的口径错，见 §十·3）。

## 三、数字

### ① 三种切分的词表与单字占比

| 口径 | 词表大小 | 中文单字占比（按出现次数） |
|---|---|---|
| A 现状（jieba） | **60,022** | **30.3%**（122,148 / 403,481） |
| B 字级 | **4,839**（A 的 0.08×） | **81.3%**（484,892 / 596,278） |
| C 领域词典 | **57,786** | **20.1%**（79,181 / 393,579） |

* **与计划里那个 30.2% 对上了**：尺子另外按**与 cross-language 尺子逐字同法**（前 800 段拼串）
  又算了一遍，得 **122,148 / 404,316 = 30.2%** ⇒ 计划那一行复现成立。
  两个数（30.3% / 30.2%）都对，差 0.1pt 来自**分母口径**（逐段分词 vs 拼串分词，段落边界上的切分不同）
  —— **引用时必须说清是哪一条**。
* ⚠ B 的词表**不是"更大"而是"换了检索单位"**：4,839 ≈ 汉字种数 + 少量拉丁词。
  字级不是把词切得更细，是**取消了"词"这个单位**。

### ② 领域词典（C）是怎么挖的

* 前半段 356 段里：n=2 有 13,651 个 ≥3 段的串，其中**现状切不出整词的 3,963 个**；
  n=3 有 5,379 / 3,921；n=4 有 1,363 / 1,260 ⇒ 只收"现状切不出整词"的，取前 **5,000** 条。
* 词典样例：`卻說 / 德曰 / 操曰 / 笑曰 / 引軍 / 之事 / 視之 / 去了 / 有一 / 而去 / 怒曰 / 於是`。
* 生效检查：**5,000 / 5,000 现在都能切成一个 token = 100.0%**。
* ⚠ **这份词典是机械自挖的 n-gram，不是人编的词典**：里面「德曰」「笑曰」「有一」这类
  **不是词、只是高频片段**。它证明的是"补词典这条路有收益"，
  **不能**推出"一部正经的古籍词典会更好"（也可能因为过切而更差）。

### ③ 检索命中率（1,200 条查询，n=2/3/4 各 400）

| 口径 | recall@5 | recall@20 | MRR | 空查询 |
|---|---|---|---|---|
| **A 现状** | 30.8% | 47.4% | 0.210 | **15** |
| **A+**（索引不动，查询侧不丢单字） | 34.3% | 54.2% | 0.232 | 0 |
| **B 字级**（单字 AND） | 40.2% | **72.2%** | 0.270 | 0 |
| B' 字级（单字 OR，对照） | 39.8% | 71.2% | 0.261 | 0 |
| **C 领域词典** | **42.3%** | 65.7% | **0.286** | **15** |

按查询词长度拆开（机制不同：n=2 现状多半切得出整词，n=4 基本切不出）：

| n | A 现状 | A+ | B 字级 | C 领域词典 |
|---|---|---|---|---|
| 2 | 55.0% / 67.8% / 0.375 | 56.2% / 69.5% / 0.378 | 67.2% / 96.0% / 0.435 | **72.0%** / 90.0% / **0.478** |
| 3 | 23.5% / 39.5% / 0.156 | 28.7% / 47.8% / 0.178 | 32.2% / **67.5%** / 0.221 | **34.2%** / 59.2% / **0.231** |
| 4 | 14.0% / 35.0% / 0.101 | 18.0% / 45.2% / 0.141 | **21.2%** / **53.2%** / **0.154** | 20.8% / 47.8% / 0.153 |

* ⚠ **绝对值是送分题**（查询词从原文抄）⇒ 只能横向比，**不能当产品效果**。
* **B 与 B' 几乎一样**（40.2% vs 39.8%）⇒ 字级的收益**不是**来自"查询变松"，是来自"检索单位换成字"。
* **A 的 15 条空查询**（1.25%）= 表达式被清空 ⇒ 该查询在 FTS 上**保证 0 命中**。
  机制**已知且已写进代码注释**：`fts_match_expr` 会丢弃单字符词
  （`src/core/text_utils.py` 规则 3），而 jieba 把某些 2 字词切成两个单字 ⇒ 表达式为空。
  A+ 把这一栏清零（0 条空查询）是它涨分的一部分。
* ⚠ **C 的空查询也是 15 条**：词典只从**前半段**挖，后半段独有的词 C 也不知道 ⇒ 与 A 同样为空。
  这说明**自挖词典不能覆盖全部词**（这也是 C 在 n=4 上不如 B 的原因之一）。

## 四、判定与拍板（2026-10-09，自动续接链第 5 轮；业主已授权本项自决，决定与理由留痕在此）

**拍板：不改生产口径。** `segment_for_fts` / `fts_match_expr` / `clause_fts` 索引**一个字不动**，
不重建索引、不加载用户词典。

三条理由：

1. **主因不在切分**（§三·④）：古籍上的致命伤是**繁简**（简体提问 0 命中），
   而三条切分路**都救不了**它。先投切分 = 顺序错了。
2. **证据面只有一部语料**：712 段的明代小说，**一部**。本仓 P3.3 自己立的规矩是
   "**换资料类型就跑一遍**、每次新增资料类型都要有一份四类对照表" ⇒ 一部语料不足以支撑
   一次**索引口径**变更。且绝对值是**送分题**，真实收益未知。
3. **代价与收益不匹配**：
   * A+ 要改 `fts_match_expr`（**全库生效**的检索口径，属必验类别），且它放宽了
     原本有意丢掉的噪声（`的`/`是` 这类单字）—— **对法规语料有没有副作用，本轮没量**。
   * B 要改 `segment_for_fts` + 改 `fts_match_expr` + **重建 522k 条索引**；
     而且"把单字占比推到 81.3%"本身就是把"词"这个单位取消掉，与现状"按词找"的立论相反。
   * C 需要一部**正经的**领域词典（本轮的词典是机械 n-gram），并重建索引。

> 与 §二乙（2026-10-09）和 E9 的拍板同一条规矩：**拿到判据之前不改**。

## 七、已知边界（别把本文结论放大）

* 语料是**一部**明代小说（繁體、文言），不是生产库；量的是"切分口径"这类通用性质，
  不是产量指标。
* 查询词**从原文抄**（送分题）⇒ 绝对值不能当产品效果；它的用途是**横向比较**。
* **词典是自挖的机械 n-gram**（§三·②），不是人编词典。
* C 的词典只从**前半段**挖 ⇒ 后半段独有的词 C 也切不出（C 的空查询 = A 的 15 条），
  这是**保守**的测法，不是 C 的上限。
* `jieba.load_userdict` 是**全局副作用**（尺子里 C 必须在 A/B 量完之后才加载）；
  生产上要用它需要另设计初始化时机，**本轮没碰**。
* 字级口径的查询侧**不能复用 `fts_match_expr`**：它那条"丢弃单字符词"的规则会把字级查询清空
  ⇒ **选字级就必须同时改 `fts_match_expr`**，这不是免费的索引选项。

## 十、留痕：本批纠掉的三处口径错（两处自查、一处复核抓出）

1. **单字占比一开始算错了口径**：第一版用 `fts5vocab` 的 **`doc`（含该词的段数）**，
   得到 A = **31.8%** —— 而 cross-language 尺子量的是**出现次数**，同一份语料是 **30.2%**。
   同一份语料两个数、读的人无法判断哪个对。**已改成 `cnt`（出现次数）**，并**额外**按
   cross-language 的逐字同法复算一遍（30.2%）⇒ 两个口径都印出来。
2. **一度把"B 单字占比 100%"写进结论**：那是 `doc` 口径下的数（B 的每个单字出现在
