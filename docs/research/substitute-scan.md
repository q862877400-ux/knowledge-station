# 替代品扫描（substitute scan）——"谁已经交付了同样的用户价值"

> **性质**：研究产物。**与"技术扫描"（`docs/research/channels/*`）是两件事**：
> 技术扫描问"他们怎么抓/怎么解析、能不能加固我们"；本次问"**他们是不是已经把用户的问题解决了**"。
> 起因：R1 的调研只做了前者，导致"通用层已被商品化"这个事实直到业主甩来 WeKnora 才被看到。
> 一手来源见各条链接；**凡"我没读/没验证"的都显式标注**。

## 一、扫描结果：四类替代品（+ 一类交付形态替代）

### A 类·通用知识库 / RAG 平台（替代"问答 + 引用"这一层）

| 对象 | 交付的价值 | 状态 |
|---|---|---|
| **WeKnora**（腾讯开源，MIT） | 通用文档知识库：多格式解析、混合检索、引用溯源、多租户、Agent/MCP、**DSH 插件**、Lite 单二进制/桌面版 | 已详评：`weknora-assessment.md`（我读了 7 页一手文档） |
| RAGFlow / Dify / FastGPT / MaxKB / AnythingLLM 等 | 同上品类（开源/商业并存） | ⚠ **本次只看到聚合对比文章，未逐一读一手文档**——但它们与 WeKnora 同品类，结论同 A 类 |

**结论**：A 类把"把文档变成可问答、带引用的库"做成**免费或廉价**。**我们产品的通用面被替代**。

### B 类·商业法律数据库（替代"法规全文 + 效力状态 + 更新"这一数据层）

| 对象 | 交付的价值 | 证据 |
|---|---|---|
| **北大法宝**（pkulaw） | 法律法规总库；**按"效力性/时效性"聚合**（URL 里就带 `EffectivenessDic` / `Aggs.TimelinessDic`）⇒ 它**已经有"现行有效/失效/已被修改"这一维** | 搜索命中的官方检索页 URL（见文末来源） |
| **威科先行**（CCH / Wolters Kluwer） | 企业级法律信息库 + 合规（外资/大企业常用） | 产品手册命中 |
| LexisNexis / 法信 等 | 同类（国际/司法系统） | ⚠ 未逐一验证 |

**结论**：**"法规有没有失效、有没有新版"这件事，B 类早就做了，而且有专职编辑团队维护**。
我们靠渠道巡检拼出来的时效数据，**在覆盖面与权威性上很难超过 B 类**。
⚠ **未验证的关键一点**：B 类能否"点一条结论 → 跳到 PDF 原文那一行"（这决定我们的取证优势是否成立）。

### C 类·官方免费查询（替代"权威数据源"——我们自己就是接它）

国家标准全文公开系统（openstd）、全国标准信息公共服务平台、国家法律法规数据库。
它们**免费、权威**，但**只给查询/状态，不给问答、不给举证、不给落地件**。
⇒ 它们不是产品替代品，但**是 B 类与我们的共同上游**（我们已接；别人也能接）。

### D 类·垂直合规闭环系统（**最危险：替代整个产品价值**）

**赛为安全「AI 合规智审系统」**（深圳市赛为安全技术服务有限公司，1993 年起做安全咨询/培训）
—— 一手读到的功能（[原文](https://www.safewaynt.com/news/2026062610182115851.html)）：

| 它的能力 | 对应我们的东西 |
|---|---|
| **合规库建设**：按行业（危化/矿山/建筑）**自动从国家及地方官方权威渠道持续采集/清洗/分类**，**增量更新与版本管理**，**"自动替代失效文件"** | = 我们的 **渠道巡检 + 现行版正确性**（R6a–R6g 整条线） |
| **适用性分析**：法规库 × 企业业务/设备/工艺/风险清单 ⇒ 生成**《合规义务清单与评价标准》**（精准到岗位/设备/流程） | = 我们的 **义务清单 / 检查表** |
| **培训宣贯**：按岗位自动生成微课程 + 考核试题库 | 我们**没有** |
| **合规性评价**：AI 给专家组推**电子检查表**，现场拍照**智能比对条款并判"不符合"**，结构化评估报告 | 我们的检查表 + 报告，**他们多了现场取证** |
| **整改闭环**：不符合项 → 带编号的整改工单（责任人/验证人/时限）+ 逾期逐级预警 + 证据链 | 我们**没有**（这是管理闭环，不是证据层） |

**Benchmark Gensuite**（国际 EHS 平台，[RegTracker / Regulatory Compliance & Auditing](https://benchmarkgensuite.com/app/reg-tracker/)）：
法规追踪 + 合规日历/义务管理 + 审核 + CAPA + 培训(LMS) + 文档管理 + **Genny AI（含 MCP Connector）**。
同类还有 VelocityEHS、Enablon、Cority、Intelex、Sphera…

**结论（这一条最要紧）**：**"法规跟踪 + 义务清单 + 检查表 + 整改闭环 + 培训 + 报告"是一个成熟品类**
（国内叫"安全生产合规管理系统"，国际叫 EHS/Regulatory Compliance Management）。
**我们正在做的东西，是 D 类的一个功能子集**——而且 D 类还多出培训、工单闭环、现场评价，
并且通常**带咨询服务**（赛为本身就是咨询公司，卖的是"体系 + 软件 + 培训"）。

### E 类·Skills / Agent 交付形态（替代"我们作为 DSH 插件"这一格）

- **WeKnora 的 DSH 插件**（官方维护，4 个工具）——已经占了同一个宿主位置；
- **THUYRan/Legal-Skills-Chinese**（清华背景的法律 Skills 集合，含 `legal-norm-validity-check`
  "**法条效力核验**"技能）——⇒ **"把法条效力核验做成一个 skill"这件事已经有人做了**
  （⚠ 我只看到仓库与技能目录名，**没读到实现质量**）。

## 三、方向选项（请你选，或给我新的约束）

| 选项 | 定位 | 优势 | 代价/风险 |
|---|---|---|---|
| **A·证据层** | 给已有 EHS/合规系统、律所、安评/审计提供"**可举证的证据层**"（条款级坐标 + 效力 + 可核验时效），形态 = DSH 插件 + API/MCP | 唯一没被替代的格子；指标可量化（引用准确率/版本正确率/发现时延/举证成功率） | **客户是谁、谁付费不清楚**；若无分发渠道 = 技术好没人买 |
| **B·通用研究+交付** | 回到"通用资料研究 + 交付物（报告/PPT）" | 市场大；"评审硬门 + 权威两轴"确实少见 | 正撞 A 类主场；交付物人人都在做；材料平面**还没在真机跑过** |
| **C·时效数据订阅** | 只卖"你关注的标准/法规的现行性与变化"（告警/API/报表），不做问答 | 与长周期目标同源（已建一半）；可嵌入别人系统（B2B2B） | 与**北大法宝/赛为正面撞车**；数据维护是长期成本；定价难 |
| **D·A+C 合并（我的推荐）** | **上游**时效与效力数据面 + **下游**举证级引用；形态 = 插件 + API；**明确不做管理闭环**（培训/工单/检查表流程） | 把"没人做的那一格"做成产品；D 类可成为**渠道**而不是对手（给他们供证据层） | 需要接受"我们不做完整合规系统"这个自我约束；仍要解决"谁付费" |

## 四、动手前必须验证的四件事（我建议照这个顺序）

1. **B 类的取证能力**：北大法宝/威科 能否"结论 → 原文位置"跳转？——**若有，我们的取证优势也不成立**，方向要重排。
2. **D 类的证据粒度**：赛为/Benchmark 的"证据"是否也能点回原文页/坐标？——决定我们是"差异化"还是"补功能点"。
3. **谁付费**：业主自己的公司在用什么软件（EHS 系统？法规数据库？）——**最有效的用户调研就是业主本人**；
   以及"如果要你为'能点回原文的合规结论'单独付钱，你会付给谁"。
4. **接入可行性**：WeKnora 的 chunk 是 rune 偏移、我们是 `clause_revision_id` + bbox ⇒ 坐标映射能不能做通
   （这决定"站在它上面"这个选项是否真实）。

## 六、第二轮扫描（同日追加）：**我上一轮的"空格"结论被推翻**

### 6.1 命中一：**北大法宝已经把它做成了 MCP Skill，而且覆盖"核验"**

一手证据：`infometa/workbuddyskills` 里的
[北大法宝 SKILL.md](https://github.com/infometa/workbuddyskills/blob/main/connectors/pkulaw/skills/SKILL.md)
（v4.0.0，快照 2026-08-12）。它自称"**官方法律检索与核验 MCP Skill**"，**10 个工具、三层能力**：

| 层 | 工具（用途） |
|---|---|
| 检索 | 法条语义检索 / 法条精确取条（两种）/ 法规列表 / 案例语义检索 / 案例列表 |
| **核验** | **法规名称识别**（"这段话引了哪些法"）、**案号识别与验真伪**、**法条正文权威原文对照**（"这条内容对不对"） |
| 呈现 | **整段文本批量加 Markdown 超链**（生成条级锚点 `?tiao=47#tiao_47`、款级 `#tiao_1077_kuan_1`） |

而且它的**纪律条款与我们主张的几乎逐条重合**（一手摘录）：
"**禁止凭记忆答法条/案号**"、"**每条依据附链接**"、"**时效强制标注**"、
"时效值含**现行有效／废止／失效／已被修改／尚未施行**（`timeliness`/`TimelinessDic`）"、
"**效力位阶**（`effectiveness`/`EffectivenessDic`）"、"**条号迁移是高频错源**"、
"空结果不编造"、"核验结论要克制（字段为空只说'未验证到'，**不得断言对方编造**）"，
甚至有**反幻觉闭环**（生成→抽取→核验→修正→加链接）与"**核验另一个 AI 的输出**"这一主场景。
计费已跑通（积分制：`90001` 积分用尽）。

⇒ **我们产品的核心主张（只依据检索到的原文作答、每条结论可点回原文、效力/时效标注、引用核验、反幻觉纪律）
= 北大法宝 MCP 的现成能力**，而且背后是**权威库 + 条级锚点 + 成熟计费**。

### 6.2 命中二：**标准侧的"巡检/跟踪/推送"是官方出版社在卖的会员服务**

一手证据：[中国标准在线服务网（spc.org.cn，中国标准出版社）会员服务](https://www.spc.org.cn/gb168/stdlib/vipinfo)：

- **标准行业定制推送**："选择行业分类定制后，及时推送所选行业分类的标准更新信息
  （**新上线、新实施、被代替、废止**等）" ← = **我们的巡检**
- **标准跟踪**："自动跟踪已购买标准（不限条数）；手动跟踪未购买标准……
  当所跟踪的标准的**状态变更**时，**我们及时为您免费推送**" ← = **我们的关注面巡检 + 变化告警**
- 国内标准在线阅读 **10 万+**、标准文本下载、**标准查新**、标准出版进度查询
- **联合会员 1328 元/年**（含**工程建设标准知识服务库（工标库）**：标准阅读、**标准对比**、
  **条文说明阅读**、**强制性条文聚合**）
- 附加包：电力行业 500 元/年

⇒ **"标准时效 + 跟踪 + 推送 + 条文说明 + 强条聚合 + 标准对比"= 官方出版社的现成商业服务**，
而且**他们有正版全文**（我们没有授权全文，只有公开系统抓取）。

### 6.3 命中三：**"条文级引用核验/版本追溯"进了 WPS**

⇒ **"条文级溯源 + 版本追溯 + 引用错误检测"已经是办公软件里的一个功能**，入口是亿级装机量的 WPS。

### 6.5 修正后的结论（这才是现在的判断）

**逐格盘点，我找不到"只有我们做"的格子：**

| 格子 | 已被谁占 | 我们的相对位置 |
|---|---|---|
| 通用问答 + 引用 + 反幻觉纪律 | **北大法宝 MCP**、WeKnora、Dify 类 | **明显劣势**（数据更权威、分发更成熟、更便宜） |
| 法规效力/时效数据 | 北大法宝（`TimelinessDic`/`EffectivenessDic`） | 劣势（覆盖面 + 专职编辑） |
| 标准时效/跟踪/推送 | **中国标准在线服务网**（官方，1328 元/年含全文与工标库） | 劣势（他们有正版全文） |
| 条文级引用核验/版本追溯 | **WPS 黑马校对** | 劣势（入口与装机量） |
| 管理闭环（义务/检查表/整改/培训） | 赛为、Benchmark Gensuite 等 | 我们只做了子集 |
| 通用知识库 + DSH 插件 | **WeKnora**（官方插件） | 同一生态位 |

**只剩一个"组合"还没看到有人做**（⚠ 是"组合没人做"，不是"单点没人做"）：

> **把"法条域（北大法宝这类）"与"标准域（spc/工标库这类）"缝进同一条引用链**
> ＋ **锚到你手上那份 PDF 的页/坐标（不是网站锚点）**
> ＋ **企业自有材料（评审硬门 + 权威两轴）**

这个组合的价值主张是"**跨域 + 锚到本地文件 + 可审计**"；
它的成立条件只有一个：**有人愿意为此付钱**（而这正是"客户是谁"还没定的问题）。

## 七、第三轮扫描：**连"那个组合"也大半被占了**（工标库一手）

|---|---|

| **通用规范条文跳转**："**一键直连废止条文**" | 条文间关联 + **废止条文关联** |
| **标准关联查询**："标准规范知识点之间**相互关联查询**" | 关联检索 |

| **条文说明整合**（"计划版阅读"：一边读标准一边看说明） | 我们**没有**（且这是评价/设计的刚需） |

| **AI 智能检索**（"输入您的问题"） | 问答 |
| **标准查重 / 智能审校**（`/ai/editor`） | **引用/条文核校** |
| **术语库近 10 万条** | 术语 |

## 八、需求侧扫描（这一节是**目前最有价值的发现**）

供给面已经密到"每一格都有人做"，所以我换了方向：**买方为什么付钱**。第一手命中一个
**行政处罚案例**（[EHS 网转载应急管理部"应急普法"](https://www.ehs.cn/article-24177-1.html)，2025-08-14）：

> **案情**：2024-11-22 执法检查发现，某工程咨询公司编制的安全预评价报告（备案稿）中，
> 31 车间与品控研发楼的**防火间距引用为 ≥12m**，而《精细化工企业工程设计防火标准
> **GB 51283-2020**》**第 4.2.9 条**规定值为 **≥25m** ⇒ **"法规标准引用错误"**。
> **依据**：《安全评价检测检验机构管理办法》第二十二条第一款第五项（不得出具虚假或**重大疏漏**的报告）、
> 第三十条第十项 + 应急管理部《应急管理行政处罚裁量权基准》⇒ **警告 + 罚款 9500 元**，
> 并责令限期整改。
> **"重大疏漏"的明文情形**（专家评析）：**法规标准引用错误**、关键危险有害因素漏项、
> 重大危险源辨识错误、对策措施建议与存在问题严重不符。

**这条证据为什么重要（比前面所有替代品都重要）**：

1. **需求是被监管认定的**，不是我们编的：**"法规标准引用错误"是法规明文列举的"重大疏漏"**，
   会被行政处罚，有真实案例、有精确条文依据、有金额（≤1 万，本案 9500 元）；
2. **客户画像第一次清晰**：被罚主体是**安全评价机构 / 工程咨询公司**——有资质、有执业风险、
   报告要**备案**、会被**技术评审 + 行政执法**双重检查；
3. **错误形态正好打在我们的能力上**：本案错的是"**引用的规定值**"（≥12m vs ≥25m）——
   即**数值/条款级引用核对**；我们做的"条款级引用 + 数值核验 + 只引现行版"是它的靶心；
4. **"可举证"是刚需而不是锦上添花**：报告要给人查、给执法看，所以"点回原文那一页"有制度性需求。

⚠ 但要冷静：**这也意味着"谁能提供准确的引用核对"就有市场**——而 WPS（PDF 条款定位）、
工标库（智能审校）、北大法宝（法条核验）都已经在这条路上。我们在**标准数值/条款级核对 +
现行版判定**上仍有位置，但**不是空地**。

## 九、下一步搜索方向（按我判断的优先级）

1. **把需求侧做透**：还有哪些场景把"**引用错误**"写进处罚/评审/否决？
   （安全评价、环评、消防设计审查、施工图审查、研报合规、检验检测报告…逐个人工找一手依据）
2. **安全评价机构的工具现状**：他们今天用什么做"标准引用核对"？（Excel 模板？人工？WPS？工标库？）
   ——这决定我们是不是要卖给**评价机构**。
3. **收尾供给面**：`aihse.cn`（EHS 网的 AI 产品）、云厂商（腾讯/阿里/华为/百度）的合规 AI、
   以及"标准数值/条款核对"是否已有专门产品。
4. 若前三步都指向"有人做但都不覆盖**用户自己那份文件 + 评审门 + 处罚级可举证**"，
   那么**"空格"就从"功能"退化为"组合 + 场景"**——那时再回到方向问题。
