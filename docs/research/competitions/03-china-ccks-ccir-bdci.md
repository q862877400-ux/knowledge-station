## 2. 逐赛道逐方案点评

### 2.1 CCKS 2024 开放领域知识图谱问答（CKBQA）—— 唯一拿到较完整技术细节的一条线

这条线有两个不同的获奖队，公开程度差很多。

#### (a) 第 2 名 + 科技创新奖：「基于大模型多跳感知的知识图谱问答解决方案」

**证据等级：【转述】** —— 来源是老刘说NLP 公众号第 35 讲（2024-11-15）的复盘，搜狐转载 <https://news.sohu.com/a/836373756_121616897>（2024-12-13，已直连读到全文，抓取 2026-11-05）；另有 oschina / segmentfault / 腾讯云开发者社区三个同源转载。
**它自己只报了名次（CCKS2024 开放领域知识图谱问答评测第二名、科技创新奖）与方法框架，没报分数、没报队伍数、没公开代码。**

四段拆解：

| 段 | 它的做法 | 判断 |
|---|---|---|
| **检索** | 实体识别用 **OneKE 大模型 + BERT 联合抽取**（BERT 抽不出结构时回退用 OneKE）；实体链接阶段用 **rerank 重排**候选实体 | 这一步是本方案的重心。它的核心主张就是"实体链接在大模型 KBQA 里极其重要" |
| **融合重排** | 即上面的 rerank；多跳阶段不是一次生成，而是**微调大模型迭代预测"下一跳子图"**，直到模型自己输出 `quit` 作为终止符 | 把"多跳"变成"带终止条件的迭代"，而不是一次生成完整 SPARQL |
| **生成** | 输出 SPARQL 时**用逻辑表达式压缩**，减少输出 token 长度 | 一个纯工程优化，但被明确点名为提分点之一 |
| **自检拒答** | **无**。终止条件是 `quit`（跳数够了），不是"答不了" | 这是它最大的缺口：没有拒答机制，只有停止条件 |

**赢在哪一段**：老刘的复盘把"实体识别（OneKE+BERT 联合）+ 实体链接 rerank + 多跳迭代"列为三个重点；**结合 2023 年冠军诺谛智能的同一句主张（"减少对实体抽取和实体链接的依赖"）**，两条独立证据指向同一件事：**在这类中文 KBQA 赛里，实体链接是决定名次的那一段**。区别只是 2023 冠军选择"绕开它"，2024 亚军选择"做好它"。

**可复现性**：中。OneKE 是公开模型（DeepKE 项目，浙大），BERT rerank 是常规做法，SPARQL 逻辑表达式压缩是纯文本工程。真正不可复现的是"微调大模型迭代预测下一跳子图"这一段的训练数据构造方法（怎么把问答对扩成逐步子图预测的样本）—— 公众号没写。

### 2.2 CCKS 2024 人物知识图谱复杂问答推理 —— 赛道定义清楚，冠军方案未公开

**赛题（【一手】，任务书 docx 经搜索摘要读到）**：<https://sigkg.cn/ccks-ijckg2024/wp-content/uploads/2024/05/任务三：人物知识图谱复杂问答推理评测.docx>
- 图谱规模（**来自一篇参赛论文的实测描述，非官方任务书**）：256,378 实体 / 240 关系 / 785,553 三元组；训练集 1,238 问；初赛测试 1,000 条、复赛 2,000 条；指标 Averaged F1。来源：【一手论文摘要/正文片段】<https://springer.zxlib.top/content/pdf/10.1007/978-981-96-1809-5_33.pdf>（Springer 章节，题为 *A Person Attribute Knowledge-Based Question Answering Method Leveraging Large Language Models*）。抓取 2026-11-05。
- 赛题把难点显式分成三类：**多跳查询 / 统计计数 / 逻辑组合**，外加一类**无法查询得出、必须做关系推理**（例子："某人的侄子是谁"需由兄弟关系 + 儿子关系推出）。

**该 Springer 章节的做法（四段拆解）**——注意：**这是参赛论文，是否冠军未确认**：
- 检索：**动态 few-shot 示例检索**（不用固定示例，按 query 检索相关示例拼进 prompt）
- 融合重排：先用 LLM 在训练集 500 题上生成"带解题轨迹"的示例，再过掉答案错的
- 生成：迭代式 "Action 1: Search[...] Observation 1: ..." 的 ReAct 式搜索循环
- 自检拒答：未见

**获奖情况**：【转述】人保科技 2nd / 200+ 队 <https://tech.picc.com/techwebsite/webfile/dynamic/2024-09-26/8aa2a499920ec79b01922d5e901f0005.html>。**冠军队伍未查证。**

### 2.6 CCKS 2023 开放领域 KBQA 冠军（诺谛智能）—— 已知底数，这里补判断

已知（业主已核）：280 队、冠军诺谛智能、LLM 生成图谱查询语句、7,000 余条训练数据、6,600 万三元组 / 1,100 万实体 / 41 万关系、查询准确率 75.63%。
来源：【转述】中国日报转载东方网 <https://ex.chinadaily.com.cn/exchange/partners/82/rss/channel/cn/columns/sz8srm/stories/WS64f170a8a310936092f1fcc2.html>（2023-09-01），抓取 2026-11-05。另有镜像站转载同一稿（<https://cdhxkj.com/jzq/1041.html>，错字较多，疑机器洗稿，不采信）。

**补一条别人没提的判断**：这篇稿子里唯一有技术含量的一句是"**在减少模型对语句中实体表述抽取和实体链接依赖的同时增加正确答案的检索准确性**"。把它和 2024 亚军"**强化实体链接（rerank）**"放在一起看，会发现两条路线**相反**：
- 诺谛（2023 冠军）：弱化实体链接，让 LLM 直接从自然语言生成查询语句；
- 2024 亚军：强化实体链接，OneKE+BERT 联合抽取 + rerank。

**两者都拿到了名次**，说明这条赛道上"实体链接该强化还是该绕开"没有定论 —— 取决于图谱规模和 schema 复杂度。诺谛面对的是 1,100 万实体的超大开放图谱（链接候选爆炸 ⇒ 绕开更划算），2024 人物图谱只有 25.6 万实体（链接可控 ⇒ 做好更划算）。**这个解释是我的推断，不是任何一方的说法。**

### 2.7 CCIR Cup 2025「法律知识检索与生成」—— 国内最贴近本仓场景的一条线

**赛题**（【一手】山东大学通稿 <http://gail.sdu.edu.cn/info/1005/1754.htm>，抓取 2026-11-05）：
- 主办：中国中文信息学会信息检索专委会；CCIR 2025（第三十一届），2025-08-15~17 新疆石河子。
- 数据：法律专家标注的**多轮法律对话** + 法律知识库（**法律条文 / 法律书籍 / 类案**），覆盖民事、刑事等多个细分领域。
- 考察：会话知识检索 + 响应生成。
- 规模：**53 名参赛选手**（来自中科院计算所、泉城实验室等）。注意：这是"选手"数不是"队伍"数，两者不可混。

**冠军：山东大学通用智能实验室**（郭茹菁，指导 张孟奇/刘泽阳）
- A 榜 **39.148**、B 榜 **41.0224**，均第一。【一手·校方通稿】
- 方法一句话：**多轮对话问题重写 + 定制化向量检索模型 + 滑动窗口打分重排**。【一手·校方通稿】

**第 3 名：中科院计算所（Da Li / Zecheng Fang / Qiang Yan / Wei Huang / Xuanpu Luo）** —— 这条有**完整论文**，是本节最有价值的部分。
【一手·论文全文】<https://arxiv.org/html/2510.15722v1>（*The 3rd Place Solution of CCIR CUP 2025: A Framework for Retrieval-Augmented Generation in Multi-Turn Legal Conversation*，2025-10-17）。已直连读到全文，抓取 2026-11-05。

**先说数据集统计（这张表本身就是可用的评测规格）**：
| 项 | 数值 |
|---|---|
| 对话总数 | 1,013 |
| query 总数 | 5,065 |
| 法律条文数 | 17,229 |
| 法律文献（书籍）数 | 212 |
| 平均 query 长 | 19.43 |
| 平均答案长 | 165.92 |
| 每条 query 平均相关条文数 | **1.09** |
| 每条 query 平均关键词数 | 3.57 |

**指标（关键：检索与生成各占一半）**：
- 检索 = `100 × NDCG@5`
- 生成 = `50 × BERT-F1 + 50 × Keyword_Accuracy`
- 总分 = `0.5 × 检索 + 0.5 × 生成`

四段拆解（第 3 名）：

| 段 | 做法 | 消融贡献（Vanilla RAG = 30.74） |
|---|---|---|
| **检索** | ①**查询改写**：Qwen3-235B-a22b 把"历史对话 + 当前问题"重写成检索 query，并**强制输出 3–5 个法律术语**（用 `<keyword></keyword>` 标签包住）；②**多路召回**：dense（Qwen3-Embedding-8B，每部法律文献各召回 50 条）+ BM25（全库召 1,000 条） | 改写 +0.92；多路召回 +1.97（累计 33.60→35.57） |
| **融合重排** | ①**法律文献过滤**：Qwen3-14B 逐条判断"这条法律文献是否可能涉及该问题"，只输出 Yes/No；**过滤掉 73% 无关法典、保留 96% 相关**；②**精排**：Qwen3-Reranker-8B **用竞赛数据微调**，取 top-5 | 精排 +1.94；文献过滤 +1.32 |
| **生成** | Qwen3-235B-a22b + **两条 in-context 示范**锁风格；要求按参考条文"从头到尾顺序引用"；照法律文书的**三段论**格式写 | — |
| **自检拒答** | **无**。论文的 Limitations 自己承认：无法处理复杂多步法律推理，静态语料无法覆盖新法 | 这是它 40% 错误里"生成不一致"那一类的根源 |

**它自己承认的错误分布（很有参考价值）**：生成不一致 **40%**、上下文误解 **32%**、检索缺口 **28%**。
⇒ 也就是说，**在这个赛题上，检索已经不是最大的错误源了**（28%），最大的是生成。这与国际 CRAG 类赛题（检索是主战场）明显不同。

**一个必须点出的负面发现（微调 rerank 的负样本构造）**：
论文写"我们从 top-10 里随机选 5 条不相交的作为负样本"。这是**难负样本（hard negative）**做法，本身是对的，但论文**没有做"随机负样本 vs 难负样本"的对照实验**，所以"难负样本带来多少收益"无法归因。它的 NDCG@5 提升 0.08 是"微调后的 reranker vs 直接用检索分数"，不是"难负样本 vs 随机负样本"。

**可复现性**：**高**。全部组件都是公开模型（Qwen3 系列），四个模块的 prompt 全文都贴在论文里（改写、文献筛选、条文筛选、生成各一段），超参也给了（dense 50/文献、BM25 1000、过滤看 top-500、精排取 top-5、dense 权重 α=1.0 —— 注意 **α=1.0 意味着最终打分完全不用 BM25**，BM25 只用来扩候选池）。唯一不可复现的是竞赛训练标注数据。

### 2.8 CCF BDCI 2024「对话式检索增强生成」—— 全赛道特等奖

**赛题**：多轮历史对话 + 最新问题 → 检索相关文档 → 大模型生成回答。数据用 **CORAL** 基准（论文 <https://arxiv.org/pdf/2410.23090>），知识库来自 Wikipedia。指标 **ROUGE-L**。
【转述·公众号复盘】火山引擎开发者社区 <https://developer.volcengine.com/articles/7459667653465276470>（作者 Winnie / 马千里，2025-01-13；同文在公众号"致Great"发布）。已直连读到全文，抓取 2026-11-05。比赛页 <https://www.datafountain.cn/competitions/1074>。

四段拆解：

| 段 | 做法 |
|---|---|
| **检索** | ①问题改写（历史对话 + 当前问题喂给**微调过的模型**改写）；②**两路召回**：嵌入召回 + **关键实体召回**（用 spaCy 抽 PERSON/ORG/WORK_OF_ART，直接在文档里搜实体，作者明确说"比 BM25 更快且能召回更多可能相关的文档"） |
| **融合重排** | ①Cross-Encoder reranker 精排取 **top-5**；②**上下文感知重排** —— 这是它自称的获奖关键：把 5 篇文档**枚举所有排列**，逐排列打"语义是否连续、信息是否互补"的分，取最高分那个顺序；并按 index 排序剪枝（"不把牛尾放在牛头前"）+ **启发式补全**（有 90/92/93 就自动补 91） |
| **生成** | 长文档场景把问题**放中间**防截断（作者同时承认会导致 "lost-in-the-middle"，建议多试排布） |
| **自检拒答** | **无** |

**赢在哪**：**不是检索，是重排**。作者原话"这是我们拿到赛道一等奖和全赛道特等奖的关键"指的是**上下文感知重排**（枚举排列 + 补全 index），不是召回。
**反证**：作者在"抖个激灵"一节明确说，针对 ROUGE-L 试过很多**偷分方式**（如拼接多次输出），"但都不如直接用模型输出"。⇒ 这条赛道的指标（ROUGE-L）**有明确的刷分空间**，只是这个队没刷成。这一点必须记进反证节。

**可复现性**：中高。两路召回 + Cross-Encoder + 排列重排都是可实现的；"排列打分"的具体打分器作者没给（只说"相似度打分"或"让大模型评估"），这是复现的缺口。另外**枚举 5 篇文档的全部排列 = 120 种**，成本不低，实际落地要剪枝。

### 2.9 CCF BDCI 2024「基于运营商文本数据的知识库检索（RAG）」—— 一个"故意禁掉大模型"的对照赛

这条赛道的**规则本身**比冠军方案更值得记。

【一手·赛题规则转述】GitHub 课程项目 README <https://github.com/Jiadong001/DS2024-Course-Project>（比赛页 <https://www.datafountain.cn/competitions/1045>），抓取 2026-11-05。原文列出：
- **主办方限定用 `bge-large-zh-v1.5` 做向量化，不允许微调**
- **禁止使用 LLM 直接生成最终答案**
- **禁止用 LLM 调整精排后的文本块（如压缩长度）**
- **禁止用 LLM 从文档直接抽取答案**
- **不允许用外部信息回答**
- 答案必须至少是文档中的一个完整句子
- 主办方明说意图：**"消除大模型的使用对大家的不公平性"**，让选手专注文本解析、切片、检索过滤排序

**亚军方案**（【转述】CSDN <https://blog.csdn.net/m0_37733448/article/details/147960669>，2025-05-14，A 榜第 1、B 榜第 2；作者原文首发知乎 <https://zhuanlan.zhihu.com/p/7192240626>）。已直连读到全文，抓取 2026-11-05。四个版本的演进（**每一版都有一个明确被前版逼出来的动机，这是本文最值得抄的结构**）：

| 版本 | 做法 | 为什么要有这一版 |
|---|---|---|
| **V1** | 原文切成句子 → 生成**所有连续句子组合** → 每组用 **reranker** 与问题打分 → 取最高分组合 | 出发点：reranker 既然能判相关性，也应该能定位答案句 |
| **V2** | 先用 **BERT 问答模型**抽出关键答案片段做"核心关键词"，只保留**包含该关键词**的句子组合，再 rerank | V1 的毛病：reranker 看整体语义，会漏掉"篇幅小但关键"的细节 |
| **V3** | 分析 BERT 的 `start_logits`/`end_logits` 概率分布，阈值 + top-k 取出**多个**答案片段当关键词集，要求保留文本**同时包含全部关键词**，再 rerank | V2 的毛病：单关键词表达不了多信息点答案 |
| **V4** | 取 top-20 起止位置，用**最小起点 / 最大终点**为基准**向两端扩到最近的自然段落边界**，**去掉 reranker** | V3 的毛病：计算开销大；V4 直接提段落，效率最高、实用性最好 |

- **可复现性：很高。** 四个版本全部只用到公开 BERT QA 模型 + reranker，无训练、无私有数据、无大模型。
- 作者自己的收口建议：**常规场景 V4 就够；追精度用 V3+V4；实际 RAG 系统里 V4 最实用。**
- **对本仓的迁移点**：这是"**检索到了正确文档块之后，如何精确落到答案句**"的标准解法，而且恰好就是本仓"条文级定位"要解决的问题。V4 那一步（**用 QA 模型的起止 logits 定位，再扩到自然边界**）可以直接搬，代价是要一个中文抽取式问答模型。
- **必须点出的反证**：这条赛道**禁止用 LLM**，所以它的最优解在"允许用 LLM"的场景里未必最优。作者 V4 明确说"去掉 reranker 大幅提高效率"，那是因为禁 LLM 的约束下算力成了硬门槛；如果允许调用强 LLM，V4 的效率优势就不再是决定性的。

### 2.13 CCKS 2025「工业技术文档多模态推理问答」—— 一个把代码全公开的参赛队

【一手·代码仓库】<https://github.com/DXWEIE/ccks2025_pdf_multimodal>（README 已读，抓取 2026-11-05）；【转述·技术博客】<https://adg.csdn.net/69524ae05b9f5f31781b65a0.html>（2025-08-09，含完整代码片段）。

赛题约束（很关键，说明了这类赛的边界）：
- PDF 本质是**图片格式**，不能直接转文本
- 初赛 4 选 1 选择题（准确率），复赛问答题（F1 + ROUGE）
- **只允许用开源模型，参数量不超过 32B**
- **不允许用训练集之外的 QA 数据微调**

它的做法：
| 段 | 做法 |
|---|---|
| **检索** | PDF 逐页 600 dpi 转图 → **gme-Qwen2-VL-7B-Instruct 把每页图片编码成 3584 维向量** → 按问题向量做**跨模态（文本 query ↔ 图片页）相似检索**，取 top-3 页 |
| **融合重排** | 无独立重排；改用**问题分类分流**：`if "第X页" and "图"` → 直接从问题里正则取出页码，只喂那一页；否则走检索 |
| **生成** | Qwen2.5-VL-32B-Instruct + LoRA 微调（rank 8 / alpha 32 / 5 epoch / lr 1e-4），vLLM 4 卡 TP；后面再接一道"**风格修正**"小模型调用，把长答案压成 20 字以内的规范答法 |
| **自检拒答** | **无** |

- **它自报的负面结论（比成绩有用）**：①**OCR 没用** —— "OCR+Qwen3 微调后也差不多是 98%-99%，本身没有提升空间"，所以放弃了 OCR 路线；②相对位置关系类问题答不准；③LoRA 微调 + 推理开销极大（**训练 ~300 GB 显存 / A100 约 7 小时；初赛 4000 条约 7 小时，复赛 3500 条约 6 小时**）。
- **可复现性：高**（代码全公开），但**算力门槛高**（300 GB 显存）。
- **对本仓的迁移点**：①"问题里已含页码/位置线索时，跳过检索直接定位"这条分流规则；②"**输出后接一道风格归一化**"——回答短、格式统一，这一条在法规问答里同样需要（条文引用格式）；③"**OCR 未必有用**"是一个反直觉的实测结论，值得记住。

### 2.14 CCIR 2024 —— 未查到 RAG 类赛道

【转述·公众号】中国移动研究院通稿 <http://mp.weixin.qq.com/s?__biz=MzI4NTcyMjA0NQ==&mid=2247596440&idx=1&sn=d433627a497640513c91699e7ca06d14>（2024-10-23）：
- CCIR 2024 由**中国移动研究院**承办，赛道是「**基于大模型的文本内容智能评判**」—— 做的是"大模型当裁判"，**不是 RAG/检索**。
- 规模：**近 200 支队伍**。一二三等奖来自 bilibili、北京邮电大学、同花顺。
- 同段还提到该评测中心四年办过的赛道里有「**基于通用大模型的知识库问答**」—— 但那是往届，**具体年份与冠军方案未查证**。

⇒ **结论：CCIR 2024 没有公开的 RAG/文档问答赛道。CCIR 2025 有（法律知识检索与生成），已写在 §2.7。**

## 3. 国内赛 vs 国际赛的差异（7 条，每条带证据）

> 国际侧的对照材料全在 A 线报告 [01-kddcup-crag.md](01-kddcup-crag.md)。本节只做**逐条对撞**，不重复 A 线的队伍拆解。

### 差异 1｜"队伍数"这个指标，国内是加总口径，国际是单赛道口径

- 国内：CCKS 2024「2,400+ 队」= **11 条赛道加总**；OpenKG 页面给出的单赛道数字是 **223～1,237 队**。【一手】<http://openkg.cn/eval/>
- 国际：KDD Cup CRAG 2024「384 队」= **一条赛道**。【一手·组织者论文】IEEE Data Eng. Bull.
- ⇒ **同一句话"CCKS 比 CRAG 大"在加总口径下是 6 倍，在单赛道口径下反过来（223 < 384）。** 引用时必须写明口径。
- **反直觉的旁证**：CCKS 2025 单赛道最高是「工业技术文档多模态推理问答」**489+ 队**，仍低于 CRAG 的 384 队是同量级而非碾压。【转述·知乎赛事合集】<https://zhuanlan.zhihu.com/p/1936544200641451546>（2025-08-05）。

### 差异 2｜国内赛的"生成"环节被规则性地削弱，国际赛不削弱

- 国内：CCF BDCI 运营商 RAG 赛道**明令禁止用 LLM 生成答案、禁止用 LLM 压缩文本、禁止用 LLM 抽取**，理由是"消除大模型的使用对大家的不公平性"。【一手·赛题规则转述】<https://github.com/Jiadong001/DS2024-Course-Project>
- 国内：CCKS 2023 KBQA 任务书**禁止使用未公开/需授权的代码或工具**，且"**不允许基于测试集或 KB 用规则 Case By Case 解决问题**"。【一手·参赛者协议】<https://www.biendata.net/competition/ccks2020_ckbqa/rules/>
- 国际：CRAG 允许任意 LLM、任意外部数据，只禁"用测试答案建映射表"。【一手·组织者论文 §E.3】（见 A 线 §5.3）
- ⇒ **国内赛更倾向把评测拆成"可公平比较的组件"**，代价是**赛题与真实生产场景脱节**（真实 RAG 一定会用 LLM）。
- **这条直接决定本仓该抄什么**：国内这几条禁 LLM 赛道的解法（段落级压缩、句子窗口搜索）**在允许用 LLM 时仍然有效，但不再是瓶颈**。

### 差异 3｜国内赛的防作弊靠"赛后人工审代码"，国际赛靠"私有测试集 + 断网"

- 国内：CCKS 各任务书反复出现同一条 ——"**复赛前 3（或 4）名队伍必须提交代码（及编辑后的模型 checkpoint）进行复现审核，无法提交代码或结果相差较大将取消名次并依次递补**"。【一手】<https://tianchi.aliyun.com/competition/entrance/532472>（CCKS2026 知识编辑赛制，原文）；CCKS 2024 知识编辑任务书同款条款（docx 摘要）。
- 国内：CCKS 2020 有一位组织者**在论坛公开承认**"去年就有一个前三名的队伍被取消了资格"，原因是 case-by-case 或把测试集问题人工找答案放进训练集。【一手·论坛原帖】<https://www.biendata.net/forum/view_post/1188/>（2020-09-30 提问，2020-10-09 组织者 NICKLIN 回复）
- 国际：CRAG 改成**私有测试集 + 隐藏 auto-eval 提示词 + 推理时断网**，因为公开榜"很快被刷到 100% 准确"。【一手·组织者论文 §E.3】
- ⇒ **国内靠"事后审"，国际靠"事前堵"。** 事后审的漏洞很明显：**审的是前 3 名，第 4 名以后没人审**；而且 2020 年那条论坛帖里，选手的原话是"现在一共一千多的数据，几十次的测试次数，太容易 case by case 解上去了"—— **提交次数多 + 测试集小 = 刷榜空间大**。
- **这是本报告最重要的一条反证，见 §4。**

### 差异 4｜国内 KGQA 的主战场是"结构化图谱查询"，不是"非结构化文档检索"

- 国内：CCKS 的 KBQA 任务一律要求"**最终答案必须来自给定的知识库**"，输入是三元组图谱（如人物图谱 256,378 实体 / 785,553 三元组），输出是实体或属性值。【一手·任务书摘要】人物 KG 任务、CKBQA 任务均如此。
- 国际：CRAG 是**网页检索 + 生成**，语料是 HTML 网页 + 模拟 API，输出是自然语言答案 + 引用。
- ⇒ **两边的"检索"根本不是一件事**：国内是"在图上找路径 / 生成 SPARQL"，国际是"在网页里找段落"。
- **对 RAG 的启示**：国内 KGQA 的经验（实体链接该强化还是绕开、多跳怎么迭代）**不能直接搬到文档 RAG**；反过来，文档 RAG 的 chunking/rerank 经验也解决不了图谱查询。

### 差异 5｜"拒答"在国际赛是核心得分项，在国内赛基本不存在

- 国际：CRAG 的评分**对错误答案重罚**，导致"拒答"成为最大单项（A 线 §5.1：MARAGS 靠重标把 CRAG 分从 −0.204 拉到 +0.186；Dianping 靠课程学习把 truthfulness 从 +0.027 拉到 +0.151）。
- 国内：**本报告详评的 7 条国内方案里，自检拒答环节全部为"无"。**
  - CKBQA 2024 亚军：只有 `quit` 终止符（跳数够了），不是"答不了"
  - 人物 KG 问答参赛论文（Springer）：ReAct 循环，无拒答
  - 中医 TCMBench 冠军：纯微调，无拒答
  - CCIR Cup 2025 第 3 名：论文 Limitations 自承无法处理复杂多步推理，但**没有拒答机制**
  - CCF BDCI 对话式 RAG 特等奖：无拒答
  - CCKS2025 工业文档队：无拒答
  - CCF BDCI 运营商 RAG 亚军：赛道禁止 LLM，无从拒答
- **唯一的例外**：CCKS 2024 知识编辑赛制的复赛权重里有 `0.2ES`（Edit Success）与 `0.25GEN`、`0.3Con`（Consistency），把"改对"和"别改坏"分开算 —— 这是一种**结构化的自我约束**，但不是拒答。【一手】<https://tianchi.aliyun.com/competition/entrance/532472>
- ⇒ **想抄"拒答"只能抄国际赛（CRAG），国内赛在这块是空白。** 这条差异决定了本仓的拒答设计没有国内先例可循。

### 差异 6｜国内赛的冠军方案更难拿到，公开率显著低于国际赛

统计本报告涉及的 9 条国内赛道：

| 赛道 | 冠军方案是否公开 | 证据档 |
|---|---|---|
| CCKS 2023 CKBQA | 只有企业新闻稿，一句技术描述 | 【转述】 |
| CCKS 2024 CKBQA | **冠军身份都未查到** | — |
| CCKS 2024 人物 KG 问答 | 冠军未查到；亚军只有名次 | 【转述】 |
| CCKS 2024 TCMBench | 校方通稿给了分数 + 数据来源，方法一句 | 【一手·通稿】 |
| CCKS 2024 知识编辑 | 冠军未查到 | — |
| CCKS 2024 零样本抽取 | 冠军未查到，只有官方基线 | 【一手·仓库】 |
| CCKS 2025 文档结构化 | 冠军给了方法名（无细节） | 【转述】 |
| CCIR Cup 2025 法律 RAG | **冠军只有通稿；第 3 名有完整论文** | 【一手·论文】 |
| CCF BDCI 多条 RAG | **特等奖/亚军都有详细复盘** | 【转述·公众号】 |

- 国际侧对照：CRAG 前 3 名**全部**有 arXiv 技术报告或官方 spotlight；db3 还开全部代码。【一手】A 线 §3.3。
- ⇒ **国内公开率约 3/9（CCIR 第3名、BDCI 两条），且其中两条是"亚军/第3名"而非冠军。冠军级方案几乎不公开。**
- **实务含义**：想学国内冠军的具体做法，**大概率学不到**；能学到的是"第 2～3 名 + 企业亚军"的复盘。这不是巧合 —— 冠军多为企业队，方案是商业资产。

### 差异 7｜国内赛的指标更"可刷"，国际赛的指标更"抗刷"

- 国内：CCF BDCI 对话式 RAG 用 **ROUGE-L**，冠军队自己在复盘里写"针对 ROUGE-L 尝试过很多**偷分方式**，比如拼接多次输出"。【转述·公众号】<https://developer.volcengine.com/articles/7459667653465276470>
- 国内：CCKS 2024 人物 KG 用 **Averaged F1**（逐样本算 F1 再平均）。
- 国际：CRAG 用**人工评测 + 私有测试集 + 流量加权**，且组织者承认前 10 名里 auto-eval 与人工只有 6/9 重合。【一手】A 线 §5.3。
- ⇒ **ROUGE-L 这类"字面重叠"指标天然可刷**（拼长、拼多次输出、copy 原文），**F1 逐样本平均会被"答一堆候选"抬高**（召回高、精确低也能拿分）。这两个指标在国内被广泛使用，是"分数可信度"的实质风险。
- **但要说清**：**没有证据表明任何一支队伍实际刷分了。** 我说的只是"指标本身留有空间"，不是"有人刷了"。这条区别必须保留。

### 4.2 搜出来的实质结论：分三问回答

#### 问一：CCKS 的"含金量"有没有公开质疑？

#### 问二：这些国内方案有多少靠"私有数据 / 超大模型 / 硬编码规则"赢的？

这是本任务最实质的一问。我按**每个方案逐条判定**，并给出判定依据：

| 方案 | 私有数据？ | 超大模型？ | 硬编码规则？ | 判定 |
|---|---|---|---|---|
| **CCKS 2023 CKBQA 冠军（诺谛）** | **很可能**（未公开） | 未说 | **很可能**（未公开） | **不可判**。只有新闻稿，三样都无法核实。**唯一确定的事实是"只用了 7,000 余条训练数据"——这反而不像靠数据堆出来的。** |
| **CCKS 2024 CKBQA 亚军（多跳感知）** | 否（用公开 OneKE） | 是（微调大模型） | 部分（SPARQL 逻辑表达式压缩是规则） | **半可复现** |
| **CCKS 2024 人物 KG 参赛论文（Springer）** | 否 | 是（LLM 生成 500 条解题轨迹） | 否 | **可复现**（但要 LLM 调用预算） |
| **CCKS 2024 TCMBench 冠军（大工）** | **是**（自建三源训练集：医疗考试集 + 中医考试网 + 中医大模型训练集） | 是（扫多个基座） | 部分（按任务定制指令模板） | **不可复现**。核心资产是那份自建训练集，没有公开 |
| **CCKS 2024 零样本抽取** | 否（官方基线 OneKE） | 是 | 否 | **可复现**（官方给了完整流程） |
| **CCKS 2024 知识编辑** | 未查证 | 未查证 | 未查证 | **不可判** |
| **CCIR Cup 2025 冠军（山大）** | 未公开 | 未知 | 未知 | **不可判**（只有通稿） |
| **CCIR Cup 2025 第 3 名（中科院计算所）** | 否（公开 Qwen3 系） | 是（Qwen3-235B-A22B） | 否（四个 prompt 全公开） | **可复现**，但**成本高**（235B 模型跑 5,065 条 query，每条要过改写、文献筛选、条文筛选、生成四道 LLM 调用） |
| **CCF BDCI 对话式 RAG 特等奖** | 否（CORAL 公开集） | 是 | 部分（实体召回用 spaCy + 正则） | **可复现**，唯一缺口是"排列打分"的具体打分器没给 |
| **CCF BDCI 运营商 RAG 亚军** | 否 | **否**（赛道禁 LLM） | 部分（V4 用段落边界规则） | **高度可复现** |
| **CCKS2025 工业文档队** | 否（代码全公开） | 是（Qwen2.5-VL-32B + 300 GB 显存训练） | 部分（正则抽页码） | **可复现但算力门槛高** |
| **CCKS2025 文档结构化冠军 BetterRAG** | 未查证 | 未查证 | 未查证 | **不可判** |

**汇总判读**：
- **12 个方案里，明确"可复现"的 5 个**（人物 KG 论文、零样本抽取官方基线、CCIR 第 3 名、BDCI 对话式 RAG、BDCI 运营商 RAG），**再加 1 个"可复现但贵"**（工业文档队）。
- **明确"不可复现"的 1 个**（TCMBench 冠军 —— 靠自建训练集）。
- **完全不可判的 4 个**（2023 CKBQA 冠军、2024 知识编辑、CCIR 2025 冠军、2025 文档结构化冠军）—— **都是冠军**。
- ⇒ **"冠军不可判、亚军可复现"是本报告最强的结构性发现。** 这不是偶然：冠军多为企业队（诺谛、阡陌），方案是资产；亚军/第 3 名多为高校队，需要论文产出，所以公开。

**关于"超大模型"这一项的具体读数**：CCIR 第 3 名用 Qwen3-**235B**-A22B 做改写与生成、Qwen3-**14B** 做筛选、Qwen3-Embedding/Reranker-**8B**；CCKS2025 工业文档队用 Qwen2.5-VL-**32B** + 300 GB 显存训练 7 小时。**⇒ 国内头部的算力门槛已经在 32B～235B 区间，个人开发者用 7B 级别去追是追不上的。** 这对本仓（本地部署、便携）是一个明确的负面信号：**这些冠军方案的整体算力配置，本仓用不了。**

**关于"硬编码规则"这一项**：CCKS 参赛协议**明文禁止** case-by-case 规则，且 2020 年确有前三名被取消资格。**⇒ 规则不是"没人管"，是"被抓到就取消"。** 但要注意：**赛制允许的"领域规则"与"case-by-case"界限模糊** —— CCKS 2025 工业文档队用正则从问题里抽页码、CCF BDCI 对话式 RAG 用 spaCy 抽实体，这些都属于"允许的规则"。**界限在哪，官方从未给过定义**，2020 年那位选手的原话就是这个诉求："希望主办方给出明确 guideline，什么样的规则是允许的，什么样是不允许的"。**六年过去，这条 guideline 我仍然没有找到。**

#### 问三：这些国内方案的"分数"能不能横向比？

**不能**，三条理由都有证据：
1. **指标不同**：CCKS 人物 KG 用 Averaged F1；CCIR Cup 2025 用 0.5×NDCG@5 分 + 0.5×(BERT-F1/Keyword_Accuracy)；CCF BDCI 对话式 RAG 用 ROUGE-L；CCF BDCI 运营商 RAG 用"检索正确率（Top-3 命中）"。**四个赛道四种指标，没有一个可跨赛道比较。**
2. **同一赛道跨年不可比**：CCKS CKBQA 每年换图谱（2023 是 6,600 万三元组的开放图谱，2024 人物图谱只有 25.6 万实体 / 78.5 万三元组），**难度差 2 个数量级**。
3. **分数上限被指标扭曲**：CCIR Cup 2025 冠军 A 榜 39.148 / B 榜 41.0224，第 3 名 test 39.38 —— **冠军和季军差不到 2 分（百分制里不到 2%）**。⇒ **这条赛道的头部区分度极低，"名次"比"分数"更可靠，而"分数差"几乎不含信息。**

### 4.3 一条我自己发现的、对"能不能抄"最要紧的反证

**CCKS 2024 的 11 项任务里，与本仓场景（法规/标准文档问答）真正同构的只有 1～2 项**（CKBQA 是图谱查询不是文档检索；人物 KG 是图谱；知识编辑是改参数；零样本抽取是建图；中医是考试题微调）。**唯一同构的是 CCKS 2025 任务 2「人工智能领域论文复杂问题问答」——而它的任务书、榜单、获奖方案我全部没查到。**

⇒ **本报告最诚实的结论是：国内 CCKS 这条线上，与本仓同构的赛道只有一条，且它完全没公开。真正能直接抄的，是 CCIR Cup 2025（法律 RAG，第 3 名论文）和两条 CCF BDCI RAG（对话式、运营商）。** 前面所有 CCKS 的内容，价值在"看懂国内赛在比什么"，不在"抄冠军"。

## 5. 中文 RAG 评测集（**这四个都不是竞赛**）

> 先把边界写在最前面：**下面四个都是"数据集/榜单"，不是竞赛**。没有奖金、没有名次、没有截止日期。它们衡量"模型/系统好不好"，不产生"谁赢了"。把它们和 CCKS/CRAG 并列讨论，是常见错误。

### 5.1 RGB（Retrieval-Augmented Generation Benchmark）—— 测"抗干扰"，不是测"查得准"

- 【一手·论文摘要】<https://arxiv.org/abs/2309.01431>（*Benchmarking Large Language Models in Retrieval-Augmented Generation*，**AAAI 2024 录用**）。抓取 2026-11-05。
- **出处**：中科院软件所 中文信息处理实验室（Jiawei Chen / Hongyu Lin 等）。代码与数据 <https://github.com/chen700564/RGB>。
- **测什么**：把 RAG 需要的四项基本能力**拆成四个独立测床**——**噪声鲁棒性（noise robustness）、负例拒答（negative rejection）、信息整合（information integration）、反事实鲁棒性（counterfactual robustness）**。中英双语语料。
- **它的结论（这才是它最值钱的部分）**：LLM 有一定噪声鲁棒性，但在**负例拒答、信息整合、处理虚假信息**三项上"仍有很大困难"。更狠的一条（【转述·论文摘要索引页】<https://huggingface.co/buckets/huggingchat/papers-content/tree/2309/2309.01431.md>）：**即使模型本身知道正确答案、且提示里已经警告"检索内容可能有风险"，它仍然倾向于相信并优先采用检索到的信息，而不是自己的知识。**
- **谁在用**：AAAI 2024 之后成为 RAG 拒答方向的常用对照基准；国内做 RAG 的论文与开源框架普遍引用。
- **局限（明确写）**：它是**评测基准**，主语是"LLM 在给定检索结果下的表现"，**不评测检索器本身**。用它来证明"我的检索做得好"是误用。
- **对本仓的直接用途**：**"负例拒答"这一项就是本仓最缺的自检拒答**。RGB 的四个测床本身就是一份拒答能力的验收清单。

### 5.2 CRUD-RAG —— 唯一把"检索器"和"知识库构建"也纳入评测的中文基准

- 【一手·论文摘要】<https://arxiv.org/abs/2401.17043>；期刊版 **ACM TOIS 2025, 43(2), 41.1–41.32**，DOI `10.1145/3701228`（【转述·NSTL 书目】<https://fz.nstl.gov.cn/paper_detail.html?id=e70e1eda7b75964f9719824d255e944d#1>）。抓取 2026-11-05。
- **测什么**：把 RAG 应用场景按 **CRUD 四分**——
  - **C**reate：加外部信息做创造性输出（诗、故事、代码）
  - **R**ead：知识密集型问答/对话/推理
  - **U**pdate：用检索内容修正原文里的错（拼写、语法、事实）
  - **D**elete**：把长文压成短文（摘要）
  每个类别都建了独立数据集。
- **它的核心批评（原文）**：现有基准"**绝大多数只评问答**"，"**只评 RAG 流水线里的 LLM 那一环，忽略了检索器与外部知识库的影响**"。它把 **retriever、context length、知识库构建、LLM** 四个因素都做了对照分析。
- **谁在用**：中文 RAG 论文的标准引用之一（ACM TOIS 正式发表，引用量在涨）。
- **局限**：中文场景为主，任务是"中文长文本 + 四类任务"，**不含法规/标准这类强结构化、强引用要求的场景**。
- **对本仓的用途**：它把"**知识库构建**"当成一个可评测的变量 —— 这一条与本仓"PDF 解析→切片→入索引"的质量问题同构。它证明"同样的 LLM，知识库构建方式不同，结果差别很大"。

### 5.3 DuReader_retrieval —— 中文段落检索的事实标准，但它只是"检索"，不含生成

- 【一手·论文】<https://ar5iv.labs.arxiv.org/html/2203.10232>（*DuReader_retrieval: A Large-scale Chinese Benchmark for Passage Retrieval from Web Search Engine*）。抓取 2026-11-05。
- **数据规模（【转述·数据卡】<https://modelers.csdn.net/69a782767bbde9200b9cf26a.html>，需以论文为准）**：训练集约 **8.6 万** `<q, Pq>` 样本（由 DuReader 2.0 构建）；开发集 **2K**；测试集 **4K**；段落语料库 **809 万段**（从真实网页文档抽取）。问题全部来自**百度搜索真实用户日志**。
- **测什么**：给定 query，从 809 万段里找回相关段落。指标是检索类指标（MRR / Recall 等）。
- **谁在用**：中文稠密检索模型（BGE 系列、m3e 等）的标准训练/评测语料之一；C-MTEB 的检索子集里也有同源任务。
- **局限（论文自己点出的）**：构建方式是**远程监督（distant supervision）**，因此存在**假阴性**（实际相关但被标成负例）——论文原文承认这是段落检索数据集的通病，且大模型检索出的段落可能比标注的正例更好。**⇒ 用它算出来的分数不能当绝对真值。**
- **注意区分**：它**不是** DuReader-RAG。DuReader_retrieval 是 2022 年的**纯段落检索**基准；本线调研**没有找到**名为「DuReader-RAG」的独立评测集，**明确记为未查证**（见 §6）。

### 5.4 C-MTEB —— 选 embedding 模型用的榜，不是 RAG 评测

- 【一手·仓库】<https://github.com/FlagOpen/FlagEmbedding/tree/master/C_MTEB>（BAAI 维护）。
- **测什么**：**35 个中文数据集、6 类任务**——Retrieval（T2Retrieval / MMarcoRetrieval / CmedQA，指标 nDCG@10）、Reranking（T2Reranking / MMarcoReranking，MAP）、STS（ATEC / BQ / STS-B，Spearman）、Pair-Classification（Cmnli / Ocnli，AP）、Clustering（CLSClusteringS2S，V-measure）、Classification（TNews / IFlyTek，Accuracy）。【转述·技术文档】<https://raw.githubusercontent.com/ForceInjection/AI-fundamentals/8a586844f98c63ed25692d88b25c6f2a85a5e7dd/07_rag_and_tools/rag_basics/chinese_rag_embedding_model_selection.md>
- **谁在用**：所有中文 embedding 选型的第一站。
- **局限（两条，都要写清）**：
  1. **总榜均分 ≠ RAG 效果**。做 RAG 只该看 **Retrieval 单项**，Classification 等任务对 RAG 参考价值很低。
  2. **榜单会被"应试训练"**。同一模型在 MTEB 82.3 / BEIR 78.6 / C-MTEB 74.1，差异来自数据集切分、硬负例构造、长度截断三处不一致 ⇒ **跨榜不可比**。【转述·CSDN 问答】<https://ask.csdn.net/questions/9273419>（2026-02-08）。另一条同向的【转述】："榜首几个月就易主一次，榜上高分未必等于在你的数据上好用"<http://mp.weixin.qq.com/s?__biz=Mzg3Njk4MjkyNg==&mid=2247483713&idx=1&sn=7682c15b023438204b9593ae6befdeee>
- **对本仓的用途**：**只用来缩候选范围，最终排名必须用自己的数据测。** 这条建议来自上述两篇二手文章，但结论与 RGB/CRUD-RAG 的"基准不可跨用"是一致的。
