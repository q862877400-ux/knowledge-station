## 〇、先给结论：四篇论文不是在教四种技术，是在量同一件事的四个位置

我把四篇的消融表并排放之后，看到的是**一个统一结论被四个独立实验反复确认**，而这条结论**恰好违反直觉**：

> **文档结构不帮你"找到"，它帮你"不认错"。**
>
> 四篇里，凡是把结构塞进**召回**的，召回要么不显著提升、要么**反而变差**；凡是把结构塞进**证据组装与核验**的，下游质量全部上升。

| 论文 | 结构放进哪一层 | 召回指标 | 生成/诊断指标 |
|---|---|---|---|
| **ETSI Normative RAG**（arXiv 2604.09868） | 索引（parthood + citation 图） | **recall 无显著变化**（作者原话 "does not seem to have a statistically significant impact on recall"） | precision、MRR 上升 |
| **GEMS-RAG**（arXiv 2610.33277） | 分层先验 + 图扩展 | **去掉分层先验，检索反而 +0.24** | 但生成 −0.08、可靠性 −0.36、总分 **−0.22** |
| **IndusSpec**（EMNLP 2026） | 索引期把规则**绑**到 scope path | — | F1 0.461 → **0.557**；Table 类 **+120.2%** |
| **GB/T-Bench**（arXiv 2608.06312） | 不放进检索，放进**审查技能拆分** | diagnosis recall 0.5203 → 0.6906 | CMCS 0.3280 → **0.5094** |

**⇒ 这条结论对我们意味着什么**：仓库里那条「提召回 ≠ 提排序，两者要分开治」，**不是我们一家手搓实验的偶然产物**——ETSI 那篇用完全独立的语料和自建尺子，量出了同一件事。而我们要动的地方，因此不是「给索引加结构」，是「**在召回之后、生成之前，加一层按结构组装的核验**」。

## 一、四篇论文的骨架（只留能被复算的部分）

### 1.1 GB/T-Bench：把「标准审自己的稿」做成了可诊断的题

| 项 | 数 |
|---|---|
| 语料 | **488 篇真 GB/T**，切成 **64,991 个 section** |
| 错误实例 | **7,306 条**（均值 14.97/篇，10–18） |
| 体系 | **5 维 × 25 类** |
| 标注可靠性 | 抽 30% 人工复核：维度一致率 **96.33%**（κ=0.947）、错误类型 **95.92%**（κ=0.955） |
| 单位 | 华南师大 + 上海交大 + **中国标准化研究院** |

**五个维度与 25 类错误**（`Drev = {DSTR, DSCP, DNMS, DTER, DNREF}`）：

| 维度 | 管什么 | 落在哪一层 |
|---|---|---|
| **DSTR** 结构审查 | 章节组织/顺序/标题命名/附录属性是否符合 GB/T 1.1 | **文档级** |
| **DSCP** 范围审查 | 正文是否超出「范围」章声明的适用对象与边界 | **文档级** |
| **DNMS** 模态强度审查 | 「应/宜/可」是否承载了正确的义务强度 | **条款级** |
| **DTER** 术语一致性审查 | 正文用词是否与「术语和定义」章一致 | **条款级** |
| **DNREF** 规范性引用审查 | 引用清单是否完整、准确、无冗余；正文引用与清单是否对得上 | **条款级** |

**它的结果——这是全篇最有价值的一张表**：

| 方式 | DMTR_8 | DMTR_9 | DMTR_10 | Recall | CMCS |
|---|---:|---:|---:|---:|---:|
| **人类专家** | 0.9442 | 0.9021 | 0.8479 | 0.8308 | **0.6640** |
| GPT-5.6-sol | 0.5435 | 0.3696 | 0.2174 | 0.5203 | 0.3280 |
| 闭源平均 | 0.3465 | 0.2189 | 0.1256 | 0.4172 | 0.2504 |
| DeepSeek-v4-Pro | 0.2193 | 0.1230 | 0.0492 | 0.3961 | 0.2269 |
| 开源平均 | 0.1324 | 0.0664 | 0.0291 | 0.3043 | 0.1671 |
| **GB/T-Reviewer（GPT-5.5）** | **0.9026** | **0.8445** | **0.7860** | **0.7314** | **0.5094** |
| GB/T-Reviewer 闭源平均 | 0.7698 | 0.6273 | 0.5080 | 0.6311 | 0.4160 |

**分维度拆开（GPT-5.6-sol 等几个强模型的单轮表现）**：

| 维度 | 分数区间 | 读法 |
|---|---|---|
| DSTR 结构 | 0.3199 – **0.7581** | 有显式结构线索，模型能做 |
| DSCP 范围 | 0.4333 – **0.8181** | 同上，甚至更好 |
| **DNMS 模态** | 0.1697 – 0.4166 | **崩** |
| **DTER 术语** | 0.1772 – 0.2540 | **最崩** |
| **DNREF 引用** | 0.3302 – 0.4828 | 弱，且对冗余引用/规范性 vs 资料性混淆不稳 |

作者原话：「current LLMs are effective at identifying document errors with explicit structural cues, but remain limited in **rule-intensive reasoning involving normative judgment, definition consistency, and cross-section verification**.」

**它的消融——我认为是全篇最重要的发现**：

| 去掉什么 | CMCS | DMTR_10 |
|---|---:|---:|
| 完整 GB/T-Reviewer | **0.5094** | **0.7860** |
| **去掉 Direct-All（全局通读一遍）** | **≈0.22** | **≈0.08** |
| 去掉维度专家 | ≈0.44 | ≈0.57 |
| 去掉错误类型专家 | ≈0.48 | ≈0.60 |
| 去掉规则/局部扫描器 | recall、CMCS、DMTR_10 同时下降 | — |

> **去掉全局通读，比不做拆分还差**（0.22 < 单轮 0.328）。
> 作者的解释：「Direct ALL 在任何专家推理开始前，先建立对整篇文档的统一理解。没有这个整体上下文，下游 agent 在碎片化的证据上工作。」

**⇒ 原理**：**拆分的收益，依赖拆之前有没有一张全局地图。** 先碎后拼，比不碎更糟。这一条直接否定「直接把文档切成块、交给多个 agent 分别看」这种做法。

### 1.2 IndusSpec：结构是"乘数"，不是"加数"

【一手·全文】EMNLP 2026 Main，pages 33282–33311。

**问题设定**：工业标准里，**同一个词在不同章节指不同规则**。作者举的例子：`Grade 50` 在「Chemical Requirements」下是碳当量上限（随板厚分档），在「Mechanical Requirements」下是屈服/抗拉强度。

**它的表示法**（三步）：

1. **Section-as-Concept**：把每个章节标题当成一个**概念**，从根到当前节组成 **scope path** `pi = s1 → s2 → … → sk`。
2. **Knowledge Unit**：`Ui = (pi, xi)` —— **内容与它的结构上下文绑在一起存**，不许分开。
3. **Rule-aware triplet**：每条规则建一个 **case 节点**，条件用 `has_condition_AND/OR` 连；**嵌套的 AND/OR 用 `logic_group` 节点当括号**（`A ∧ (B ∨ C)` 用 logic_group 保住结合顺序）。表格的行/列条件与单元格值当成**一个规则单元**，不许拆散。

**结果（三个真实工业标准：ASTM A578/A578M、API 2W、ASTM A6/A6M）**：

| 方式 | A578 F1 | API_2W F1 | A6/A6M F1 |
|---|---:|---:|---:|
| LLM 单问 | 0.000 | 0.000 | 0.000 |
| **LLM 喂全文** | 0.372 | 0.376 | 0.273 |
| Text-only RAG（BM25 / Dense 最好一档） | 0.348 | 0.372 | 0.179 |
| Document-to-Graph RAG（GraphRAG） | 0.410 | 0.416 | 0.252 |
| **KG-based RAG（MindMap/KG-Retriever）** | 0.601→0.706 | 0.413→0.435 | 0.339→0.271 |
| **Ontology-based KG-RAG** | **0.719–0.722** | **0.564** | **0.543** |

平均值：**Text-only 0.257 → Document-to-Graph 0.283 → KG-based 0.461 → Ontology 0.557**。

**它的三格消融（API_2W 规则数据）——这是我见过最干净的一次因子分解**：

| 配置 | F1 |
|---|---:|
| LLM 喂全文 | 0.447 |
| **只加结构（+Ontology）** | **0.421（比喂全文还差）** |
| **只加规则（+KG）** | **0.591（+32.2%）** |
| **结构 + 规则（+Ontology+KG）** | **0.612（在 +KG 上再 +3.6%）** |

**按题型拆**（对比 KG-based）：

| 题型 | KG-based | Ontology-based | 变化 |
|---|---:|---:|---:|
| Rule | 0.601 | 0.668 | +11.1% |
| Multi-hop | 0.515 | 0.573 | +11.3% |
| **Table** | **0.287** | **0.632** | **+120.2%** |

**⇒ 两条原理**：

1. **结构本身零价值，甚至负价值**（0.421 < 0.447）。它只有在**有"规则单元"可绑**的时候才兑现。**结构是乘数：乘的是规则结构的量。** 只有骨架没有肉，骨架是负担。
2. **结构收益极不均匀**：规则类 +11%，表格类 **+120%**。**表格是结构收益最高的地方**——因为表格的"同一行同一列"就是天然的条件-结论绑定。

**它最有说服力的是一张错误案例表（Table 4）**，我原样记下，因为它是"结构能救什么"的最精确证明：

| 方式 | 检索到的证据 | 输出 |
|---|---|---|
| Text-only RAG | 直接命中 Table S8.1 里 `225<厚度≤300` 那一行 | **22 mm ✅**（靠表面匹配**侥幸**对） |
| Document-to-Graph RAG | 只拿到归一化后的厚度区间摘要，丢了确切行与对应值 | `200–250 excl; 250–300 excl` ❌ |
| **KG-based RAG** | 拿到了正确的厚度条件，但**混进了 S9 节另一条竞争规则** | **10 mm ❌** |
| Ontology-based KG-RAG | 先把问题**限定在 S8 的平底孔标定语境**，再在该 scope 内匹配条件与结论 | **22 mm ✅** |

> **这张表的真正信息量**：**做了半套结构的系统（KG-based）比不做结构的（text-only）答得更错。**
> 因为半套结构把"有关系的规则"拉进来了，却没有"范围"去判断哪一条适用范围对。
> **⇒ 结构做一半，比不做更危险。** 这是"要么做完、要么别做"的硬证据。

### 1.3 ETSI Normative RAG：唯一敢报"没用"的一篇

【一手·全文】arXiv 2604.09868，6 页，ETSI EN 301 489 系列约 50 份标准、约 3000 页。

**信息模型**（把标准建成图）：

- 节点 **InfoUnit** `u = {t, b}`（标题 + 正文），来自目录解析。
- **两类边**：`P` = parthood（文档→节→子节，**每个节点至多一个父节点**）；`C` = citation（**多对多**）。
- **引用解析启发式**（这一条很实用）：
  ```
  Resolve(mention) =
    ui_section        若 mention 只含 {节号}
    Dk                若 mention 只含 {文档名}
    uk_section        若 mention 同时含 {文档名, 节号}
  ```
  「正文只提节号、不提标准名」时，**默认是内部引用**。

**八模块管线**：Parse Sections → Split Chunks → Embed InfoUnits（IBM Granite）→ **Smoothing** → **BM25 Prefilter** → Dense Re-ranker → **RRF(k≈60)** → **Expander & Graph Re-ranker**。

两个值得单独记的式子：

**① 平滑（把图结构压进向量，不做 GNN）**
```
em_j ← α·em_j + (1−α)·Σ_{n∈N(u_j)} em_n
```
`N(u_j)` = 子节点、父节点、兄弟节点、出引用、入引用。**用邻居均值轻量地替代图神经网络。**

**② 图重排（带"反枢纽"正则）**
```
score(n) = α·Σ_{s∈S} 1{n∈N(s)}·cos(em_s, em_q) + β·cos(em_n, em_q) − γ·log(1+degree(n))
```
最后一项 `−γ·log(1+degree(n))` 是**惩罚"枢纽节点"**——连了很多边的节点不该因为连接多就得分高。**这是一个容易被忽略但很关键的细节：图结构天然会把通用条款（引用多、被引用多）顶到前面，那是噪声。**

**结果（800+ 合成问答，8 种配置 × 3 个 K）**：

| 发现 | 原话/读数 |
|---|---|
| 保留结构 | **对 precision 和 MRR 有正效应，对 recall 无统计显著影响** |
| RRF 混合稠密+稀疏 | 对 precision/MRR 正效应，对 recall 无影响 |
| **邻居扩展 + 图重排** | **「does not seem to be effective」**——作者明确说还需要找适合本领域的邻居打分函数 |
| 平滑 | **略微提高 recall**（相对于只保结构/只切块） |
| 综合最优 | **结构 + 切块（超 300 词就切，附表不切）** |

**方法学上最值钱的一件事**（这是我要抄的，不是技术）：

> 他们造合成 Q&A 时，**刻意不重用自己那套图构建逻辑**——退回原始 PDF，当成扁平字符串抽文、切块，再让 LLM 出题、出答案，并要求 LLM **逐字引用最相关的那几段**（作者叫它 **witness strings / fine-grained golden chunks**）。
> 匹配判据：**检索到的块若包含金标块的 ≥75% 子串，就算命中。**
> 理由（作者原话意思）：**避免把评测框架耦合到被评测的索引构建上。**

**⇒ 这条直接回应了你说的"我们自己的手搓实验不严谨"**：这篇的解法不是"再仔细一点"，而是**让尺子和被测系统用两条独立的代码路径造出来**。

### 1.4 GEMS-RAG：多模态标准，以及一组"结构反而伤召回"的读数

【一手·全文】arXiv 2610.33277，语料 **MUTCD**（美国交通控制设施手册，含规章、技术图纸、标准化装置）。

**三条立论**（对标准类文档的三处通病，我们全中）：
1. 把文档当独立 chunk 的集合 → **削弱了决定条款适用范围的层级上下文**；
2. 图只按页/标题/图片级索引 → **拿不到工程符号、标准化装置里的细粒度视觉语义**；
3. 稠密/稀疏检索**不显式建模交叉引用、规则依赖、节-图-表-装置之间的关系**。

**它的做法**：分层解析 → **把图拆成细粒度视觉实体**（不是把整张图当一个单位）→ 建**多模态知识图**（节/图/装置/规章概念/规范性陈述互连）→ 稠密+稀疏+**视觉**三路检索 + 图扩展 + **规则感知排序**。

**结果**：

| 项 | 读数 |
|---|---|
| 12 个视觉语言模型的检索表现 | 19.35–19.63 / 25（**高度一致**） |
| Recall@5 | 86.7% – 88.0% |
| 证据充分性 | 93.3% |
| 视觉裁剪命中率 | 75.3% – 83.5% |
| **Context precision** | **< 50%**（**一半以上喂进生成的是无关证据**） |
| 答题总分 | 85.08 – 88.08 / 100 |
| 严格满分率 | 最高 **80.0%**（Claude Fable 5） |

**消融（这张表最反直觉）**：

| 条件 | 检索/25 | 生成/60 | 可靠性/12 | 总分/100 |
|---|---:|---:|---:|---:|
| GEMS-RAG | 19.35 | 55.18 | 10.90 | **88.08** |
| **去掉 VLM 图筛选** | **19.59（+0.24，更好）** | 55.12（−0.06） | 10.70（−0.20） | 88.06（−0.02） |
| **去掉层级先验** | **19.59（+0.24，更好）** | 55.10（−0.08） | 10.54（−0.36） | 87.86（−0.22） |
| **去掉重排** | 17.78（**−1.57**） | 52.77（**−2.41**） | 10.38（−0.52） | **83.43（−4.65）** |

**⇒ 三条**：
1. **层级先验和图筛选都让检索指标变好不了，反而略降**——与 ETSI 同向。
2. **重排是唯一的大杠杆**（−4.65，是其他项的 20 倍）。**四篇里只要有重排，重排总是最大的单项。**
3. **误差来源的分布**（作者原话）：大部分扣分来自**漏掉定义、例外、数量、阈值、引用**，而不是结论本身错。**⇒ 错误不在"推理"，在"证据不全"。**

**它的不可答（unanswerable）设计值得抄**：30 道锁死的不可答题，分五类原因——`Unsupported Precision`（问手册没写的精度）、`False Presupposition`（假前提）、`Out Of Scope`（超范围）、`Contradicted Premise`（前提矛盾）、`Absent Information`（信息缺失）。**每类都要答"手册未规定该信息"而不是编。** 这是"拒答"的可操作定义。

## 二、把四篇的结论交叉起来：三条可以当公理的

### 公理一：结构改善"选择"，不改善"召回"

四篇里三篇给了同向读数：ETSI（recall 无显著变化）、GEMS（去结构检索 +0.24）、IndusSpec（结构单用 0.421 < 全文 0.447）。

**推论**：把结构放进倒排索引/向量索引的**召回路径**，期望提高召回率，是**方向性错误**。结构应该在**候选集已经产生之后**起作用——限定范围、排除竞争项、判断"这条适用范围对不对"。

> 这与我们库里独立测出的"提召回 ≠ 提排序，两者要分开治"，是同一件事的两个独立证据。

### 公理二：结构是乘数，乘的是"规则单元的密度"

IndusSpec 的三格分解给了定量：**只加结构 −0.026；只加规则 +0.144；结构+规则 +0.165**。

**推论**：**在没有把"条件-结论"抽成结构的地方，加层级不会兑现。** 而**表格是条件-结论最密集的地方**（+120.2%）。

### 公理三：结构做一半，比不做更危险

IndusSpec 的 Table 4：text-only 侥幸对（22mm），**KG-based（半套结构）错到 10mm**——因为它把 S9 节的竞争规则拉进来，却没有"范围"判它适不适用。

GB/T-Bench 的消融是同一个病：**去掉全局通读（只剩下碎片的专家推理），CMCS 0.22 比单轮 0.328 还差**。

**推论**：**"有边但没有 scope"、"有拆分但没有全局图"是两个已知的负收益陷阱**，而且它们的表现是"看起来更高级、实际更错"。

## 三、拿这三条公理量我们这座库（全部只读实测）

## 四、从四篇里真正能"学思想"的六条（不是抄模块）

### 4.1 "scope path" 才是结构的最小可用单位，章节标题本身不是

IndusSpec 的 `pi = s1 → s2 → … → sk` 与 GB/T-Bench 的 `xi = (pi, hi, ci)`（节号/标题/内容三元组）**是同一个东西的两种写法**。ETSI 的 `parthood` 传递闭包也是它。

**思想**：**结构不是"树"，是"从根到当前节点的路径"。** 单看一个节点的标题没有信息量；**路径才有**——它决定了"这句话在什么前提下成立"。

**对我们的动作**：国标已有 `hierarchy_path`（88.3%），**但它是路径的字符串，不是可判等的 scope**；法规的路径要**从混在正文里的 `## 第X编/### 第X章` 抽出来**，而不是留在正文里当噪声。

### 4.2 `logic_group` 节点：嵌套 AND/OR 必须显式保括号

IndusSpec 的做法：`A ∧ (B ∨ C)` 不能拍平成三元组，必须建 `logic_group` 节点当括号。

**思想**：**标准里"多条件组合"极多**（我们实测 **43,790 条**条款含 `a）` 式枚举），而三元组结构**天生装不下括号**。拍平就是丢信息。

**对我们的动作**：这是"条件槽位"和我们那条 `exception` 字段（3.8%）的正确形态。**不是抽"一个 exception 字符串"，是抽"一棵条件树"。**

### 4.3 反枢纽正则：图结构会天然抬高"通用条款"

ETSI 的 `score(n) = … − γ·log(1+degree(n))`。

**思想**：**在图里，连接度高的节点会被结构本身奖励**，而标准里的"通用要求"章恰好引用最多、被引最多——**它们不是答案，它们是枢纽**。

**对我们的动作**：`evidence_edge` 一旦补起来，**必须有反枢纽惩罚**，否则"通用要求"章会淹没具体条款。

### 4.4 平滑：用邻居均值近似图嵌入

ETSI 的 `em ← α·em + (1−α)·mean(邻居)`，邻居 = 父/子/兄弟/出入引用。

**思想**：**不训练 GNN，也能把图结构压进向量。** 代价极低（一次均值），且作者实测"略微提升 recall"——**这是四篇里唯一一个"结构提升了召回"的读数，而且它只有这一行代码。**

**对我们的动作**：这是"结构进召回层"的**唯一被证实的正收益形式**，但收益量级是"略微"。**列为可选，不列为主攻。**

### 4.5 先全局、后专家：拆分的顺序是硬约束

GB/T-Bench 的消融：**去掉全局通读，0.5094 → 0.22，比单轮还差。**

**思想**：**分解不是"分头看"，是"先合成一张地图，再分头查"。** 顺序反了，专家看到的是碎片。

**对我们的动作**：这直接否掉"文档切块 → 多个 agent 各查一块"的做法。正确形态：**先出全文档的节序 + 目录 + 术语表 + 引用表（一张地图），再按维度分头查**。

### 4.6 尺子必须与被测系统解耦：两种可复制的造法

这是我要抄的两件**方法学**（不是模型）：

| 论文 | 造法 | 为什么它可信 |
|---|---|---|
| **ETSI** | 造题时**故意不重用自己那套图逻辑**，退回原始 PDF 按扁平字符串切块；LLM 出题+出答案+**逐字引 witness strings**；命中判据 = 检索块包含金标块 **≥75% 子串** | 尺子与被测索引**走两条独立代码路径** |
| **GB/T-Bench** | **可控反例注入**：结构类错误用**确定性规则**造，语义类错误用 **LLM 在规则约束下改写**；每例保留 原文/篡改后/位置/维度/类型/描述 | **不等自然发生的错误**，而是**造出可追溯的错误**；且 30% 人工复核 κ=0.947 |

**⇒ 直接回应"我们手搓的实验不严谨"**：这两篇给的答案不是"更仔细"，是**结构性地把尺子和被测物分开**——一个用独立代码路径，一个用注入式金标。

### 6.2 值得先做的（按公理排的序）

| 序 | 动作 | 依据 | 判据 |
|---|---|---|---|
| **1** | **把表体抽进库**（38,631 条在引用表、0 条有表体） | IndusSpec：Table +120.2%，是结构收益最大处 | 以"表 X"被引次数为分母，量抽取覆盖率；再量含表题的命中率 |
| **2** | **把规则单元抽成 case + logic_group 树**（现在 object/behavior/condition/restriction 全 0） | IndusSpec：只加规则 +32.2%（远大于只加结构） | 抽 200 条人工核，量与人工判定的一致率 |
| **3** | **给结构配 scope**（国标已有路径、法规要从章标题抽并剥离） | 公理三：有边无 scope 更危险 | 剥离后「总则」类假命中应大幅下降（现 34,382 条假词） |
| **4** | **建跨文档引用图**（现在跨文档 0 条、normative_refs 0/8983） | GB/T-Bench DNREF；ETSI citation 边 | 覆盖率 + 引用一致性可判 |
| **5** | **重排**（四篇里唯一稳定的大杠杆：GEMS −4.65 是其他项 20 倍） | GEMS、COLIEE、IndusSpec 都靠微调重排 | 在**独立的**尺子上量，不在我们自己的考卷上量 |
| **6** | **拒答**（可答性 + 不可答五类） | GEMS 的 30 道锁死不可答题 | 按五类分别量，不报总分 |

### 6.3 必须先有的一件东西：一把与我们解耦的尺子

**在动第 1 项之前**，先按 ETSI 与 GB/T-Bench 的两种造法，造一把尺子：

- **路子 A（ETSI 式）**：从我们库的**原始 PDF** 出发（不经我们现在的切分/入库），按扁平切块造题，LLM 逐字引 witness strings，命中判据 = **≥75% 子串包含**。
- **路子 B（GB/T-Bench 式）**：**注入式金标**——结构类错误（附录属性被改、节号跳号、引用清单缺项）用**确定性规则**造；模态类（应→宜、应→可）用**规则约束的替换**造。每条保留原文/改后/位置/类型。

**理由**：这两条都不经过"我们现在的切分入库"，因此**不会被第三章那堆缺陷带偏**。这正是你要求的"不拿现有数据当基准"。
