## 〇、一句话结论

> **没有「国家标准检索/RAG 竞赛」这一类比赛。** 但有**四类东西是真的存在**，且比比赛更有用：
>
> 1. **国标自己已经给 RAG 立了标准**（GB/Z 253-2026、GB/Z 236-2026、SJ/T 12116-2026）；
> 2. **国标自己已经给「标准数字化」定了五级能力模型**（GB/T 48000.1-2025：电子化→结构化→**语义化**→智能化→可拓展）——**这就是官方给的路线图**；
> 3. **四个已经上线的标准问答产品**（同道、标知、标准大数据平台、建筑标准智能体），其中两个是国家级机构做的；
> 4. **五篇以「标准文档」为语料的学术论文**（含一篇 EMNLP 2026 主会、一篇带公开数据集）。

## 一、比赛：没有「国标 RAG 比赛」，只有「人考标准化知识」

| 名称 | 性质 | 届次/时间 | 规模 |
|---|---|---|---|
| **全国标准化知识竞赛** | **人考**（不是 AI 比赛） | 首届 2024-09；**第二届 2026-08-26 决赛** | 第二届 **24.6 万人**线上答题、31 省、3 万多家单位、20 个行业 |
| 苏州市标准化人员职业技能竞赛 | 人考（**含标准编审实务案例**） | 2023，称"全国首次面向标准化人员" | 近 300 人 |

【一手】sac.gov.cn 英文页 + 国内多家通稿。

- 初赛：线上随机抽题，**50 题 / 100 分 / 75 分钟**，单选+多选+判断。
- 决赛：初赛前 8 省的队伍现场答题，**第二届安徽队第一**。
- **考纲**（这是唯一能当"用户会问什么"清单的东西）：标准化法律法规及政策、原理概念、体系与管理、**标准编写规则与制定程序**、国际标准化、行业/地方/团体/企业标准化、综合标准化。
- **题库不公开**，只有考纲。

**⇒ 结论：没有可参与的「国标 RAG 比赛」。** 我搜了 DeepSeek + WorkBuddy 两套独立索引，均未命中。

## 二、项目/产品：四个已上线的「标准问答」系统（这是最直接的对标）

| 产品 | 谁做的 | 时间 | 能力 |
|---|---|---|---|
| **"同道"标准大模型** | **中国电子技术标准化研究院（CESI，工信部直属）** | 2025-10-14 互联网版上线 | **同道问答**（基于知识库的精准权威解答）、**同道编写**（生成标准草案初稿+润色扩展）、**同道解读**、**同道认证**；覆盖标准全生命周期；支持多格式文件的多模态交互 |
| **"标知"标准大模型** | **中国标准出版社 + 同方知网** | 2026-06-30 发布 | ①AI 多维增强检索，**精准定位标准条文/术语/指标/图表**，毫秒级；②**基于 RAG 的溯源问答，所有输出可对应原始标准文献**；③智能起草（多人协同+格式自动校验）；④**条文智能比对**（自动识别文本差异） |
| **标准大数据公共服务平台** | CESI | — | 对国标/行标深度加工拆解成 **90 余万条标准百科知识**（**标准条款、图、表、公式、术语与定义**）；标准深度检索、**标准知识图谱**、标准智能问答机器人 |
| **建筑标准知识智能体** | 中国建筑标准设计研究院 + 云问科技 | 二期 2025-11 上线并全院推广 | 标准文档与图集统一管理；大模型 + 知识图谱；智能问答 |

【转述】新华网/百家号/cesi.cn 通稿。【一手】cesi.cn 平台介绍页。

**⇒ 三条读数（对我们最有用的）：**
1. **「标准条款、图、表、公式、术语与定义」这五类被官方列为拆解对象**——和我们要做的证据单元完全一致。
2. **「溯源问答，输出对应原始标准文献」是产品的核心卖点**，不是附加功能。
3. **「条文智能比对」**（新旧版本差异）是一个我们没有的能力，而它是标准行业的刚需。

**另一条：** 2026-07-30 一篇【转述】文章标题就是《基于标准本体的 RAG 系统解决大模型标准引用失真问题》，它点的三个传统 RAG 缺陷**与我们检索到的库缺陷高度重合**：
- 无法区分**同义异词、同词异义**的标准术语 → 语义漂移
- 无法识别标准体系的**层级关系、条款从属关系、新旧替代逻辑**
- 缺乏**合规规则约束**

## 三、国标自己给 RAG 立的标准（**这是本轮最重要的发现**）

### 3.1 三项 RAG 标准

| 标准号 | 名称 | 发布/实施 | 起草 |
|---|---|---|---|
| **GB/Z 253-2026** | 人工智能 检索增强生成通用技术要求 | 2026-08-27 发布即实施 | CESI 牵头，百度网讯、蚂蚁等 |
| **GB/Z 236-2026** | 人工智能 检索增强生成系统**评价指标与方法** | 2026-08-27 发布即实施 | CESI、蚂蚁集团等 |
| **SJ/T 12116-2026** | 人工智能 关键技术 检索增强生成通用技术要求（**电子行业标准**） | 2026-04-27 实施 | 工信部发布 |

【一手】std.samr.gov.cn 标准页 + openstd.samr.gov.cn + antpedia 标准解读页。

**GB/Z 253 / SJ/T 12116 的技术框架（对我们直接可用）**：

```
知识库模块：数据接入 → 知识获取 → 知识切分 → 知识增强 → 知识索引
            ├ 数据接入：数据库/数仓/文件；结构化+半结构化+非结构化；周期接入、连接器、质量保障、异常处理
            ├ 知识获取：文档解析、表格解析、图像/视音频解析；**版面分析 + 逻辑结构识别**
            ├ 知识切分：段落切分、表格切分、图像/视频分片；**切分结果保留文档结构映射**
            ├ 知识增强：问题生成、文本摘要、实体抽取、实体消歧与融合
            └ 知识索引：向量索引、全文索引、融合索引；索引维护

检索增强生成模块：查询理解 → 知识检索 → 语义排序 → 答案生成
            ├ 查询理解：多轮改写、问题判定、**问题拆解**
            ├ 知识检索：全文检索、语义检索、混合检索、多模态检索；检索优化、访问控制
            ├ 语义排序：统一粗排 + 精准重排
            └ 答案生成：生成式模型接入、上下文融合、**合规性检查**、性能优化
```

**⇒ 三条硬对照（这是判断我们对错的官方依据）：**
1. **「切分结果保留文档结构映射」写进了国标**——我们库里法规条款把「第X章 总则」并进正文、`hierarchy_path` 法规 0% 覆盖，**按国标口径就是不合格**。
2. **「知识获取」要求「版面分析 + 逻辑结构识别」**——不是"抽成纯文本就行"。
3. **「答案生成」要求「合规性检查」**——对应我们的 `typed_verifier`，方向对。

### 3.2 标准数字化系列：**GB/T 48000.1-2025 给了五级能力模型**

| 标准号 | 名称 | 发布/实施 |
|---|---|---|
| **GB/T 48000.1-2025** | 标准数字化 第1部分：通用指南 | **2025-10-05 发布，2026-05-01 实施** |
| **GB/T 46917.1-2026** | 标准语义知识库 第1部分：标准内容语义化表达通用要求 | 2026-01-28 |
| GB/T 46917.2 / .3 | 数据接口要求 / 语义集成技术要求 | 2026 |
| **GB/T 46686.1-2025** | **标准知识图谱 第1部分：实现指南** | 2025-12-02 |
| **GB/T 47013.1-2026** | 标准内容模块化 第1部分：主结构与配置通用技术要求 | 2026-01-28 |

【一手】openstd.samr.gov.cn 标准页。

**GB/T 48000.1 的「内容数字化」五级（这是官方路线图，原文目次）**：
```
7.2 支持电子化实现
7.3 支持结构化实现
7.4 支持语义化实现
7.5 支持智能化实现
7.6 支持可拓展实现
```

**⇒ 这一条直接回答「我们的技术路径该怎么走」**：国标官方把标准数字化分成五级，**我们库里现在停在 7.2～7.3 之间（电子化 + 勉强结构化），而业主想要的效果（问答、推理、合规判定）落在 7.4～7.5**。**官方口径就是「先结构化、再语义化、再智能化」，不能跳级。**

## 四、学术研究：五篇以「标准文档」为语料的论文

| 论文 | 语料 | 做法 | 结论/数据 | 可得性 |
|---|---|---|---|---|
| **GB/T-Bench**（arXiv 2608.06312，2026-08）华南师大 + 上海交大 + **中国标准化研究院** | **488 篇真 GB/T**，64,991 个 section | 5 维 × 25 类审查分类法；**7,306 条错误实例**；诊断式评测（错误位置+维度+类型三重精确匹配） | 最强单模型 **CMCS 0.3280**；**人类专家 0.6640**；多 agent 框架 **0.5094** | 数据集**未查到公开下载地址** |
| **Ontology-Based KG for Industrial Standards**（**EMNLP 2026 主会**，ACL Anthology 2026.emnlp-main.1456） | 3 篇工业标准 | **把章节结构建成本体** + 规则三元组（含复合条件） | 在**表格类规则题**与**多条件推理**上提升最大 | ✅ **代码 GitHub 公开**（`Ontology-KG/ontology_based_kg_paper`），✅ **数据集 IndusSpec-QA 公开在 HuggingFace** |
| **Normative RAG with Graph-based approaches**（arXiv 2604.09868，2026-01） | **ETSI EN 301 489 系列** | 用 Graph RAG 把文档结构嵌入检索；轻量低延迟策略 | 结构+词汇信息进索引**能提升检索**（"at least to some extent"） | 自建合成 QA 集，未见公开 |
| **GEMS-RAG**（arXiv 2610.33277，2026-10） | **MUTCD**（美国交通控制设施手册，大工程标准） | 层级解析 + 视觉实体抽取 + **多模态知识图谱** + 图接地混合检索（稠密+稀疏+视觉） | 优于纯文本 / 多模态 / 图 RAG 基线 | — |
| **SALC：基于结构感知的煤矿标准文档解析**（《煤矿安全》，杨海军等） | 煤矿安全标准 | **微调 LayoutLMv3** → 结构感知逻辑切片（Structure-Aware Logical Chunking） | 针对"物理切片导致语义表征漂移与逻辑边界缺失" | — |

【一手】ACL Anthology / arXiv 原文 / GitHub 仓库原文。

**⇒ 五篇合起来给出一条一致的结论**：
> **「把文档结构显式建模」这件事，在标准文档上有独立证据支持**（EMNLP 2026 主会 + ETSI 案例 + 煤矿标准 + MUTCD）。而它正是**国标 GB/Z 253 明文要求**的那一条。**学术与标准在这里收敛了。**

**其中最该先看的是 EMNLP 2026 那篇**，因为：
- 它是**唯一同时公开代码和数据集**的（IndusSpec-QA 在 HuggingFace）；
- 它的问题分类正好是 **Rule / Multi-hop / Table** 三类，与我们需要的「适用型 / 跨条 / 表格」对得上；
- 它的核心主张就是「**同一句话出现在文档不同位置可以指不同规则**」——这正是我们的痛点。
