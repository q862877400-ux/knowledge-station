## 结论先行（≤15 行）

1. **任务书的「TREC 2022 ToT」不存在**：TREC ToT 只办过 2023/2024/2025 三届。TREC 31（2022）议程页没有 ToT 条目，TREC ToT 官网「Previous editions」只列这三年，NTCIR ToT 页原话是「previously organized as a TREC Track (2023-2025)」【一手】。三年冠军已全部取到，见 §一。
2. 三年冠军 NDCG@1000：**2023 CMU-LTI 0.5554 / 2024 h2oloo 0.8159 / 2025 SRCB 0.6824**；相对同年最好官方基线 = **4.00× / 3.43× / 4.01×**【一手，三份总览 Table】。
3. **冠军路线三年换了两茬**：2023 靠「外部大语料 + 稠密重排」，2024 靠「GPT-4o 直接吐标题」，2025 靠「LLM 改写查询 + 稠密检索 + 三级重排」。共同点只有一个：**都在检索之前先把自然语言请求加工一遍**【一手】。
4. **最该进我们路线的是「查询改写」**，三条独立一手证据：GuRE 在 BM25 上把法条 nDCG@10 从 **15.33 拉到 47.69（+32.96）**；DS@GT 改写使 nDCG@10 **+33.88%**、首段召回 **+20.61%**；2025 冠军第一条技术就是「把请求变成 cue list」【一手】。
5. 但**改写必须按「改写成条款语域」做，不许做成「删词/同义词扩展」**：UAmsterdam 实测删 hedges 在合成 dev3 上 +25.4%，在真人测试集只有 **+2.7%（不显著）**；RM3 伪相关反馈在三个划分上**全部变差**（dev3 −45%）【一手，UAmsterdam p.1/p.4/p.7】。
6. **第二该抄的是两级重排（pointwise → listwise round-robin）**：YaleNLP 只加这一层，NDCG@1000 从 **0.5424 → 0.6049（+0.0625）**，且不需要训练【一手，p.6 Table 4】。
7. **第三是引用层的验收与闸门**：ALCE 的 citation recall/precision 与人工打分差 1~2 分（ASQA：人工 74.7/76.6 vs 自动 75.3/74.4），可直接当我们「红箭头点得准不准」的指标【一手，Table 8】；Sufficient Context 的「证据不足就拒答」把「答了的里答对的比例」提高 2~10%【一手，摘要】。
8. **图/树类（RAPTOR、GraphRAG、LightRAG、HippoRAG）看完不抄**：它们都往库里塞 LLM **合成节点**，点不回 PDF 页；且成本非线性——GraphRAG 光索引 Podcast 数据集（1M token 级）就要 **281 分钟**，LightRAG 引的 GraphRAG 检索一次要 **610 个社区 × 1,000 token = 61 万 token**、几百次 API 调用【一手，各自原文】。
9. **Late Chunking 不值得动**：换长上下文 embedding 模型、按 token 池化，收益只有 **+1.9 绝对点 nDCG@10**（3.63% 相对），而「换向量底座」已在任务书 §六判死【一手】。
10. **TREC 的语料与方法对我们零迁移的地方要说清**：ToT 问的是「我记不清的那部电影叫什么」，语料是维基实体页；我们问的是「哪一条国标条款规定了这个」，语料是**编号强、字面重复高的条款**。ToT 的「检索到唯一答案」和我们的「检索到可引用的条款」不是一个任务，**只有方法零件可迁，评测口径不可迁**【推断】。
11. 六通道里，**唯一被这些论文直接点名的短板是「重排」**：我们的链路是六通道 RRF 融合后直接进生成，没有重排器；而 2024/2025 两届冠军、YaleNLP、Webis 全部在 RRF 之后还有一层可训/可调的排序【一手 + 推断】。⚠ **2026-10-25 Lead 就地更正（原话保留，不删）**：**"没有重排器"这句与本仓代码不符**——`src/core/retrieval/reranker.py` 有 cross-encoder（`BAAI/bge-reranker-base`，fastembed/ONNX），2026-10-09 已修掉"恒等置换"缺陷；生产上**是显式 `rerank=False`**，因为本机实测（`eval/recall-funnel/exp-11-rerank-fix`，预注册判据）：**主终点 7→9（+1.67pt）、McNemar 双侧 p=0.5、单次 rerank p50 1.10 s** ⇒ 收益不抵代价（见 `docs/RETRIEVAL-LONG-RANGE-PLAN.md` 0.7-修）。⇒ 正确说法：**pointwise 重排我们试过并判"不接生产"；没试过的是"pointwise → listwise LLM"两级**（§三第 2 条），那条要重新量成本，不能拿 YaleNLP 的 +0.0625 当我们的预期。
12. 表格/公式两条：**表格用「序列化进文本」而不是建独立索引**（OTT-QA 的 early-fusion 把表格单位拼成融合块后 EM 从 9.9% 抬到 >27%）；**公式暂不建结构索引**（ARQMath-3 结构检索只在公式型主题上强，文本型主题反而稀疏检索更好）【一手】。
13. **没有一条论文能替我们解决「中文条款级引用」**：我逐篇核过，本地 9 份 ToT 论文 + 12 篇方法论文（另有 1 节综述只到「未取证」），**零篇**处理过「条款编号/效力状态/多版本并存」，GuRE 用的 LePaRD 是美国判例不是法条，且作者自陈局限就是「只有美国联邦判例一个数据集」【一手，GuRE Limitations】。

## 一、竞赛：TREC ToT 各年度冠军

### 1.0 先推翻一个前提：没有 TREC 2022（trec31）ToT

- `https://trec.nist.gov/pubs/trec31/` 议程页的全部 `papers/Overview_*.pdf` 反链只有 cast / deep / fair / hm / neuclir / trials 六个，**没有 `Overview_tot.pdf`**；直接请求 `papers/Overview_tot.pdf` 返回 276 字节 404 页【一手，2026-10-25 抓】。
- TREC ToT 官网 `https://trec-tot.github.io/previous` 的「Previous editions」只有 **2025 / 2024 / 2023** 三条【一手】。
- NTCIR ToT 页面原话：「The ToT task was previously organized as a **TREC Track (2023-2025)**」【一手，`https://ntcir-tot.github.io/`】。
- ⇒ 所以本节按 **TREC 32 / 33 / 34 = 2023 / 2024 / 2025** 三年写。任务书要的「2022 年度冠军」这个对象不存在，不是我没找到。

### 1.1 TREC 2023（TREC 32）· 电影域 · 23.16 万维基页 · 11 队 33 个 run

- **冠军：CMU-LTI，run `dpr-1000-rerank-robin`**。NDCG@10 **0.5169**、NDCG@1000 **0.5554**、MRR@1000 **0.5016**、Recall@1000 **0.7933**【一手，`Overview_tot_trec32.pdf` p.5 Table 2】。
- 亚军同队 `dpr-100-rerank` NDCG@1000 0.5070；第三名 snuldilab `pre_aug_vat_max4` 只有 **0.3301** ⇒ 前两名与第三名之间有 **0.18 的断崖**，总览原文称其为「the two outlying runs」【一手，p.4 §4.3】。
- **官方基线**：BM25 `baseline_bm25` **0.1388**、稠密 `baseline_distilbert` **0.1426**、GPT-4 基线 `baseline_gpt4_db` **0.2624**（同表 p.5）⇒ 冠军对最好基线是 **0.5554 / 0.1426 = 3.89×**，对 BM25 是 **4.00×**。
- **检索路线**：run 名里的 `dpr-` = 稠密双塔检索，`rerank` = 重排，`robin` = 轮转（round-robin）式 listwise 重排——后者在 YaleNLP 2024 论文里被明确记为「Borges et al. 在 TREC ToT 2023 的做法」【一手，YaleNLP p.2 §2.3】。总览另给一条**关键归因**：「前两名使用了 TOMT-KIS，它比 TREC-ToT 数据集大得多。这似乎是其高性能的关键」【一手，p.5】。TOMT-KIS 规模 **128 万条**英文电影 ToT 查询【一手，DS@GT 综述转引 Fröbe et al. 2023】。
- **代价**：需要外部 128 万条同域查询做训练/重排素材；这是英文电影域数据，中文法规域**没有等价物**，也不许照搬（任务书 §六已判死「照抄 TREC ToT 冠军的外部数据」）。
- **方法细节的缺口（不许猜）**：TREC 32 议程里 ToT 只有总览 + `RSLTOT.T.pdf` 一份参赛论文，**CMU-LTI 没交论文**。所以「dpr-1000-rerank-robin 具体怎么 rerank」我只能读到总览这一层，**没有一手方法描述**。

### 1.2 TREC 2024（TREC 33）· 电影+名人+地标 · 318.5 万维基页 · 6 队 18 个 run

- **冠军：h2oloo（组名；TREC 33 附录的 Org 字段只写 `h2oloo`，未给机构名，网上旧记录指向滑铁卢但本轮没在官方材料里核到），run `rg4o_t100_test`**。NDCG@10 **0.8042**、NDCG@1000 **0.8159**、MRR@1000 **0.7910**、Recall@1000 **0.9250**【一手，`Overview_tot_trec33.pdf` p.6 Table 1】。亚军、季军也是 h2oloo（0.7003 / 0.6204）。
- **官方基线**：`baseline-dense` **0.2377**、`baseline-bm25` **0.1484**（同表 p.6）⇒ 冠军对最好基线 **0.8159 / 0.2377 = 3.43×**。
- **检索路线（一手来源是官方提交表单，不是论文）**：TREC 2024 ToT 附录里 h2oloo 三个 run 的自我描述字段写着 `gpt4o-1 - https://github.com/TREC-ToT/bench/blob/main/GPT4.md like baseline (generalized to more types)`，并列明「用了官方基线 run」【一手，`trec33/appendices/trec2024-tot-main.html`】。⇒ **2024 冠军事质上是「让 GPT-4o 直接吐出候选实体名，再映射回语料」**，即组织者自己的 GPT-4 基线（2023 年该基线只有 0.2624）被**扩到更多实体类型后做到 0.8159**。
- **这条比看起来重要**：它说明在「答案是唯一命名实体」的任务里，**把生成式 LLM 当召回器**能压过全套稠密检索管线，代价是每次查询一次前沿模型调用。
- **方法细节的缺口**：TREC 33 议程的 ToT 参赛论文只有 yalenlp / IISER-K / webis.biogen.rag.tot 三份，**h2oloo 没交论文**。它的方法我只能读到提交表单那一栏，**没有一手方法描述**。

### 1.3 TREC 2025（TREC 34）· 通用域 · 640.8 万维基页 · 9 队 32 个 run

- **冠军：SRCB（理光软件研究所北京），run `scrb-tot-04`**。NDCG@10 **0.6576**、RR **0.6258**、Recall@1000 **0.9051**、NDCG@1000 **0.6824**【一手，`Overview_tot_trec34.pdf` p.6 Table 1；同值见 `SRCB.mllm.tot.pdf` p.8 Table 7】。
- **官方基线**：`pyterrier-bm25` **0.1700**（三个基线里最好）、`anserini-bm25` 0.1032、`lightning-ir-dense` **0.0514**（p.6 Table 1）⇒ 冠军对最好基线 **0.6824 / 0.1700 = 4.01×**；对稠密基线 **13.3×**。
- **检索路线（一手，SRCB 论文 §3，p.3–p.7）**，六步：
  1. **查询预处理**：DeepSeek-V3 把原始 ToT 查询改写成**线索清单（cue list）**，去掉冗余噪声、修错字；「本文所有模块的输入都是 cue list 而不是原始查询」（p.4）。
  2. **稠密检索**：Qwen3-Embedding/Retriever-8B，只索引每页**前 512 token**，取 top 2000；电影域另用构造的三个增强数据变体微调。
  3. **候选过滤**：用 Wikidata 的 "instance of" 属性算与「Movie」的余弦相似度，把 **640 万篇压到约 50 万篇**（p.4）——相当于**先用元数据把候选池砍一个数量级**。
  4. **pointwise 重排**：Qwen3-Reranker-8B + LoRA，负样本按 hard/medium/easy 三档 **1:3:3** 采样（对应名次 1–10 / 10–100 / 100–2000），展开后正负比 4:28（p.6）。
  5. **LLM 召回补位**：「LLM 预训练时见过维基」，直接让 DeepSeek-R1 与 GPT-5 吐实体名取并集 top-10，**插到重排结果的第 6 位之后**（p.4、p.6；run 描述 p.8）。作者自陈这条**只用在测试集**，因预算原因没在 dev 上评（p.4）。
  6. **listwise 重排**：先用 DeepSeek-V3（RankGPT 式提示）对 top-20 / 第 2–10 位做列表式重排，再用 **GPT-5 对 top-4 做细粒度重排**；最后对「原查询 + 3 个同义改写」四条链的结果做 **RRF** 融合（p.6–p.7）。
- **各步的边际收益（同一队四个 run，一手 p.8 Table 7）**：0.6458（稠密+重排+LLM 重排）→ 0.6700（+LLM 召回补位）→ 0.6787（+三级排序）→ **0.6824**。⇒ **LLM 召回补位这一步值 +0.0242，三级细化只值 +0.0037。**
- **代价要说清**：一次查询要打 **DeepSeek-V3（改写）+ DeepSeek-R1 + GPT-5 + GPT-5（细排）** 至少 4 家前沿模型，外加 4 条改写链各跑一遍全管线（RRF 融合前）。

### 1.4 三年横向：路线怎么换的、共同点是什么

| 年度 | 语料 | 队/run | 冠军 | NDCG@1000 | 同年最好基线 | 倍数 | 主路线 |
|---|---|---|---|---|---|---|---|
| 2023 | 23.16 万页 | 11 / 33 | CMU-LTI | **0.5554** | 0.1426（稠密） | 3.89× | 稠密 DPR + 重排 + 外部 128 万查询 |
| 2024 | 318.5 万页 | 6 / 18 | h2oloo | **0.8159** | 0.2377（稠密） | 3.43× | GPT-4o 直接吐实体名再映射 |
| 2025 | 640.8 万页 | 9 / 32 | SRCB | **0.6824** | 0.1700（BM25） | 4.01× | LLM 改写成 cue list + 稠密 + 三级重排 + RRF |

- **共同点（三条，都可迁）**：① 查询先加工；② 有一个「非学习的粗排 → 学习的精排」两段结构；③ 都在**候选池**上下功夫（2025 用元数据把 640 万砍到 50 万）【一手】。
- **不可迁**：语料域（英文维基实体页）、外部数据（TOMT-KIS）、评测口径（单答案 known-item）。【推断】
- **别把「稠密一定强」当结论**：2025 年稠密基线 NDCG@1000 只有 **0.0514**，被 BM25 的 0.1700 反超；2024 年反过来（稠密 0.2377 > BM25 0.1484）。同年 IISER-K 纯 BM25 + 查询改写拿到 **0.4239**，是 2024 稠密基线的 1.78 倍【一手，各队论文】。

### 1.5 其他参赛队（只取能迁的方法零件）

- **YaleNLP 2024**（耶鲁，NDCG@1000 0.6049，全场第 4）：DPR 通用模型（用 10 万+ LLM 合成查询训练）+ **pointwise 打分 1000→100 + listwise round-robin（5 批 × 20）**。**只加 pointwise 这一层 +0.0625**（0.5424→0.6049），作者判断「显著」【一手，p.6 Table 4 / §4】。它还把「通用模型 > 按域路由到专家模型」做成了结论（0.5424 vs 0.5098）【一手】。
- **IISER-K ThinkIR 2024**（NDCG@1000 0.4239，R@1000 0.8067）：**纯 BM25**（训练集网格搜出 k1=0.6, b=1.0）+ 四阶段 LLM 查询改写（llama3-70b：改写成百科体 → 保真校验 → 同义词扩展 → 收束成一段）+ **两层检索**（先按类别元数据筛到 30 万篇，再在子集里打分）【一手，p.4–p.5 Table 2】。这是**最便宜的一条可比基线**：不训模型、不换检索器。
- **Webis 2024**（nDCG@10 0.4588，R@1000 0.82）：ChatNoir **BM25-F** + 5 个 LLM 长查询缩减变体做并集（各取 top-1000）+ monoT5-base / monoT5-3b 两级重排 + min-max 归一化 RRF【一手，p.7 §4.1 Table 7】。
- **Webis 2025**（nDCG@10 0.3078，R@1000 0.7637）：同上路线，只把闭源 GPT 换成开源模型做「删掉损害检索的词」【一手，p.1 §3 Table 1】。
- **UAmsterdam 2025**（负面结果，最值得读的一篇）：删 hedges 在合成 dev3 上 **+25.4%（p<0.001）**，在真人测试集只有 **+2.7%（不显著）**；**RM3 在三个划分全变差**（dev3 −45%）；否定惩罚无效果；**BM25 top-100 里含正解的比例：合成 dev3 0.6623 vs 真测试 0.3248**，即真查询里 **67.5% 的答案压根不在 top-100**，重排再好也救不回来【一手，p.1 摘要 / p.4 / p.6 Table 3 / p.7】。
- **DS@GT 2025**（单轮 8B LLM 改写 + 多级）：Mistral 改写使 BM25 nDCG@10 **0.3366→0.4609**、R@1000 **0.7705→0.8284**（dev3，Table 6）；**但把 bi-encoder + 晚交互融合加进来，nDCG@10 反而 −18.0%（0.4609→0.3778）**，只把 Success@100 抬高（0.7183→0.7724，Table 7）；RM3/Bo1/KL 三种伪相关反馈**全部低于原查询**（R@1000：0.5093 / 0.7295 / 0.7332 vs 原 0.7705）【一手，`docs/research/papers/mst.txt` §4.1–4.2】。

### 1.6 其余竞赛（覆盖到的一手材料）

- **KDD Cup 2024 CRAG**：冠军 **db3 队**，三个任务**全部第一**，得分 **28.4% / 42.7% / 47.8%**（任务 1/2/3）[arXiv 2410.00005 摘要](https://arxiv.org/abs/2410.00005)。路线：任务 1 是「网页/开放数据检索 + 对 LLM 做面向 RAG 的调优」，任务 2/3 是「**受规范约束的 API 集合** + 用调优 LLM 生成 API 调用」，KG API 只抽取直接相关信息。有参赛队的另一篇复盘（arXiv 2409.15337）：**Domain Router + Dynamism Router** 两个小分类器（Llama3-8B + MoE/MLP 头、LoRA），按域和时效性分流；网页先用 Newspaper 解析，任务 3 对 50 个网页先切 1024-token 块再用 BM25 取 top-50 再精排。【一手摘要 + 复盘 HTML】
  - **对我们的意义**：它是「**按问题类型路由到不同检索路径**」的工程实证，和我们的「六通道并行」是同一族思路；但它是**多源异构检索（网页+KG+API）**，我们的六通道是同一库内的六种匹配方式，不可直接对标【推断】。
- **COLIEE 2024 Task 1（法条/判例检索）**：冠军 **TQM 队**（第一篇论文 2404.00947）：沿用上届冠军 THUIR 的框架——**词法匹配 + 语义检索双路，再用 LTR 融合**，外加启发式前后处理（剥噪声、按相关判例的共有性质做后处理）。数据是加拿大联邦法院判例（每查询候选 5,616 篇，平均相关 4.16 条）。【一手摘要 + HTML 正文 §3–§4】
  - **注意方向相反**：这是**判例→判例**检索，查询本身就长（整段判决理由），不是「大白话→条款」。
- **LeCaRD / LeCaRDv2（中文法条/案例检索数据集）**：LeCaRDv2 是 SIGIR 2024 的大规模中文案例检索数据集（[DOI](https://dl.acm.org/doi/10.1145/3626772.3657887)）。有一条很对我们胃口的一手结论：ACL 2026 Findings 的「自演化规则改写」论文开篇写「**实证研究显示 BM25 在法域仍是强基线**」，其方法就是**用 LLM 自动演化查询改写规则来增强 BM25、不做任何参数训练**，在 LeCaRD-v2 上超过人工设计规则与贪心选规则[aclanthology 2026.findings-acl.2152](https://aclanthology.org/2026.findings-acl.2152/)。【一手摘要】
- **CCKS / CCF BDCI**：**没取到法条检索赛道的冠军方法，明确记为未取证**。CCKS-IJCKG 2024 公开的 10 项评测任务里没有法条/条款检索任务（大模型知识编辑、零样本知识抽取、双语 Text-to-SQL 等）；CCF BDCI 2024 有「基于运营商文本数据的知识库检索」（要求按问题返回答案所在文本块），但**冠军方案未取得一手**。

## 二、方法论文

### Contextual Retrieval（Anthropic，2024-09-19）
- 解决什么：切块后每块丢了「它在整篇里的位置」，于是「本公司营收环比涨 3%」这种块检索不到。
- 方法一句话：用 LLM 给每个块生成 **50–100 token 的定位上下文**，前缀拼回去，**embedding 和 BM25 索引都建在这份加了上下文的文本上**。
- 数字（一手，官方博客）：检索失败率（= 1 − recall@20）**上下文 embedding 降 35%、再加上下文 BM25 降 49%、再加 Cohere 重排降 67%（5.7% → 1.9%）**；成本约 **$1.02 / 百万文档 token**（靠提示缓存）。
- **能不能用**：**能，而且我们不需要 LLM 就能拿到大部分收益**。我们的块天然带 `标准号 + 条款号 + 章/节标题 + 页码`，这些字段现在**存在元数据里、没进被索引的正文**。把「《GB/T XXXXX》第 5.2.3 条（第 6 章 试验方法）」拼到条款正文前面再进 FTS5，就是零成本的 contextual retrieval。
- **不能用的部分**：拿 LLM 逐块生成上下文。千万级条款 × 每块一次调用，成本与 B 线解析成本叠加，且会引入「LLM 生成的文字进了被检索文本」的可回溯风险（作者自己在其他转述里也提到前言有幻觉风险）。

### Late Chunking（Jina，arXiv 2409.04701）
- 解决什么：同一个「块丢上下文」问题，但走 embedding 侧。
- 方法一句话：先用长上下文模型编码**整篇**，**切块放到 transformer 之后、mean-pooling 之前**，于是每块的向量自带全文上下文；无需训练。
- 数字（一手，p.3 §3）：相对朴素切块 **+3.63% 相对（+1.9% 绝对）nDCG@10**（句边界），固定长度边界 +1.8 绝对，重叠边界 +1.5 绝对。
- **能不能用**：**不用**。① 收益 1.9 个绝对点，不值一次向量管线重做；② 「换向量底座」任务书 §六已判死；③ 它要求向量通道是主力，而我们的向量通道现在是 606 ms 的弱项。
- 留一句：如果我们将来真换了长上下文向量模型，这条是**免费的顺手收益**，那时再评估。

### RAPTOR（ICLR 2024，arXiv 2401.18059）
- 解决什么：单向量检索答不了「整篇讲什么」这类跨段落/全局问题。
- 方法一句话：递归「聚类 → LLM 摘要」建一棵树，检索时在不同抽象层上取节点。
- 数字（一手）：摘要宣称接 GPT-4 后 QuALITY 准确率「比此前最好成绩**高 20 个绝对点**」；但**受控实验**（UnifiedQA-3B 作 reader）里 SBERT 加树只从 **54.9% → 56.6%**，QASPER F1 只从 **36.23 → 36.70（+0.47）**（p.7–p.8 Table 2）；GPT-4 配置下 QuALITY **62.4%**，比 DPR/BM25 高 2 / 5.1 点（p.7）。
- **能不能用**：**检索层不用**。树的中间节点是 LLM 摘要，**点不回 PDF 页**，直接违反我们的红箭头引用。**可用的是它的「摘要节点」当目录索引**（只用来选文档/选章节，不直接引用），且要我们自己的抽取式摘要而不是生成式。
- 注意「对不上的地方」第 5 条：摘要的 20% 与受控实验的 +1.7 点不是一回事。

### GraphRAG（Microsoft，arXiv 2404.16130）
- 解决什么：RAG 答不了「这批文档的整体主题是什么」这类全局问题。
- 方法一句话：LLM 抽实体关系建图 → 为紧密相连的实体群预生成「社区摘要」→ 查询时每个社区各生成部分答案再汇总。
- 数字（一手，p.7–p.8）：对 1M token 级语料的全局问题，在**全面性**上对向量 RAG 的胜率 **Podcast 72–83%、News 72–80%**（p<.001），多样性胜率同量级；索引 Podcast 数据集花 **281 分钟**（A.2 节）。
- **能不能用**：**不抄**。① 目标不同（全局综述 vs 定位条款）；② 建图成本随语料线性涨，千万级条款不可行；③ 社区摘要是生成文本，不可引用。
- 唯一可借的思路：**「先聚类成主题、再按主题路由」**——我们已经有条款的章/节结构，等于免费拿到这一层，不需要图。

### LightRAG（arXiv 2410.05779）
- 解决什么：GraphRAG 太贵；且新数据要重建索引。
- 方法一句话：图 + 向量双索引，**低层（具体实体）/高层（主题概念）双级检索**，增量更新不重建。
- 数字（一手）：Legal 数据集上总体胜率 NaiveRAG **15.2% vs LightRAG 84.8%**（Table 1 p.7）；成本对比（p.9–p.10）：**GraphRAG 一次检索 610 个社区 × 1,000 token = 610,000 token + 数百次 API 调用，LightRAG <100 token + 1 次调用**；增量更新阶段两者抽取开销相近。
- **能不能用**：**不抄图**，但**「双级关键词检索」这个想法可借**：我们的六通道里「法理要素 / 行为客体」两路本质就是高层概念、FTS5 是低层字面；现在的问题是**两路结果只靠 RRF 平均**，没有按查询类型决定谁说了算。可做的最小改动是「按查询类型加权 RRF」，不建图。

### HippoRAG（NeurIPS 2024，arXiv 2405.14831）
- 解决什么：多跳问题（一个答案要靠串起多条事实）。
- 方法一句话：LLM 抽 KG → 用 **Personalized PageRank** 在图上做一次传播，把「同义边」也算进去，替代迭代式多跳检索。
- 数字（一手，p.6 Table 2）：MuSiQue R@5 **52.1** vs Contriever **46.6**；2Wiki R@5 **89.5** vs Contriever **57.5**（+32 点）；平均 R@5 72.6 vs BM25 58.4；且比 IRCoT 便宜 **10–20 倍**、快 **6–13 倍**（摘要）。
- **能不能用**：**半可用，但要先有边**。我们已有 **22,992 条条款互引边，但有边的条款只占 4.93%，且跨文档边 = 0**（任务书 §三 表）。在「0 跨文档边」的图上跑 PPR，等于在单文档内打转，**收益上限就是文档内**。
- 结论：**先补边（跨文档条款互引），再考虑 PPR**；不要先上图算法。

### Sufficient Context（ICLR 2025，arXiv 2411.06037）
- 解决什么：错了到底是「没检到」还是「检到了但模型没用上」——不分开就不知道该修哪。
- 方法一句话：训一个「证据够不够」判别器（autorater），把错误按「上下文是否充分」分层；并据此做**选择性生成**（不够就拒答/追问）。
- 数字（一手）：autorater 准确率 **93%**（Table 1）；用充分性做闸门后，「模型作答时答对的比例」**提高 2–10%**（Gemini / GPT / Gemma）；大模型在证据不足时**倾向于瞎答而不是拒答**（摘要）。
- **能不能用**：**能，直接进生成层**。这是我们「引用可回溯」的守门员：先判「检索到的条款是否足以支撑这个回答」，不足就**不给引用**。它比「让模型自己说不知道」可靠，因为判别器是独立一次调用。成本：一次额外调用/问答。

### OTT-QA（ICLR 2021，arXiv 2010.10439）
- 解决什么：开放域问答里**表格和文本混在一起**，证据分散在两类载体。
- 方法一句话：**early fusion**——把若干高相关的表格单元和文本单元**拼成一个融合块**再检索；配 cross-block reader。
- 数字（一手）：迭代检索 + BERT reader 基线 **EM 9.9%**；两个技巧合用后 **> 27%**（摘要 + p.12 §5）。数据集表格平均 **>300 词/张**。
- **能不能用**：**能，这是我们的表格通道该走的路**——不要给表格建独立索引，而是**把表格行按「表头: 值」序列化成文本块，掺进正文索引**。好处：引用可复用同一套 PDF 页/bbox；坏处：长表会被切碎，需要按「行组」而不是「页」切。

### FeTaQA（TACL 2022，arXiv 2104.00369）
- 解决什么：表格问答只考「抄一个格」，不考「跨多个不连续单元格合成一段话」。
- 方法一句话：构建 1 万条 {表格, 问题, 自由文本答案, **支撑单元格**} 四元组；答案必须能指回具体格子。
- 数字（一手）：两种基线（语义解析流水线、端到端生成）都表现吃力（摘要与 §5）。
- **能不能用**：**它的「支撑单元格」标注口径可借**——我们的表格引用粒度应该到「单元格」而不是「页」。但数据本身是英文维基表，不可直接用。

### ALCE（EMNLP 2023，arXiv 2305.14627）
- 解决什么：LLM 生成的内容带引用，但**引用准不准没人自动评**。
- 方法一句话：定义 **citation recall / citation precision** 两个指标 + 三个维度（流畅、正确、引用质量）的自动评测台。
- 数字（一手，p.9 Table 8）：自动分与人工分几乎一致（ASQA，ChatGPT 原版：人工 74.7/76.6 vs 自动 75.3/74.4；加 rerank：79.3/81.9 vs 83.9/80.8）；**ELI5 上即使最好的模型也有 50% 的句子引用支撑不全**（摘要）。
- **能不能用**：**能，当验收指标用**。我们现在的引用验收只有「字段有没有」，没有「这条引用是否真的支撑这句话」。citation recall/precision 正好对上「红箭头点过去，那一页那一条是不是真支撑」。
- 代价：需要标注一小批「句子—条款」对做金标，或用强模型做评审（那就退化成转述）。

### GuRE（NLLP 2025，[aclanthology 2025.nllp-1.31](https://aclanthology.org/2025.nllp-1.31/)；本机全文 `docs/research/PAPER-GuRE-法条检索生成式查询改写-NLLP2025-全文抽取.txt`）
- 解决什么：**法条段落检索（LPR）**里，查询与目标条款之间词面严重不匹配。
- 方法一句话：训一个**生成式改写器**（SaulLM-7B 为骨干），把「办案上下文」改写成「像目标条款的一段伪段落」，再喂给任意检索器。
- 数字（一手，p.3 Table 1，LePaRD 10K 候选池）：纯 BM25 nDCG@10 **15.33 → BM25+GuRE 47.69（+32.96）**；R@1 **9.91 → 34.88**；R@10 **28.19 → 62.20**；对 DPR、ModernBERT、以及「直接微调检索器」都全面胜出（作者指出检索器微调因 in-batch 负样本在 LPR 上反而次优）。
- 代价（一手，Limitations）：训练算力约是直接训检索器的 **2 倍**；但训好后是**插到任何检索器前面的插件**，不用按检索器各训一遍。
- 局限（一手，Limitations 原话）：**只用了一个数据集**（美国联邦判例 LePaRD），作者自己把「多语种、跨法域」列为未来工作。
- **能不能用**：**能，这是本线最值得进路线的一篇**。我们的 FTS5 就是 BM25 家族，而我们的核心痛点正是「53.0% 的大白话提问与原文零字面重叠」。训练数据我们有现成的：**22,992 条条款互引边**天然是「上下文段落 → 被引条款」的对，可以拿来构造改写训练集。
- **不能照抄的地方**：它是**美国判例**、目标是**判例段落**；中文条款的改写目标域不同，必须自己造训练对并重新验收。

### 公式检索（ARQMath-3 总览 + SIGIR 2023 融合论文）
- 解决什么：数理表达式检索——同一个公式不同书写、不同变量名。
- 数字（一手，ARQMath-3 总览）：Task 1 最好的是 **Approach0 的人工 run，nDCG′ 0.508**；最好的自动 run 是 **MSM 0.504**；主指标用 nDCG′（去掉未判定文档的 nDCG@1000）。
- 关键结论（一手，SIGIR 2023 融合论文）：**结构检索在公式型主题上强，词法稀疏检索在文本型主题上强，两者融合最好**；把数学 token 也放进稀疏权重反而制造大量误命中。
- **能不能用**：**暂不建结构索引**。我们的公式需求是「条款里的公式能被检索到」，MinerU 已给 LaTeX——把 LaTeX 原文一起进 FTS5（`\frac` 之类按符号分词）就够用；建 MathML/OPT 结构索引属于另一个工程，受众比例太低。

### RAG 综述里关于「引用可回溯 / 评测」的部分
- 我没找到一篇专门讲「条款级引用可回溯」的综述，**明确记为未取证**。最接近的一手材料是 ALCE（引用质量指标）与 Sufficient Context（证据充分性），两者合起来正好覆盖我们「引用点得准 + 证据够不够」两件事。转述性综述（如 Gao 等的 RAG 综述）我**没有逐页读**，不引用其结论。

## 三、对我们：值得进技术路线的 1~3 条（写清层位）

**第 1 条（召回层 + 重排层）：条款语域的查询改写，做成「改写器插件」而不是「删词过滤器」。**
- 进哪一层：**召回之前**（第六通道之外的前置步骤），FTS5 / 向量 / 法理要素三路共用同一份改写结果。
- 证据：GuRE +32.96 nDCG@10（BM25 上）、DS@GT +33.88% nDCG@10 与 +20.61% 首段召回、SRCB 第一步就是 cue list、IISER-K 纯 BM25 靠改写拿到 0.4239、Webis 三轮都靠这一点。
- 具体做法：用 22,992 条条款互引边造「用户问法 → 条款」训练对，训一个 7B 级改写器；**输出是「像条款的表述」而不是同义词列表**。
- 验收红线：必须在**真人提问**上验收，不能在合成集上验收（UAmsterdam：合成 +25.4%、真人 +2.7% 不显著）。
- 必须先做的反证实验：先拿 200 条真人问题做 A/B，若改写后 FTS5 的 top-50 召回没有 ≥10 点提升，整条不做。

**第 2 条（重排层）：RRF 之后加「pointwise 打分 → listwise 轮转重排」两级，先不训模型。**
- 进哪一层：**重排**（六通道 RRF 之后、生成之前）。
- 证据：YaleNLP 只加 pointwise 这一层 +0.0625 NDCG@1000（0.5424→0.6049）；SRCB 三级重排 0.6824；Webis 用 monoT5 小模型就在 BM25 之上拿到 0.4588 nDCG@10。
- 具体做法：先用现成的中文重排模型（BGE Reranker 类）做 pointwise 把 top-1000 收成 top-100，再用 LLM 做 listwise 轮转（batch=20）重排 top-100。**这一步不需要训练**，也不改索引。
- 代价：每问多 1 次重排模型前向 × 1000 条（可控）+ 5 次 listwise LLM 调用（可控）。对 522,021 条条款的库，这是**唯一能在不改底座的前提下把 NDCG 抬上去的地方**。

**第 3 条（引用层）：把 citation recall/precision 变成我们的验收指标，把「证据充分性闸门」变成拒答条件。**
- 进哪一层：**引用 + 生成**。
- 证据：ALCE 自动分≈人工分（差 1~2 分），且揭示「最好模型也有 50% 句子引用支撑不全」；Sufficient Context autorater 93% 准确、闸门把作答正确率抬 2–10%。
- 具体做法：每条引用断言三件事——① 引用的条款号存在于库中；② 条款文本确实支撑这句话（citation precision）；③ 覆盖率足够（citation recall）。三件事任一不成立就**不出这条引用**，直接减少「红箭头点过去对不上」的情况。
- 代价：需要 200~500 条人工标注的「句子—条款」对做金标；每问多一次充分性判别调用。

## 四、看完了也不该抄（附理由）

| 东西 | 不抄的理由（一手依据） |
|---|---|
| **Late Chunking** | 收益只有 +1.9 绝对点 nDCG@10（p.3）；要求长上下文 embedding 模型；「换向量底座」已判死 |
| **RAPTOR 树** | 中间节点是 LLM 生成的摘要，**点不回 PDF 页**，与红箭头引用冲突；受控实验里只 +1.7 点（QuALITY 54.9→56.6） |
| **GraphRAG** | 目标是全局综述不是定位条款；索引 Podcast（1M token 级）要 281 分钟，成本随语料线性涨；社区摘要不可引用 |
| **LightRAG 的图** | 同上；但它的「双级关键词检索」思路可借（见 §二） |
| **HippoRAG 直接上图** | 我们**跨文档边 = 0**、有边条款只 4.93%，PPR 会在单文档里打转；先补边再谈图算法 |
| **TREC ToT 的外部数据（TOMT-KIS）** | 128 万条英文电影 ToT 查询，中文法规域零迁移；任务书 §六已判死 |
| **照抄 2024 冠军的「GPT-4o 吐标题」** | 它成立的前提是「答案是维基实体、名字唯一可枚举」；条款名不唯一，且这条路一次查询打一次前沿模型，对我们百万级条款的日常检索不可接受 |
| **用 LLM 给每个块生成上下文（Contextual Retrieval 的 LLM 版）** | 千万级条款 × 每块一次调用；且 LLM 生成的文字会进被检索文本，污染可回溯性。**我们用确定性的「标准号+条款号+章节标题」前缀代替** |
| **RM3 / Bo1 / KL 伪相关反馈** | 三条独立一手反证：UAmsterdam「RM3 在三个划分全部变差（dev3 −45%）」；DS@GT「RM3/Bo1/KL 全部低于原查询，R@1000 从 0.7705 掉到 0.5093/0.7295/0.7332」 |
| **按域路由到多个专家检索器** | YaleNLP 实测「通用模型 0.5424 > 按域路由 0.5098」（Table 4）；多训 N 个模型还多 N 份维护 |
| **在合成查询上验收** | UAmsterdam 的核心警告：合成 dev3 的 Success@100 是 0.6623，真人测试只有 0.3248 |

## 五、对不上的地方（来源互相矛盾，单列不抹平）

1. **任务书的「TREC 2022 ToT」不存在**。见 §1.0：TREC 31 议程无反链、官网只列 2023–2025、NTCIR 页明写 2023-2025。这是任务书前提错，不是我没查到。
2. **Webis 2025 论文的表头标签与总览口径冲突**：论文 Table 1 列名写 `Recall@100`、值 0.7637；TREC 34 总览表里同一 run（`webis-bm25-gpt-oss`）的 `recall_1000` = 0.7637。同一数字挂在两个不同指标名下 —— 我按**总览**口径记为 Recall@1000，并保留这条冲突。
3. **2024/2023 两届冠军都没有参赛论文**：TREC 33 的 ToT 论文只有 yalenlp / IISER-K / webis 三份；TREC 32 只有 Overview 与 `RSLTOT.T.pdf`。所以 h2oloo 与 CMU-LTI 的方法我只能读到**总览叙述**（2023）和**官方提交表单那一栏**（2024），**不是一手方法描述**。别把这两条当选型依据。
4. **「稠密 vs 稀疏」两边打架**：2024 总览说稠密基线（0.2377）胜过 BM25（0.1484）；2025 总览说 BM25（0.1700）远胜稠密（0.0514）。同年 IISER-K 纯 BM25+改写（0.4239）比 2024 稠密基线高一倍。**结论只能写成「取决于语料与改写质量」，不能写成「稠密更强」**。
5. **RAPTOR 的「20%」与它自己的受控实验不是一回事**：摘要说 QuALITY「比此前最好成绩高 20 个绝对点」（那是接 GPT-4、与历史最好配置比）；同一篇受控实验里（UnifiedQA-3B reader）只从 54.9% 到 56.6%（+1.7 点）。引用时必须写清是哪一个口径。
6. **Anthropic Contextual Retrieval 的 35%/49%/67% 是相对降幅、且是内部评测**：metric 是 1 − recall@20，绝对量级只有 5.7%→1.9%；它的「无公开基准、无同行评审」是博客自身的局限，转述时不能当「检索准确率提升 67%」。
7. **DS@GT 自报的提升与它的官方提交成绩不在一个口径**：论文说改写让 nDCG@10 +33.88%，但该队在 TREC 2025 的官方最好 run `gmn-rerank-500` NDCG@1000 只有 **0.4106**（总览 Table 1）。它的数字是 dev3 伪测试集上的对照，不是官方测试集名次。
