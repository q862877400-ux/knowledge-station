## 结论先行（≤15 行）

1. **任务书里有两处前提错了，和 D 线核出的「TREC 2022 没有 ToT」同一类**：① **TREC 没有 FTS / Full Text Search 赛道**（`pages.nist.gov/trec-browser` 的 TREC-1→TREC-34 完整赛道索引里没有，`trec.nist.gov/data.html` 的 73 条赛道菜单里也没有）；② **TREC Deep Learning 是 2019–2023，不是 2020–2025**，2024/2025 议程里已无该赛道【一手】。
2. **最贴我们的一条赛道被所有人漏了：TREC Legal（2006–2011）**。它是 TREC 唯一一档法律文档检索评测，685,592 份文档、召回优先、允许每主题最多 1,000 次人工判定。它的结论直接打我们的脸：**「多数参赛系统在各级 cutoff 上大幅高估了自己的召回」**【一手，LEGAL.OVERVIEW.2011 p.9】。
3. **法条检索的"检索到就算成功"已经被主办方判为"没有挑战"**：COLIEE 2025 总览原话是「相似度式法条检索（Task 3）几乎没有剩下什么挑战」，下一届改为**联合检索+蕴含，且必须显式给出用于蕴含的法条、引用齐全（recall=1）才计分**【一手，DOI 10.1007/s12626-026-00199-9 §6】。⇒ 我们的验收口径不该停在 top-k 命中。
4. **中国法条级检索确实有比赛**：**CCIR 2025 Cup「法律知识检索与生成」**，冠军是山东大学通用智能实验室，方案 = **多轮问句重写 → 定制向量检索 → 滑动窗口打分重排**，A 榜 39.148 / B 榜 41.0224 双第一（53 名选手）【一手·获奖单位官方通报】。这和我们六通道 + 重排的骨架同构。
5. **但"中文国标（GB/GB/T）条款级检索 + 引用评测"——没有比赛，只有数据集**。明确回答见 §五：找到 4 个国标类评测对象（SAR / SCT / GB/T-Bench / 电力标准集），**没有一个是以赛题形式办的**，且都只有几十到几百条条款。
6. **引用层已经有一套可搬的口径，而且天花板很低**：TREC 2024 NeuCLIR 中文报告生成榜首 **引用精确率 0.859 / 引用召回率 0.327**（ARGUE 框架）；TREC 2025 RAG 的 support 加权精确率榜首 **0.9522**；RAGTIME 2025 的自动-人工一致性 topic 级 Pearson 只有 **0.440**【一手，三份总览表】。
7. **自动评只能用来排名，不能当绝对分**：TREC 2025 RAG 的相关性判定任务，最好的自动裁判与人工一致率只有 **0.30–0.34**、kappa **0.21**【一手】。L 层的"自动评分"若写进验收，必须配同批人工锚点。
8. **我们"六通道 + RRF"的方向被三次独立赛事验证**，但缺的是**融合后的重排**和**融合前的候选池控制**：NeuCLIR 技术文档任务两届榜首都是"异构多路融合"（2023 naverloo 0.496；2024 ISI 0.496）；RAGTIME 2025 的 MLIR 榜首是"PLAID-X + LSR + Qwen3 三路融合 → Qwen3 + Jina 双重重排"（nDCG@20 0.661，BM25 基线 0.417）【一手】。
9. **"先粗排保住召回、再神经重排"有硬数字**：COLIEE 2025 冠军 JNLP 实测 **BM25 top-100~200 就能拿到 76–85% 召回**，候选空间从 7,130 降到 100–200；任务 1 全场最高 F1 只有 **0.3604**【一手】。⇒ 漏斗第一步该是 BM25 家族（我们已有 FTS5）。
10. **现成中文稠密模型在中文技术文本上会输给 BM25**：NeuCLIR 2024 技术文档任务里 `gte-qwen-desc+title` 的 nDCG@20 = **0.195**，是全表最低，低于所有 BM25 变体（最好的协调方 BM25 0.309）【一手，Table 12】。这条直接反驳"先换向量模型就能提升"。
11. **"废止条款不许召回"已经有现成量化指标**：SAR 数据集用 **AbolishedRate@5**——前 5 条里混进已废止条款的比例，**BM25 = 25.9%，加入替代边过滤后 = 0%**；SAR+LLM 混合 **MAP 45.6%**（GB 55037-2022 + GB 50016-2014，633 条含 93 条已废止）【一手·作者自述，Zenodo v3】。
12. **推理密集型查询会让强嵌入模型崩塌**：MTEB 上 59.0 nDCG@10 的 SFR-Embedding-Mistral，在 BRIGHT 上只有 **18.3**；加显式推理后提升最多 **+12.2 点**【一手，arXiv 2407.12883】。这与我们"53.0% 的大白话提问与原文零字面重叠"是同一个病。
13. **别把"榜上第一"当技术路线**：TREC 2025 报告生成的榜首是**协调方自己的抽取式基线**（AutoARGUE F1 0.562），压过全部 13 支队伍的 LLM 生成管线【一手，RAGTIME Table 8】。抽取式在"要可引用"的场景里更稳。
14. **看完不该抄的**：ToT 式外部数据（§六已判死，不再提）、SRCB 式每问打 4 家前沿模型、CRAG-MM 多模态可穿戴、LongBench/∞Bench 长上下文榜、类案检索的图神经网络、LEXTREME/LEXam/LegalBench 这类"考模型懂不懂法"的榜——理由逐条见 §七。

## 一、TREC 系（逐条：问什么 / 榜首路线 / 指标 / 与我们的语料差异）

### 1.1 TREC Deep Learning（2019–2023，**最后一届是 2023**）
- **问什么**：MS MARCO 段落/文档排序，两个子任务（全库检索 fullrank / 只重排给定 top-100 rerank）。判定 4 档（3 完美 / 2 高度 / 1 相关 / 0 不相关）。
- **2023 榜首**：h2oloo 的 `naverloo-rgpt4`，fullrank + **prompt（LLM 直接排序）**，nDCG@10 = **0.6994**、nDCG@100 = 0.5370、AP = 0.3382；同年最好 `nnlm` 路线 0.5972、最好传统 DPH 0.2825【一手，trec32 Overview_deep.pdf p.7 Table 2】。
- **官方原话**：「今年的头号结果是用 LLM prompting 的 run 压过了连续四年最强的 nnlm 路线」；并且「多数 prompt 路线其实也用了 MS MARCO 训练数据」【一手，p.1 / p.10】。
- **2022 榜首**：Ali 队 `pass3`，nnlm 多级（稠密检索 + 重排），nDCG@10 = **0.7184**【一手，trec31 p.8 Table 2】。**注意**：与 2023 不同测试集，**不可横比**。
- **差异**：英文网页问答段落，答案是"一段话里有没有答案"；我们是"哪一条条款"。**评测口径完全不可迁**，只有"粗排→精排两段式"这一条结构结论可迁。

### 1.2 TREC NeuCLIR（2022–2024，**2025 起由 RAGTIME 接续**）——**本线最重要的一条**
- **问什么**：英文主题 → 中文/波斯文/俄文新闻的跨语言检索（CLIR）、三语统一排序（MLIR）、**中文技术文档 CLIR**（英文主题 → 中文学术摘要）、以及 2024 新增的**报告生成**（英文报告 + 每条陈述引用目标语言文档）。
- **语料规模**：中文新闻约 **300 万篇**（官方表述；2024 年另有 **765,299 篇**中文文档因语种识别问题被排除在集合之外。我不把两者相加当"原始规模"，那是推断）；**中文技术文档 = CSL 期刊摘要 396,209 篇，1,980 种期刊，2010–2020，67 个学科**（工程/理科/农/医为主）【一手，trec33 §2.2；trec32 §3.1】。
- **相关性判定口径（关键）**：技术文档任务让评审员"假装在写论文的相关工作章节"，判断"我会不会打算读这篇并可能引用它"【一手，trec32 §3.4】。⇒ **这是"引用价值"作为相关性，不是"提到关键词"**。
- **2024 中文新闻 CLIR 榜首**：hltcoe `kitchen_rankfuse.mt5rerank.gpt4rerank`（多路融合 + monoT5 重排 + GPT-4 重排）nDCG@20 = **0.664**、R@1k = **0.993**；协调方 BM25 基线 **0.468**【一手，Table 8】。
- **技术文档任务两届榜首都是 0.496**：2023 naverloo `EverythingRun_RR`（混合稀疏+稠密 + RRF）；2024 ISI `tech-ISI_SEARCHER-ANE_run1`【一手，trec32 Table 9 / trec33 Table 12】。
- **反面教材（必看）**：2024 技术文档任务里 `gte-qwen-desc+title`（现成中文稠密模型）nDCG@20 = **0.195**，**全表最低**，低于所有 BM25 变体；2023 里纯稠密 mContriever 0.339 vs BM25(qt) 0.356【一手】。
- **方法细节**：2023 榜首 run 名里的 `RR` = reciprocal rank fusion（多路结果融合）；2024 榜首 "rankfuse" 同理。**两次都不是靠单一模型赢的**【一手+推断】。
- **差异**：中文技术摘要 vs 中文条款——都是"术语密集、字面重复高、需要专业判断相关性"；**这是所有赛道里与我们语料最接近的一个**。但它是"英文问→中文答"，我们是"中文问→中文答"。

### 1.3 TREC CAsT（2019–2022）与 iKAT（2023–2025）
- CAsT 2022 加入 **response generation**（用检索到的段落当 provenance）和 **mixed initiative**（系统可以反问澄清），并开始评"多轮路径"级指标【一手，trec31 Overview_cast.pdf p.1】。**2022 后停办，官方把 iKAT 定为它的 successor**。
- iKAT 2025：7 队 30 个 auto/gen-only run + 16 个交互 run；主流管线 = **PTKB 命题相关性预测 → 会话查询改写（CHIQ-AD / LLM4CS / AdaRewriter）→ SPLADE/BM25/ANCE 检索 → 多级神经重排 → LLM 摘要**【一手，trec34 Overview_ikat.pdf】。
- ⚠ **官方站 `www.treccast.ai` 已被域名劫持**，2026-10-25 抓取返回印尼语博彩站。只能用 `trec.nist.gov/data/cast.html` 与 PDF。
- **与我们的差异**：多轮 + 个人化。我们单轮为主。可借的只有"查询改写 + 反问澄清"这个交互形状。

### 1.4 TREC RAG（2024–2025）与 RAGTIME（2025）
- **TREC RAG 2025**：把"短关键词查询"换成"多句式长叙事"，四层评测 = 相关性 / 响应完整性（nugget）/ **引用支撑度** / 一致性。16 组 51 个 RAG run + 9 组 25 个 AG run【一手，trec34 Overview_rag.pdf】。
- **引用支撑度榜首**：WING-II `no-llm-refined`，加权精确率/召回率 **0.9522 / 0.9522**（**纯抽取、不做 LLM 精修**）；第二名 ii_research RAG 0.9298 / 0.9189【一手，Table 11】。
- **自动相关性裁判不可信**：最好的自动判定 run 与人工一致率 **0.34**、kappa **0.21**；多数在 0.28–0.32【一手，Table 13】。
- **RAGTIME 2025**：四语（阿拉伯/中/英/俄）各 **1,000,095 篇**；13 队 125 run。MLIR 榜首 `hltime-qwen-jina` = **PLAID-X + LSR + Qwen3 三路融合 → Qwen3 + Jina 双重重排**，nDCG@20 = **0.661**，MAP 0.454，R@1000 0.610；BM25 基线 nDCG@20 = 0.417，仅标题 BM25 = 0.297【一手，Table 11】。
- **报告生成榜首是协调方的抽取式基线**：`extractive_rag` AutoARGUE F1 = **0.562**（Nugget 覆盖 0.498 / 句子支撑 0.771），压过全部参赛 LLM 管线【一手，Table 8】。
- **自动评与人评的一致性**（关键限制）：句子支撑 topic 级 Pearson **0.440**、run 级 Kendall **0.663**；并把"LLM 填值"与"乐观/悲观"三种赋值法对比，悲观赋值与 LLM 填值的相关高达 0.998【一手，Table 5/6】。⇒ **自动分对"怎么算没覆盖"极其敏感**。

### 1.5 TREC Legal（2006–2011）——**任务书没列，但是本线最重要的发现**
- **问什么**：e-discovery。2011 只剩 Learning Task：给 3 个"提交文书请求"，参赛队可以对每主题向 Topic Authority 要**最多 1,000 次**是/否相关性判定，然后**对全库 685,592 份文档排序，并给出每篇的"响应概率"**【一手，LEGAL.OVERVIEW.2011 p.1】。
- **语料**：EDRM Enron 数据集 v2，455,449 封去重邮件 + 230,143 个附件 = 685,592 份，约 100GB；主题 401 有 20,017 篇相关（约 2.9%）【一手，p.2 / Table 4】。
- **指标**：各级 cutoff（2k/5k/20k/50k/100k/200k）上的 **Recall / Precision / F1**，外加 **Hypothetical F1**（枚举全部 685,592 个 cutoff 取最优）与 **AUC**；还有"自估召回准不准"【一手，§5.2–5.3】。
- **榜单（只取到榜单，无冠军队论文一线方法）**：主题 402 在 top-2,000 上 **rec03TF R=51 P=77 F1=61**（全表最佳）；主题 401 在 top-2,000 上最好 F1 只有 **18**（mlblrnTM / ISIROTTF），在 top-20,000 上 ISITrFAM **R=53 P=51 F1=52**【一手，Table 5/6】。
- **最有价值的两条结论**：① **70% 召回只需看全库的 1%–11%**（主题 403 甚至 top-5,000 = 不到 1% 就到 70%；主题 402 是 top-20,000 = 3%），但代价是精确率很低；② **「多数 run 在多数主题上严重高估自己的召回」**——官方原话 "dramatically overestimated recall at all cutoff levels"，并警告这会让复核负责人**过早收工**【一手，p.9】。
- **差异**：美国邮件、诉讼取证，不是法条；**"每篇给响应概率"这种口径和我们不对应**。但**召回优先 + 自估召回校准**这两件事完全对应我们。

### 1.6 TREC Clinical Trials（2021–2023）
- **只取到赛题与年份，未取到冠军方法与指标**：`trec32/papers` 下 `Overview_trials.pdf` 等 8 个候选文件名全部 404，`pages.nist.gov/trec-browser/trec32/clinicaltrials/` 也 404；官方索引页只列 2021/2022/2023 三届，2024 起不再办。
- 形状（患者画像 → 可入组临床试验）与条款检索差太远，**判不适用**。

## 二、NTCIR 与 CLEF

### 2.1 NTCIR-18（2024–2025）
- **7 个 core task**：AEOLLM（自动评测 LLM）、FairWeb-2、FinArg-2、Lifelog-6、MedNLP-CHAT、RadNLP、**Transfer-2（基于资源迁移的稠密检索）**；另有 HIDDEN-RAD / SUSHI / U4 报名条目【一手，NTCIR-18 官网】。
- **Transfer-2**：跨语言（日↔其他）+ 复用 TREC NeuCLIR 2023 的中/波/俄新闻集合，查询 54–60 条，指标 nDCG@20；明确写"正在与 TREC NeuCLIR 组织者协商"【一手，NTCIR-18 kickoff 讲义】。
- **中文法规**：无。**各任务冠军与分数本轮未取证**。
- 历史定位：NTCIR 的 ToT 页原话已确认 ToT 原本是 TREC 2023–2025 的赛道（D 线已引）。

### 2.2 CLEF
- 官网只给到组织架构、历届时间地点（2024 格勒诺布尔 / 2025 马德里 / 2026 耶拿 / 2027 布加勒斯特）与"CLEF 始于 2000 年的 Cross-Language Evaluation Forum"。**lab 时间线是交互式按钮渲染，本轮读不到结构化数据**【一手，官网首页】。
- **CLEF-IP（专利检索）的年份与冠军本轮未取证**，不写结论。
- ⚠ **任务书把 JURISIN 归到 CLEF 系，取证不支持**：COLIEE 2025 总览原文写 "COLIEE is usually co-located with JURISIN, the Juris-Informatics workshop series"——JURISIN 是与 COLIEE 同场办的 JSAI 系 workshop，**不是 CLEF 的 lab**（CLEF 的姊妹计划是 TREC / NTCIR / FIRE / MediaEval，官网原话如此）【一手】。

### 3.6 COLIEE 2025（第 12 届）——**只写 D 线没有的增量**
> D 线已记 COLIEE 2024 Task 1（TQM 队，词法+语义双路 + LTR）。这里只写 2025 届。
> 一手来源：Review of Socionetwork Strategies **20:183–213 (2026)**，DOI `10.1007/s12626-026-00199-9`，**开放获取全文**（Springer HTML 可读；PDF 直链被反爬拦）。

- **规模**：4 个正式任务 + 1 个新 pilot。判例数据 = 测试 1,870 案（400 查询 / 1,470 候选）、训练 6,835 案；Task 2 测试 100 查询 / 3,283 段落；**规则：只许用开源 LLM，GPT-4o / Gemini 等闭源模型禁止**【一手】。
- **Task 1（判例检索，8 队 21 run）**：最好 **F1 = 0.3604（JNLP）**，同队第二名 0.3531，第三 UQLegalAI 0.3091–0.3113。F1 之所以低：平均只有约 4 篇"noticed"案要从 1,470 篇里挑（**正例约 0.3%**），且**所有引证标记都被替换成 `FRAGMENT_SUPPRESSED`**，逼系统靠语义而不是"它引了谁"。
- **Task 1 冠军路线（JNLP）**：沿用上届 UMNLP 框架 → **先用 BM25 筛候选**（实测 **top-100~200 就保住 76–85% 召回**，候选空间 7,130 → 100–200）→ 再用"BM25 分 + SAILER 分"等特征训练前馈网络做成对判别。**全场 8 支队都改成了多级流水线**（初筛 → 神经重排 → 后处理）。
- **Task 2（判例蕴含，6 队 18 run）**：最好 **0.3195（NOWJ）**：BM25 检索 + **DeepSeek-V3 与 Qwen/QwQ-32B 重排**。
- **Task 3（法条检索，8 队 22 run）**：最佳系统 = **少量候选初筛 → LLM 交叉编码器重排 → 多个 LLM 共同判定**；官方描述"**对单法条题几乎完美，但对多法条题仍找不全**"。**该表数值本轮未取到**（只有文字描述）。
- **Task 4（法条蕴含，11 队 29 run）**：最好 **准确率 0.9041（KIS，日语 few-shot）**；组织者注：**用日语的队明显更强**，以往不是。
- **新 pilot（日本侵权）：TP 准确率 0.765（CAPTAIN，70B 生成模型）**；**RE F1 0.712（KIS，130M 的 ModernBERT）**——**小编码器打败 70B 生成模型**，组织者明确写"encoder-based 仍有竞争力"。
- **最该带走的三句**：① 主办方结论：**"相似度式法条检索（Task 3 这种设定）几乎没有剩下什么挑战"**，下一届改为**联合检索 + 蕴含，且要求显式给出用于蕴含的法条**，评测用"**只有在引用齐全（recall = 1）时才计正确率**"（并考虑加 precision / F2 防"多给一堆条款"）；② **数据集去重的影响**：原 2,159 → 1,870 测试文件、7,350 → 6,835 训练文件，去重后多数队 **F1 涨 5–10%**、名次不变 ⇒ **我们先查重再谈评测**；③ 正例率 0.3% 的极端不平衡用 F1 而不是 nDCG@10——**我们的条款检索该用哪套指标，这条给了参照**。

| **GB/T-Bench**（arXiv 2608.06312, 2026-08） | 488 份 **GB/T** 标准文档 | 定位到章节 | 评"错误定位+维度+类型精确匹配" | 7,306 个错误实例 |
| **电力标准评测集**（IEEE 11517387） | 电力行业标准多版本 | 标注到"标准号+版本+条款+页" | **是**（要求可审计推理链） | 未取到（【转述】） |

**（c）所以准确的结论是三句话**：
1. **中文法条的"条款级检索 + 引用"有竞赛（CCIR Cup）**；
2. **国标的"条款级检索 + 引用"只有数据集，没有竞赛**，且最大规模是 633 条（SAR），离我们的百万级差 3 个数量级；
3. **没有任何一个公开对象同时满足**"中文国标/法规 × 百万级条款 × 引用齐全（recall=1）才计分 × 持续榜"。**这个位置是空的。** 我们要么自建验收，要么直接对标 COLIEE 2026 的新口径（§3.6）+ ARGUE 的指标定义。

## 六、对不上的地方（来源互相矛盾，单列不抹平）

1. **LEXam 的题量三个官方来源三个数**：ICLR 2026 论文摘要 **7,537 题**；HKU 讲座页（2025-12-08）**4,886 题（2,841 开放 + 2,045 选择）**；arXiv 正文（2505.12864）**3,628 题（2,867 开放 + 398 选择 + 363 判断）**。我**没有裁定哪个对**——只记"同一数据集有三个规模口径"。

## 七、对我们：值得迁的 3 条 + 不该抄

### 值得迁（按该迁的先后）
**① （召回层 + 重排层）把"融合"做实，别再加通道，而是在 RRF 之后加一级"可注释的重排"。**
- 证据：NeuCLIR 技术文档任务两届榜首都是**多路融合**（2023 `EverythingRun_RR` 0.496 = 混合稀疏+稠密 + RRF；2024 "rankfuse" 0.496）；RAGTIME 2025 MLIR 榜首 = **三路首段融合 + 双重重排**（0.661 vs BM25 0.417）；COLIEE 2025 冠军 = **BM25 粗排（top-100~200 保住 76–85% 召回）→ 神经重排**（F1 0.3604，全场最高）；CAsT/iKAT 主流管线也都是"改写 → 检索 → 多级重排"【均一手】。
- 具体形状：**融合后的 top-N 用"pointwise 打分 → 小批量 listwise"两级收窄**；先不训模型。第一级用现成中文重排模型把 top-500 收到 top-50，第二级用 LLM 对 top-50 做批量重排。
- ⚠ **D 线已实测过 pointwise 重排并判"不接生产"**（`eval/recall-funnel/exp-11-rerank-fix`：主终点 7→9、McNemar 双侧 p=0.5、单次 rerank p50 1.10 s）。所以这条**不是"再试一次 pointwise"**，而是**"试没试过的第二级 listwise"**，且验收必须按 D 线定的红线：在真人提问上量，不许在合成集上量。
- 顺带抄一条**候选池控制**：SRCB 式"先用元数据把候选池砍一个数量级"我们已经有（效力状态、标准号、章节），但现在没用它做**前置过滤**。

**② （评测层 + 引用层）把"引用齐全"当闸门，而不是把 top-k 命中当成功。**
- 证据：COLIEE 2025 主办方判定"相似度式法条检索几乎没有挑战了"，2026 年改为**必须显式给出用于蕴含的法条，且只有在引用齐全（recall=1）时才计分**，并考虑加 precision / F2【一手】；ARGUE 的 nugget coverage + sentence support + citation precision/recall 已经在中文上跑通（NeuCLIR 2024 中文报告生成：精确率 **0.859** / 召回率 **0.327**）；TREC RAG 2025 的 support 加权精确率榜首 **0.9522**；ALCE 的 citation recall/precision 与人工差 1~2 分（D 线已引）。
- 具体形状：每条回答的引用断言三件事都必须过——① 条款号在库且**效力状态不是已废止**；② 该条款文本支撑这句话（precision）；③ 该说的条款没漏（recall）。**任一不过就不出这条引用。**
- **必须同时加"废止闸门"**：SAR 的 **AbolishedRate@5**（前 5 条混进已废止条款的比例）——BM25 **25.9%** vs 加替代边过滤 **0%**【一手·作者自述】。这条指标我们库里有现成字段就能算，成本极低。

**③ （解析层 + 切分层）照 READoc / SCT / CLaw 三家的口径，把"条款级切分"从"我们的实现"变成"可对外证明的东西"。**
- 证据：CCKS 2025 的 READoc 用 **5 维度 × 10 指标**评"PDF → 结构化 Markdown"，A 榜 300 份 PDF、406 支队；SCT-aerospace 的语料**就是用 MinerU 转的 Markdown**，且把 `supporting_facts`（标准文件名 + 段落原文 + 三元组）直接当 CiteAcc 的 ground truth；CLaw 把"国家法律切到款/项级 + 每条带修订时间点"当成论文的**第一贡献**；Legal-DC 把"条款边界切分索引"当成独立贡献【均一手】。
- 具体形状：① 我们的条款表加两列本来就该有的东西——**款/项层级**与**修订时间点/效力状态**；② 切分正确性用一个**能从切分结果反推的指标**（条款号 → 原文段落可逆率）来验收，别只看"切出来几条"。
