# 跨平面交叉引用（法条 ↔ 你自己的文档）：评估与待决方案

> **性质**：**评估产物**。本轮**未改任何产品代码、未写任何库**（真库全程只读 `mode=ro`）。
> 结论与数字全部来自本轮实测，探针脚本列在文末，任何人可当场复算。
> **一句话**：这件事的门槛**不在"跳"，在"格式进得来 + 位置说得清"**——而这两件今天都不成立。

---

## 一、问题与已定的范围

**业主的用法（原话要点）**："我在研究一个技术文档的问题，比如参考技术文档去编写软件，这时候涉及到法律法规了，
**它互相之间要交叉着跳**。" ⇒ 目标不是"两个库并存"，而是**一次提问里两边能互相走**。

**本轮业主裁定（2026-09-24）**：

| 项 | 裁定 | 落成范围 |
|---|---|---|
| 格式 | "Word、PPT、Markdown、HTML、PDF，甚至 JSON、代码文件都会有" | 先做通 **PDF / DOCX / MD / TXT / HTML**；**PPT 缓办**；**代码/JSON 不作专门解析**（当纯文本兜底） |
| 精度 | **要精确到条款号**（例：GB 30871-2022 第 5.2 条） | 必须做**版本钉版 + 标准号约束** |
| 缺目标 | "问我要不要去找并入库" | **允许一次问一批**（列清单、逐项可勾、可全否） |

⚠ **第三条收窄了现有纪律**：`docs/CODE-REVIEW-CHECKLIST.md` 把"**采集每次先问**／安全面只紧不松"列为评审面。
本轮裁定只放**粒度**（可一次问一批），**不放开"必须人批、无旁路"**。已登记 [NOT-DOING](../NOT-DOING.md) #20。

## 三、枢纽：**定位坐标契约**（不定这个，做出来就是 PDF 专用）

| 格式 | 位置该怎么表示 | 跳过去看到什么 | 今天 |
|---|---|---|---|
| PDF | 页号 + 字符区间（解析器给得出时再加位置框） | 那一页 + 红箭头 | ✅ 已有（法条侧） |
| DOCX | **标题路径 + 段落序号** | 文字视图滚到那一段 | ❌ 现在谎称"第 1 页" |
| Markdown | **标题路径 + 字符区间** | 文字视图 + 高亮 | 🟡 字符区间有效，无渲染视图 |
| HTML | 标题路径 + 元素锚点 | 渲染或文字视图 | ❌ 格式不支持 |
| PPT | 幻灯片号 + 形状序号 | 那一页幻灯片 | ❌ 格式不支持（**本轮缓办**） |

**两条硬要求**（都是从今天的毛病倒推的）：
1. **一个契约 + 一个格式字段**，不是每种格式各造一套。（本仓因"同一机制两份实现"反复栽过。）
2. **"没有页"必须如实说没有** —— 今天 DOCX 把它填成 `1`，于是引用定位指向一个不存在的页。
   这是本仓最恨的"看着正常、其实错了"。

## 四、一个好消息：格式越结构化，跳得越准

**Markdown / HTML 里的引用本来就是机器可读的**（链接、锚点、`id`）；**不需要正则猜**。
而散文 PDF 里"应符合 GB 30871 的规定"**只能靠正则猜** —— 这套正则的脏度本轮实测：

| 项 | 实测 |
|---|---|
| 法条正文抽出的外部引用字符串 | 170,814 条（分布在 **84,796** 条文里，占全库条款 16.24%） |
| 其中**不像标准号**的（裸数字"2008""1000"） | **47.6%**（根因：`classifier.py:81` 把标准前缀写成**可选**） |
| 形如标准号且**库内确有** | 10,559 条 |
| ⇒ 能获得**真实跨文档跳**的正文 | **8,926 条（1.71%），涉及 3,861 部标准** |

⇒ **顺序应反过来**：先做 Markdown/HTML（零猜测、当天可验证），再啃散文 PDF。

## 六、怎么证明"跳对了"

### 档一：文档 → 哪一部标准（**有免费金标，今天就能跑**）

每篇标准正文第 2 章「**规范性引用文件**」逐条列出了它引用了哪些标准。实测：

| 项 | 实测 |
|---|---|
| 有这一章的文档 | **5,400 篇 = 全库 79.4%**（5,667 条文） |
| 从这些章节抽到的标准号提及 | 47,745 条 |
| **其中库内确实有的** | **803 条（1.7%）** |

⇒ 这是**免费的、原文自带的"该跳到哪里"标准答案**。
⚠ **诚实边界**：只有 **1.7%** 两头都在库里 ⇒ **跨文档边的上限今天是"库里覆盖到哪"，不是"抽得准不准"**。

**而这一条本身立刻是个功能**：告诉你「这份文档引用了 23 部标准，**库里有 9 部，另外 14 部要不要入库**」
= 主计划 **R55「引用完整性与缺失依赖检查」**（当时标"未查证"）的确定性实现。

### 档二：精确到条款号（**没有免费金标**）

「规范性引用文件」只到"部"、**不给"条"** ⇒ 条款级答案**必须人工标一小批**（估约 150 对），
且样本必须挑最难的三类：

| 错法 | 量化反例（本轮实测） |
|---|---|
| **跳到同号不同标准** | `clause_number='5.2'` 命中 **4,910 行**，**只有 1 行**属于 GB 30871-2022；全库 37,989 个条款号里 **15,691 个（41.3%）横跨多部标准** |
| **跳到旧版** | **39 组**标准号基名有多个年份版本并存；其中 **78 篇旧版仍标"现行"**（例：GB/T 10346-2006 与 2023、GB 5768.2-2009 与 2022） |
| **跳到不存在的条款** | 引用方提到的标准**库里没有** ⇒ 必须**明说"库里没有这一部"**，不许静默跳过、不许跳个差不多的 |

**钉哪一版不用我们猜**：引用方自己那段话写明了规则——"**注日期的引用文件，仅该日期对应的版本适用；
不注日期的，最新版本适用**"。照它执行即可，可审计。（这是与"版本链"合流的地方。）

⚠ **预告（先说，免得到时候觉得被骗）**：**档一会好看，档二会难看** —— 47.6% 的噪声与 41.3% 的歧义
**全都堆在档二这一层**。要条款级精度，就得先接受"初版准确率不漂亮"，再决定值不值得投。

### 档三：人眼抽样 + 阈值门禁

固定一批文档 → 抽取的边 → 人标"对/错/漏"；每次改动跑同一批，**准确率掉超阈值就拦住**
（照现有金标门禁做法，指标换成"边"这套）。抽样按置信区间给量（法律取证里叫 elusion test），不凭感觉。

## 七、最小可验证切片（**零写入、零模型钱**）

| | 拿什么 | 量什么 |
|---|---|---|
| **切片 A** | 一份 **Markdown 或 HTML**（引用是显式链接） | 跳对几条 / 跳错几条 / 库里缺哪几部 |
| **切片 B** | 一份**散文 PDF**（靠正则猜） | 同上 |

抽取是正则、解析是查库 ⇒ **不花模型钱、不碰真库写入**。
**两个数的差距一出来，"能不能上、先支持哪些格式"就有答案了** —— 比先建表再发现不行便宜得多。

## 八、代价顺序（建议）

1. **只读原型量准确率**（切片 A/B）← 先做这个：零风险、当天出数
2. **定位坐标契约**（不定则后患无穷）
3. 补 HTML 解析 + DOCX 真实位置
4. 修抽取正则（消掉那 47.6%）
5. 跨平面边表 + 幂等迁移
6. 一跳跨表走 + 显示"跳的理由"
7. 通用侧语义检索
8. 通用侧"打开原件到位置"（最贵、碰的是出过事故的区域）
9. 缺标准批量问
