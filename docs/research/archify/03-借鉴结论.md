# archify 对比与借鉴结论

> **性质**：决策记录（research artifact），不是产品文档。
> **取证基础**：`01-archify-逆向.md`（archify HEAD `654da74`，2026-10-19）+ `02-ks-现状.md`（本仓）。
> 本文的每条判断都能指回那两份报告里的文件与原文片段；凡属**我的分析**而不在证据里的，逐条标注。
> **本文不含施工**。要施工的那一条另开任务书，按本仓规矩先问业主。

## 一句话结论

**该抄的是它的「呈现层」，不是它的「证据层」。**

它把证据做得像证据，是因为它把编号、上标、页脚列表、结论先行、一屏一问都做成了可执行的编译期规则；而在「这条证据到底支不支持这句话」上，它只校验了**位置存在**（DOM 里有没有这个来源锚、仓库里那个 commit 下有没有这几行），**没有校验语义支持**——这一层我们本来就比它强，只是没显示出来。

所以我们真正缺的是**把已有的证据显示出来**，不是把证据做得更硬。

## 一、业主的两个判断，逐条核

### 判断一：「用它的结构，回答会更简单易懂」——**成立**

它的结构可以逐条指到字段（`archify/schemas/explainer.schema.json`）：

| 它的硬约束 | 原文 |
|---|---|
| 结论必须在最前，且**只有结论是必填** | `"required": ["summary"]` |
| 理由**最多四条** | `"maxItems": 4` |
| 每个面板只回答一个问题 | `## What is exchanged before the first request?` 这类标题即面板标题 |
| 面板里放的是块，不是散文 | 13 种块：`prose/list/callout/comparison/facts/metric/steps/diagram/code/snippet/chart/diff/image` |

这不是文风建议，是**数据结构上的强制**：你想多写一条理由，schema 直接不收。

我们这边对应的东西是**提示词里的一段话**——`plugin/src/chatmode.js` 第 2 条把「依据 → 推导 → 结论」写成给模型看的文字要求。模型漏写、写歪、换模型，都没有任何东西兜底。**这是"半有"，不是"有"。**

### 判断二：「它的证据比我们的红箭头更聪明」——**部分成立，但成立的那一层不是我们以为的那层**

把「它的证据」拆成三层，结论完全不同：

**第一层：编号、上标、页脚列表 —— 它确实比我们强，这一层成立。**

原文（`archify/references/explainer-authoring.md`）：

> `[reference text](source:docs)` renders the text followed by a numbered superscript; `[](source:docs)` renders only the superscript. Numbers follow first appearance; uncited sources follow in declaration order. The footer lists titles with URLs or repository positions.

我们**连编号都没有**。更要紧的是：我们其实**已经有那个编号原语了，却把它扔了**——

- 引擎提示词要求内部 LLM「每条结论后紧跟引用标记，格式 `[[c:i]]`，i 为下方证据序号」（`src/core/llm/ks_answer.py`）；
- 引擎会**校验它越界**（`citation_index_out_of_range: [[c:{i}]] 越界`），校验结果放进 `verification.citation_index_warnings`；
- 但**没有任何一处把它渲染出来**：全仓 grep `[[c:` 只有提示词、校验、注释三类命中，没有一处做剥离或渲染。它原样留在 `derivation` / `conclusion` 字符串里，往模型上下文里传。

**编号已经有了、绑在证据数组上了、还带越界校验——就是没显示。** 这一层的差距不是"我们做不到"，是"我们做了一半就停手了"。

**第二层：钉 commit + 冻字节 + 重算 sha256 —— 看着最唬人，但我们不需要。**

它怎么做的（`archify/renderers/shared/repository-evidence.mjs`）：`/meta/repository/revision` 必须是 40 位完整 SHA，否则 `repository-evidence/revision-invalid`；来源文件用 `git show <rev>:<path>` 真读字节、切行、算 sha256 进 `dependencies[]`；`check` 阶段再重算一遍比对（`dependency-hash`、`source-binding`）。

**它为什么必须付这个代价**：因为它指的是**行号**，而源码会变，行号会漂。不钉死，今天指第 30 行，明天指的可能就是别的代码。

**我们为什么不付**：我们指 PDF 的**页 + 行级坐标**。那份 PDF 是用户机器上的原件，任何人打开，第 37 页就是第 37 页，坐标不会漂。**搬这套过来，是为一个我们没有的问题付钱。**

（顺带一条它自己的降级：不给 `--repo-root` 时，带 `path`+`lines` 的来源**不报错**，而是静默退化成纯文字位置——`sources.mjs` 里那个 `catch {}` 是空的。它自己仓库里的 4 个案例页就是这样：`preparedSources` 里没有 `text`，来源是"位置声明"而不是"钉死并附摘录的证据"。所以"它把证据钉死了"这句话，在它自己的示例产物上并不成立。）

**第三层：证据的可见性 —— 这一层我们比它强。**

它 HEAD 上**已经把可见的证据徽标删干净了**：`installBeacons` 被 `4bd3013` 删掉绘制代码、被 `0942c7f` 删掉遗留空壳，测试反过来断言 `assert.equal(result.badgeCount, 0, type)` 与 `legacyMethodPresent === false`，`archify/assets/template.html` 里的注释自己写着 `without adding visual marks`。证据收进了「点一下节点才出现的 Semantic Passport」。

**它的做法是拿可见性换精确性——读者得先知道要点那里。我们的红箭头是常驻可见的。** 业主说「它这个证据似乎要更聪明一点」，如果指的是"一眼看得见证据在哪"，那**我们才是更聪明的那个**。

（`DESIGN.md` / `CHANGELOG 2.13.0` / `README_ZH.md` 至今还在描述旧徽标行为，所以从文档上读会误以为它有。这是 01 报告里的更正项，`01-archify-逆向.md` §4.4。）

### 判断二补一条：它的"证据"其实**没有语义校验**，我们有

这是最该说清的一条。它的闸门（`archify/explainer/check.mjs`）查的是：

- `source-target`：声明过的来源，DOM 里有没有对应的锚；
- `source-binding` / `dependency-hash`：仓库摘录的字节、sha256、commit 对不对得上；
- `unresolved-reference`：正文里 `[x](#id)` 指的 id 存不存在。

**它从不检查"这句论断是不是真的被这条来源支持"。** 引用一条 RFC 去支撑一句跟 RFC 无关的话，它照样放行——只要那条 RFC 的 URL 合法、锚存在。

我们的 `src/core/verification/typed_verifier.py` 查的是：条款号闭包（引的条款号在不在本轮证据里）、数值闭包（答案里的数字有没有在证据里出现过）、模态强度（"应"被写成"宜"要抓）、法理要素；越界条款号还被升级成三态可操作说明（`unknown` / `same_standard_not_retrieved` / `outside_evidence_standard`）。

**这是两件不同的事：它管"证据在哪"，我们管"证据成不成立"。我们这一层比它深。**

> ⚠ 但这一层**在界面上几乎看不见**：`plugin/client` 全目录 grep `unsupported` 零命中。核验做了，用户没看到。

## 三、能抄的三件事（按性价比排序）

### 抄 1：把 `[[c:i]]` 渲染成编号上标 + 让依据行可点

**为什么排第一**：原语已经有了、编号已经绑在证据数组上了、越界已经校验过了，**只剩最后一步没做**。

**改哪里**（全部在我们自己的 React 里，不碰宿主）：

- `plugin/client/KsTurnTab.tsx` —— 它已经拿到了 `conclusion` / `derivation`（宿主 `plugin/src/index.js` 的 `recordKsTurn` 存的就是引擎原始公开字段），但**目前一个字都不显示**。让它把两段渲染出来，并把 `[[c:i]]` 换成 `<sup><a>i+1</a></sup>`，点击 → 跳到对应 `evidence[i]` 的 PDF 那一页（红箭头照旧）。
- `plugin/client/KsKnowledgePage.tsx` 的 `ks-ask-evrow` —— 现在是纯文本（标准号 + 标题 + 摘要），**没有 `evidence_url`、没有 onClick**。给它编号，并让它可点。

**用户会看到什么**：答案里每个论断后面跟着一个小数字；下面的依据列表编号与它一一对上；点数字或点依据行，都跳到 PDF 那一页，红箭头指着原文。

**工作量**：小。两个文件，纯前端，不改引擎、不改提示词、不动 schema。

**风险**：低。`[[c:i]]` 的 i 已经过越界校验，越界的不会进证据区（有 `citation_index_warnings` 记着）；渲染时对越界 i 直接降级成纯文本，不编造链接。

**可回退性**：完全可回退——只是把字符串解析成元素，删掉解析就回到现在。

**⚠ 附带发现一个真 bug**：`KsTurnTab.tsx` 读的是 `verification?.cite_warnings`，而引擎返回体里的真名是 `citation_index_warnings`（`ks_answer.py` 的 `_assemble_verification` 返回的就是这个名字，`plugin/src/trim.js` 白名单里也是这个名字）。**那一项永远读到空数组**——引用越界警告在「本轮」tab 上从来没显示过。抄 1 施工时一并修。

### 抄 2：给「结论 / 理由」加一个硬上限

**抄什么**：`answer.reasons` 的 `"maxItems": 4`，以及"每个面板只回答一个问题"。

**为什么值得**：业主说的"更简单易懂"，落到底就是**不许写成一大段**。它用 schema 挡，我们只能在提示词里挡，但挡得住比不挡好。

**改哪里**：`plugin/src/chatmode.js` 第 2 条与 `plugin/src/compliance-sentry.js` 第 5 条，把「依据 → 推导 → 结论」补成「结论先行；理由不超过 4 条；每条一句话」。同一处顺手要求模型把 `[[c:i]]` 渲染成编号。

**工作量**：极小（改提示词）。**风险**：中——提示词改动的效果要真机量，不能只凭"改完看起来好了"。**可回退性**：改回去即可。

**⚠ 老实说清边界**：这是提示词约束，不是 schema 约束。模型可能不听。要变成硬约束得走抄 3。

### 抄 3：答案先落成结构化块，再渲染（大改，建议先问业主）

**抄什么**：`answer.summary/reasons/scope` + `panels[].blocks[]` 这套"先落结构再渲染"。

**我们其实已经有这个模式了**：`src/core/exports/research_report.py` 的 `build_report_blocks` → `_to_markdown` / `_to_html`，同一份 blocks 出两种形态。**但它只服务材料平面**（入参是 `prj_…`），答案链路上没有对应物。

**改哪里**：引擎侧把 `derivation` / `conclusion` 从两个自由文本字符串，改成 blocks 数组（复用 `research_report.py` 已有的块模型，不新造）；`ks_answer` 返回体加这个字段（旧字段保留，不破坏既有消费方）；界面按块渲染。

**工作量**：中到大。要改引擎提示词（让内部 LLM 直接出结构）、改返回体、改 `trim.js` 白名单、改三处渲染、补冒烟断言。

**风险**：中高。这是**结构性大改**，按本仓裁定（NOT-DOING #4）**必须先问业主**，不能自己开工。

**收益判断（我的分析，不是证据）**：抄 1 做完之后，"简单易懂"的大部分收益已经拿到了。抄 3 的增量主要是"能出图、能出对比表"，而我们真正需要出图的比例有多大，**我不知道，得业主说**。

## 四、明确不该抄的

| 不该抄 | 理由 |
|---|---|
| **钉 commit + 冻字节 + 重算 sha256**（`repository-evidence.mjs` 那一整套） | 它存在的唯一理由是"行号会漂"。我们指 PDF 页 + 坐标，不漂。搬过来是为一个我们没有的问题付代价。 |
| **`finalize` 的原子替换 / no-clobber 硬链接 / 交付锁** | 那是给"多个 agent 并发写同一个 HTML 文件"设计的。我们的产物走 Markdown、无并发写同文件。纯复杂度。 |
| **`browser-check` 那套真浏览器视觉闸** | 我们已有自己的冒烟链（含渲染级断言）。再叠一层是重复建设。 |
| **单文件自包含 HTML 作为交付物** | 交付物只出 Markdown（NOT-DOING #1）。`.html` 只作界面预览形态，不作出厂交付物。 |
| **它的渲染器当组件用** | 它自己就不可复用：`package.json` 无 `exports`/`main`、`private: true`、只暴露 `bin`、入口读 `argv`。**想复用只能 fork 它的 CLI，那是把我们的答案链路绑死在一个外部项目的内部实现上。** |
| **十种原生图** | 它是代码仓库/系统架构场景。我们是 PDF 条款场景，用不上 ERD / 类图 / 瀑布图。真需要图时再单独议。 |
| **`SRC n` 徽标** | 它自己已经删了（`badgeCount === 0`）。抄一个上游刚废弃的东西没有道理。 |

## 五、如果只做一件事，做哪件

**做抄 1。**

理由不是"它最容易"，是**它是唯一一件"我们已经有全部零件、只差装上去"的事**：

- 编号原语 `[[c:i]]`：有（引擎在产出、在校验）；
- 证据数组的稳定序号：有（`evidence[i]`，`evidenceAnchor` 已经能拼出可点 URL）；
- 跳转与红箭头：有（已经能用，业主已验收）；
- 缺的只有：**把 `i` 变成一个能点的数字**。

做完之后，"它的证据比我们聪明"这个感受会消失一大半——因为**编号是"看起来聪明"的主要来源**，而不是那套 commit 钉死。

## 六、遗留待业主裁定

1. **抄 1 要不要做**（小改，纯前端，可回退）。按 NOT-DOING #4 的补充口径「小改动你直接改」，它够小；但它改的是**答案的呈现形态**，属于业主天天看的那一屏，所以先问一句。
2. **抄 3 要不要立项**（结构性大改，必须先问）。
3. **核验信息要不要显示**（对照表 #8）。`unsupported_context` 现在算了不给用户看。要不要在「本轮」tab 上显示"这次有 N 条引用不被证据支持"？**这一条我没替业主判断**——它是"多显示"还是"多干扰"，只有业主知道。
4. **交付形态**：archify 那条路通向"一页 HTML"。我们的裁定是交付物只出 Markdown。如果业主将来想要"一页能发出去的东西"，那是**重新开一次裁定**，不是本轮顺手做。

## 附：一句话回答业主的原话

> 「它这个证据似乎要更聪明一点。」

按两份取证，它更聪明的地方是**显示**：编号、上标、页脚列表、结论先行、一屏一问。这些都能抄，而且我们缺的正是这个。

它不更聪明的地方是**证据本身**：它只验证"这个来源存在"，不验证"这句话被这个来源支持"；那一层我们有 `typed_verifier` 在做，比它深，只是没显示出来。

还有一层是我们比它强的：**它的可见证据徽标已经被它自己删了**，证据收进了"点一下才出现"的面板；我们的红箭头一直在那儿。

**所以要抄的是它的排版，不是它的证据。**
