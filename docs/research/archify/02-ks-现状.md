# 02 · KS 现状：问答 → 答案呈现 → 证据跳转（事实清单）

> 只取证，不提案。每条结论都附文件路径 + 可搜索原文片段；**不写行号**。
> 未读到的、判不了的，一律写「未确认」。

## 一句话结论

KS 的问答链路是「**引擎产出结构化 JSON（证据 + 两段自由文本 + 核验块）→ 模型自己按提示词写成 Markdown 三段式 → 宿主按 Markdown 渲染 → 证据靠一条伪 URL 跳进 PDF 并画红箭头**」；**答案正文本身没有任何结构化中间表示，界面上也没有一页式版面，更没有证据编号上标**——我们比 archify 强的地方在"证据落到原件页那一行"，弱的地方在"答案怎么被组织成一屏"。

## 五条要点

1. **模型拿到的是一次 JSON，不是一个结构**：`ks_answer` 返回 `tier / evidence[] / derivation / conclusion / verification / notes / scope / material_usage`，其中 `derivation` 与 `conclusion` 是**自由文本字符串**（引擎的提示词只让内部 LLM 输出 `{"derivation":…,"conclusion":…}` 两个字段）。证据条目是结构化的（标准号/条款号/页码/snippet/evidence_url/bbox），答案正文不是。
2. **三段式是提示词约定，不是数据结构**：`plugin/src/chatmode.js` 第 2 条与 `plugin/src/compliance-sentry.js` 第 5 条把「依据 → 推导 → 结论」写成**给模型看的文字要求**，模型自己按格式写 Markdown；引擎不产出"结论块/理由块/范围块"这类可渲染对象。
3. **`evidence_url` 由宿主侧 `evidenceAnchor()` 生成**，形状是 `http://127.0.0.1:1/__ks_evidence__?doc=…&page=…&rev=…&bbox=…&bboxPage=…`；client 半 `evidenceUrlOf()` 是同口径镜像。它不是 PDF 页码链接，是**我们自己的伪协议**，由 `entry.ts` 的 document 级 capture 监听接管，转成右侧栏 `openResource`。
4. **红色定位箭头是"行级 bbox + 一个绝对定位的 SVG div"**：坐标来自 `source_span.bbox_json`（PDF 底部原点），由 pdf.js `convertToViewportPoint` 换算，画在覆盖层 `KsArrowOverlay` 上，`pointerEvents: none`；退化框（宽 < 5pt 或高 < 3pt）在引擎与宿主**两处都被丢掉**，跨页时宁可留空也不画错页。
5. **界面上的答案呈现分三处，没有一处是"一页"**：对话气泡里是宿主 `MarkdownText`（GFM + KaTeX，能出表格/列表/公式）；右栏「本轮」tab 只列**证据行 + 核对结论 + notes**，**不显示结论/推导**；右栏 PDF tab 是原件。三处之间只靠"看原文"按钮单向连。

### 2.3 引用标记只做校验，不做渲染

```

```

```

```


**未确认**：这些 `[[c:i]]` 标记在交给外层 DSH 模型前是否被剥掉——`plugin/src/index.js` 的 `trimAnswer` 里 `derivation` 只是 `String(...).trim()`，**没有剥标记**；client 侧也 grep 不到任何 `[[c:` 处理。⇒ 事实是：**标记原样透传给外层模型**，没有转成上标编号。
