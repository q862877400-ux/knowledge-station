## 四、踩过的坑（**别再踩**）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **调 bunny 缺 User-Agent** | HTTP 403，**一批 360 次调用全废** | 必须带浏览器式 UA |
| **只看进度条、不看成功数** | 上面那批盲跑半小时才发现全 403 | **发车前先跑 1 条校验，失败即停** |
| **归并键用"条款号"** | 不同标准都有 `3.2` ⇒ 撞号后**两条不同条文拿到完全一样的问法** | 用**批次内唯一序号**归并 |
| **批量写结果只在最后落盘** | 中途主动 kill ⇒ 全丢 | **边跑边写 + 断点续跑** |
| **`role: reviewer` 当异模型对照** | 实测派的仍是 `space-bunny-free`（不是 deepseek-flash） | 生效的角色表在 `cordis.patch.yml`，不是 `team-roles.yaml` |
| **`spawn_teammate` 跑批量** | 8 个队员上限；实测 3/7 任务收不到结果 | **直接调 HTTP API** |
| **打印凭据** | 我的遮蔽正则只匹配 `sk-`，而 key 是 `oc_sk_` 开头 ⇒ **密钥明文进了对话** | 已建议业主轮换 `OPENCODE_GO_API_KEY` |
| **`timeout_ms: 900000` 长时间等待** | 业主反馈"你是不是卡住了" | **用短查看（60~150 秒）**，别阻塞十几分钟 |
