# 反向造题的考卷（reverse-benchmark）

> **这是什么**：一批「外行问法 ↔ 标准条文」的配对，**从条文反推问法**造出来的。
> **要解决什么**：正向造题（先有问法、再找条文）实测通过率只有 4%～13%，
> 因为"问法 ↔ 条文"的对应**根本不保证存在**。反推则**配对天然正确** —— gold 就是那条条文本身。
> **本文是这批资产的归属层**：方法、结果、已知缺陷、怎么复跑。

---

## 一、结果

```
生成：104/110 条条文拿到了问法（gemini-3.8-flash）
盲判：171/310 条配对通过（bunny 三路独立判定）
      = 55.2%
可用：171 条，其中把握"高" 166 条 / "中" 5 条
类型：定义类 136 条 / 要求类 35 条
```

**按条文类型的通过率差别很大：**

| 条文类型 | 通过率 | 说明 |
|---|---|---|
| **定义类**（"X 是……"） | **136/203 = 67%** | 反推效果好 |
| **要求类**（"应……"） | **35/107 = 33%** | 明显更差，是主要短板 |

## 二、五条路的实测对比（同一套 bunny 三路判定口径）

| 造题方法 | 通过率 | 说明 |
|---|---|---|
| 正向·旧配法（术语标签）+ 旧语料 | 13.4% | 106 条，语料已用完 |
| 正向·旧配法 + 冷门术语 | 1.9% ~ 3.1% | 更冷门的话题配不出外行问法 |
| 正向·向量相似度找候选 | 4.0% | **且向量名次与配对质量负相关**（rank1 通过率 0%） |
| **反向·bunny 生成** | **21.2%** | 提示词照抄了正向的"必须问合规/罚款"⇒ 自己造出不匹配 |
| **反向·gemini + 提示词按类型分支** | **55.2%** | ← **本目录** |

## 三、方法

**三步：**

1. **建条文池**（`clause-pool`，脚本可重建）：
   从真库 522,021 条里取**长度 30~300 字**、且**能读出问法**的：
   - **定义形态** 47,366 条（条款以「术语名 英文名 定义正文」开头）
   - **要求形态** 61,090 条（含 `应/不应/不得/必须`）
2. **反推问法**（`generate.py`，调 **Google Vertex 的 `gemini-3.8-flash`**）：
   - 关键设计：**按条文类型分支给指令**
     - 定义类 ⇒ 问"这是啥 / 怎么分辨 / 拿它干嘛"；**明确禁止**问办手续、罚款、合规
     - 要求类 ⇒ 可以问办手续、限值、后果；**明确禁止**问"这是什么意思"
   - 硬约束：**不许出现条文中连续 4 个及以上的字**（防抄原文）
   - 允许"想不出"⇒ `lay: []` + `why_empty`（把"这条外行一辈子不会问"变成可统计输出）
3. **盲判**（`verify.py`，调 **bunny 三路**）：
   **判定文档与正向流程完全一样，不透露"这是从条文反推的"** —— 否则模型会顺着说对。

## 四、⚠ 三个必须知道的缺陷

### 1. **有循环论证的味道（最重要）**

**问法是"看着条文写出来的"⇒ 这批 gold 天然偏向"能读出问法的条文"。**
- **后果**：用它测召回会**虚高**；而且容易的题偏多
- **缓解**：判定独立（bunny 不知道来源）；**但循环本身消不掉**
- **诚实的说法**：这批题适合量"**这条条文能被外行问到吗**"，
  **不适合**直接宣布"系统的召回率是 X%"

### 2. **要求类是短板（33%）**

**定义类 67% / 要求类 33%。** 要求类条文的问法更难写对 —— 失败样本里
「办手续 / 超了没有 / 会不会罚」这类问题经常**把话题带偏到别的条文上**。

### 3. **判定模型自己有偏**

**抽查发现：有的配对其实是对的，但 bunny 判了"对象不对"。**
例如「平台上挑选代加工厂时显示的质量等级，主要代表啥意思？」
配「云制造服务 QoS 评估」—— **语义上是对的**，被判 FAIL。
**⇒ 所以 171 条是【下界】，不是上界。**

## 五、文件

| 文件 | 是什么 |

重建方法：按 §三 第 1 步的条件扫 `clause_revision`（只读）。

## 六、怎么复跑

```powershell
# 前置：凭据库里有 GOOGLE_CLOUD_API_KEY（造题）与 OPENCODE_GO_API_KEY（判定）
& .venv\Scripts\python.exe eval\reverse-benchmark\generate.py   # 造题
& .venv\Scripts\python.exe eval\reverse-benchmark\verify.py     # 盲判
```

**三个踩过的坑（都写进脚本注释了）：**

| 坑 | 表现 |
|---|---|
| **归并键用"条款号"** | 不同标准都有 `3.2` ⇒ 撞号后两条不同条文拿到**完全一样**的问法。**必须用批次内唯一序号归并** |
| **缺 User-Agent** | 调 bunny 被 403，一批 360 次调用全废 |
| **每批术语给太多** | bunny 整批整批地丢；降到每批 2~3 条后基本不丢 |

## 七、边界

- **只读真库**（`sqlite3` + `mode=ro`），不改任何源文件。
- **`gen-V2.jsonl` 只读**：它是总纲 §1.2 全部数字的唯一基准。
- **造题用 gemini，判定用 bunny** —— **刻意分开**，不拿写题的模型去判自己写的东西。
