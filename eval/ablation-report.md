## 三、决策（有据可查）

1. **exact 保留**（主力通道，禁用即崩）。
2. **fts 保留**（弱贡献 -1.1pp，超过删除阈值，且是口语检索的兜底）。
3. **vec 保留，不删除**：当前数据贡献 0pp，但删除不可逆、未来规模化（语义召回）必需；
   按 v5 框架"10.5 bge-m3 迁移以数据证明 dense 弱为触发"——本实验的 0pp 即"数据不支持
   大规模投入"的证据，反向也证明**不触发 10.5**（不升 bge-m3，保持 512 维）。
4. **modality / legal_element / behavior_scope：当前问答场景无贡献，但本 Task 不物理删除**：
   - behavior_scope 是合规审查设计主力，其真实价值需行为域字段填充后复测（见 §二）；
   - 三者按 v5 框架从"独立召回通道"转型为"pre-filter + 排序权重"是既有方向，
     挂 Phase 13 死代码清除（13.1/13.3）实施，实施前保留通道以维护契约稳定性。
5. **通道最小集结论**：当前数据下 exact+fts 两通道即达 recall@5=96.7%（全开 97.8%），
   其余通道按 pre-filter 语义保留——这与 v5"≤4 个有实测贡献通道"目标一致，
   且无需契约变更（通道枚举冻结，权重可调）。

## 四、10.5（bge-m3 升级）触发判定

**不触发**。依据：消融显示 vec 通道有贡献的迹象不足（0pp），Golden Set recall@5=97.8%
远超 R5 验收线（≥85%）；badcase 归因无"语义召回弱"证据。按 ROADMAP 10.5 记录"数据不支持，不执行"。

## 五、后续建议

- 行为域字段填充（auto_tag / law_text 补 behavior_scope）后，重跑 §二 审查场景消融；
- Phase 13 将 modality/legal_element/behavior_scope 降级为 pre-filter + 排序权重，
  并补相应 pre-filter 单测；
- 库规模 >5 万条款后重跑本消融（vec 贡献可能显现），届时再评估通道集与 10.5。
