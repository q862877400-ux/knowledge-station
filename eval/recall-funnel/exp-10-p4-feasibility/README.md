# exp-10 · P4 可行性实测（Jev 地域封锁）—— **判决：P4 在本机做不了**

> 2026-10-09 人工轮。**只读**：不改生产代码、不写库。**不是召回实验**，是"下一件能不能开工"的前置体检。

## 一、结论

**P4「检索分类闸」不能在本机开工** —— 它的蓝本要求用 **Jev** 做路由 / 预算 / 候选打分 / 自适应停止，
而 **Jev 对本机所在地区返回 HTTP 451**（`Typesafe is not available in your region.`）。

⇒ **`NEXT-DEV-PLAN §三序 6` 与交接单 ④ 把 P4 排"下一件"的理由（"不依赖新语料、不依赖外网"）不成立**，
已就地更正（见总纲 P4 段与 `NEXT-DEV-PLAN`）。

## 二、证据（`probe-result.json`，同一目录）

| 检查 | 读数 |
|---|---|
| 直连（**显式禁用代理**）`GET api.typesafe.ai/v1/systemone` | **451**，正文 `{"title":"Typesafe is not available in your region.","status":451}` |
| 走环境代理（`https_proxy=127.0.0.1:9033`） | **451**（同上） |
| **对照组** `GET https://example.com/`（禁用代理） | **200** ⇒ **网络本身是通的**，不是断网 |
| 项目自己的客户端 `jev_client.system_one(...)` | `JevUnavailable: jev HTTP 451 ...` |
| 合规哨兵 `jev_guard.judge("让程序自动点已阅读并同意")` | **`None`**（退回词表） |
| 合规哨兵 `jev_guard.judge("帮我写个 python 快排")` | **`None`** |

⇒ **直连与代理都是 451、对照站 200 ⇒ 是对方的地域封锁，不是本地代理/网络。**

## 三、连带后果（比 P4 更该被业主知道的一条）

生产的**合规哨兵**（`src/core/llm/jev_guard.py`）**设计上就是"Jev 不可用 ⇒ 返回 `None` ⇒ 退回词表"**，
本机 `jev_guard_enabled=True`、Key 也配了 ⇒ 于是它**静默退化**：

* 它当初被造出来，正是为了抓**词表抓不到的"隐性合规"**（蓝本实测：同一批样本 **词表 1/8、Jev 8/8**）；
* 现在连那个样本（`让程序自动点已阅读并同意`）也返回 `None` ⇒ **这一层能力在本机等于没有**，
  而且**界面上看不出来**（降级是"静默"的，只写一条 `logger.info`）。
* 另有**熔断**：连续失败 3 次后熔断 60s（探针日志实测）。
