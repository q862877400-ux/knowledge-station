# P2 实验 #1：提高「每路取数上限」

> **写在改任何代码之前。** 跑完只许按这里的阈值机械判决，不许事后放宽。

## 一、要解决什么（有诊断依据，不是拍脑袋）

P2 的靶子是总纲 §2 判据②「**排得上去**」。诊断（`tools/p2-diagnose.py` + `tools/p2-check-status.py`）量出：

headline 120 条的分档 = **L0 8 / L1 72 / L2 33 / L3 4 / L4 3**，其中 **L2+L3+L4 = 40 条（33.3%）
已经在六路并集里**，只差排上去。

**两条假设查过了：**
| 假设 | 结论 |
|---|---|
| 时效过滤把 gold 滤掉了 | ❌ **推翻** —— 五档的 gold 文档 `legal_status` **全是 effective（120/120）** |
| **每路只取前 20 条，gold 在进融合前就被砍了** | ✅ **成立** |

成立那一条的**直接证据**（一条 L2 的全貌）：
```
gold = GB/T 23031.6-2023 3.1.3
并集 @20=false  @100=true  @1000=true      ← 读 1000 条能捞到
生产口径 pool=39  hit=false                 ← 生产捞不到
融合 gold_rank=null（融合里根本没有）
  fts  n=20（生产截断）  **deep_gold_rank = 46**   ← gold 在 FTS 第 46 名，被 20 的截断砍掉
```
且 **L2 的 33 条 100% 在融合里找不到 gold**，L0/L3/L4 则 **0%**。

⇒ **L2 不是"排序不好"，是"候选被截断"。**
⇒ 这一条**不在 P2 原列的五个排查项里**（权重 / RRF 常数 / BM25 / 片段长度 / 同号次序），是诊断新发现的。

## 二、唯一变量

**只改"每路取数上限"，三处一起改**（它们语义相同：一路取多少候选进融合）：

| 位置（`src/core/retrieval/hybrid_engine.py`）| 现在 | 改成 |
|---|---|---|
| FTS 那一路：`+ " ORDER BY rank LIMIT 20"` | 20 | **100** |
| 向量那一路：`" WHERE embedding MATCH ? AND k = 20"` | 20 | **100** |
| 行为客体那一路：`+ " ORDER BY rank LIMIT 20"` | 20 | **100** |

**明确不动**（它们是之后的刀，本轮一律不碰）：
 · `RRF_K = 60`；· `CHANNEL_WEIGHTS`（含 `exact=2.0`）；· BM25 的任何参数；
 · reranker；· 任何条文文本、任何向量；· `top_k` 的默认值。

**配套的一处对齐（同属"这个变量"）**：`eval/recall-funnel/funnel.py` 里有一个
`PROD_CAP = {"fts": 20, "vec": 20, ...}`，它**声明自己是生产常量的镜像**（注释原文：
「照 `hybrid_engine.perform_hybrid_search` 的常量」）。**上限改了，这个镜像也要跟着改**，
否则它算出来的"生产口径"是假的。**跑分器本身的代码不改**，只在驱动器里覆盖这个常量。

## 三、对照与判据

| | |
|---|---|
| **对照（control）** | 入库后的库 + 上限 20 ⇒ `funnel-summary-after.json`（**已在跑**）|
| **处理（treatment）** | 同一个库 + 上限 100 |
| **库** | 生产库**只读**（8,983 篇 / 663,634 条）；不复制、不写 |
| **考卷** | `eval/recall-funnel/benchmark-v2.jsonl` 171 条（headline 120 条为主线）|

**主指标**：`fused@20`（headline）—— 生产实际给用户的前 20 里有没有 gold。
**次指标**：`fused@100` / `fused@1000` / `union.prod_caps.hit` / 分档里 L2 的条数 / **每条耗时**。

### 判决（**机械执行，不许事后放宽**）
| 结论 | 条件 |
|---|---|
| **推广** | `fused@20` 提升 **≥ +6 pt** |
| **观察** | 提升 **+2 ~ +6 pt** |
| **放弃** | 提升 **< +2 pt** |
| **⛔ 硬失败** | `fused@20` **下降**（任何下降）—— 成本增加了却更差，直接回退 |
| **⛔ 硬失败** | 单条耗时增长 **> 3×**（相对对照）—— 换来的收益若靠"慢 3 倍"，产品上不成立 |

> 6 pt 是本仓既有的分辨率线（E1 / E3b 都用它当放弃阈值），**不是为本轮新定的**。
