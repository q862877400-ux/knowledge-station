### ⚠ 要修的两处
1. **多切**：`split_law_text` 按「第X条」**逐处**切分，**正文里引用别条时（"依照本法第X条规定"）也会切一刀** ⇒ 98 条的法律切出 126 条。
2. **每条都背上文档头部前缀**：实测入库后的条文长这样 ——
   ```
   第一条 # 中华人民共和国劳动合同法  2007年6月29日 第十届全国人大… 为了完善劳动合同…
   第二条 # 中华人民共和国劳动合同法  2007年6月29日 第十届全国人大… 中华人民共和国境…
   ```
   **同一条法律下，每条都重复同一段"立法沿革"**，会把该条自身的特征在向量里稀释掉。
   根因是 `split_law_text` 把"第一个条文之前的所有内容"当章节上下文，逐条前置。
   ⇒ 应当在切分**之前**把 markdown 的 front matter / 标题 / 立法沿革剥离。

## 二、国标 OCR（805 本 MinerU markdown）→ **切分不可用**

| 指标 | 实测 |
|---|---|
| 可切位点合计 | 55,078 |
| 现有切分函数实切 | 15,892 |
| **总命中率** | **29%** |
| **切成 0 条的本数** | **146 / 805 = 18%**（入库时直接 `status=error`）|
| 每本命中率 **中位** | **20%** |
| 命中率 < 20% 的本数 | 399（50%）|
| 命中率 < 50% 的本数 | 672（84%）|
| **其中一级条款标题（`## 7` 这类）** | **11,138 个 —— 当前完全不被识别** |
| 可疑条号（如 `477.38`）| 1,155 处 |

### 根因（三条，第一条是主因）

1. **★ `split_gb_text` 只认"带点的"条款号**（`1.1`、`4.2.3`），**不认 `## 7 技术要求` 这种一级条款**。
   它的正则要求 `\d+[．.]\d+`。而 MinerU 把章标题输出成 `## N 标题`（**单数字**）⇒
   一级条款被跳过、其下内容被**并进相邻的带点条款** ⇒ 条款数骤减 + 内容错乱。
   实测入库后的条文形态：
   ```
   [6.3] 6.3 **复合硅酸盐水泥的强度等级分为 、 、 、 四个等级。** 42.5 42.5R 52.5 52.5R ## 7 技术要求 #
   ```
   （`## 7 技术要求` 被吞进 6.3。）
2. **假条号**：`477.38` 这种把数值当成条款号的情况，共 1,155 处。
3. **MinerU 的阅读顺序**：句内数字被搬到句后（`分为 、 、 、 四个等级。` 然后才出现 `42.5 42.5R…`）。
   **这是 OCR 工具的问题，不是切分的问题** —— 但它直接影响"条文读起来对不对"。
