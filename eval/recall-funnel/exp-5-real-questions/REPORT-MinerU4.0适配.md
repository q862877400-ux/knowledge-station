# 真正的拦路虎：**MinerU 3.4 → 4.0 换了结构，生产解析器读不到，静默返回 0 条**

> 业主 2026-10-07 的线索：「这种后处理原先 KS 已经做了很多了，但是那时候 MinerU 还是 3.4 版本不是现在用的 4.0」。
> **这条线索是对的，而且它推翻了我上一轮的结论。**

---

## 一、我上一轮错在哪

上一轮我拿 `law_text.py`（`ingest_law_text`）试跑 —— 那是个**"法条纯文本直灌"**通道，读的是
`markdown.md`，为**法规**写的。**那不是国标的正经入库路径。**
⇒ 于是我得出了"切分只命中 29%"的结论，**那个数字描述的是错入口**。

**国标的正经路径是 `pipeline.py`**：
`load_middle_items(middle_json)` → `split_items_into_clauses(items)`，
里面本来就有：章头 `_CHAPTER_CLAUSE`、附录 `_CLAUSE_APPENDIX`、防误切闸门
（首段 ∈ 1..60、表格数值不当条款号）、目录/索引过滤，还有一句注释
**"还原 MinerU 吞点的条款号 41→4.1"** —— **3.4 时代的坑早就处理过了**。

## 二、真正的问题：**结构换了，而且是静默失败**

`load_middle_items` 第 615 行：

```python
for page in mj.get("pdf_info", []):        # ← 3.4 的键
```

而 MinerU **4.0** 的 `middle_json.json` 顶层是：

```
['metadata', 'extensions', 'pages', 'is_full_document', 'schema', 'schema_version']
```

**没有 `pdf_info`** ⇒ `.get("pdf_info", [])` 给空列表 ⇒ **返回 0 条，且不报错**。
实测 5/5 本 `items=0` —— 这正是本仓最警惕的那类"症状离原因很远"的静默失败。

## 三、两侧结构对照（可对应，所以能加薄适配）

| | MinerU **3.4** | MinerU **4.0** |
|---|---|---|
| 根 | `pdf_info`（列表）| **`pages`**（列表）|
| 页内块 | `para_blocks` | **`blocks`** |
| 页尺寸 | `page_size:[w,h]` | `extensions.docvortex_layout.pages[i].width_pt/height_pt` |
| 子块 | `block["blocks"]` | **`block["content"]`** |
| 文本 | `lines[].spans[]`（`type=text`/`inline_equation`）| `content[]`（`type=text`/`equation_inline`）|
| 表格 | `table_body` 的 `spans[].html`（**嵌两层**）| **`table_body.content` 直接就是 HTML** |
| 页眉页脚 | `discarded_blocks`（解析器本就不读）| 混在 `blocks` 里，类型 `header`/`footer`/`page_number` |

4.0 的块类型实测：`text / paragraph_title / header / page_number / doc_title / table / equation /
image / footer / page_footnote / chart / aside_text / code / index` —— **与 3.4 同一套命名**。

表格 HTML 实测（GB 1094.5-2008）：

```html
<table><tr><td>额定容量/kVA</td><td>最小短路阻抗/%</td></tr>
<tr><td>25~630</td><td>4.0</td></tr><tr><td>631~1 250</td><td>5.0</td></tr>…</table>
```

**数字都在正确的格子里** ⇒ 这也推翻了我上一轮"数字被搬到句尾"的担心（那是 `markdown.md` 的问题）。

## 五、结论与建议

1. **既有后处理不用重写** —— 它很全，而且 3.4 时代的坑（吞点、章头、附录、误切）都已处理过。
   **缺的只是一层形状适配**。
2. **真正的拦路虎是 MinerU 4.0 的结构变更**，而且**以静默失败的形式表现**（0 条、不报错）。
   ⇒ 建议同时加一道**显式护栏**：`load_middle_items` 若发现 `pages` 存在而 `pdf_info` 不存在，
   应当**明确报错**（"这是 MinerU 4.0 产物，需要适配层"），而不是静默返回空。**这条比适配本身更重要。**
3. **适配层原型已验证可行**（933 本 / 69,517 条 / 0 本失败）。
   **下一步**：把它从"实验脚本"变成正式的适配层（放哪、怎么测、要不要保留 3.4 分支），**这要业主定**。
4. ⚠ **原型只做了形状转换**，正确性由"条款数合理 + 条款号形态合法 + 条文可读"**间接判断**，
   **尚未逐条与 PDF 原文核对**。上生产前需要抽样逐条比对。

---

## 六、边界

- 全程**只读源目录**；**未连库、未写库**；
- 条款号形态用正则判（`^\d+(\.\d+){0,4}$` 或 `^[A-Z]\.\d+…$`），**不代表内容正确**；
- `前置1` 这类合成编号是既有行为，不是本原型的产物。
