# E4：embedding shadow test（换 Qwen3-Embedding-0.6B，**第一轮固定 512 维**）

> **止损线先冻结**（`stop-loss.json` + `stop-loss-freeze.txt`），后跑。
> 归属：检索长周期计划「换更强的嵌入」是**登记过的未试项**；外部评估 2026-10-06 第 2 轮点名本模型。

---

## 一、为什么现在做它（前置闸门已过）

| 顺序 | 事项 | 结果 |
|---|---|---|
| 0 | 基准清洗 + 分层 + 盲分桶 | ✅ 完成 |
| 1 | query-side（E3b） | ✅ 判决**放弃**；但副终点挖出关键结构：**按字找 @1000 +14.62pt（p=0.0004 ★）、向量 @1000 +0.00pt（p=1.00）** |
| **2** | **换嵌入模型（本实验）** | E3b 的结论**正面指向这里**：查询侧唯一帮得上的那一路已做到显著，而**向量那一路完全没动** |

## 二、唯一变量 = **嵌入模型**（其余逐项冻结）

| | 内容 |
|---|---|
| **对照臂** | 现役 `clause_vec`（`bge-small-zh-v1.5`，512 维，fastembed/ONNX） |
| **实验臂** | `Qwen/Qwen3-Embedding-0.6B`（595.8M 参数），**输出截断到 512 维并重新归一化**（MRL） |

**按外部裁定：第一轮固定 512 维** —— 把"换模型"与"512 → 1024 升维"两个变量**拆开**。
1024 维与 BGE-M3 留作后续候选，**本轮不碰**。

**逐项冻结**：
- **条文文本一字不动**：仍用现役口径（实测 `clause_revision.title` 仅 43/522,021 条有值 ⇒ 实际等于 `content_text[:512]`）；
- 检索算法、六路、RRF、每路取回数、gold、171 条考卷 —— 全部不动；
- 查询侧不动（查询用**同一个实验模型**嵌入，这是"换模型"的固有部分，不是第二个变量）；
- **不接通 E/F、不上 ANN、不调 RRF**。

EmbeddingBackend

实验向量写进**独立表** `clause_vec_qwen`，且只在**副本**上写（真库全程只读）。

## 四、已实测的成本（把外部"我没有实测数据"那句补上）

`throughput.json`（真实条文 512 条抽样，中位长度 53 字，fp16，RTX 4080 SUPER 17.2 GB）：

| batch | 条/秒 | 全库 521,978 条预计 |
|---|---|---|
| **16** | **224.9** | **38.7 分钟** |
| 32 | 140.9 | 61.8 分钟 |
| 64 | 86.5 | 100.5 分钟 |
| 现役 fastembed（CPU）对照 | 65.4 | 2.2 小时 |

⇒ **GPU 路约为现役 CPU 路的 3.4 倍速**，全量重算约 **39 分钟**（取 batch=16）。
⚠ 小 batch 反而更快，与常见直觉相反 —— 本机同时跑着别的服务，大 batch 的收益被显存/调度吃掉了。**照实测取 16**。
⚠ 现役 CPU 路实测 **65.4 条/s**，与 E1 那轮测到的约 69 条/s **互相印证**，说明探针本身可信。

## 五、验收

**主终点**：**Vector @1000（主结果 120 条口径）** —— 与 E1 同口径，便于横向比较。
**副终点**：Vector@20 / @100；全量 171 口径；六路同预算并集 @1000；FTS @1000（应**不受影响**，是仪器对照）。

**必须两侧都报**：若新模型**更差**，那就是"更差"的结论，不许只报好的一侧。

### 止损线（外部给定，本仓照用；**下方另标我们实测的分辨力**）

| 观察到的 @1000 增幅 | 决策 |
|---|---|
| **< 8pt** | **放弃这个模型** |
| **8 ~ 10pt** | **灰区**，不能据此换生产模型 |
| **≥ 10pt** | 进入第二轮验证，但仍须看**簇级置信区间** |

⚠ **本仓实测提醒**：主结果 120 条口径下，显著性阈值 **≈8.18pt**、80% 把握度 MDE **≈11.68pt**
（`../exp-1-contextual/power-factcheck.json`）。
⇒ 所以 **8pt 是"分辨率线"**（刚够显著），**10pt 仍低于 80% 把握度**；
**"≥10pt 进第二轮"不等于"确证有效"**，只是"值得再验一次"。8pt 不是生产切换线。

## 六、明确不做

- 不做 1024 维、不做 BGE-M3（第一轮只测一个模型、只测一档维度）；
- 不做微调、不改文本配方、不调 RRF、不接 E/F、不上 ANN；
- **不覆盖生产 `clause_vec`**（硬边界）；
- 不把本实验与 E3b 的结果混着说（一个改查询、一个改表示）。

### ★ 一处必须写明的解释：**查询侧两臂都不加指令前缀**

冻结项写的是"查询侧不动"。换模型之后，查询**必须**由新模型嵌入（这是"换模型"的固有部分），
于是产生一个歧义：**要不要用 Qwen3 官方推荐的 `instruct: …\nquery: …` 前缀**？

**本轮的解释：不用。** 理由：加了它，"指令 vs 无指令"就成了**第二个变量**，
违反"一次只改一处"。现役 bge 侧本来也是**无前缀**（长周期计划实测过"加 bge 官方前缀无差别"）。
⇒ **两臂都无前缀**，纯换模型。**Qwen3 的指令前缀留作第二刀**（未测，别当已测）。

```text
对照臂：bge-small（无前缀）  → clause_vec
实验臂：Qwen3-0.6B（无前缀） → clause_vec_qwen
```

## 七、这一步回答不了什么

- 它只回答"**换一个 0.6B 的嵌入模型、512 维下，向量那一路能不能明显变好**"；
- 它**不回答**换模型后**整个产品**会不会更好（还有重排、融合、截断等环节）；
- 考卷本身的缺陷（gold 未经人工确认）**不会因为换模型而消失**。

## 八、★★ 结果（2026-10-07 跑完）—— **判决：进第二轮验证**，效应巨大

### 前置都过了

| 检查 | 结果 |
|---|---|
| 两臂候选集合 | 已对齐（删掉对照臂那 43 条**正文为空**的条文）⇒ `521978 = 521978` ✅ |
| 对齐后对照臂复现基线 | 12 / 21 / 43 ⇒ 0.1000 / 0.1750 / 0.3583 **逐位一致** ✅ |
| **FTS@1000 仪器对照** | 两臂**完全相同**（0 条不一致），差异恒为 `+0.00pt`、CI `[0,0]`、p=1.0 ✅ |
| 真库 | 未动（判决器机械校验：真库里不存在 `clause_vec_qwen` 表）✅ |

### 主终点（冻结口径：Vector@1000，主结果 120 条）

| 量 | 值 |
|---|---|
| bge-small → Qwen3-0.6B | 0.3583 → **0.6833** |
| 净提升 | **+32.50pt** |
| 簇级 95% CI | **[+22.95, +42.52]** |
| 簇级 p | **0.0000** |
| 翻进 / 翻出 | **44 / 5** |
| 判决 | **进第二轮验证**（≥10pt 档）|

### 全部终点（**涨跌两侧都报**：没有任何一项变差）

| 终点 | all_171 | headline_120 |
|---|---|---|
| 向量 @20 | 0.0877 → **0.2105**（+12.28pt，p=0.0000，进22/出1） | 0.1000 → **0.2417**（+14.17pt，p=0.0000，**进17/出0**） |
| 向量 @100 | 0.1520 → **0.3450**（+19.30pt） | 0.1750 → **0.3583**（+18.33pt） |
| **向量 @1000** | 0.3450 → **0.6667**（**+32.16pt**） | 0.3583 → **0.6833**（**+32.50pt**） |
| 六路并集 @20 | 0.1111 → 0.2222（+11.11pt） | 0.1250 → 0.2500（+12.50pt，进15/出0） |
| 六路并集 @1000 | 0.3918 → **0.6784**（+28.65pt） | 0.4000 → **0.6917**（+29.17pt） |

### ★ 最直观的一个数：**救回来多少**

| 量 | 值 |
|---|---|
| 原本"六路前 1000 都没有" | **104 条** |
| **换模型后救回** | **56 条（53.8%）** |
| 同时丢掉原本能找到的 | **7 条** |
| **净** | **+49 条** |

⇒ **整个系统**在"六路并集 @1000"上从 **67/171（39.2%）** 变成 **123/171（71.9%）**。

### 这说明了什么

1. **之前那句"瓶颈在向量那一路"被证实并量化了** —— E3b 里查询侧怎么改都动不了向量路（+0.00pt），
   而**换模型把它从 35.8% 抬到 68.3%**。**卡点就是嵌入模型本身。**
2. **它在 @20 上是 17 进 0 出** —— 不是"把候选摊开"，是**真的把对的排上来了**。
3. **按字找那一路纹丝不动** —— 这正是仪器对照要证明的事（换模型不该影响按字找）。

### ⚠ 但"进第二轮验证"**不等于"可以换生产"**（外部原话：8pt 是分辨率线，不是生产切换线）

还没回答的：

1. **考卷本身没换** —— gold 未经人工确认（那 25 条二审还等着），换模型不会修好考卷；
2. **成本与延迟没量** —— 新模型 **595.8M 参数**，是现役 bge-small 的约 **25 倍**；
   现役管线是 **CPU（fastembed/ONNX）**，而本次是 **GPU（torch/CUDA）**跑出来的。
   **"生产每来一个问题要等多久"这件事本实验没量** —— 那是换生产前必须先回答的；
3. **一批候选还没试**（第一轮只测一个模型、一档维度）：1024 维、BGE-M3、Qwen3 的查询指令前缀；
4. **这一轮是 shadow**：生产 `clause_vec` 与生产检索链**一行没改**。

### 建议的"第二轮"该验什么（不是再测一个模型就完事）

| 要验的 | 为什么 |
|---|---|
| **单条查询延迟 / 显存占用**（CPU 与 GPU 两条路各量一次）| 决定"能不能上线"，不是"准不准" |
| **1024 维**（同模型升维）| 与"换模型"拆开的第二个变量，外部要求分开测 |
| **一条强基线：BGE-M3** | 外部列为第二候选（多路表示）|
| **在清洗后的金标上重跑** | 现在这 32pt 是在"gold 未确认"的考卷上量的 |
