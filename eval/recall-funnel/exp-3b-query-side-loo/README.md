# E3b：查询侧术语桥（**留一法**版）—— E3 判据更正后的重做

> **为什么另立**：E3 的防作弊判据写错了（把"结构性重合"当成"逐条泄漏"），当场触发硬失败 ⇒ E3 作废。
> 处理经过见 `../exp-3-query-side/VOID-hardfail-record.md`。**这里用更正后的判据、新的冻结止损线重做**，
> **不是**在 E3 里放宽阈值。

---

## 一、与 E3 的唯一差别（其余全部沿用）

| | E3（作废） | **E3b（本实验）** |
|---|---|---|
| 防作弊判据 | 「术语索引 ∩ 考卷 gold 必须为 0」—— **在这套考卷上不可能满足**（120 条里 98 条是定义类，而索引正是从定义条款抽术语） | **留一法**：选术语**之前**，把该条的 gold 条款从候选里剔掉 ⇒ 收益**构造上**不可能来自"gold 在索引里" |
| 其余 | 唯一变量=查询串 / 主终点=六路并集@1000（全量171）/ 三档阈值 / 索引与通道口径 | **逐项沿用，一字不改** |

**留一法实现**：`topk_by_cos(qv, vectors, k+8, matrix)` 取前 k+8 个，**丢掉 `clause_revision_id == gold_cr_id` 的那些**，
再取前 k 个 —— 与"先过滤索引再 top-k"等价，但不必为每条查询重建 42,181×512 的矩阵。

**同时量的诊断量**（E3 没量，这是关键）：
**不做留一法时，被选中的术语里有多少个的定义条款就是 gold** —— 这个数**量化了 E3 本来会有多少泄漏**。

---

## 二、硬失败条件（**更正后**）

1. 两臂候选集合双向差集 ≠ 0；
2. **留一法之后**，仍有被选中术语的定义条款 == gold ⇒ 说明过滤实现有 bug ⇒ 作废
   （这是**可当场机械校验**的，不留解释空间）；
3. 术语索引构建时读了考卷信息（结构上不可能：`select()` 只吃 query）—— 若代码被改动则作废。

⚠ 原 E3 那条「集合交集必须为 0」**已被判定为错判据，不再作为条件**，理由见 VOID 记录。

## 四、★ 结果（2026-10-07 跑完）

**判决：`放弃（query-side 这条闸门不通过）`** —— 由 `02-verdict-e3b.py` 按冻结阈值机械算出。

### 仪器与防作弊先过

| 检查 | 结果 |
|---|---|
| 对照臂复现基线 | 并集@1000 **0.3918**（171）/ **0.4000**（120）；向量@1000 **0.345 / 0.3583** ⇒ 逐位一致 ✅ |
| **留一法过滤有效** | `direct_hit_loo = 0` ✅（硬失败条件②通过）|
| **泄漏诊断** | `direct_hit_full_index = **14**` ⇒ 不做留一法时，会有 **14 个**被选中术语的定义条款**就是 gold** ⇒ **E3 若跑完，那个数是被泄漏垫高的**（这正是那条错判据拦住的东西）|

### 主终点（冻结）：六路同预算并集 @1000（全量 171）

| 量 | 值 |
|---|---|
| 对照 → 实验 | 0.3918 → **0.4269** |
| 净提升 | **+3.51pt**（+6 条）|
| 簇级 95% CI | **[−3.87, +11.36]** |
| 簇级 bootstrap p | **0.4034** |
| 翻进 / 翻出 | 20 / 14 |
| 判决 | **+3.51 < 6 ⇒ 放弃** |

### ★ 但副终点里有一个**统计显著的大效应**

| 终点（全量 171）| 对照 → 实验 | Δ | 簇级 95% CI | p | 显著 |
|---|---|---|---|---|---|
| **FTS（按字找）@1000** | 0.1345 → **0.2807** | **+14.62pt** | **[+6.47, +23.21]** | **0.0004** | **★** |
| FTS @100 | 0.0877 → 0.1170 | +2.92pt | [−3.68, +9.80] | 0.435 | |
| **向量 @1000** | 0.3450 → **0.3450** | **+0.00pt** | [−5.68, +5.92] | **1.00** | |
| **向量 @20** | 0.0877 → 0.0877 | **+0.00pt** | [−1.73, +1.73] | **1.00** | |
| 并集 @100 | 0.1988 → 0.2222 | +2.34pt | [−4.22, +9.20] | 0.538 | |

（主结果 120 口径同向：**FTS@1000 +16.67pt，CI [+7.02, +26.50]，p = 0.0006 ★**；向量@1000 +2.50pt，不显著。）

### 这组数字说明了什么（**关键算术**）

**FTS@1000 新找到 25 条**（23 → 48 条），而**并集只多 6 条**（67 → 73 条）
⇒ **新找到的 25 条里有 19 条本来就被向量那一路找到了**。
所以"按字找"的巨幅提升**大部分与向量路重复**，进不了并集。

⇒ **瓶颈不在"按字找"这一路。** 术语桥把这一路做得很强（p<0.001），
但**它一点没帮到向量那一路**（@1000 与 @20 都是 0.00pt，p=1.00），
而剩下的失败主要躺在向量那一路的名次里。

### 对下一步的意义

按冻结的止损线，**query-side 这条闸门不通过 ⇒ 进入第 2 项（Qwen3-Embedding-0.6B shadow test）**。
而且**本结果正面支持这么做**：既然查询侧唯一帮得上的那一路（按字找）已经做到 `+14.6pt / p=0.0004`，
而**向量路完全没动**，那**动向量路（换嵌入模型）就是下一个该试的地方**。

⚠ 纪律：**没有因为副终点好看就改主终点**。判决仍是「放弃」；FTS 那条是**副终点的观测**，
要单独立项验证它值不值得进生产（那是另一件事，本周不排）。
