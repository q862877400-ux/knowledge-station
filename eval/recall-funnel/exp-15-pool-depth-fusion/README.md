## 一、结论先行

**在 `exact / fts / vec / modality` 四路 + 加权 RRF 的构型下，「把每路取数放大」×「换融合方式」这 7 格，
没有一格能越过预注册的观察线（+2pt）。最好的两格只有 +1.67pt、p=0.5。**

而且**"放大池子"本身是有效的** —— 它真的把正确条文捞进了池子：

| | 池子里有 gold | 前 20 里有 gold |
|---|---|---|
| 生产（池中位 **40**） | **15 / 120 = 12.50%** | **10 / 120 = 8.33%** |
| 放大到池中位 **1,930** | **42 / 120 = 35.00%** | **12 / 120 = 10.00%** |

> **池子里多了 27 条正确条文（+22.5pt），前 20 只多捞到 2 条（+1.67pt）。**
> ⇒ **卡住用户的地方不是"池子太小"，是"排不到前面"。**

**⇒ 直接后果：P2 那条「怎么把深读候选筛进那 ~40 条池子」的路，本批用数据收口 ——
"限量方式"不是杠杆。深读候选要进前 20，只能靠【候选本身的名次质量】（= 表示层），
不能靠【池深】或【融合公式】。这与 E4 的 +32.50pt（换嵌入模型）**同向**。**

## 五、机制：为什么"放大池子"捞不动

### 5.1 数字上的三段（都在本批台账里）

| 段 | 条数 | 占比 |
|---|---|---|
| ① 生产池（中位 40）里**有** gold | 15 | 12.50% |
| ② 生产前 20 里**有** gold | 10 | 8.33% |
| ③ 深读池（每路 1000）里**有** gold | **42** | **35.00%** |
| ④ 深读池 + 加权 RRF 前 20 里有 gold | **12** | **10.00%** |

⇒ **③−① = +27 条进了池子；④−② = 只多 2 条进前 20。**

### 5.2 那 42 条里，gold 的**最好深读名次**本来就不差

| gold 的最好深读名次（**互斥分桶**，14+11+16+1=42） | 条数 |
|---|---|
| ≤ 20 | **14** |
| 20 < x ≤ 100 | 11 |
| 100 < x ≤ 1000 | 16 |
| 没有（只被 exact/modality 命中） | 1 |

> ⚠ **表头更正**（第 15 轮复核附带指出）：原表头写「≤ 100 / ≤ 1000」，读起来像**累计**，
> 实为**互斥分桶**。**累计**值应是 ≤100 = **25**、≤1000 = **41**。属表述，不是读数错。

⇒ **连"深读名次已经在前 20"的那 14 条，生产只捞到 10 条、放大池子后也只捞到 12 条**
⇒ 问题**不在"没看见"，在"看见了排不上"**。

### 5.3 三个"变平/变强"的尝试都不行（这是本批最有信息量的部分）

* **把衰减变平**（`k` 60→200→1000）：+1.67pt → 0 → **−1.66pt**。
  机制清楚：`w/(k+rank+1)` 里 `k` 越大，名次差被压得越平 ⇒ **前 20 变成近似随机**。
  ⇒ **"让深读候选有机会竞争"这条路，代价是把"名次"这个信号本身也抹掉。**
* **换 RRM（max 算子，只取最强的一路名次）**：**翻进 0 / 翻出 0** —— 与生产**命中状态（`@20`）逐条相同**。
  ⚠ **不是"前 20 名单逐条相同"**（★ 第 15 轮复核 **P1-2** 更正，原话「与生产逐条完全相同」超出证据）：
  翻进/翻出 只说明**是否命中**这一位相同；抽样实算 top-20 **名单**有 **5/14 条不同**（如 i=84 连 gold 名次都 1→7）。
  与 `exp-7` 的结论一致（算子改不动），且本批在**放大的池子**上再证一次。
* **按文档去重（每篇最多 3 条，治"同文档挤占"）**：**翻进 0 / 翻出 0** —— **命中状态（`@20`）也逐条相同**
  （同上，**名单层不同**：抽样实算 **7/14 条不同**）。
  ⇒ `exp-1` 量到的"最近邻同篇率 43.0% → 85.9%"**没有转化成前 20 的收益**。

### 5.4 代价侧（真库 663,634 行，10 条提问 × 3 次，`probe-knn-cost.py`）

| `k` | KNN p50 | 相对 k=20 |
|---|---|---|
| 20（生产） | 717.5 ms | 1.00× |
| 100 | 738.6 ms | 1.03× |
| **1000** | **1108.9 ms** | **1.55×** |

⇒ **放大池深要 +391 ms/问（×1.55），换 +1.67pt（p=0.5）⇒ 不值。**
⚠ **未量**：`fts LIMIT 1000` 那一路的额外耗时（本探针只量了向量路）。

## 六、诚实边界

| 项 | 说明 |
|---|---|
| **考卷本身** | gold **未人工确认**（`T015` 未做）⇒ 这些百分比**不是"系统的召回率"**，只是本考卷上的对照 |
| **oracle 是上界** | `35.00%` 是"gold 落在每路前 1000 的并集里"的比例，**不是一个能实现的系统**；不许读成"只要放到 1000 就能拿 35%" |
| **`P1000_doc3` 的预算口径** | 该臂把 fts/vec 各压到 20 条（去重后），`exact`/`modality` 仍全量 ⇒ 池中位仍是 40，与 `A0_prod` **同预算**，这才可比 |
| **`P1000_rrf200/rrf1000`** | 它们把 `k` 也改了 ⇒ 与 `A0_prod` 差**两个**变量（池深 + 衰减）。这是**故意的**：本批要回答的就是"这两个一起改行不行" |
| **未做的** | ❌ 没量 `fts LIMIT 1000` 的耗时；❌ 没测"用重排器在放大池上筛"（那是另一个变量，且 `exp-11` 已量出重排收益上限很小）；❌ 没测重排器换更强模型；❌ 没换嵌入模型（E4 的变量）；❌ 没接生产 |
| **只读活库** | 重跑不保证逐位相同（生产代码自己写着有的 SQL 没有 `ORDER BY`、返回次序未定义） |
| **★ `@100` 曾报错（复核 P1-1）** | 初版台账只存「top-20 名单里的名次」⇒ `@100`/`@1000` **恒等于 `@20`**。**已修**：聚合改读台账里**已经存着**的 `hit@100`（真值 = 11.67 / 14.17 / 15.00 / 15.83 / 13.33 / 12.50 / 10.00%，与复核独立复算**逐个相同**）；`@20` 与判决**逐位未变**。`run.py` 已改为在台账里**分别存** `rank20`/`rank100`/`rank1000`（供后续批次）。 |
| **★ `@1000` 本轮【未测】（复核 P1-1）** | 初版台账**没有** `rank1000` 字段 ⇒ 本批**不上报** `fused@1000`（置 `null`，**不是 0%**）。它也不在 `stop-loss.json` 的终点清单里。 |
| **★ "与生产逐条完全相同"是错话（复核 P1-2）** | 原措辞超出证据：翻进/翻出 0 只证明**命中状态（`@20`）**逐条相同，**不证明前 20 名单逐条相同**（抽样实算 RRM 臂 5/14、文档去重臂 7/14 条名单不同）。**已全批改为「命中状态（`@20`）逐条相同」**。 |
