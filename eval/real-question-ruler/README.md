# 真人问答召回尺子（ruler-v1）

> **业主令（2026-10-11）**：「我们现在已经有了这么多真人问答，那些 AI 生成的 1832 条外行说法
> 就都用不了了，也不需要了。我们现在有真人的了，就是这些尺子，我们可以基于它生成一套更好的尺子。」
>
> **本尺子替代** `eval/lay-phrasing/`（1,832 条 AI 生成的外行说法）那条"大白话"线。
> ⚠ **`lay-phrasing/` 本身没删** —— 归档还是删除由业主定；本尺子只是**不再依赖它**。

---

## 一句话

**用 41.5 万条真人问答里"答复点名了库内文件"的那些，抽 500 条，做成一把能机械复算的召回尺子。**

## 怎么用

```powershell
Set-Location 'D:\AI\work space\zcode'

# 造尺子（只读输入，写本目录）
.venv\Scripts\python.exe eval\real-question-ruler\build.py

# 独立复算（不依赖 build 的内存状态）
.venv\Scripts\python.exe eval\real-question-ruler\verify.py
```

**产物**：
- `ruler-v1.jsonl` —— 500 条，每行一条（schema 见下）
- `stats-v1.json` —— 分层统计 + 五道排除计数

### ⚠ 一处**与旧文档不一致**（我修了工具，数字变了）

`docs/PLAN-REAL-QUESTION-RULER.md` 与 `tools/gov-qa/locate-rate.json` 里写的是
**28,597**，本尺子用 **28,601**。**差 4 条，原因是一个真缺陷**：

`measure-locate-rate.py` 原来用 `f.read_text().splitlines()` 读 jsonl，
而 **`str.splitlines()` 不只按 `\n` 切** —— 它还按
`\v \f \x1c \x1d \x1e \x85 \u2028 \u2029` 切。
采集数据的 **JSON 字符串值里含 `U+2028`**（实测 **7 个源共 40 处**），
⇒ **一条记录被从中间切成两半** ⇒ 两半都不是合法 JSON ⇒ **那条记录被静默丢掉**。

| 读法 | 行数 | 解析失败 |
|---|---|---|
| `read_text().splitlines()`（旧） | 415,771 | **40** |
| `split("\n")` / `f.open()` 迭代（新） | **415,742** | **0** |

**已修**（`tools/gov-qa/measure-locate-rate.py`，留痕注释在改动处）。
修后实测 **28,601**，"跳过 40 行"那句消失。

⚠ **同类缺陷在 `tools/gov-qa/**` 里还有 34 处未修**（`recon/` 下的一次性勘察脚本）。
**门禁不受影响** —— 门禁那三步用的是 `open()` 迭代（正确写法）。

## 抽样怎么保证"不偏科"

- **按 `source` 分层**（592 个源）；
- 每层配额 ∝ **候选数的平方根**（避免大源通吃，也避免小源挤爆）；
- 层内用**固定种子**随机抽（种子写进 `stats-v1.json`）。

**实测结果**：

| 判据 | 实测 | 阈值 |
|---|---|---|
| 最大单一 `source` 占比 | **2.4%** | ≤ 10% |
| 覆盖 `source` 数 | **393** | ≥ 20 |

> 对照：原始候选里 `nat-tax`（税务）一家占 **11.9%** ⇒ 不分层就会偏科。

## ⚠ 三条必须知道的口径（不然数字会被误用）

### 1. `gold` 只到**文档级**，不是条款级

答复里 **58.5%** 提到条款号，但**答复里的条款号 ≠ 我们库里的条款号**
（版本可能不同）⇒ 下钻会引入版本错配。**所以 `gold_std` 是文档。**

### 2. "零重合"是拿**整篇文档全文**比的 —— **与 `lay-phrasing` 不是一回事**

| | `lay-phrasing`（旧） | 本尺子 |
|---|---|---|
| 比的对象 | **单条条文** | **整篇文档全文** |
| 零重合比例 | 53.0% | **4/500 = 0.8%** |

**⇒ 两边的数字不许互相引用。** 本尺子的 `zero_overlap` 只有 4 条，是因为
一篇法规动辄几万字，问句与它"有 2 字公共子串"几乎必然成立 ——
**这个分层在文档级口径下几乎没有区分度**。

### 2b. ✅ **已修（2026-10-12）：加了一个真正有区分度的分层 `layering_v2`**

`layering`（文档级零重合）**保留**只为对齐旧文档；**实际要用的是 `layering_v2`**。

**换参照物**：不比"整篇法规"，改比**官方答复**（采集数据里的 `answer` 字段）。

**为什么不循环**：问句是**老百姓**写的、答复是**官方**写的 —— **两个不同的人写的**
⇒ 不存在"照着条文编问题"那种循环论证（那是 `eval/reverse-benchmark/` 的缺陷）。

**判据**：`overlap_with_answer = |问句的 2 字组 ∩ 答复的 2 字组| / |问句的 2 字组|`

**实测分布（500 条，铺得开 ⇒ 有区分度）**：

| 档 | 范围 | 条数 |
|---|---|---|
| `L1_几乎无重合` | `[0, 0.2)` | **220** |
| `L2_低重合` | `[0.2, 0.4)` | **164** |
| `L3_中重合` | `[0.4, 0.6)` | **60** |
| `L4_高重合` | `[0.6, 1.0]` | **56** |

最小 **0.0** · 中位 **0.2198** · 最大 **1.0**。

⇒ **四档都有相当数量**，可以拿各档的 `recall@5` **差值**量"大白话 vs 官话"的落差
（这是 L2 层原本要的东西；旧口径给不出来）。

⚠ **仍有一条边界**：`overlap_with_answer` 量的是**用词重合**，是**字符串代理指标**，
**不等于"语义上对不对"** —— 与全仓那条「53% 零重合是字符串代理指标」的更正同一个道理。

⚠ **答复原文不入库**（版权待核）—— `_answer` 只在内存里用来算重合度，
产物里**没有**这个字段（有断言钉住）。

### 3. 追溯键是 **`(source, id)`**，不是 `url`

实测（2026-10-12）：

| 键 | 唯一值数 | 重复 |
|---|---|---|
| `url` | 375,689 | **164 个重复**（最高 ×8,045）；另有 **9,174 条 url 为 None** |
| `id` | 403,880 | 10,374 个重复（占 22,236 条） |
| **`(source, id)`** | **415,742** | **0** ✅ |

⇒ 拿 `url` 当键会**指向错记录**（我第一版就是这么错的：实测 25 条 `question` 对不上）。
**尺子里每条都有 `trace_key = "<source>|<id>"`**，用它回查原始数据**逐字一致（500/500）**。

## schema（`ruler-v1.jsonl` 每行）

```json
{
  "id": "40802194",
  "source": "ah-kb",
  "trace_key": "ah-kb|40802194",
  "url": "https://lyj.ah.gov.cn/hdjl/dwzsk/40802194.html",
  "dept": "安徽省林业局",
  "question": "什么是生态护林员？他们主要做什么？",
  "q_len": 20,
  "gold_std": ["中华人民共和国森林法"],
  "gold_doc_id": ["doc_01M4..."],
  "gold_weak": false,
  "layering": "has_overlap",
  "layering_v2": "L2_低重合",
  "overlap_with_answer": 0.3158,
  "layering_term": "no_term",
  "dup_count": 1,
  "has_clause_ref": false
}
```

| 字段 | 含义 |
|---|---|
| `trace_key` | **`<source>\|<id>`** —— 回查原始数据的**唯一键** |
| `gold_std` | 答复点名的、**在我们库里存在**的文件（标准号/法规名） |
| `gold_doc_id` | 同上，对应的 `doc_id`（**可能是多个** —— 13.5% 命中多个库内文件） |
| `gold_weak` | 只点到「征求意见/通知/公告/公示/解读/函」这类**程序性公文** |
| `layering` | `zero_overlap` / `has_overlap` —— **文档级**，**几乎没有区分度**（只 4/500）；保留只为对齐旧文档 |
| **`layering_v2`** | **`L1_几乎无重合` / `L2_低重合` / `L3_中重合` / `L4_高重合`** —— **实际要用这个**（见上面第 2b 条） |
| **`overlap_with_answer`** | 问句与**官方答复**的 2 字重合比例（`layering_v2` 的原始值） |
| `layering_term` | 问句里出现了库内标准名 ⇒ `has_term` |
| `dup_count` | 同一问题在原始数据里出现几次（去重前的计数） |
| `has_clause_ref` | 答复里含「第X条」⇒ 有条款级线索（**不等于 gold 是条款级**） |

## 已知缺陷（**明确未做，不许当成已解决**）

1. **`layering`（文档级零重合）几乎没有区分度**（实测 `zero_overlap` 只 4/500）。
   ⚠ **但已由 `layering_v2` 补上**（见第 2b 条：四档 220/164/60/56，中位 0.2198）。
   ⇒ 量"大白话 vs 官话"**用 `layering_v2`**；`layering` 只为对齐旧文档而保留。
   **仍**未做的是：把 `gold` 下钻到**条款级** —— 那需要先解决
   "答复里的条款号 vs 库里条款号的版本错配"。
2. **`gold` 是文档级** ⇒ 拿它算 `recall@5` 会**偏宽松**（命中该文档任一条款即算）。
   要条款级召回，见缺陷 1。
3. **答复原文不入库**（版权待核）⇒ 本尺子**只有问题 + gold**，不能测"答得对吗"。
   （`overlap_with_answer` 是**在内存里**算完就丢，产物里没有答复原文 —— 有断言钉住。）
4. **`layering_term` 的判据很粗**（问句里出现任一库内标准名）⇒ 实测只 28/500 命中。
5. **未做人工抽样复核**（业主 2026-10-07 裁定"放弃人工审核、改用外部 AI 复核"）
   ⇒ 若要复核，出口在这里：`verify.py` 能逐条复算，人工/AI 只需看 `question` 与 `gold`。
6. **`overlap_with_answer` 是字符串代理指标** —— 它量**用词重合**，**不等于语义对不对**。
   与全仓那条「53% 零重合是字符串代理指标，不等于语义对不上」的更正同一个道理。

## 不在本尺子范围内

- **L3「答对尺子」**（我们的答案 vs 官方答复）—— 需要"答案片段"字段，结构性变化，另立。
- **重建 `eval/recall-funnel/` 的 171 条** —— 另一件事。
- **调参 / 改检索** —— 本尺子**只量，不改**。
