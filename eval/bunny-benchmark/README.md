# bunny 三路判定出的可用考卷（2026-10-06）

> **这是什么**：一批「外行问法 ↔ 标准条文」的配对，每条由 **space-bunny-free 独立判定 3 次**，
> 用来当检索系统的考卷（问这句话，系统该找到这条条文）。
> **本文是这批资产的归属层**：方法、结果、已知缺陷、怎么复跑，都写在这里。

---

| 文件 | 是什么 |

## 二、结果（150 条）

```
✅ 可用（多数 PASS）   24 条  —— 三路一致 16 / 多数裁定 8；把握=高 23、中 1
❌ 淘汰                126 条
⚠ 三路有分歧          12 条（8%），全是 2:1，无 1:1:1
```

**通过率与词面重合长度强相关**（这是本轮最有用的一个读数）：

| 档 | 通过率 | 池里有多少 |
|---|---|---|
| ★ 与条文重合 ≥4 字 | **30%** | 20 条 |
| ◆ =3 字 | **15%** | 114 条 |
| ▲ =2 字 | **12%** | 629 条 |

**⇒ 把类型对上的 763 条池子全过一遍，估计也只能捞到约 100 条**（不到 150）。

## 三、怎么造出来的

**三步：**

1. **配 gold —— 按问法类型配条款类型**（2026-10-06 新加的判据）：
   - 说法里出现**数值或判定词**（`\d` / "合规吗""允许""给过""罚"）⇒ 配**要求条款**（含 `应/不应/不得`）
   - 否则 ⇒ 配**定义条款**（`TERM_RE` 命中的术语定义）
   - 只是在同术语命中的条款里挑**与说法重合最长**的那一条
2. **送审**：把每一对写成**自包含文档**（问法原话 + 条文原文 + 出处 + 章节性质 + 五问判据 + 输出格式），
   **明令不许读库、不许上网、不许猜"库里有没有更对的"**
3. **三路判定**：同一文档，**独立调用 3 次**（不共享上下文），取多数

**类型对上的比例：763/943 = 81%**（其余 180 条因为该术语名下没有对应类型的条款，回退掉了）

## 四、⚠ 两个已知缺陷（用这批数据前必读）

### 1. **判定会摇摆 —— 同一对多跑几次会变**

**实证**：候选 `#1`（「评酒会上这杯以己酸乙酯为主香的原酒，报哪个组？」配 `GB/T 10781.1-2006 3.1 浓香型白酒`）
- **我独立测一次**：`FAIL / 对象不对 / 高`
- **正式跑的三路**：`PASS / 都对`（三路全同）

**⇒ 同一对输入，4 次调用得出相反结论。**

**⇒ 所以 `usable-24.jsonl` 里的条目只能算【待复验】，不能算"已确认可用"。**
**⇒ 要真确认，得对同一对跑更多次（比如 5 次）取多数。**

### 2. **这份语料的天花板：约 100 条**

**根因**：桥用的是「**说法 → 关联术语 → 该术语的条款**」，而**"说法↔术语"这个关联是生成时贴的标签，不保证说法在问那个术语**。

**⇒ 这与本目录外的既有记录一致**（`eval/lay-phrasing/README.md` §二.2）：
> 「**说法是按「领域+口吻」生成的，不是按「定义」生成的**」

**⇒ FAIL 里"两者都不对"占 61%（77/126），就是这个的体现。**

**⇒ 想突破 150 条，只能扩语料**（提示词在 `docs/research/lay-phrasing-prompt.md`，
术语表 `terms-100000.txt` 有 10 万条，现在只用了 500 条）。

## 五、怎么复跑

```powershell
# 依赖：凭据库里要有 OPENCODE_GO_API_KEY（$DSH_HOME/.credentials.yaml）
& .venv\Scripts\python.exe eval\bunny-benchmark\run-batch.py
```

**脚本要点（都是踩过坑换来的）：**

| 要点 | 为什么 |
|---|---|
| **model 固定 `space-bunny-free`** | 业主硬要求："全部用 bunny" |
| **必须带浏览器式 `User-Agent`** | 🔴 **缺 UA 会被 403** —— 实测一批 360 次调用全废 |
| **发车前先跑第 1 条校验** | 上面那个坑就是因为"只看进度条不看成功数"，盲跑了半小时 |
| 并发 4 + 失败重试 4 次 | 实测 450 次里成功 447（99.3%） |
| 每题 3 次独立调用 | 才算得上三路 |

**⚠ 别用 `spawn_teammate` 跑这个**：它受 **8 个队员上限**约束、且实测有 3/7 的任务
`failed`/`inactive` 却收不到结果；**直接调 API 没有这些问题**。

**⚠ 别用 `role: reviewer` 当"异模型对照"**：实测它派的仍是 `space-bunny-free`，
**不是** `deepseek-flash` —— 本机生效的角色表在 `cordis.patch.yml`，不是 `team-roles.yaml`。

## 六、边界

- **只读真库**（`sqlite3` + `uri=True&mode=ro`）；不改任何源文件。
- **`gen-V2.jsonl` 只读**：它是总纲 §1.2 全部数字的唯一基准（见 `eval/lay-phrasing/README.md`）。
- **判定模型只有 `space-bunny-free` 一种**，所以"三路一致"**不能**排除"同源同向犯错"。
