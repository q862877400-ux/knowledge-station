## 二、回收区 `_trash-2026-10-05/`

**2026-10-05 的整理把「7 天以上、且不是脚本」的东西移到了这里**（同盘移动，**随时可搬回**）。

| 子目录 | 内容 | 体积 |
|---|---|---|
| `stdscan/` | 3 个本机探测日志（原在仓库根的 `stdscan/`） | 小 |
| `var-tmp-stale/` | `var/tmp/` 里 **1,048 个** 7 天以上的条目（含三个大件） | **18,886 MB** |

**三个大件是什么**（原在 `var/tmp/` 顶层）：
`zhwiki-alias.db`（662.7 MB，09-25）、`term-index-keepall.json`（539.8 MB）、`term-index-full.json`（469.2 MB）
—— 都是 2026-09-25 那批实验的一次性产物。

**脚本没动**：`var/tmp/` 里剩 **520 个条目**，其中 `.py` 259 / `.mjs` 249 / `.ps1` 9
—— 文档里有引用它们的（如 `var/tmp/measure-channel-anchors.py`），**移走会断引用**。

**效果**：`var/tmp/` 从 **18,894.6 MB → 8.7 MB**。

## 三、怎么处置回收区（**别急着删**）

1. **先确认没人还在用**：本仓有过一次教训——批准清掉 30 棵陈旧副本时，把某轮复核**正在用的"改前对照树"**一起删了，那份原始 JSON 证据**永久丢失**。清之前 MUST 确认没有正在跑的复核在用。
2. **确认后**再删（`Remove-Item -Recurse -Force`）。
3. **拿不准的搬回原位**，不要删。

**⇒ 回收区是"只移不删"纪律的产物，不是垃圾堆。删之前 MUST 走第 1 步。**
