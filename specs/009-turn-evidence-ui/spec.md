# Feature Specification: 「本轮依据」三处界面改动

**Feature Branch**: `009-turn-evidence-ui`

**Created**: 2026-10-10

**Status**: Draft

**Input**: 业主实跑后提出三条（原话）：
1. 「一个文件里的多个条款就不要重复文件标题了，一个文件标题下面多个条款按先后顺序排列。」
2. 「现行有效后面的 GB 字样删除。」
3. 「点击查看原文那个虽然能成功跳转但是红色箭头没有出现。」

---

## 背景：这三条各自是什么

### 问题 1：同一文件的多个条款重复显示文件标题

**现状**：`KsTurnTab.tsx` 的 `KsTurnEvidenceRow` **一条依据一张卡**，
卡里第一行是 `{standard_no} {clause_number}` + 效力徽章 + `legal_hierarchy`。

**问题**：同一份文件（如《建筑防火通用规范》GB 55037-2022）如果命中 3 个条款，
就出现 **3 张卡、3 遍文件标题**。

**业主诉求**：**一个文件标题，下面按先后顺序列它的多个条款**。

⚠ **"先后顺序"是什么顺序**：业主原话只说"按先后顺序"。
本项目里条款自带 `clause_number`（如 `5.2.3`），**自然读法是按条款号升序**。
⇒ 本 spec 取**条款号升序**（数值感知：`5.2.3` < `5.10.1`，不是字典序），
并**在文档里写明这个选择**（业主没说，我按最自然的读法定，登记为我的判断）。

### 问题 2：`现行有效` 后面的 `GB` 字样

**现状**：`KsTurnTab.tsx:185` 渲染 `legal_hierarchy`，值来自引擎的
`_clause_to_evidence`（`src/core/llm/ks_answer.py:113`）：
`"legal_hierarchy": clause.legal_hierarchy or "GB"`。

**实测（真库，2026-10-10）**：

| `doc_meta.legal_hierarchy` | 篇数 |
|---|---|
| `GB/T` | 6130 |
| `法律` | 1430 |
| **`GB`** | **1043** |
| `规范性文件` | 261 |
| `其他` | 84 |
| `部门规章` | 19 |
| `征求意见稿` | 16 |

**交叉核（标准号前缀 × 层级）**：`GB…` × `GB` = **1024**、`其它` × `GB` = **19**
⇒ **`GB` 绝大多数是真实的"强制性国标"分类**，但**有 19 篇是法律/条例被兜成了 GB**
（`src/core/domain/models.py:102/124` 的默认值是 `"GB"`）。

**业主诉求**：**删掉这个字样**。他嫌的是**显示冗余**——
徽章已经说了"现行有效/已被替代"，再挂一个 `GB` 对用户没有增量信息。

⚠ **这是显示层改动**（业主说的是界面），**不动数据**：
数据层的 19 篇兜底错标是**另一个问题**，登记但不本批修（改数据要动生产库，属要业主点头的类）。

### 问题 3：红箭头不出现（跳转成功）

**根因（已确证，两处叠加）**：

1. **引擎侧**：`_clause_to_evidence`（`src/core/llm/ks_answer.py:96-128`）输出的公共字段里
   **完全没有 `bbox`** —— 只给了 `page_start`。
2. **前端侧**：`KsTurnTab.tsx` 的 `turnEvidenceHref`（第 74-84 行）构造证据 URL 时
   **只传 `doc` / `page` / `rev`，从不传 `bbox`**。

而箭头完全依赖 `bbox`：`KsEvidenceTab.tsx:513` 的
`const anchor = evidence.current?.bbox`，第 520 行 `if (anchor !== undefined && …)`
⇒ **`bbox` 为空时箭头直接不画**（跳页照常，所以业主看到"能跳转但没箭头"）。

**bbox 在真库里是有的**（实测）：

| 表 | 关联列 | 几何列 | 行数 |
|---|---|---|---|
| `source_span` | `clause_revision_id` | `bbox_json` + `page_number` | **1,842,493** |

`bbox_json` 真实样例：`[76.0, 643.43, 117.0, 655.43]` —— 正是
`[x0, y0, x1, y1]`、**左下原点**（与 `ksEvidence.ts` 的契约逐字一致）。

⇒ **修法**：把 `source_span` 的**首个 span**（`sort_order` 最小）的 `bbox` 与 `page_number`
带进证据字段，前端 `turnEvidenceHref` 把它传给证据 URL。

## 用户场景与验收

### US1（P1）：同一文件的多个条款归到一个标题下

- **AC-1.1** 同一 `doc_id` 的多条依据**只渲染一次文件标题**。
- **AC-1.2** 该标题下的条款**按条款号升序**（数值感知：`5.2.3` < `5.10.1`）。
- **AC-1.3** 每个条款仍**各自**有：条款号、效力徽章、摘要、看原文入口。
- **AC-1.4** 判据：渲染级（jsdom）断言"同一 doc_id 的标题只出现一次"+"条款顺序正确"。
- **AC-1.5** 判据有牙：把两条同文件依据拆开 ⇒ 必红。

### US2（P1）：删掉 `GB` 字样

- **AC-2.1** 「本轮依据」卡上**不再显示** `legal_hierarchy`。
- **AC-2.2** 判据：负向——渲染结果里不出现该字段值。
- **AC-2.3** 判据有牙：把它加回去 ⇒ 必红。
- ⚠ **边界**：只删**显示**，`evidence` 数据里该字段**保留**（其它消费者可能要用）。

### US3（P0）：红箭头必须出现

- **AC-3.1** 引擎的证据字段带 `bbox`（4 个数）与 `bbox_page`。
- **AC-3.2** 前端 `turnEvidenceHref` 把 `bbox` 传进证据 URL。
- **AC-3.3** 判据：① 引擎侧单测——证据 dict 里 `bbox` 存在且是 4 个数字；
  ② 前端侧单测——`turnEvidenceHref` 对带 bbox 的条目产出的 URL **含 `bbox=` 参数**。
- **AC-3.4** 判据有牙：把 bbox 摘掉 ⇒ 两边判据各红一次。
- ⚠ **诚实边界**：本批**不能**在真宿主里验证箭头真的画出来了（宿主 GUI 的会话树在本机渲染不出，
  见 `UI-BASELINE` §五）；能验的是"bbox 一路传到了证据 URL"。**箭头最终画不画，仍归渲染层**，
  而渲染层已有既有判据（`smoke-evidence-*`）。

---

## 范围与边界

**做**：
- 三条改动 + 各自的判据（含变异验证）。
- 引擎侧把 `bbox` 接进证据字段（**只读 `source_span`，不动数据**）。

**不做**：
- **不改数据**：那 19 篇兜底错标的 `legal_hierarchy` 只在文档里登记，**不动生产库**。
- **不碰**并行线写入面（`tools/gov-qa/**`、`scripts/run-gates.ps1`、`specs/004`、`specs/006`、公告组件）。
- **不动**红色箭头的视觉本体（`NOT-DOING` 第 2 条红线：箭头是既定形态）。

## 依赖与风险

| 风险 | 对策 |
|---|---|
| 引擎查 `source_span` 会拖慢回答 | `clause_revision_id` 上有索引则一次点查；**实测耗时**后再定，超预算就只对最终入选条款查 |
| 条款号排序：非标准号（如"第一条"）怎么办 | 排序键要**稳健**：能解析成数字段的按数值比，否则按原串比（不许抛错） |
| 改了证据字段，快照/契约测试会红 | 先跑相关测试看影响面，逐条按新行为更新 |
| 真宿主验不了箭头 | 如实写进边界；验到"URL 带 bbox"为止 |
