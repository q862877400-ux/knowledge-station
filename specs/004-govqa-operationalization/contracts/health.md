# 契约：健康结论命令 `health.py`

**对应需求**: FR-017 ~ FR-021 ｜ **对应成功判据**: SC-009 / SC-010 / SC-011

---

## 命令面

```bash
# 一句话结论（主用法）
python tools/gov-qa/health.py

# 详细（展开每项判据的实测值）
python tools/gov-qa/health.py --detail

# 机器可读（给闸门 / 脚本用）
python tools/gov-qa/health.py --quiet

# 只跑单项（调试用）
python tools/gov-qa/health.py --only coverage
```

---

## 退出码

| 码 | 含义 |
|---|---|
| `0` | **可用** —— 全项达标 |
| `1` | **不可用** —— 有红项（与 `check.sh` 一致） |
| `2` | 体检本身执行失败 |

---

## 输出契约

### 人类可读（默认，中文，**一句话结论优先**）

```
❌ 当前不可用：标签覆盖率 87.3% 未达 90%。

  ✅ 数据总数      359,823 ≥ 地板 357,823
  ✅ 零数据适配器  0
  ✅ 重复 id       0
  ❌ 标签覆盖率    87.3% < 90%       ← 未达标
  ⏱️ 用时 4.2s
```

**要求**（宪法 I「说人话」）：
- 第一行必须是**一句话结论 + 原因**，让用户不用往下读就知道能不能用
- 不用内部术语（不写「judge 4 failed」，写「标签覆盖率未达标」）

### 机器可读（`--quiet`，**纯 ASCII**）

```
VERDICT=not_usable
TOTAL=359823
FLOOR=357823
EMPTY=0
DUPS=0
COVERAGE=87.3
COVERAGE_GATE=90
ELAPSED=4.2
```

## 行为契约

| # | 性质 | 如何验证 |
|---|---|---|
| 1 | **一次运行检出全部故障** | 人为制造 3 类故障（删文件 / 塞重复 id / 注册空适配器），一次全检出（SC-009） |
| 2 | **耗时 ≤60s** | `ELAPSED ≤ 60`（SC-010） |
| 3 | **机器输出纯 ASCII** | `--quiet` 输出可用 `grep -E '^[A-Z_]+='` 完全解析（R5） |
| 4 | **结论无模糊态** | `VERDICT` 只有 `usable` / `not_usable` |
| 5 | **能定位到文件** | 重复 id / 数据缺失时，指出**具体是哪个文件** |

## 前置条件

- `tools/gov-qa/data/*.jsonl` 可读
- `tools/gov-qa/recon/*.py` 可用
- `.round-floor` 存在（不存在则视为地板 0）

## 副作用

**只读**。不写任何数据文件。
可选 `--trace <file>` 追加执行轨迹（供事后定位环境差异，见下）。

---

## 与 `check.sh` 的关系

`check.sh` 是**闸门**（Stop hook 用，管「能不能停」）；
`health.py` 是**体检**（人用，回答「能不能用」）。

两者**判据必须一致**，但**用途不同**：
- `check.sh` 只输出「过 / 不过」+ 简因
- `health.py` 输出「可用 / 不可用」+ 完整实测值 + 一句话解释

> ⚠ **不要合并**：`check.sh` 必须极快且极简（hook 有 300s 超时，已因超时踩过坑）；
> `health.py` 可以慢一些、详细一些（给人看）。
