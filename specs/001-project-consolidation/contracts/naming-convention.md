# 契约：命名与分类规范 v1

**Feature**: 001-project-consolidation | **Date**: 2026-10-05 | **状态**: 待执行

本文件是 **E1 命名规范** 的契约。**每条规则都给出机械判据**——脚本能判，才算规则。

---

## 一、字符集与大小写

| 对象 | 规则 | 机械判据 |
|---|---|---|
| 目录名 | 全小写 ASCII + 数字 + `-` | 正则 `^[a-z0-9]+(-[a-z0-9]+)*$` |
| 文件名（普通） | 同上，扩展名除外 | 同上（去扩展名后判） |
| 文件名（例外清单） | 允许全大写 | 见 §二 |

**反例**：`wenjianmulu/`（不是英文）、`STD_STATUS_CHANNELS.md`（下划线 + 全大写）、`B3A-REPORT.md`（全大写非例外）。

---

## 二、允许全大写的例外（仅这些）

| 文件名 | 理由 |
|---|---|
| `README.md` | 通用约定，工具与人都认这个名字 |
| `AGENTS.md` | DSH 约定的注入名；**改它会让指令失效** |
| `CLAUDE.md` | 同上（符号链接） |
| `LICENSE` / `LICENSE.md` | 法律文件通用名 |
| `INDEX.md` | 本特征引入的索引名，全大写以示"这是索引不是内容" |
| `CONTRACT.md` | 子系统契约名，同上 |

**新增例外 MUST 在这里登记**，不许就地起一个。

---

## 三、分类靠目录，不靠文件名前缀

- **MUST NOT** 用 `plan-` / `research-` / `ledger-` 这类前缀当分类器。
- **分类由所在目录表达**：一个文件从"计划"变成"历史"只需移动，不需改名。

**反例**：`NEXT-DEV-PLAN-2026-09-28.md` 靠后缀表达"这是计划"——它变成历史后，名字还在说它是计划。

---

## 四、日期后缀

只有**会被后续版本取代的真源**才带日期。判据：

| 带日期 | 不带日期 |
|---|---|
| 计划、方案、阶段台账、状态快照（会被下一版取代） | 研究笔记、组件契约、map、索引、规范 |
| 例：`NEXT-DEV-PLAN-2026-09-28.md` | 例：`docs/wiki/map.md` |

**格式**：`-YYYY-MM-DD`，放扩展名前。
**反例**：给一份研究笔记加日期——它不会被取代，日期只会让人以为它过期了。

---

## 五、日期用哪个

- **文件名与正文里的日期，一律用该文档的"事实发生日"，不是"我记得的那天"。**
- **写日期前 MUST 核系统时钟**（`Get-Date`）。
  > 2026-10-05 实测教训：本轮两份新文档的日期全部写成了上文带过来的 `2026-09-30`，
  > 而当天是 `10-05`。**从上文继承日期而不核时钟，必错。**

---

## 六、目录职责表（一个东西只归一处）

| 目录 | 装什么 | 不装什么 |
|---|---|---|
| `docs/` | **当前真源**：现在是什么、该怎么做 | 历史、过程记录 |
| `docs/wiki/` | **接手文档**：大 map、项目现状、组件契约 | 具体实现细节（那些在代码里） |
| `docs/archive/` | **历史**：被取代的计划、过期基线、调研过程、已完成复核 | 任何仍然算数的东西 |
| `docs/research/` | **外部研究**：读别人的东西得到的结论 | 本仓自己的计划与台账 |
| `specs/` | **Spec Kit 工作区**：规格、计划、任务 | 产品文档、研究笔记 |
| `var/` | **本地产物**（不进版本控制） | 任何需要被交接的东西 |

**边界判定口诀**：**"交接时新人需要看它吗？"** 需要 ⇒ 不是 `var/`；不需要 ⇒ 不该在 `docs/`。

---

## 七、"历史"与"真源"的判据

一个文档进 `docs/archive/` 当且仅当**满足其一**：

1. 有**更新的同类文档**取代了它（旧计划、旧方案）；
2. 它记录的是**过程**，而结论已经落进别的文档；
3. 它对应的工作**已经收口**（如已完成的复核任务书）；
4. 它的**数字/结论与当前基线冲突**且无人维护。

**拿不准 ⇒ 进归档，不删。**
（`var/` 下的东西不受版本控制，**只移动、不删除**。）

---

## 八、改名执行契约

1. **先出对应表**（E2），逐行含现名/新名/分类/理由/受影响引用数。
2. **脚本机械执行**，MUST NOT 手敲路径。
3. **同步改正三类引用**：
   - 文档间链接（开工前实测 **207** 处）
   - 代码里引用的文档路径（开工前实测 **28** 处）
   - 门禁脚本里的断言
4. **独立的全仓断链检查**：MUST 用 `git grep` 全仓搜旧文件名验证残留为 **0**；
   **MUST NOT** 只凭"门禁绿了"断言（门禁扫不到全部文档）。
5. **最后跑门禁**：测试基线 MUST NOT 下降。

---

## 九、撞车与例外处理

- **两个文件算出同一新名** ⇒ **停下来报告**，MUST NOT 静默加 `-2` 后缀。
- **某文件在例外清单外确实需要全大写** ⇒ 先在 §二 登记，再改名。
- **某文件被别人的未提交改动覆盖** ⇒ **跳过并登记**，MUST NOT 触碰。
