# 契约：命名与分类规范 v2

**Feature**: 001-project-consolidation | **Date**: 2026-10-05 | **状态**: 待执行

> ⚠ **v1 → v2 是就地更正，不是新增。** v1 的两条规则经实测**不可执行**，
> 错话与原委保留在 §十。按本仓纪律：错话 + 更正都要留。

---

## 零、v1 错在哪（先说清楚，免得有人按 v1 执行）

v1 写「文件名 MUST 全小写 ASCII」。实测扫出来后暴露两个致命问题：

**错误 1：与硬约束直接矛盾。**
`AGENTS.md` 按**全大写**引用本仓文档（`docs/NOT-DOING.md`、`docs/DEVELOPMENT-HISTORY.md`、
`docs/CHANNEL-COVERAGE-PLAN.md`、`docs/INTERACTION-DESIGN.md`、`docs/CODE-REVIEW-CHECKLIST.md`、
`docs/TEST-FLAKES.md`）。**而本特征明令不许改 `AGENTS.md`。**
⇒ 按 v1 改名 = 把 `AGENTS.md` 里的引用全弄断，且**无权修**。

**错误 2：把代码文件也判成违规。**
v1 按"全小写"扫，判出 **327 个代码文件违规**——但那是 `routes_channels.py`、`fetch_law.py`
这类 **Python 的 PEP8 snake_case**，**是正确写法**。
⇒ 按 v1 改名 = 把每一个 import 都弄断，且违反语言约定。

**⇒ v1 作废。以下 v2 为准。**

---

## 一、第一原则：**代码文件跟随语言的约定，文档跟随本仓的既有约定**

| 类别 | 规则 | 依据 |
|---|---|---|
| **Python 代码** | `snake_case.py` | PEP8；全仓 327 个文件已如此 |
| **JS/TS 代码** | 跟随**同目录既有**写法（本仓混用，不再强推一种） | 改名会断 import |
| **文档** | **沿用本仓既有的"标准文档全大写、其他按目录"约定** | `AGENTS.md` 依赖它，且不许改 |
| **目录** | 全小写 kebab-case | 实测 0 违规，已是现状 |

**⇒ 结论：本特征不改任何代码文件名。** 理由：改名收益为零（代码文件本来就不该在文档导航里被指认），
风险是断 import + 违反语言约定。

---

## 二、真正要统一的是**分隔符**，不是大小写

**文档文件名 MUST 用连字符 `-`，MUST NOT 用下划线 `_`。**

**实测的真违规只有 6 个**（排除代码文件后，全仓 track 文件）：

| 现名 | 新名 |
|---|---|
| `docs/CHANNEL-PROBE-REPORT.md` | `docs/CHANNEL-PROBE-REPORT.md` |
| `docs/LAW-SOURCE-PLAN.md` | `docs/LAW-SOURCE-PLAN.md` |
| `docs/REALTIME-VALIDITY-VERIFY-RESEARCH.md` | `docs/REALTIME-VALIDITY-VERIFY-RESEARCH.md` |
| `docs/STD-STATUS-CHANNELS.md` | `docs/STD-STATUS-CHANNELS.md` |
| `docs/WSL2-VLM-BACKEND-DECISION.md` | `docs/WSL2-VLM-BACKEND-DECISION.md` |
| `tests/fixtures/rental-contract.md` | ⚠ **待判**：测试夹具，改名可能断测试，需先查引用 |

**反例**：`src/core/api/routes_channels.py` —— 它是**代码**，下划线是**对的**，不在本规则内。

---

## 三、大小写（文档）

- **标准文档**（被 `AGENTS.md` 或 `README` 点名的）**保留全大写**——它们是"常驻引用"，
  全大写本身就是"这是标准文档不是笔记"的信号。**MUST NOT** 为了整齐改成小写。
- **其余文档**：保留现有大小写；**新增文件**按所在目录既有写法。
- **`README.md` / `INDEX.md` / `CONTRACT.md` / `AGENTS.md` / `LICENSE`**：全大写，通用约定。

---

## 四、分类靠目录，不靠文件名前缀（v1 保留，未变）

- **MUST NOT** 用 `plan-` / `research-` / `ledger-` 这类前缀当分类器。
- 分类由所在目录表达：文件从"计划"变成"历史"只需移动，不需改名。

---

## 五、日期后缀（v1 保留，未变）

只有**会被后续版本取代的真源**才带日期。格式 `-YYYY-MM-DD`。

| 带日期 | 不带日期 |
|---|---|
| 计划、方案、阶段台账、状态快照 | 研究笔记、组件契约、map、索引、规范 |

---

## 六、写日期前 MUST 核系统时钟

> 2026-10-05 实测：两份新文档的日期全写成上文带过来的 `2026-09-30`，而当天是 `10-05`。
> **从上文继承日期而不核时钟，必错。**

---

## 七、目录职责表（一个东西只归一处）

| 目录 | 装什么 | 不装什么 |
|---|---|---|
| `docs/` | **当前真源** | 历史、过程记录 |
| `docs/wiki/` | **接手文档**：大 map、项目现状、组件契约 | 实现细节 |
| `docs/archive/` | **历史**：被取代的计划、过期基线、调研过程、已完成复核 | 任何仍然算数的东西 |
| `docs/research/` | **外部研究**的结论 | 本仓自己的计划与台账 |
| `specs/` | **Spec Kit 工作区** | 产品文档 |
| `var/` | **本地产物**（不进版本控制） | 任何需要交接的东西 |

**边界口诀**：**"交接时新人需要看它吗？"** 需要 ⇒ 不是 `var/`；不需要 ⇒ 不该在 `docs/`。

---

## 八、"历史"与"真源"的判据

一个文档进 `docs/archive/` 当且仅当满足其一：
1. 有更新的同类文档取代了它；
2. 它记录的是**过程**，结论已落进别的文档；
3. 它对应的工作**已收口**；
4. 它的数字/结论与当前基线冲突且无人维护。

**拿不准 ⇒ 进归档，不删。**（`var/` 下不受版本控制，**只移动、不删除**。）

---

## 九、改名执行契约

1. **先出对应表**（每行：现名 / 新名 / 理由 / 受影响引用数）。
2. **脚本机械执行**，MUST NOT 手敲路径。
3. **同步改正三类引用**：文档间链接 / 代码引用的文档路径 / 门禁断言。
4. **独立的全仓断链检查**（`scripts/docs/check-links.py`）验证残留为 **0**；
   **MUST NOT** 只凭"门禁绿了"断言。
5. **最后跑门禁**，测试基线 MUST NOT 下降。
6. **撞车停下来报告**，MUST NOT 静默加后缀。

---

## 十、v1 原文留痕（不许删）

v1 的两条错规则：

> - **目录名**：全小写 kebab-case，用**名词**（`docs/archive/old-plans`）。
> - **文件名**：全小写 kebab-case；**专业缩写保留大写**（`README.md`、`API.md`、`AGENTS.md`）。
> - **分类靠所在目录**，不靠文件名前缀。**不许**用 `plan-` / `research-` 这类前缀当分类器。
> - **日期后缀**只给"会被后续版本取代的真源"。

**作废的是第 2 条（文件名全小写）。** 第 1、3、4 条未变，保留在 §三/§四/§五。

**v1 里那句"专业缩写保留大写"其实已经埋了伏笔**——`NOT-DOING.md`、`CHANNEL-COVERAGE-PLAN.md`
这些整名都是大写的标准文档，本就不该被"全小写"覆盖。v2 把这条说清了。
