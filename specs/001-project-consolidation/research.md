# Phase 0 研究：整理策略决策

**Feature**: 001-project-consolidation | **Date**: 2026-10-05

每条按 **Decision / Rationale / Alternatives considered** 记。所有数字都是开工前实测。

---

## D1. 命名规范：分类靠**目录**，不靠文件名前缀

**Decision**：
- **目录名**：全小写 kebab-case，用**名词**（`docs/archive/old-plans`）。
- **文件名**：全小写 kebab-case；**专业缩写保留大写**（`README.md`、`API.md`、`AGENTS.md`）。
- **分类靠所在目录**，不靠文件名前缀。**不许**用 `plan-` / `research-` 这类前缀当分类器。
- **日期后缀**只给"会被后续版本取代的真源"（如 `NEXT-DEV-PLAN-2026-09-28.md`）；
  研究笔记、契约、map **不带日期**。

**Rationale**：
- 现状是四种混用：中文拼音（`wenjianmulu/`）、全大写（`B3A-REPORT.md`）、
  下划线全大写（`STD_STATUS_CHANNELS.md`）、kebab（`gen-doc-index.py`）。
  ⇒ **读者无法从名字判断"这是当前真源还是历史"**，而这正是业主诉求的核心。
- 用前缀分类会**把分类写死在名字里**：一个文档从"计划"变成"历史"就要改名。
  用目录分类则只需移动文件——**目录是分类器，文件名只表身份**。
- 日期后缀造成"同一个东西有多个名字"（`NEXT-DEV-PLAN` 已有 `2026-09-28` 版本），
  且日期会与"最后修改日"混淆（git 已经有后者）。只在真的会被取代的真源上保留。

**Alternatives considered**：
- **前缀分类**（`plan-*.md` / `research-*.md`）：被否，见上；且会与既有 `docs/research/` 目录重复表达同一件事。
- **保留现有名字只规范新增**：业主明确选了"全量重命名"，且实测 **37 份文档只被引用 1 次**，
  说明命名不统一**已经在制造孤岛**，只规范新增解决不了。

## D2. 归档体系：按"它是什么"分，不按"什么时候的"

**Decision**：`docs/archive/` 下按**文档性质**分四类：

| 分类 | 装什么 | 判据 |
|---|---|---|
| `old-plans/` | 已被取代的计划/方案全文 | 有更新的同名计划取代它 |
| `old-baselines/` | 过期快照（如旧 UI 基线、旧规模数字） | 内容与被维护的基线冲突且未更新 |
| `research-process/` | 调研**过程**记录（怎么查的、试了几版） | 结论已落进别的文档，此份只剩过程 |
| `review-briefs/` | 已完成的复核任务书 | 对应的复核已收口 |

**Rationale**：
- 按**时间**分（`2026-09/`）会让"找某类历史"变成翻多个目录；按**性质**分则一次到位。
- 业主原话是"知道在哪找，就像需要的时候才去看" ⇒ **要的是"按用途能找到"，不是"按时间排列"**。
- 实测 `docs/verify-briefs/` 已有 14 份、271 KB，是**现成的 `review-briefs/` 候选**——可直接整体迁入。

**Alternatives considered**：
- **按时间分**：被否，见上。
- **全部平铺进 `archive/`**：被否，113 份平铺等于没整理。

## D3. wiki 结构：三级递进，入口唯一

**Decision**：

```
README.md（仓库入口）
  └─ docs/README.md ······ 大 map：仓库每一类文件在哪、干什么
       └─ docs/wiki/architecture.md ······ 项目目标 + 现状 + 主要子系统一览
            └─ docs/wiki/components/<子系统>.md ······ 职责 / 接口 / 依赖 / 明确的非目标
```

- **大 map 的唯一职责**：回答"我要找的东西在哪一类里"。
- **契约的唯一职责**：回答"这块负责什么、提供什么、依赖什么、**明确不做什么**"。
- **覆盖范围**：分层——**1 张大 map + 每子系统 1 篇 + 关键接口契约**（业主选定）。
  范围依据实测：`src/` 19 个子系统 + `plugin/` 对外 3 个模型可见工具 + 数据库对象。

**Rationale**：
- 实测 `src/` 是 19 个子系统（`core/*`），而 `plugin/` 对 agent 只暴露 **3 个工具**
  （`ks_ping` / `ks_resolve_clause` / `ks_answer`，另有 `ks_materials` 只读）。
  ⇒ **"每子系统一篇"是 19+ 篇的量级，可控**；"每模块一篇"会到 38+ 篇，且大量内容会与代码重复。
- 业主原话"逐步递进""一套读完就了解清楚" ⇒ **必须有唯一入口且层层可达**，不能是平铺的 113 份。

**Alternatives considered**：
- **全量（每模块一篇，38+）**：被否——业主选的是"分层"，且实测文档已是代码的两倍，
  再按模块 1:1 写会立刻重演"又臭又长"。
- **VitePress 站点**：被否（业主选了仓内 md 分级）——首要读者是 agent，站点需要构建，反而难读。
- **另起第四套总览**：被否——`ENCYCLOPEDIA.md`(74KB) / `INTRODUCTION.md` / `VISION-TREE.md` / `README.md`
  已是四份总览，业主选了"改造它们"，本决策遵此。

## D4. 去重策略：判据是"同一事实在两处各写一份全文"

**Decision**：**保留一处全文，别处改链接**。判断"冗余"只看这一条，不看体量、不看年龄。

**例外（不许动）**：
- **"错话 + 更正"留痕**：宪法原则 V 要求就地保留，**即使它读起来像重复**。
- **业主原话照抄**：多处引同一句原话是刻意的（`AGENTS.md` 里写明"两处都写是刻意的"）。

**Rationale**：
- 实测：**37 份文档只被引用 1 次、13 份零引用** ⇒ 孤岛多，但**孤岛不等于冗余**——
  它可能是某话题的唯一归属层。**只有"两处写同一件事"才算冗余。**
- 拿体量当判据会误杀：`DEVELOPMENT-HISTORY.md` 1 MB，但它不是"冗余"，
  是**职责错位**（见 D5）——两个问题要用两种解法。

**Alternatives considered**：
- **按体量删大的**：被否，会误杀唯一归属层。
- **按年龄删旧的**：被否，`NOT-DOING.md` 里的旧否决恰恰是最需要留的。

## D5. `DEVELOPMENT-HISTORY.md`：分层，不是删除

**Decision**：**按轮次分层**——近期轮次留正文；早期轮次迁 `docs/archive/history/`，
正文只留**一行索引**指向归档。**保留**：决策理由、作废留痕、关键实测数字。

**Rationale**：
- 实测 **11,888 行 / 1,053 KB**，`§10.71`–`§10.80` 每节是一轮工作，**内容与 `git commit message` 重复**。
- 但宪法原则 V 要求"作废留痕"存在，且本仓规则明写"打回的说法必须就地更正并留痕，**不许悄悄删掉**"。
  ⇒ **删全文会违反原则 V；分层不违反。**
- 业主诉求是"需要时才去看" ⇒ **归档正好符合**：正文轻，历史可查。

**Alternatives considered**：
- **整份归档**：被否——开发史是 `AGENTS.md` 点名的事实归属层，整份移走会打断归属链。
- **原地删除早期轮次**：被否，违反原则 V。

## D6. 改名执行策略：脚本机械执行 + **独立**断链检查

**Decision**：
1. 先生成**新旧名称对应表**（现名 / 新名 / 归属分类 / 理由），**逐行可审**。
2. 由**脚本**机械执行改名（不手敲路径）。
3. 改名后跑**独立的全仓断链检查**，覆盖三类引用：
   文档间链接（实测 **207** 处）、代码引用文档路径（实测 **28** 处）、门禁断言。
4. 最后跑门禁。

**Rationale**：
- 本仓纪律：「长文档一律字节级搬运，不许手抄：手抄实测 77 行错 2 处（2.6% 失真）」
  ⇒ 改名同理，手敲必有漏。
- **门禁扫不到全部文档** ⇒ 不能只凭门禁绿断言 SC-001（宪法原则 III：假绿判 failed）。
- 实测断链检查可机械做：`git grep` 全仓搜旧文件名即可。

**Alternatives considered**：
- **靠门禁验证**：被否，见上。
- **一次性 `git mv` 全量后手工修**：被否，235 处引用手改必漏。
