# Phase 1 数据模型：本特征产出的六类实体

**Feature**: 001-project-consolidation | **Date**: 2026-10-05

本特征不建数据库。这里的"实体"是**仓内的文件与结构**，字段是它们必须回答的问题。

---

## E1. 命名规范

**是什么**：一份文档，规定目录/文件/分类三类命名规则。

| 字段 | 必填 | 内容 |
|---|---|---|
| 目录命名规则 | ✅ | 字符集、大小写、分隔符、语义（名词还是动词） |
| 文件命名规则 | ✅ | 同上，外加"专业缩写保留大写"的清单 |
| 分类归属规则 | ✅ | 一个文件该放哪个目录，依据什么 |
| 日期后缀规则 | ✅ | 什么时候带日期、什么时候不带 |
| 每条规则的反例 | ✅ | 至少一个"这样写是错的" |

**校验**：规范里的每条规则 MUST 能被机械检查（脚本可判），否则不算规则。

**关系**：E2 由 E1 推出；E1 决定 E3 的目录名、E4/E5 的文件名。

---

## E2. 名称对应表

**是什么**：改名的唯一依据。一行 = 一次改名。

| 字段 | 必填 | 内容 |
|---|---|---|
| 现名 | ✅ | 相对仓库根的路径 |
| 新名 | ✅ | 相对仓库根的路径 |
| 归属分类 | ✅ | 由 E1 的规则推出 |
| 改名理由 | ✅ | 为什么改（不是"规范要求"，要说具体原因） |
| 是否受影响引用 | ✅ | 该文件被多少处引用（实测数字） |

**校验**：
- MUST 覆盖全部需改名对象；**跳过项 MUST 显式列出并写明原因**（不许静默跳过）。
- 两行 MUST NOT 算出同一个新名（撞车必须停下来报告，不许静默加后缀）。

**关系**：依赖 E1；驱动改名执行；改名结果影响 E3/E4/E5 里的路径。

---

## E3. 归档区

**是什么**：`docs/archive/` 下的分类目录树 + 一份索引。

| 字段 | 必填 | 内容 |
|---|---|---|
| 分类目录 | ✅ | 见 research D2 的四类（`old-plans` / `old-baselines` / `research-process` / `review-briefs`） |
| 每份归档件的来源路径 | ✅ | 从哪搬来的（**可追溯、可回退**） |
| 归档理由 | ✅ | 为什么判定它属于历史 |
| 归档索引 | ✅ | 回答"哪类历史在哪、怎么查" |

**校验**：从仓库入口到任一归档件 **≤ 3 步**（SC-005）。

**状态转移**：`当前真源` →（被取代）→ `归档`。**归档不可逆地回到真源**——
若要复活某份归档件，MUST 作为"新结论"重新落进归属文档，不许直接把归档件移回来。

**关系**：E6 是其索引。

---

## E4. 大 map

**是什么**：一张表，仓库每一类文件 × 归档位置 × 功能。

| 字段 | 必填 | 内容 |
|---|---|---|
| 文件类别 | ✅ | 覆盖仓库**每一个顶层条目** |
| 位置 | ✅ | 它在哪（目录路径） |
| 功能 | ✅ | 这类文件干什么用 |
| 是否受版本控制 | ✅ | 是/否（`var/` 这类要标明） |

**校验**：仓库顶层条目中，无法在 map 里找到归属的数量 MUST 为 **0**（SC-003）。

**关系**：E4 是 wiki 的第一级；指向 E5。

---

## E5. 组件契约

**是什么**：每个子系统一篇，含职责/接口/依赖/非目标。

| 字段 | 必填 | 内容 |
|---|---|---|
| 职责 | ✅ | 它负责什么（一段话） |
| 对外提供什么 | ✅ | 接口/端点/工具名，含调用方式 |
| 依赖什么 | ✅ | 上游模块、外部服务、数据表 |
| **明确不做什么** | ✅ | 非目标——**这是最重要的一栏** |
| 关键数据 | ✅ | 涉及的表/对象、关键字段 |
| 改了它会影响谁 | ✅ | 下游消费者 |

**校验**：`src/` 的 19 个子系统 + `plugin/` 对外的 3 个模型可见工具，**覆盖率 100%**（SC-006）。

**为什么"明确不做什么"必填**：接手者最常犯的错是**把别的模块的职责塞进来**。
不写非目标，契约就只剩"它能干什么"，无法防止越界。

**关系**：E5 是 wiki 的第三级；由 E4 指向。

---

## E6. 归档索引

**是什么**：回答"哪类历史在哪"的单一入口。

| 字段 | 必填 | 内容 |
|---|---|---|
| 分类清单 | ✅ | 有哪些类 |
| 每类的位置 | ✅ | 目录路径 |
| 每类的判据 | ✅ | 什么样的东西进这一类 |
| 怎么查 | ✅ | 具体动作（例如"要查旧计划 → 看 `docs/archive/old-plans/README.md`"） |

**校验**：从仓库入口按"历史在哪"的指引 **≤ 3 步**到达目标（SC-005）。

**关系**：E6 描述 E3；被 E4 引用。

---

## 实体之间

```
E1 命名规范 ──推出──> E2 名称对应表 ──驱动──> 改名执行 ──影响──> E3/E4/E5 里的路径
                                                                    │
E4 大 map ──指向──> E5 组件契约                                      │
   │                                                                 │
   └──指向──> E6 归档索引 ──描述──> E3 归档区 <────────────────────┘
```

**一个事实一个归属层**（宪法原则 IV）在本模型里的落法：
E4 只说"东西在哪"，E5 只说"这块干什么"，E6 只说"历史在哪"——
**三者 MUST NOT 互相抄内容，只许链接。**
