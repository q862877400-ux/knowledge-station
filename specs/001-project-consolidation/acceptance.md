## 二、V5：外人只读 wiki 的答问结果

**方法**（这一条**必须**用没读过本仓的 agent——本仓有过「父代理看串了」的实测记录，我自己验会不自觉地替文档补全）：

给一个独立 agent **只读三份文件**：`README.md`、`docs/README.md`、`docs/wiki/architecture.md`；
**不许读别的**；问五个问题（项目目标 / 现在做到哪 / 改检索该动哪 / 改 schema 前必须做什么 / 有没有删了会出事的东西）；
**明确要求「三份里没写就写'没找到'，不许猜」**。

## 三、V7：门禁**未达成** —— 如实记

**门禁 -Quick 实测：3/5 通过。**

| 步骤 | 结果 |
|---|---|
| `mypy`（引擎类型） | ✅ 152 个源文件 0 问题 |
| `verify:commands` | ✅ 22/22 |
| `pssa-guard` | ✅ 9 个脚本零命中 |
| `tsc`（客户端类型） | ⛔ 失败 |

**两条红都定了性，且都有机械证据表明不是本特征引入的**（详见 [baseline.md](baseline.md) §六）：

- **`tsc`**：本特征改过的 75 个文件里，**`plugin/` 下的是 0 个**；报错文件的最后一次改动是 `dbe39bc 2026-09-28`（那次把图标名从 `*14|16` 改成 `*Regular`），而现在的报错说 `*Regular` 不存在、该用 `*14|16`——**方向相反**。⇒ DSH 宿主在 09-28 之后又调了图标导出名。
- **`smoke`**：同样是 **0 个 `plugin/` 文件被改**，而 smoke 渲染的正是 `plugin/client/`。两次重跑都红、同样 2 个场景（`kb|kb-filemenu@520`、`kb|kb-dirmenu@520`，`ui-render-shot exit=null`），不在已知 flake 清单里；`ui-render-shot.mjs` 自述这 2 个场景是 2026-09-22 新增、当时就出过事。

**⇒ 结论：本特征未引入新红，但【门禁整体不绿】。**
**⇒ SC-007 记「未达成」**，不粉饰。要绿须先修那两个独立缺陷，那超出本特征边界（文件组织与文档）。
