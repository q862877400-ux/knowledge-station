## 一、要解决的问题

**你现在知道：用大白话提问，一半以上找不到正确条文。**

**但你不知道【是在哪一步丢的】。**

丢法有四种，**修法完全不同**：

| 如果丢在 | 说明 | 该修哪儿 |
|---|---|---|
| **合并那一步** | 各条路本来都找到了，合起来反而丢了 | 改合并规则。**换模型没用。** |
| **现在用的快速索引** | 精细地找能找到，走现在的索引就找不着 | 调索引参数。**换模型没用。** |
| **好几个环节** | 从第一环就开始丢 | 从最先丢的那环动手 |
| **连精细地找都找不到** | **模型根本不认识**这个意思 | **这才能轮到"换个模型"** |

**⇒ 这个计划就是把"哪一种"测出来。测出来之前，任何改动都是猜。**

---

## 二、怎么测（四种找法）

**你手上有一批问题，每条你都知道正确答案是哪一条条文。**

**拿这些问题，分别用四种办法去找，看每条在哪种办法下能找到：**

| 找法 | 用大白话说 |
|---|---|
| **第一种：只按字找** | 像 Ctrl+F，字面对不上就找不到 |
| **第二种：按意思找·精细版** | 一个一个比，慢，但最准。**它代表"模型到底认不认识这句话"** |
| **第三种：按意思找·现在线上用的那套** | 走你现在实际在跑的那套快速索引 |
| **第四种：全部合起来** | 线上最后给你的那个结果 |

**⇒ 第四种 = 用户实际遇到的情况；第二、三种是用来"夹出"问题在哪的。**

---

## 三、为什么第二种最关键

**它是分界线：**

```
第二种都找不到        ⇒ 模型不认识 ⇒ 才轮到"换模型/换表示"
第二种能找到、
但第三种找不到        ⇒ 模型认识，是【索引】把答案弄丢了 ⇒ 只调索引
第二种、三种都找到、
但第四种丢了          ⇒ 是【合并】弄丢的 ⇒ 只改合并
```

**⇒ 一句话：只要第二种能找到，就【不许】说"该换个更好的模型"。**

**⚠ 这正是这个计划最想挡住的一个错误判断** —— 因为"换个模型"听起来最像解法，但很可能是白费力气。

---

## 四、怎么算做成了

**只有一个标准：**

> **能明确说出"丢在哪一步"，而且必须是上面四种之一。**
> **不接受"好像哪都不太行"这种结论。**

外加几条硬的：

- 那批问题的**答案必须是人工确认过的**（不能用自动生成的答案——那样整份结论都不作数）
- 同一套设置**跑两次结果要一样**（不一样说明环境有问题，不是"正常波动"）
- **每一步改动只能改一处**，而且**开跑前先定好"涨多少算有用、涨多少算白干"**
- **结论必须能挂回具体数据**，不能是印象

## 五、六步验收（大白话）

| 步 | 做什么 | 看到什么算过 |
|---|---|---|
| **1** | 查那批问题的答案有没有抄错 | 抄错的能被抓出来 |
| **2** | 先拿 20 条跑一遍 | 能出一道表，每条都看得出"在四种办法下能不能找到" |
| **3** | 同一批再跑一遍 | 两次结果一样 |
| **4** | 按类型分开看（短条文 / 字面对不上的 / 带标准号的 / 普通的） | 每一类都能单独出数 |
| **5** | 汇总 | **能说出"丢在哪一步"** |
| **6** | 改一处，再跑一遍 | 前后一对比，知道这一处改动有没有用 |

## 六、⚠️ 一件必须提前告诉你的事

**第二种找法（"精细版"）本仓到底能不能单独跑起来，我还没确认。**

- **能跑** ⇒ 按上面那套判读走
