# Feature Specification: gov-qa 合规收口与目标达成

**Feature Branch**: `005-govqa-conformance`

**Created**: 2026-10-10

**Status**: Draft

**Input**: 业主指令「你先列个施工计划然后按照spec规范持续自动施工，直到你完成这个模块开始设定的目标」

---

## 背景：为什么需要这个特性

`tools/gov-qa/` 由另一个 Agent 在 2026-10-07 至 10-10 建成：4 天 297 个提交、
345 个适配器、39.5 万条数据、888.7 MB。技术上局部扎实（增量轮询、覆盖口径修正都是真活），
但它**从未按本仓规范验收过**。Lead 的独立诊断（`docs/GOVQA-DIAGNOSIS-2026-10-10.md`）
用实测确认了四处硬伤：

1. **完全在门禁之外**：`scripts/run-gates.ps1` 十二步无一涉及它；
   根 pytest `testpaths=["tests"]` 不收它；它自己的闸门在 `D:/AI/output/check.sh`——
   **那个目录不是 git 仓库**，无历史、无回退。
2. **297 个提交零独立复核**：仓内 14 份 `VERIFY-REPORT` 无一把它当被验对象。
3. **"质量全绿"是假绿**：闸门报 `TOTAL=394944 EMPTY=0 DUPS=0 COVERAGE=100`，
   但同一份数据上独立复现出 **8,462 条内容重复**、**`xz-lasa` 全源 1,030 条空答复**、
   **`ln-8890` 7,807 条时间倒置**；且**实测证明**：注入 `ImportError` 使 `ADAPTERS=0` 时，
   闸门判据②仍报绿。
4. **采的东西 98% 不是业主当前口径**：口径收窄到"法规/国标/办法/条例公告"后，
   在今天的 39.5 万条上命中率仅 **1.95%**，而这条事实**只写在 GOAL.md 的散文里**，
   没进任何以退出码说话的判据。

**这个特性的目标不是"再多采几条"，而是把这个模块从"能跑的一次性机器"
变成"本仓规范的合格成员 + 目标可验证地达成"。**

### 关于"完成这个模块开始设定的目标"的口径（先讲清，不回避）

`D:/AI/output/GOAL.md` 定义了四条主线，逐条核过实际状态：

| 主线 | 原判据 | 实测状态 | 本特性能否"完成" |
|---|---|---|---|
| **M1 通道打通** | 每个来源有可复跑 adapter，**且登记了「自报总量 + 上次落盘量」** | 345 个 adapter 里**只有 37 个**登记了自报总量（`recon/targets.json`），**308 个缺** | ✅ **能**：补齐 308 个登记是可做完的工程 |
| **M2 存量采集** | 每通道存量采到 ≥90%（或触 cap） | 37 个有目标的源里，多数完成度低 | ⚠ **只能推进，不能做完**：依赖对数百个政府网站的实时抓取 |
| **M3 标签分类** | 覆盖率 ≥90% | 覆盖率已 99.96%，但**准确率从未测过**（人工样本 191 行、已填 **0 行**） | ⚠ **需业主**：准确率只能人工核 |
| **M4 覆盖面扩张** | 31 省 + 333 地级市 + 部委 + 人大 + 第三方，逐个有来源 | 省级铺满；地级市按数据口径 **152/334** | ⚠ **只能推进，不能做完**：同 M2，网络bound |
| **spec 004 可运维化** | US1–US4 四条 | 代码已落地，58 测试全过 | ✅ **能**：需补的是**验收与门禁接入**，不是重写 |

**⇒ 诚实结论**：M1 与 spec 004 可以做到完成；M2/M4 是**长周期网络采集**，
任何一轮都只能推进、不能宣布"做完"（这正是 GOAL.md 写"一直跑"的原因）。
本特性的验收因此分两类：**可完成的做到底**，**长周期的给出可验证的推进量与诚实状态**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 这个模块进得了门禁，坏了当场报红 (Priority: P1) 🎯 MVP

作为仓库维护者，我要让 `tools/gov-qa` 被本仓**唯一门禁**覆盖，
这样它的 58 个测试和 4 项质量判据不再靠"人记得跑"。

**为什么最优先**：这是其余一切的前提。没有它，后面修的每个缺陷都无法防止回退，
"改好了"也只是我说了算。

**Acceptance Scenarios**:

1. **Given** 干净的树，**When** 跑 `pwsh -File scripts/run-gates.ps1 -Full`，
   **Then** 输出里出现 gov-qa 的测试步骤且通过，退出码 0。
2. **Given** 我故意改坏 `poll.py` 的幂等逻辑，**When** 跑门禁，
   **Then** 门禁**当场报红**且指名是哪个测试（判据有牙）。
3. **Given** 适配器注册表整体导入失败，**When** 跑门禁，
   **Then** **报红**（现状是假绿——这是本特性必须消灭的行为）。
4. **Given** 语料里出现答复为空、内容重复、时间倒置，**When** 跑门禁，
   **Then** **报红**并指出是哪一类、哪个源。

---

### User Story 2 - 已实证的静默数据缺陷被修掉，且被测试钉住 (Priority: P1)

作为数据使用者，我要那些"字段非空但内容是垃圾"的记录不再混进语料。

**Acceptance Scenarios**:

1. **Given** `xz-lasa` 的 1,030 条空答复，**When** 修完，
   **Then** 该源答复非空率 ≥90%，或该源被明确移出并登记原因。
2. **Given** 8,462 条内容重复（id 不同），**When** 修完，
   **Then** 内容去重后有唯一 `(question, answer)` 的记录数被登记，且新增判据能钉住回退。
3. **Given** `ln-8890` 的 7,807 条 `answered_at < asked_at`，**When** 查明根因，
   **Then** 要么修好字段映射，要么登记"该源时间字段不可用"的结论与证据。
4. **Given** 每一处修复，**When** 我做变异验证（改坏 ⇒ 测试必红），
   **Then** 记录红/绿证据。

---

### User Story 3 - M1 补齐：345 个通道都有"自报总量"，能被一次轮询验增量 (Priority: P2)

作为运营者，我要知道**每个通道应该有多少条**，否则"采完了没有"永远是个感觉。

**Acceptance Scenarios**:

1. **Given** 345 个适配器里 308 个没有自报总量，**When** 补齐，
   **Then** 覆盖率从 37/345 提升，且每个新增登记都带**来源**（接口字段 / 枚举 / 实测）。
2. **Given** 任一通道，**When** 跑 `poll.py --channel <key>` 两次，
   **Then** 第二次新增 0 且不重复（spec 004 的 US1 在真数据上被验证，不只是单测）。

---

### User Story 4 - 口径收窄变成判据，不再只活在散文里 (Priority: P2)

作为业主，我要"这批数据里有多少是我现在要的"这件事**以退出码说话**，
而不是靠我翻 GOAL.md。

**Acceptance Scenarios**:

1. **Given** 当前语料命中率 1.95%，**When** 跑口径判据，
   **Then** 输出机器可读的命中数/命中率，且**低于阈值时非零退出**。
2. **Given** 口径索引与语料 source 命名不一致（实测精确命中 0/7,879），**When** 修好连接，
   **Then** 能按 `(source, id)` 把索引与语料对上，或登记"对不上"的确切原因。

---

### User Story 5 - 长周期主线（M2/M4）有可验证的推进量与诚实状态 (Priority: P3)

作为业主，我要能一眼看出"这轮到底多采了多少、还缺什么"，
而不是一个笼统的"在跑"。

**Acceptance Scenarios**:

1. **Given** 一轮采集，**When** 收工，**Then** 新增条数、涉及源、耗时被机器可读地记下。
2. **Given** 无法在本轮做完的部分，**When** 我写状态，**Then** 明确写"未做/做到几成"，
   不写"基本完成"这类无判据的话。

---

### Edge Cases

- **并发写**：另一个 Agent 的 `igi-chunked.py` 仍在跑（实测 07:54 还在写 `gx-igi-*.jsonl`）。
  任何修改必须避开这些文件，或先停进程——否则会造出重复 id（模块自己铁律第 4 条）。
- **`.git` 已 2,248 MB**，其中 1,953 MB 是一个孤儿临时对象。
  往 git 里再加 588 MB 级数据之前必须先处理。
- **测试污染真实数据**：spec 004 自己踩过（往真实 `data/` 写了 `fake-1-fake.jsonl`）。
  新增测试必须隔离输出目录。
- **GBK 控制台**：`audit-coverage.py --answers/--targets/--fields` 在本机**实测崩溃**
  （`UnicodeEncodeError` rc=1）。机器可读输出必须走 `ascii_kv`。
- **判据不能恒真**：新增的每一项判据都必须做变异验证。

## Requirements *(mandatory)*

### Functional Requirements

**FR-001** 本仓门禁 MUST 覆盖 `tools/gov-qa` 的测试（跑得到、看得见、退出码说了算）。
**FR-002** 适配器注册表导入失败 MUST 使门禁报红（消灭 `ADAPTERS_ERR` 假绿）。
**FR-003** 门禁 MUST 新增四项数据质量判据：答复非空率、内容重复、时间序、标签口径。
**FR-004** 标签覆盖率 MUST 只有一个出处；`health.py` 与 `label-coverage.py` MUST 同值。
**FR-005** `xz-lasa` 空答复 MUST 被修复或该源被移出并登记原因。
**FR-006** 内容重复 MUST 有判据钉住，且不因新增数据而静默回退。
**FR-007** `ln-8890` 时间倒置 MUST 查明根因并给出处置。
**FR-008** 每个适配器 MUST 登记自报总量（或登记"该站不提供总量"的确切原因）。
**FR-009** 口径命中率 MUST 以机器可读 + 退出码形式表达。
**FR-010** 唯一闸门（现 `D:/AI/output/check.sh`）MUST 纳入版本控制。
**FR-011** `.round-floor` 的更新 MUST 有机械动作，不靠人记得。
**FR-012** 交接文档 §11 的错结论 MUST 就地更正并留痕（保留错话 + 更正在后）。
**FR-013** 本特性的每一项新判据 MUST 做变异验证（改坏 ⇒ 必红）。
**FR-014** 不得破坏另一 Agent 正在写的文件；冲突面 MUST 先隔离再动。

### Key Entities

- **适配器登记项**：key / 站点 / 层级 / 自报总量 / 总量来源 / 上限 cap。
- **数据质量判据**：名称 / 阈值 / 当前值 / 涉及源 / 退出码。
- **口径命中**：语料记录 / 命中分类 / 命中层级 / 判定依据。
- **门禁步骤**：名称 / 命令 / 通过判据 / 失败含义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** `pwsh -File scripts/run-gates.ps1 -Full` 退出码 0，且输出中**含 gov-qa 测试步骤**（现为 0 处）。
- **SC-002** 注入 `ImportError` 破坏适配器注册表 ⇒ 门禁**报红**（现为假绿）。
- **SC-003** 四项新判据各自做一次变异 ⇒ **4/4 报红**。
- **SC-004** 门禁跑一次的总耗时不超过现状 +60 秒（不能慢到没人愿意跑）。
- **SC-005** 答复非空率：全库 ≥99%，且**没有任何一个源 <90%**（现 `xz-lasa` 为 0%）。
- **SC-006** 内容重复：登记修复前后的确切条数（现 8,462 条 / 5,642 组），修复后为 0 或登记为何不为 0。
- **SC-007** 适配器自报总量覆盖率从 **37/345 = 10.7%** 提升到 **≥300/345 = 87%**。
- **SC-008** 标签覆盖率：`health.py` 与 `label-coverage.py` **输出同一个数**（现 99.2 vs 100.0）。
- **SC-009** 口径判据输出机器可读的命中率（现 1.95%），且阈值可配、低于阈值非零退出。
- **SC-010** `check.sh` / `GOAL.md` 进入 git（现 `git ls-files` 为空）。
- **SC-011** 独立复核：冻 tag + 提取树 + 报告字节级入库（现 297 提交 0 复核）。
- **SC-012** 每一处"已验"宣称都能指出当次真跑的命令与输出；未做的写"明确未做"。

## Assumptions

- 业主的"完成这个模块开始设定的目标"= GOAL.md 的 M1–M4 + spec 004，**按原目标口径**验收；
  口径收窄与 M1–M4 的冲突**登记为判据项**（FR-009），不静默忽略。
- M2/M4 是长周期网络采集，本轮给出**可验证的推进量与诚实状态**，不宣布"做完"。
- 另一 Agent 的 `igi-chunked.py` 进程**不擅自杀**；先按文件隔离，需要时再请业主裁决。
- 现有 35 万条非合规数据的**处置**（删/留/隔离）需业主裁决，本特性只做**索引与判据**，不删数据。
