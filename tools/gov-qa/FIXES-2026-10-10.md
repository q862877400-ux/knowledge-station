## T201 · `xz-lasa` 全源 1,030 条答复为空

**症状**：`data/xz-lasa-拉萨市·来信选登.jsonl` 里 **1,030 条答复全是空串（100%）**，
而条数、标题、时间、部门都正常。旧闸门只看条数 ⇒ **完全看不见**。

**根因（实测，非推断）**：适配器从**列表**接口取答复
（`it.get("replyContent") or it.get("content")`），
但列表接口 `/frontMail/mailList` 返回的 25 个字段里
**既没有 `replyContent` 也没有 `content`**：

```
id / operateId / fromName / objectiveType / contentType / deptName / title /
createTime / seeTime / status / isPublic / isOverDue / overDueDate / isUrge /
isDel / isPublish / sourceId / siteName / rowNum / serialNumber /
isShowFromInfo / nextOperateDept / mailInfoStatus / symbol / replyTime
```

**真答复在详情接口**，且**参数名是 `mailId` 而不是 `id`**（实测：
传 `id` ⇒ `errorCode 99001` 参数校验失败；传 `mailId` ⇒ `status=success`）：

```
GET /communication/api-mailbox/frontMail/detail?mailId=<id>
→ data.content                       = 来信正文（问题）
  data.replyContents[].replyContent  = 答复正文   ← 要的就是它
  data.replyContents[].replyTime     = 答复时间
```

**处置**：改适配器为「列表取元数据 + 逐条取详情补答复」，并加了进度日志
（本模块为此踩过 5 次坑：明细阶段静默会被误判成"站点节流"）。
**旧文件已删（另有备份），重采 1,031 条。**

**代价**：每条约 1.2s ⇒ 1,031 条约 20 分钟。

## T202 · `ln-8890` 时间字段用错（7,807 条 100% 倒置）

**症状**：`source=ln-8890` 的 **7,807 条 100% 时间倒置**（`answered_at < asked_at`）。

**根因（实测三件事）**：

| 证据 | 数值 | 说明 |
|---|---|---|
| 同一分钟的记录数 | **4,946 / 7,807 = 63.4%** 挤在 `2026-01-23 08:16` | 折合 **82 条/秒** |
| `answered_at` 格式 | 100% 是纯日期 `YYYY-MM-DD`（无时分秒） | 字符串比较必然判倒置 |
| 对照组 | 同文件 `source=ln-8890-kb` 的 13,941 条**零倒置** | 问题只在这条路径的字段选择 |

⇒ `createTime` 是**入库/批量发布时间**（群众不可能 82 条/秒提问）；
`finishDate` 是**纯日期办结日**。**本源没有可靠的提问时刻。**

**处置**：
- `asked_at` → `None`（**不许拿发布时间冒充提问时刻**）
- 原值移入 `extra.record_publish_time`，加 `extra.time_fields_note` 说明
- `answered_at` 保留（`finishDate`，精度只到天）
- 已就地修正 7,807 条；修前备份 `D:/AI/output/_ln8890-before-t202.jsonl`（30,772,615 B）

## ★ 我自己犯的错（就地更正，保留）

### 错话：我把"倒置 20,131 条"当成真缺陷

第一版 `gate-quality.py` 用 **`str(answered_at) < str(asked_at)` 裸比字符串**，
报出 **20,131 条"时间倒置"**。逐条看下来**大半是假阳性**，三种形态：

| 形态 | 例子 | 为什么假 |
|---|---|---|
| Java `Date.toString()` | `Thu Oct 19 …` vs `Fri Oct 20 …` | 字母序 `Fri` < `Thu`，但 10-20 晚于 10-19（`nat-tax` 5,720 条全是这个）|
| 分钟截断 | `15:02:00` vs `15:02` | 同一分钟，短串排前面 |
| 中文日期 | `2026年09月7日` vs `2026年09月09日` | `"7" > "0"`，但 9-7 早于 9-9 |

**更正**：改为**先解析成 `datetime` 再比**，并容忍同分钟内的截断（60 秒）。
**解析后**：20,131 → **3,397**（其中 `ln-8890` 的 7,807 条已由 T202 修掉）。

**教训**：**判据本身也要被验证** —— 我第一版判据是"有牙的"（变异会红），
但它**判错了对象**：牙咬在了字符串上，不是时间上。
"有牙" 与 "咬对了" 是两件事。

### 错法：T111 变异脚本用 `git checkout` 还原**未跟踪**文件

`gate-quality.py` 当时未进 git ⇒ `git checkout` 是**空操作** ⇒ 6 处变异累积在文件里。
