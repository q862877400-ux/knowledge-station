fix(govqa): nat-mohurd 空 question 迁移完成 —— 230 条 → 1 条

## 为什么要「迁移」而不是「重采」

采集器的 id 是**内容指纹** `md5(question|asked_at|answer|user)`。
`question` 从空变成有内容 ⇒ **指纹变了 ⇒ 新 id** ⇒ 重采会与旧记录**并存**，
形成「同一问答两条记录」的内容重复。

⇒ **必须做替换迁移**：按「不依赖 question 的键」匹配新旧，用新替旧。

**匹配键 = `(answer, asked_at, user)`** —— 不含 question（那正是要修的字段）。

## 迁移脚本（`recon/migrate-mohurd-q.py`）

按宪法 V「留痕不许悄悄删」：
1. 迁移前**强制备份**到 `state/migration-backup-<ts>.jsonl`
2. 每条替换记录写 `extra.migrated_from`（原 id）+ `extra.migrated_at`（★ 可回溯）
3. **不删任何东西** —— 匹配不上的旧记录原样保留
4. 保留原有的标签字段（避免重跑分类器）

## 实测结果

```
迁移前：question 非空 361,822-... / 问题为空但答复有内容 230 条
迁移后：question 非空率 100.00%（361,822 / 361,823）
        问题为空但答复有内容：**1 条**（原 230 条）
        nat-mohurd 文件 671 行 → 670 行（替换时去重了 1 条）
```

**230 → 1**，剩 1 条是重采时该条目已不在源站（匹配不上，按纪律保留）。

## ★ 一条数据迁移的通用做法

> **改「参与 id 生成的字段」时，必须做替换迁移，不能只重采。**
> 否则新 id 与旧 id 并存 ⇒ 内容重复。
>
> 匹配键要选**不依赖被改字段**的那些字段。
