## 西藏自治区（`xizang.gov.cn`）

**探测入口**：`http://www.xizang.gov.cn`（HTTP 200，len=116497）

**找到的入口**：

| 栏目 | 地址 | 判定 |
|---|---|---|
| 我要写信 | `http://xzxf.xizang.gov.cn/ocp/wsxx.html` | ❌ **需登录** |
| 西藏政务服务网 | `https://www.xzzwfw.gov.cn/` | 待探 |

**信访平台的实测结论（判死）**：

```
HTTP 200 len=20961
相对路径: ['/oauth/login.html', '/oauth/logout.html', '/oauth/register.html',
           '/oauth/user/center.html', '/ocp/personal.html', '/ocp/user.html']
```

⇒ **这是「一站式信访平台（OCP）」，只有提交入口，没有公开的来信选登列表。**
所有功能路径都指向 `/oauth/login.html` —— **未登录拿不到任何问答数据**。

**判定：与国家信访局同类 —— 提交型，无公开列表。不再投入。**

⚠ 但注意：本站首页有 `/catalog/*.html` 形式的文章链接 —— 说明门户本身有内容。
**西藏不是「完全没有政务信息」，而是「没有公开的政民互动问答列表」。**

## 甘肃省（`gansu.gov.cn`）

**探测结果**：

```
http://www.gansu.gov.cn   HTTP 412 len=6321
https://www.gansu.gov.cn  HTTP 412 len=6381
```

**HTTP 412 = Precondition Failed** —— 典型的 **WAF（Web 应用防火墙）反爬**。
两种协议、两次请求都被拦，响应体只有 6KB（是拦截页，不是内容页）。

**判定：需要绕过 WAF 才能探。当前不投入。**

**绕过思路（留给下一轮）**：
1. 加 `Referer` / `Origin` / `Sec-Fetch-*` 等浏览器头
2. 先请求首页拿 Cookie，再带 Cookie 请求目标页
3. 找移动端 / 小程序接口（通常 WAF 宽松）
4. 找该省的**地市级**门户（WAF 通常只在省级部署）

## 通用结论

> **「某省 0 条」有三种原因，处置完全不同：**
>
> | 原因 | 特征 | 处置 |
> |---|---|---|
> | **没有公开问答渠道** | 信访平台需登录 / 只有提交入口 | **判死**，不再投入 |
> | **有渠道但被反爬拦** | HTTP 403 / 412 / 验证码 | 需绕 WAF，成本高 |
> | **有渠道但我们没探到** | 能找到但入口隐蔽 | **值得继续探** |
>
> **不区分这三种，就会在「判死」和「待办」之间反复摇摆。**
> `coverage-report.py` 的 `--uncovered` 只告诉你「缺什么渠道」，
> **不告诉你「为什么缺」** —— 本文件补的就是这一层。
