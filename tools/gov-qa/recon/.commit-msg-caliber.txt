fix(govqa/US2): 销号表加「含下属市」口径 —— 修「甘肃 0 条」这类误判

## 问题

销号表报「**甘肃 0 条**（`none` 单元）」，但实际甘肃已有 **4 个市级源共 9,659 条**：

```
gs-baiyin  1,875   gs-dingxi  757   gs-longnan  414   gs-zhangye  6,613
```

**原因：省级口径只统计 `level=province` 的通道** —— 甘肃的源全是地市级，
所以省级行显示 0。同样问题也出现在「山东 89 条」（它有 220 个省级通道，
但烟台等市级通道算到地级单元去了）。

⇒ **「省级 0 条」不等于「这个省没数据」**，这个口径会严重误导补采优先级。

## 修法：两个数都给

| 字段 | 含义 | 用途 |
|---|---|---|
| `total_records` | **只算本级通道** | 回答「省级门户本身有多少」 |
| `total_incl_cities` | **含下属地级市** | 回答「这个省总共有多少」 |

**状态判定改用 `total_incl_cities`**（含下属市）——
否则「省级门户没建但地市级都有」的省会被误判为 `none`。

CLI 输出也改了：

```
吉林省   本级 2,660  含下属市 2,660  还差 340 条
海南省   本级 2,241  含下属市 2,241  还差 759 条
河北省   本级 1,081  含下属市 1,081  还差 1,919 条
```

## ⚠ 已知局限（写进代码注释）

`_province_of_city()` **做不到精确** —— 中国有 300+ 地级市，硬编码映射不现实。
目前只处理「能从市名直接看出省」的情况，**其余返回 None（不汇总）**。

⇒ **`total_incl_cities` 对多数市会偏低。** 要精确需要一份「市→省」的行政区划表（下一轮补）。

## 修了一个自己引入的 bug

第一次改时逻辑写成「两个都为 0 才补默认值」，导致单独构造的 `CoverageUnit`
（`total_records > 0` 但 `total_incl_cities` 未设）算出 `gap` 全错 ——
`test_gap_calculation` 和 `test_meets_threshold_is_ok` 两个测试立刻抓到。

⇒ 改成「`total_incl_cities` 不得小于 `total_records`」。

**测试：50 passed in 2.37s**
