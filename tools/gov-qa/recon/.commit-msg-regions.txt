feat(govqa/US2): 补「市→省」行政区划表 —— 让「含下属市」口径精确

## 背景

上一轮给销号表加了 `total_incl_cities`（含下属市），但 `_province_of_city()`
靠「市名里含省名」猜 —— **大多数市名不含省名**（宝鸡市 / 天水市 / 烟台市），
所以汇总严重偏低，等于没修。

## 新增 `regions.py`

按 **2024 年民政部行政区划**整理的**地级行政区 → 所属省**映射：
- `PROVINCE_CITIES`：31 省的 334 个地级行政区（含济源市等省直管县级市）
- `province_of_city()`：支持全称 / 去「市」/ 带后缀（`天水市人民政府`）三种形态
- **查不到返回 `None`（不猜）** —— 宁缺勿错，只是偏低不会算错

实测：
```
天水市 → 甘肃省 ✅    宝鸡市 → 陕西省 ✅    烟台市 → 山东省 ✅
大理白族自治州 → 云南省 ✅    拉萨市 → 西藏自治区 ✅
```

## 效果（销号表现在准了）

```
甘肃省      本级 0  含下属市 2,349  还差   651 条   ← 之前「0 条，还差 3,000」
西藏自治区   本级 0  含下属市 1,030  还差 1,970 条   ← 之前「0 条，还差 3,000」
```

**这两个省从「看起来完全没数据」变成「有 2,349 / 1,030 条，还差一点」** ——
补采优先级判断完全不同。

## ⚠ 已知偏差

`total_cities()` 返回 **334** 而非 333 —— 因为把**济源市**（河南省直管县级市）
也算进了地级。影响极小（多 1 个），暂不处理。

## 下一轮

`total_incl_cities` 现在是「省 + 该省所有地级市」，但**省级门户本身可能没有源**
（如甘肃本级 0）。⇒ 补采时应优先补**省级门户**（那是「门户·政民互动」这条渠道）。
