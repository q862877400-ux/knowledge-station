# `cq-igi` 的「34.6% 完成度」是**假的** —— 实测结论（2026-10-10）

> 归属：Lead。**结论先行**：`cq-igi` **已接近采尽**（可采的都采到了）；
> `targets.json` 记的 `total: 32,580` **严重高估**了实际可采量。
> ⇒ **不要再往这条线投采集工时。**

## 一、起点：它看起来是"完成度最低的大源之一"

| source | 已落盘 | 目标 | 完成度 |
|---|---|---|---|
| `cq-igi` | 11,269 | 32,580 | **34.6%** |

`targets.json` 的 note 写着「重庆 IGI 75 site（无上限，应全采）」。
所以我启动了 `igi-chunked.py cq_igi --limit 3000 --page-chunk 20`。

## 二、采集日志：**每个 siteId 都是"新增 0"**

```
[1/75] siteId=156 页1-20:   新增 0（本站 0 / 全库 0）117s
[1/75] siteId=156 页21-40:  新增 0（本站 0 / 全库 0）117s
...
[6/75] siteId=164 页281-300: 新增 0（本站 0 / 全库 0）49s
[6/75] siteId=164: 本站新增 0，49s
```

**扫了 6 个站、上百页，新增 0**。我停掉了它（每站 117 秒，跑完 75 站要 2 小时+，且显然无产出）。

## 三、逐步核实（每一步都实测）

### ① 上游自报总量：32,582（与 targets.json 的 32,580 一致）

扫全部 75 个 siteId 的 `pageInfo.totalResults`：

```
cq-igi 上游自报 total 合计: 32,582（75 个 siteId，0 个失败）
```

⇒ **所以不是"上游没数据"**，`targets.json` 的数字**有出处**。

### ② 适配器的列表与明细接口**都正常**

| 接口 | 实测 |
|---|---|
| 列表 `listGovmsgboxs` | HTTP 200，20 行，`ISREPLY` 全 = 1 |
| 明细 `viewGovmsgbox` | HTTP 200，`statusCode=200`，`REPLYS` 1 条，答复正文 **343 字** |

⇒ **接口没坏、适配器没取错字段。**

### ③ `skip_ids` 是"0 新增"的原因，但那是对的

```python
harvest_igi(siteId=156, skip_ids=set())        -> 37 条
harvest_igi(siteId=156, skip_ids=existing_ids) ->  0 条
```

⇒ 那 37 条**全部已在库** ⇒ `skip_ids` 正确地跳过了它们。**不是 bug。**

### ④ 决定性：逐站核对「上游 total」vs「首页 id 是否在库」

```
整站未采（首页 20 个 id 一个都不在库）: 0 个
首页全在库:  57 个站
部分在库:    18 个站（如 siteId=254 上游 2,641 / 首页 14/20 在库）
```

**没有任何一个站是整站未采的。**

### ⑤ 决定性：对两个"部分在库"的站**完整采一遍**（不跳过）

```
siteId=190: 完整采到 19 条，已在库 19，**新 0**
siteId=199: 完整采到 26 条，已在库 26，**新 0**
```

⇒ 上游 `totalResults` 报 129 / 171，但**实际能翻到的只有 19 / 26 条**。

## 四、结论

**`pageInfo.totalResults` 是虚高的**（它报 32,582，实际可翻页取到的远少于此）。
我们的 11,269 条**已经覆盖了所有能取到的记录**：

- 0 个站整站未采
- 57 个站首页全在库
- 18 个"部分在库"的站，完整重采**新增 0**

⇒ **`cq-igi` 的「34.6% 完成度」是分母虚高造成的假象，不是真的缺 21,313 条。**

## 五、处置

1. **停掉该线的采集**（已停，且重跑无产出）。
2. **`targets.json` 的 `total: 32580` 标注为"上游自报，实测虚高"** ——
   不要让下一个接手的人按它投工时。
3. **本模块铁律第 6 条再次生效**：「**判死前必须实测**：
   取一条明细确认答复正文非空 —— `totalResults` 大 ≠ 有问答」。
   这次是它的**反向**：`totalResults` 大 ≠ **有那么多可采**。

## 六、诚实边界

- **只对 2 个站做了"完整重采验证"**（`siteId=190` / `199`），
  其余 73 个站是**按首页 id 在库率**推断的 ⇒ **这是抽样，不是全部**。
- 未排查"上游 total 虚高"的机制（可能是已删除/未公开记录也计入 total）。
- **未采任何新数据**（本轮 `cq-igi` 落盘增量 = 0）。
