docs(govqa): 薄省探测记录 —— 西藏/甘肃判死依据 + 「为什么缺」的分类

## 背景

`coverage-report.py` 报出 **西藏 0 条 / 甘肃 0 条**（`none` 单元）。本轮探了这两个省，
把结论写成 `recon/THIN-PROVINCES-NOTES.md`，**避免以后重复投入**。

## 实测结论

### 西藏 —— 判死（提交型，无公开列表）

- 找到「我要写信」→ `http://xzxf.xizang.gov.cn/ocp/wsxx.html`
- 实测：HTTP 200，但所有功能路径都指向 `/oauth/login.html`
  （`/oauth/logout.html` / `/oauth/register.html` / `/ocp/personal.html` …）
- ⇒ **一站式信访平台（OCP），只有提交入口，未登录拿不到任何问答数据**
- 判定：**与国家信访局同类，不再投入**

⚠ 但注意：本站首页有 `/catalog/*.html` 文章链接 ⇒
**西藏不是「完全没有政务信息」，而是「没有公开的政民互动问答列表」**。

### 甘肃 —— 被 WAF 拦

```
http://www.gansu.gov.cn   HTTP 412 len=6321
https://www.gansu.gov.cn  HTTP 412 len=6381
```

HTTP 412 = WAF 反爬，响应体只有 6KB（拦截页）。两种协议都被拦。

**绕过思路（留给下一轮）**：先请求首页拿 Cookie + 完整浏览器头 / 找移动端接口 /
**试地市级门户**（WAF 通常只在省级部署）。

## ★★ 通用结论（这是本轮最有价值的部分）

> **「某省 0 条」有三种原因，处置完全不同：**
>
> | 原因 | 特征 | 处置 |
> |---|---|---|
> | **没有公开问答渠道** | 信访平台需登录 / 只有提交入口 | **判死**，不再投入 |
> | **有渠道但被反爬拦** | HTTP 403 / 412 / 验证码 | 需绕 WAF，成本高 |
> | **有渠道但我们没探到** | 能找到但入口隐蔽 | **值得继续探** |
>
> **不区分这三种，就会在「判死」和「待办」之间反复摇摆。**

`coverage-report.py --uncovered` 只告诉你「**缺什么渠道**」，
**不告诉你「为什么缺」** —— 本文件补的就是这一层。
