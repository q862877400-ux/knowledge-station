# gov-qa 的唯一闸门（纳管说明）

> 2026-10-10 新建。本目录是**仓外闸门的版本控制副本**。

## 为什么有这一层

`tools/gov-qa` 从 2026-10-07 建到 10-10（4 天 297 个提交），
它的**唯一质量闸门**一直是 `D:/AI/output/check.sh` —— 而 `D:/AI/output/` **不是 git 仓库**。

后果：那个决定"质量是否全绿"的脚本**没有历史、没有回退、没有任何评审痕迹**。
本仓的纪律是"门禁即代码、以退出码为准"，而这个模块的闸门连版本控制都不在。

## 两份文件的关系

| 文件 | 位置 | 角色 |
|---|---|---|
| `check.sh` | `D:/AI/output/check.sh` | **运行时真源**（Stop hook 实际调用的那份） |
| `check.sh` | 本目录 | **纳管副本**（字节级相同，进版本控制，可 diff、可回退） |
| `GOAL.md` | `D:/AI/output/GOAL.md` | 运行时作业单 |
| `GOAL.md` | 本目录 | 纳管副本 |

**搬运方式**：脚本 + `Copy-Item`，**不是手抄**（本仓纪律：长文档手抄实测 77 行错 2 处）。
两份的 sha256 必须一致；不一致就说明有人在运行时侧改过而没同步。

**同步判据**（应做成机械检查，见 `specs/005-govqa-conformance/tasks.md` T003 的后续）：

```powershell
(Get-FileHash D:/AI/output/check.sh).Hash -eq (Get-FileHash tools/gov-qa/gate/check.sh).Hash
```

## 已知的闸门缺陷（本特性要修，见 spec 005）

1. **能假绿**：适配器注册表导入失败时，指标源打出 `ADAPTERS_ERR=ImportError` + `EMPTY=0`，
   而 `check.sh` 只 `grep '^EMPTY='` ⇒ **判据②报绿**。已实测复现。
2. **四项判据都不覆盖内容质量**：实测同一份数据有 8,462 条内容重复、
   `xz-lasa` 全源 1,030 条空答复、`ln-8890` 7,807 条时间倒置，**闸门全看不见**。
3. **标签口径与 `health.py` 不一致**：闸门用宽口径（含原始脏 `msg_type`）报 100.0，
   `health.py` 只认 `msg_type_norm` 报 99.2。
4. **口径收窄未进判据**：业主已收窄到"法规/国标/办法/条例公告"，
   当前语料命中率仅 1.95%，而闸门在它上面报"质量全绿"。
