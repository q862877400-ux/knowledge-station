## A. 变更监测（暂称：一键更新检查）

| # | 诉求原文（忠实转写） | 功能域标签 | 数值约束 / 键值对 |
|---|---|---|---|
| A1 | 在现有的查法规和审计这两个模块旁边，再加一个模块，叫做「更新」 | 前端UI·导航 / 信息架构 | entry_module_count = 3（查法规/审计/更新） |
| A2 | 一键点击一下，就会自动去把现在库里的文件的国标号放到国家的标准信息公开的那个平台里面去搜 | 外部集成·官方平台 / 后台任务 | trigger = 单次点击（one_click）；查询对象 = 库内全部 standard_no |
| A3 | 看看有没有最新版本的，或者有没有过期了的 | 元数据·版本状态 | 检测维度 = {new_version, expired_or_withdrawn} |
| A4 | 把所有的国标号放到网上去搜，一个一个搜 | 外部集成·通用Web | strategy = per_standard_no_web_search |
| A5 | 搜索 site:gov.cn 加上关键词「关于发布」，就会获取到发布某个国标或者某个法规的链接 | 外部集成·公告检索 | channel_query_tpl = 'site:gov.cn 关于发布 {standard_no|name}' |
| A6 | 有一些微信公众号专注发布法规/标准更新信息，（可作为渠道） | 外部集成·公众号 | source_type = wechat_mp（可行性未验证） |
| A7 | 「反正你就给我想个办法吧」——具体获取方案授权受托方设计 | 授权声明 | design_authority = delegated |
| A8 | 对库中的清单、文件、目录的这些国标进行变更情况的搜索和更新 | 元数据·全库巡检 | scope = {catalog_list, files, directory_tree} |

## B. 相关国标搜索下载（暂称：分类引导找标）

| # | 诉求原文（忠实转写） | 功能域标签 | 数值约束 / 键值对 |
|---|---|---|---|
| B1 | 用户会说我要下载什么相关的国标，根据描述对应到现有分类 | 检索·意图映射 / LLM对话 | input = 自然语言描述 |
| B2 | 分类的追问要比较局限比较小一点：说"安全的国标"太多了，就问它下面分为多少类 | LLM对话·澄清追问 | interaction = 多轮反问收窄 |
| B3 | 问到 3 级或者两级就可以了；问到第 4 级目录就太细了、可能又太少了 | LLM对话·澄清追问 | classification_drill_min_level = 2；classification_drill_max_level = 3 |
| B4 | 问完之后去国家标准的那个网站或刚刚说的地方搜索，找地方下载 | 外部集成·下载 | action = search_then_locate_download |
